## 导读：你到底需要"多会写代码"才能开始？

**答案是：会打字就行。**

## Part 1：环境部署——唯一需要动手的十分钟

<small>这是整个 Vibe Coding 旅程中唯一需要你"操作"的阶段。每一节都配有来自黑马程序员课程的实操截图，跟着做。十分钟后你就可以纯靠嘴写代码了。</small>

### 1.1 终端基础——程序员的"指挥台"

如果你从来没打开过终端，别慌。终端就是一个黑色的文字窗口，你在里面打字，电脑执行。没有鼠标、没有图标——只有你和计算机之间最纯粹的交流。

**Windows 用户**：按 `Win + R`，输入 `powershell`，回车。如果遇到脚本执行权限报错，以管理员身份打开 PowerShell，执行：

```powershell
Set-ExecutionPolicy RemoteSigned -Scope CurrentUser
```

**Mac 用户**：按 `Cmd + 空格`，输入 `terminal`，回车。

几个最常用的终端命令（现在看不懂没关系，用到的时候照着敲就行）：

| 命令 | 作用 | 示例 |
|------|------|------|
| `cd` | 进入某个文件夹 | `cd my-project` |
| `ls` (Mac) / `dir` (Win) | 查看当前文件夹内容 | `ls` |
| `pwd` | 显示当前所在位置 | `pwd` |
| `mkdir` | 创建新文件夹 | `mkdir my-app` |
| `Ctrl+C` | 终止当前运行的程序 | — |

> **💡 小贴士**：终端里 `Ctrl+C` 不是复制，是终止！复制用 `Ctrl+Shift+C`（Windows）或 `Cmd+C`（Mac）。

### 1.2 安装 Node.js——Vibe Coding 的"地基"

Claude Code 基于 Node.js 运行，这是我们的第一块砖。

1. 打开 [nodejs.org](https://nodejs.org)
2. 下载 LTS 版本（Windows 用户选 `.msi`，Mac 用户选 `.pkg`）
3. 安装——全程「下一步」，一个设置都不用改

![Node.js 官网下载页面——选择 LTS 长期支持版本](https://cdn.nlark.com/yuque/0/2026/png/12371070/1781688476363-3d5ac390-3931-4e0e-b055-8244b0b2787c.png)

装完后，打开终端验证：

```bash
node --version   # 应显示 v24.x.x 或更高
npm --version    # 应显示 11.x.x 或更高
```

看到版本号就说明装好了。如果提示"找不到命令"，重启一下终端再试。

> **国内用户加速技巧**：先把 npm 镜像源切到国内，后面安装 Claude Code 会快很多：
> ```bash
> npm config set registry https://registry.npmmirror.com
> ```

### 1.3 安装 Git——你的"后悔药"

Git 是版本控制工具，简单说就是"给代码拍快照"。每次让 AI 大改代码前拍一张，改坏了随时能回到过去。

1. 打开 [git-scm.com](https://git-scm.com)，下载安装
2. 安装全程「下一步」，所有选项用默认值
3. 验证：

```bash
git --version   # 应显示 2.x.x
```

### 1.4 安装 Python——后端的"发动机"

虽然前端用 Node.js，但后续 RAG 项目需要 Python 的 AI 生态（LangChain、ChromaDB 等）。

1. 打开 [python.org](https://python.org)，下载 Python 3.10+
2. **安装时务必勾选「Add Python to PATH」**——漏了这步后面到处报错！
3. 验证：

```bash
python --version  # 应显示 3.10.x 或更高
pip --version     # 应显示 24.x 或更高
```

> **国内用户加速**：切一下 pip 镜像源：
> ```bash
> pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
> ```

### 1.5 安装 Claude Code——Vibe Coding 的"大脑"

终于到主角了。打开终端，敲一行命令：

![Claude Code 安装命令——npm 全局安装](https://cdn.nlark.com/yuque/0/2026/png/12371070/1781687905727-8dccb658-fc53-4050-89f0-adc2437f0ae4.png)

```bash
npm install -g @anthropic-ai/claude-code
```

安装完成后验证：

```bash
claude --version  # 应显示版本号，如 2.1.179
```

> **💡 这里停一下**：如果你出于好奇去搜了 OpenAI CodeX，想用它接 DeepSeek，你会发现自己需要安装 Go 1.25+、克隆 Moon Bridge 仓库、手写三个配置文件（YAML + TOML + JSON）、启动代理服务……等你折腾完这些，用 Claude Code 的同学已经把项目部署上线了。CodeX 不是不能用，但它对第三方模型的支持靠的是社区用爱发电的转发层，每多一层转发就多一层出错的可能。Claude Code 原生支持自定义 API endpoint，三行 JSON 搞定。**结论：省事就用 Claude Code。**

### 1.6 VS Code 集成——在编辑器里指挥 AI

虽然 Claude Code 可以在终端里直接用，但配合 VS Code 体验更好——能在编辑器里直接对话，选中代码一键发给 AI。

![VS Code 扩展市场——搜索并安装 Claude Code 官方插件](https://cdn.nlark.com/yuque/0/2026/png/12371070/1781703637833-33f84232-c8ea-4046-a1bb-475fae685d98.png)

1. 下载安装 [VS Code](https://code.visualstudio.com)（如果还没有的话）
2. 打开 VS Code，点击左侧扩展图标（或按 `Ctrl+Shift+X`）
3. 搜索 `Claude Code`，安装官方扩展
4. 重启 VS Code

装好后，VS Code 侧边栏会出现 Claude Code 图标，点击就能在编辑器里和 AI 对话了。

**实用技巧：**
- 选中代码后按 `Ctrl+Shift+L`（Mac 用 `Cmd+Shift+L`），直接把代码发给 Claude
- Claude 修改代码后，VS Code 会显示 diff 对比，你可以逐行审查

### 1.7 配置 DeepSeek API——把"大脑"接上"云端"

Claude Code 本质上是一个"对话框架"，AI 想写出代码需要一个"有思想的模型"来做支撑，我们选择 DeepSeek V4 Pro，原因很简单：**便宜到令人发指。**

#### 第一步：获取 API Key

1. 打开 [platform.deepseek.com](https://platform.deepseek.com)，注册账号
2. 充值建议：先充 ¥10，够你用很久很久
3. 点击「API Keys」→「创建 API Key」
4. **⚠️ 立即复制保存！API Key 只显示一次！**

#### 第二步：配置 Claude Code

打开（或新建）这个文件：

- **Windows**：`C:\Users\你的用户名\.claude\settings.json`
- **Mac**：`~/.claude/settings.json`

填入以下内容（把 `你的APIKEY` 替换成刚才复制的 key）：

```json
{
  "model": "deepseek-v4-pro",
  "apiKey": "你的APIKEY",
  "baseURL": "https://api.deepseek.com/v1"
}
```

**就这三行。** 没有 Go 环境，没有 YAML，没有代理服务。保存，关闭。

### 1.8 验证一切正常

```bash
cd ~/Desktop
mkdir hello-vibe && cd hello-vibe
claude
```

进入 Claude Code 界面后，输入：

> 你是什么模型？

如果它回答「我是 DeepSeek V4 Pro……」——🎉 恭喜！环境部署完毕！从现在开始，你只需要做两件事：**清楚地表达需求，以及疯狂点 Yes。**

## Part 2：为什么是 Claude Code + DeepSeek？

先说结论：**国内 Vibe Coding 的最优解是 Claude Code + DeepSeek V4 Pro。** 没有之一。

### CodeX vs Claude Code：一篇血泪史

你可能在想——OpenAI CodeX 不是 OpenAI 亲儿子吗？应该更强才对。

好问题。我来帮你梳理一下 CodeX 接入 DeepSeek 需要做什么：

| 步骤 | Claude Code | CodeX |
|------|------------|-------|
| 1. 安装 Node.js | ✅ `npm install -g @anthropic-ai/claude-code` | ✅ 需要 |
| 2. 安装 Go 1.25+ | ❌ 不需要 | ⚠️ **需要**（一个编程 Agent 要你装 Go） |
| 3. 克隆 Moon Bridge | ❌ 不需要 | ⚠️ **需要**（第三方转发中间层） |
| 4. 手写 config.yml | ❌ 不需要 | ⚠️ **需要**（30+ 行 YAML） |
| 5. 手写 config.toml | ❌ 不需要 | ⚠️ **需要** |
| 6. 手写 models_catalog.json | ❌ 不需要 | ⚠️ **需要** |
| 7. 启动代理服务 | ❌ 不需要 | ⚠️ **需要**（保持终端常驻） |
| 8. 配置 Claude Code | ✅ 3 行 JSON | — |
| **总耗时** | **~10 分钟** | **~1-2 小时（顺利的话）** |

**我就想问一句：我一个零基础小白，你让我手写 YAML 配置文件？** 这和我直接学编程有什么区别？

CodeX 本质上是为 OpenAI 生态设计的，对第三方模型的支持靠的是 Moon Bridge——一个社区用爱发电的转发层。每多一层转发，就多一层出错的可能。网络波动 → Moon Bridge 炸了。配置写错一个缩进 → Moon Bridge 起不来。Python 版本不对 → Moon Bridge 起不来。**你连代码都还没写就已经在调试基础设施了。这叫 Vibe Coding？这叫 Vibe Debugging。**

而 Claude Code 原生支持自定义 API endpoint（`baseURL`），不需要任何中间层。三行 JSON，点保存，开干。

**结论：Claude Code 是工具，CodeX 是作业。想省事就用 Claude Code。**

### DeepSeek V4 Pro：AI 编程的拼多多

再来谈钱。这是 DeepSeek V4 Pro 和竞品的定价对比：

| 模型 | 输入价格 (每百万 token) | 输出价格 (每百万 token) | 上下文窗口 |
|------|----------------------|----------------------|-----------|
| Claude Opus 5 | $15.00 | $75.00 | 200K |
| GPT-5 | $12.50 | $50.00 | 128K |
| **DeepSeek V4 Pro** | **¥2.00 (~$0.28)** | **¥8.00 (~$1.10)** | **1,000K (100万！)** |

看清楚了吗？DeepSeek 的输出价格是 Claude Opus 的 **1/68**。

翻译成人话：你用 Claude Opus 原生模型写一个完整项目大约要 $58（≈ ¥420），用 DeepSeek V4 Pro 只要 **¥0.32**。同样的产出，价格差了一千多倍。

而且 DeepSeek V4 Pro 最魔幻的是：**支持 100 万 token 的上下文窗口。** 你可以把一个中型项目的全部代码（几万行）一次性丢给它，它不会"忘记"任何东西。你跟他聊了三小时天了，他还能记得你第一句话说的什么。

Claude Code 配合 100 万 context——这基本上等于给你配了一个过目不忘的天才程序员，时薪三毛二。

**DeepSeek V4 Pro 对 Vibe Coding 的意义，就像拼多多对县城大妈的意义——同样的东西，便宜到不买都觉得亏。**

## Part 3：Claude Code 功能全景——你工具箱里有什么

环境搭好了，模型选好了。在正式动工之前，先认识一下 Claude Code 都有哪些武器。这一节可能信息量大，但**你不需要记住全部——用到的时候回来查就行。**

### 3.1 Vibe Coding 四定律

背熟这四条，能让你少走 90% 的弯路：

**第一定律：你不需要会写代码。** 是的，没看错。但你**必须学会清楚地描述自己想要什么**。模糊的 Prompt = 垃圾产出。

- ❌ "帮我做个 AI 应用"（AI 猜不透你，给你一个 Hello World 糊弄你）
- ✅ "帮我做一个 RAG 个人知识库系统，能上传 PDF/Markdown 文档，用 LangChain 做向量检索，用户可以在浏览器里提问，回答要引用原文片段"（清晰，AI 立刻能规划方案）

**第二定律：Plan Mode 是你的好朋友。** Claude Code 有三种模式：
- **Ask before edits**：每改一行都问你，像个过度谨慎的驾校教练
- **Edit automatically**：直接改，像个急性子的修车师傅
- **Plan mode**：先出方案给你审，像个靠谱的建筑设计师

**强烈建议新手用 Plan Mode。** 因为你可能连自己真正要什么都不知道，让 AI 先帮你理清楚思路——这比自己瞎指挥靠谱一万倍。先规划、再执行，这是 Vibe Coding 最重要的习惯。

**第三定律：Effort 拉满！** Effort 控制 AI 的"思考深度"：

| Effort 级别 | 思考深度 | 适合场景 |
|------------|---------|---------|
| `low` | 快速但敷衍 | 简单问题、格式调整 |
| `medium` | 标准分析 | 日常开发、小功能 |
| `high` | 深度思考 | 复杂重构、架构设计 |
| `xhigh`/`max` | 全面验证 | 安全审计、核心逻辑 |

**拉满。别省。** 你省的那点时间会变成后面十倍的 debug 痛苦。反正你用的是 DeepSeek，token 便宜得跟不要钱一样。

**第四定律：看不懂就让它解释。** 当你看到 `chromadb.Client()` 或 `RecursiveCharacterTextSplitter` 这种东西时，不要恐慌，不要百度。**直接问 Claude Code："这是什么意思？为什么这么设计？"** 它会用你能理解的方式解释，而且永远不会不耐烦。这是 Vibe Coding 最大的隐藏福利。

### 3.2 常用命令速查

Claude Code 通过 **斜杠命令（Slash Commands）** 提供各种功能。在对话中输入 `/` 就能看到所有可用命令。

以下是日常使用频率最高的命令：

| 命令 | 用途 | 使用频率 |
|------|------|---------|
| `/help` | 查看所有可用命令 | ⭐⭐⭐ |
| `/clear` | 清空当前对话历史，重新开始 | ⭐⭐⭐ |
| `/compact` | 压缩对话历史，释放上下文空间 | ⭐⭐⭐ |
| `/init` | 在当前项目生成 CLAUDE.md | ⭐⭐⭐ |
| `/doctor` | 诊断 Claude Code 安装和配置问题 | ⭐⭐ |
| `/config` | 打开当前项目的设置文件 | ⭐⭐ |
| `/statusline` | 终端底部显示持久状态栏（token 用量） | ⭐⭐⭐ |
| `/cost` | 查看当前会话的 token 消耗和费用 | ⭐⭐⭐ |
| `/mcp` | 管理 MCP 服务器 | ⭐⭐ |

**最实用的三个命令详解：**

`/compact` —— 这是你最重要的生存技能。上下文窗口有限，当 Claude 开始忘记你 10 分钟前说的话、响应变慢、东拉西扯时，**立刻执行 `/compact`**。它会压缩历史对话为结构化摘要，释放大量空间。习惯：每 30-50 轮对话主动触发。**不要等 AI "失忆"才抢救。**

`/statusline` —— 在终端底部实时显示任务进度、token 用量、活跃模型。有了它你就不用一直猜"AI 现在在干嘛"了。

`/cost` —— 实时查看费用。适合我们这种对成本极度敏感（或者说"抠门"）的 DeepSeek 用户。每次看到那个几毛钱的数字，安心感油然而生。

> 💡 `!<命令>` 是隐藏技巧——在对话中直接输入 `!npm run dev` 就能启动开发服务器，不用切到终端。

### 3.3 Skills 技能系统——给 AI 装"专业训练"

Skills 是 Claude Code 最被低估的功能。你可以把 Skill 理解为给 AI 装一个"专业训练模块"——装了 `code-review` skill 之后，Claude 审查代码的能力直接提升一个档次。

**内置技能（开箱即用）：**

| 技能 | 用途 |
|------|------|
| `/code-review` | 全面代码审查：正确性、安全、性能、风格 |
| `/review` | PR 审查：分析完整 diff，生成结构化审查报告 |
| `/verify` | 手动验证：启动服务器、发送请求、确认改动生效 |
| `/security-review` | 安全专项审查：OWASP Top 10、注入漏洞、敏感信息泄露 |
| `/design-sync` | 设计系统同步：与 claude.ai/design 项目保持组件一致 |
| `/fewer-permission-prompts` | 分析操作记录，自动生成合理的权限配置 |

**使用要点：** commit 前养成 `/code-review` 习惯；安全代码必跑 `/security-review`；AI 的建议需要人工判断是否采纳。

**自定义 Skills：** 在 `~/.claude/plugins/` 目录下创建 skill 文件，把重复性操作固化为命令——一次写好，终身受益。

### 3.4 MCP 服务器扩展——给 AI 装"插件"

MCP（Model Context Protocol）是 Claude Code 的扩展协议。通过 MCP 给 Claude Code 添加额外工具——就像给浏览器装插件一样。

| MCP 服务器 | 提供的功能 |
|-----------|----------|
| **Playwright** | 浏览器自动化——打开网页、点击、填表、截图 |
| **Docker** | 容器管理——构建镜像、启停容器、查看日志 |
| **Sentry** | 错误监控——查看生产环境报错、分析根因 |
| **GitLab/GitHub** | 代码仓库操作——管理 PR、Issue、CI/CD |
| **Context7** | 实时文档查询——获取最新版本的库文档 |
| **Database** | 数据库查询——直接连接数据库执行 SQL |

**怎么配置：** 在 `settings.json` 中添加 `mcpServers` 字段：

```json
{
  "model": "deepseek-v4-pro",
  "apiKey": "你的APIKEY",
  "baseURL": "https://api.deepseek.com/v1",
  "mcpServers": {
    "playwright": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@anthropic-ai/mcp-server-playwright"]
    }
  }
}
```

配置好后，Claude Code 就有了浏览器操作能力——比如你可以说"打开我的网站，截个图，看看首页有没有显示异常"。

> ⚠️ 注意：部分 MCP 功能在使用第三方 API（如 DeepSeek）时可能表现不同，但大部分正常。

### 3.5 Subagent 子代理——克隆 AI 分身

当你有一个大任务需要同时做多件独立的事，比如"同时审查 10 个文件的安全问题"——Claude Code 可以**派生子代理**，每个子代理独立处理一部分，最后汇总结果。

**子代理的特点：** 每个有独立上下文，互不干扰；可以并行执行；完成后自动汇报。

**适用场景：**
- 审查多个文件 → 启动多个子代理并行扫描，最后汇总报告
- 研究对比技术方案 → 每个子代理研究一个，生成对比表格

**你不需要手动管理子代理**——告诉 Claude 你的目标，它会自动判断是否需要并行处理。你只需要享受"一个人变成一个团队"的感觉。

### 3.6 Hooks 钩子系统——自动化工作流

Hooks 允许在特定事件前后自动执行脚本。简单说就是：**"每当 AI 准备做某件事，先跑一段你的自定义脚本"**。

| Hook | 触发时机 | 实用场景 |
|------|---------|---------|
| `pre-command` | 执行命令之前 | 敏感命令二次确认 |
| `post-command` | 执行命令之后 | 自动记录操作日志 |
| `on-start` | 会话启动时 | 注入项目上下文 |
| `on-complete` | 工作完成时 | 发送通知、自动 commit |
| `pre-edit` | 编辑文件之前 | 自动备份原文件 |
| `post-edit` | 编辑文件之后 | 自动运行 lint、格式化 |

配置示例——每次 AI 修改 `.tsx` 文件后自动格式化：

```json
{
  "hooks": {
    "post-edit": [{
      "matcher": "**/*.tsx",
      "command": "npx eslint --fix \"$CLAUDE_FILE_PATH\""
    }]
  }
}
```

> 💡 对于初学者，Hooks 可以先放着不用。熟悉工作流后自然会遇到"每次 AI 改完代码我都要手动 format"这种痛点——到那时再来配置 Hook，一步到位。

### 3.7 Memory 记忆系统——AI 的长期记忆

Claude Code 有三层记忆体系：

| 层级 | 文件位置 | 作用域 | 加载时机 |
|------|---------|--------|---------|
| **项目级 CLAUDE.md** | `<project>/CLAUDE.md` | 当前项目 | 每次会话启动时完整加载 |
| **项目级 MEMORY.md** | `<project>/.claude/memory/` | 当前项目 | 会话中按需检索 |
| **用户级 MEMORY.md** | `~/.claude/memory/` | 所有项目 | 会话中按需检索 |

**CLAUDE.md** 是"项目宪法"，每次会话初始化时完整加载。保持 50-100 行，太长会吃上下文。用 `/init` 命令让 AI 自动生成，然后微调。

当你发现 Claude 犯了同样的错误两次，直接说"记住这个问题"，它会写入记忆文件，下次不会再犯。

### 3.8 上下文管理——别让 AI "失忆"

**最佳实践：**
1. 主动 `/compact`：每 30-50 轮对话主动触发
2. 任务分解：长任务拆分成多个短对话，每个聚焦一个子任务
3. 精准提问：避免开放式问题产生大量输出
4. 文件读取策略：不要一次性读取整个大文件，按需指定行范围
5. CLAUDE.md 精简：50-100 行，只放真正需要的信息
6. 利用 `.gitignore`：Claude Code 会自动忽略其中的文件

### 3.9 键盘快捷键

| 快捷键 | 功能 |
|--------|------|
| `Ctrl+C` | 取消当前操作 / 中断 Claude 输出 |
| `Ctrl+D` | 退出会话 |
| `↑` / `↓` | 浏览命令历史 |
| `Ctrl+L` | 清屏 |
| `Ctrl+R` | 搜索命令历史 |
| `Enter` | 发送消息 |
| `Shift+Enter` | 换行（多行输入） |
| `!<命令>` | 在对话中直接执行终端命令 |

## Part 4：实战——从零搭建 RAG 个人知识库助手

OK，理论讲完了。现在来做点真正酷的东西。

我们选的项目是 **RAG 知识库问答系统**——不是因为它简单（它恰恰是企业级 AI 架构的核心组件），而是因为它够大、够复杂，能真正展示 Vibe Coding 的威力。

**目标**：一个能上传文档、自动构建向量索引、支持智能问答的 Web 应用。用户提问时，AI 会检索相关文档片段，给出带原文引用的回答。

> 为什么不做 Todo List？因为 Todo List 一行代码都不用写，AI 一秒就给你答完了，你什么都学不到。RAG 这种"你本来不可能独立完成"的项目，才是 Vibe Coding 的正确打开方式。

### 4.1 第一步：在 Plan Mode 中描述你的梦想

在 VS Code 中打开 Claude Code 面板，选择 **Plan Mode**，输入：

> 我的目标是开发一个 RAG 知识库问答系统，用户可以通过浏览器上传文档并进行知识库问答。
>
> 技术选型上，LangChain 是必须选的框架。其余技术栈你来决定，解释清楚为什么这么选。
>
> 我需要这些功能：
> 1. 用户在浏览器中管理知识库——上传 PDF、Markdown、TXT 文档
> 2. 用户在浏览器中和知识库问答，回答要引用原文片段，标注来源
> 3. 多用户多会话管理，每人独立会话互不干扰
> 4. 保持用户的会话记录，不同时间登录都能找回历史对话
> 5. 基础的注册登录功能，支持修改密码
> 6. 管理员用户名 admin 密码 123456，只有管理员能管理知识库
> 7. 不仅是基础功能，也要做性能优化，达到可用级别
> 8. 其余你觉得有必要添加的功能
>
> 先出方案给我看，解释清楚为什么这么选。

Claude Code 会思考大概 1-2 分钟，然后给你甩出一个完整的架构方案——包括技术栈选型理由、项目目录结构、数据库设计、API 接口设计、前端页面规划……

你只需要**用鼠标点选你喜欢的选项**。这个阶段最魔幻的是：**你明明什么都没干，却有一种"我在主导项目"的错觉。** 这种感觉，说实话，会上瘾。

### 4.2 第二步：项目初始化 + 疯狂点 Yes

方案确认后，切换到 Edit Mode，Claude Code 开始干活：

1. 检查你的环境（Python 3.10+、Node.js、pip 等是否齐全）
2. 创建项目目录结构（`frontend/`、`backend/`）
3. 安装所有依赖（LangChain、FastAPI、ChromaDB、React……）
4. 生成 `CLAUDE.md`（项目的 AI 使用说明书）
5. 初始化数据库表结构

这个阶段你的主要工作是：**点 Yes。**

> 💡 小技巧：嫌烦就在权限里选 "Yes, allow all edits this session"，让 AI 在这轮对话里自动批准文件修改。但 `pip install` 之类的终端命令还是会让你手动确认。你也可以用 `/fewer-permission-prompts` skill 自动分析使用模式并生成合理配置。

### 4.3 第三步：功能开发——见证魔法

初始化完成后，Claude Code 会按照 PRD 规划逐步推进：

**阶段一：知识库引擎**（LangChain RAG 核心）
- `RecursiveCharacterTextSplitter` —— 智能文档切片，自动识别段落边界和语义断点
- `OpenAIEmbeddings` —— 将文本转换为向量（AI 世界里"词义相近"的数学表达）
- `ChromaDB` 向量存储 —— 轻量级、零配置的本地向量数据库
- `RetrievalQA` 链 —— 用户问题 → 检索相关文档片段 → 喂给 LLM → 返回带引用来源的答案

**阶段二：用户系统**
- 注册 / 登录 / 修改密码
- JWT Token 认证
- 管理员角色隔离（admin / 123456）

**阶段三：前端界面**
- 知识库管理页面（上传文档、查看切片结果、删除文档）
- 问答对话页面（提问、流式逐字输出、原文引用高亮）
- 历史会话管理（多会话切换、恢复历史对话）

你在这个过程中扮演的角色是：**监工 + 决策者。** 关键心态：**不要试图全懂，做选择题就够了。** 判断力比知识储备更重要。

### 4.4 第四步：Bug 自动修复

开发完成后，运行 `python backend/app/main.py`，报错了：

```
ERROR: Could not find a version that satisfies the requirement chromadb==0.5.0
ERROR: No matching distribution found for chromadb==0.5.0
```

传统开发：Google → Stack Overflow → 试 3 种方案 → 还是不行 → 想砸电脑。

Vibe Coding：**贴给 Claude Code。**

> 安装 chromadb 报了这个错，帮我修：[粘贴错误]

Claude Code 自动分析：Python 3.12 + chromadb 0.5.0 有兼容性问题。找到兼容版本，更新 `requirements.txt`。

**这个项目我一共遇到了 14 个错误，AI 自动修了 14 个。我全程只做了 Ctrl+C 和 Ctrl+V。** 而且——因为用的是 DeepSeek V4 Pro，这 14 轮修复总共花的 token 费用不超过 **¥0.30**。

### 4.5 第五步：Docker 化 + 一键启动

> 帮我写一个 docker-compose.yml，把前后端和 ChromaDB 都容器化，然后告诉我怎么一键启动。

Claude Code 生成 Docker 配置：

```bash
docker-compose up -d
```

浏览器打开 `http://localhost:3000`——**一个你"写"的 RAG 知识库助手出现在屏幕上。**

上传一篇 AI 论文 PDF，等 30 秒构建向量索引。对话框里输入："这篇论文的核心贡献是什么？" AI 逐字输出一长段总结，**底部引用了原文的三个片段，点击可以直接跳到原文对应位置。**

你盯着屏幕，沉默了。48 小时前你还不知道 RAG 三个字母代表什么。现在你有一个能跑的知识库问答系统。

## Part 5：工程化生存指南

如果你不只是玩玩，想正经用 Vibe Coding 做持续迭代的项目：

### 5.1 Git 工作流——给每次冒险上保险

**每次让 AI 大改代码前，先 `git commit`。**

```bash
git add -A && git commit -m "AI 改版前快照"
git reset --hard HEAD~1  # 改坏了？一键回到过去
```

进阶习惯：别在 `main` 分支上直接实验；小步提交；定期 `git diff` 审查 AI 的改动。大型重构可以用 **Git Worktree** 创建隔离的工作副本，完全不影响主分支。

Claude Code 内置回退：说"撤销你刚才的改动"或"把 xxx 文件恢复到改之前"即可。

### 5.2 CLAUDE.md 最佳实践

用 `/init` 让 AI 自动生成，然后微调。精简到 50-100 行——太长吃上下文，太短 AI 不了解项目。

必须包含：技术栈清单、目录结构、编码规范、重要约定（什么绝对不能碰）。

### 5.3 代码审查——别让 AI 放飞自我

AI 写的代码不一定都对。好在 AI 也能审查自己的代码。养成习惯：**commit 之前，先 `/code-review`。** 普通改动 medium，核心模块 high 或 max。

## Part 6：我踩过的坑

本着教学精神，分享几个翻车的经典时刻——让你不用重复交学费。

### 坑 #1：让 AI "随便做"

我说："帮我做一个好看的首页"。结果：霓虹灯风格、自动播放 BGM、带粒子特效。在办公室打开的时候，全公司都看向了我。

**教训**：永远给 AI 设定风格边界。把"简洁、专业、不夸张"写进 CLAUDE.md。

### 坑 #2：不看 Diff 就点 Yes

连点 20 个 Yes 之后，AI 把所有依赖版本从锁定版升级到 "latest"——项目炸了。

**教训**：重要文件（package.json、配置文件、数据库 schema）的修改，多看一眼 diff。

### 坑 #3：不说"停下来"

AI 陷入"修 bug → 引入新 bug → 修新 bug → 引入更多 bug"的死循环，改 15 个文件还没修好。

**教训**：AI 不是人，不会尴尬。发现方向错了直接说——"停，我们换个思路。"

### 坑 #4：以为 DeepSeek 什么都能做

DeepSeek V4 Pro 在代码生成和调试方面非常强，但如果涉及极端复杂的逻辑推理——可以考虑关键步骤切到更强的模型，日常开发继续用 DeepSeek。混着用，把每一分钱花在刀刃上。

## Part 7：Vibe Coding 的正确心态

**Vibe Coding 不是"AI 替你干活，你啥都不管。"** 它是"AI 负责执行层，你负责决策层。"

| 你不需要会…… | 但你需要知道…… |
|------------|-------------|
| 写 TypeScript | "类型安全很重要，代码要健壮" |
| 配置 Webpack | "打包太慢了，优化一下启动速度" |
| 写 SQL | "数据不能丢，要持久化存储" |
| 调 ChromaDB 参数 | "搜索结果不准，让 AI 重新调整检索策略" |
| 写 HTML/CSS | "这个页面布局很乱，按照设计规范重新排版" |

你扮演的角色从"码农"变成了"产品经理 + 架构师 + 质量把控"。核心能力从"写代码"变成了"做决策、做判断"。

这其实比纯写代码**更难**——因为你需要有判断力。但好消息是：这种能力会在实践中快速培养起来，因为你身边有个永远不会不耐烦的导师。

而且三毛二一次，你亏得起。
