## 导读：你到底需要"多会写代码"才能开始？

**答案是：会打字就行。**

别翻白眼。我说真的。

在正式开始之前，我们先对齐一个核心认知——**Vibe Coding 到底解决的是什么问题，以及你会遇到什么问题。** 看完这节你还没被劝退，那恭喜你，你已经具备了 Vibe Coding 唯一需要的天赋：想用代码做点东西的冲动。

### 1.1 打开终端——你的第一个"黑窗口"

首先得知道怎么打开终端。终端就是一个黑色的文字窗口，你在里面打字，电脑执行。没有鼠标、没有图标——只有你和计算机之间最纯粹的交流。

**Windows 用户：**

Windows 10 系统的同学可以在应用商店内搜索并安装 **Windows Terminal** 软件（Win11 自带，名字叫做终端）。

![Windows 应用商店搜索 Windows Terminal](/images/vibecoding/yuque/nodejs-terminal.png)

1. 找到软件终端，并打开（Win10 系统没有自带，请参考上图，在应用软件内下载安装即可）

![搜索"终端"——选择最佳匹配打开](/images/vibecoding/yuque/nodejs-powershell.png)

2. 打开终端程序，如下图

![Windows PowerShell 窗口——默认标题栏显示 Windows PowerShell](/images/vibecoding/yuque/njs-search.png)

> Windows 的终端分为 2 种类型：
> - **CMD**，传统的老式命令提示符
> - **PowerShell**，微软推出的新一代命令行
>
> 为了更好的兼容现代化软件和 **Claude Code** 的特性，课程选择 Windows 中的 **PowerShell** 作为终端使用。

我们安装的这个终端软件，默认打开的就是：**PowerShell**，如果需要打开老式的 **CMD 命令提示符** 可以按下图所示操作：

![在终端中切换到 CMD 命令提示符](/images/vibecoding/yuque/njs-powershell2.png)

**Mac 用户：**

1. 找到应用程序 **终端** 打开

![Mac 系统中找到终端应用](/images/vibecoding/yuque/njs-cmd-powershell.png)

2. 点击打开，即可打开终端程序

![Mac 终端窗口](/images/vibecoding/yuque/njs-mac-terminal.png)

### 1.2 终端基础命令

现在你有了一个黑窗口，接下来需要知道几个最基本的命令（不用背，用到时回来查）：

**路径与目录操作：**

| 功能 | Windows PowerShell | Mac / Linux |
|------|-------------------|-------------|
| 当前路径 | `pwd` | `pwd` |
| 切换目录 | `cd C:\Users\...` | `cd ~/Documents` |
| 列出文件 | `ls` | `ls -la` |

**文件增删改：**

| 功能 | PowerShell | Mac / Linux |
|------|-----------|-------------|
| 创建目录 | `mkdir 文件夹名` | `mkdir 文件夹名` |
| 创建空文件 | `New-Item 文件.txt` | `touch 文件.txt` |
| 删除文件 | `Remove-Item 文件名` | `rm 文件名` |
| 查看文件 | `cat 文件.txt` | `cat 文件.txt` |

**通用快捷键：**

| 快捷键 | 功能 |
|--------|------|
| `Tab` | 自动补全 |
| `↑` / `↓` | 历史命令切换 |
| `Ctrl+C` | **终止当前命令**（不是复制！） |
| `Ctrl+L` | 清屏（Mac）/ `cls`（Win） |

> **💡**：终端里 `Ctrl+C` 不是复制！复制用 `Ctrl+Shift+C`（PowerShell）或 `Cmd+C`（Mac）。删除命令不可恢复，操作前确认清楚。

### 1.7 注册 DeepSeek API Key

课程选择国内 DeepSeek API 作为 Claude Code 编程的模型提供商。原因很简单：原版 Claude 模型国内无法使用，中转服务不稳定，而 DeepSeek V4 Pro 在编程方面不落后原版太多，且便宜到令人发指。

1. 注册 [platform.deepseek.com](https://platform.deepseek.com)，酌情充值（¥10 够用很久）
2. 创建 API Key，起个名字（随意）

![DeepSeek 开放平台——创建 API Key](/images/vibecoding/yuque/cc-deepseek-key.png)

3. **⚠️ 点击创建后立即复制保存！API Key 只显示这一次！**

### 1.8 配置 Claude Code 接入 DeepSeek

参考 DeepSeek 官方文档：https://api-docs.deepseek.com/zh-cn/guides/coding_agents

打开（或新建）对应文件：
- **Windows**：`C:\Users\你的用户名\.claude\settings.json`
- **Mac**：`~/.claude/settings.json`

填入以下内容（替换为你的 API Key）：

```json
{
  "model": "deepseek-v4-pro",
  "apiKey": "你的APIKEY",
  "baseURL": "https://api.deepseek.com/v1"
}
```

**就这三行。** 保存，关闭。

## 入门实战：用 Vibe Coding 开发"黑马记账"APP

目前我们已经完成了所有基础环境的部署。现在以一个小白的视角，完成一个《个人记账 APP》的项目实战开发。

> 本次项目以小白视角进行——我们不对 Claude Code 提出专业要求，而是要求 Claude Code 给出方案、解释方案，我们做选择题。因为小白本身也无法给出专业方面的要求，所以由 Claude Code 做好引导。

### 项目创建

在电脑中创建文件夹 `黑马记账APP`，用 VS Code 打开它。

### 选择决策方案

点击 Claude Code 面板的举手图标，有三种方案供选择：
- **Ask before edits**：每次文件修改都弹窗请求手动审批
- **Edit automatically**：代码修改自动执行，终端命令仍需审批
- **Plan mode**：AI 先完整扫描、设计方案，不直接改文件，等你确认后再执行

![VS Code Claude Code 面板——选择 Plan mode 并拉满 Effort](/images/vibecoding/yuque/entry-planmode.png)

我们选择 **Plan mode**，并把 Effort 拉满。以非专业人士视角，由 AI 给方案并解释，我们做决策。

### 准备产品文档（CLAUDE.md）

在对话中输入如下提示词：

> 我需要生成一个APP，名字：黑马记账；我不懂编程技术，也是初次使用 Claude Code，你先帮我设计产品文档，并记录到 CLAUDE.md 中；
>
> 我的一些要求如下：
> 1. 我需要这个APP是可以运行在Windows电脑和Mac电脑上；
> 2. APP功能主要是可以记录用户每一次的花销（单位人民币），并可以记录花销的分类，分类分为2级，有一级大类、和二级小类，分类你来设计；
> 3. 技术栈选型你决定，请列出几个方案给我并列出优劣势，我来挑选并决定；
>
> 注意：在整个项目开发过程中，任何关于技术方面的事情，我无法提供具体的要求，必须是你列出方案给我，并向我解释各个方案，由我来决定，请将这个要求详细记录在 CLAUDE.md 中，在整个项目期间遵守；

Claude Code 经过思考后给出了选择。课程按如下方式选择：方案 B（Tauri + React），勾选阅读支出统计图表、数据导出 Excel/CSV。确认后点击 Submit answers。

![Claude Code 给出技术方案选项——勾选所需功能后提交](/images/vibecoding/yuque/entry-prd.png)

Claude Code 生成 CLAUDE.md 时，选择 **"Yes, and manually approve edits"**（每次手动批准修改），保持对项目的控制感。

### 项目初始化

Claude Code 按照方案自动推进：
1. **项目环境检查**：扫描 Node.js、Rust 是否齐全 → 点 Yes
2. **Rust 环境安装**：Tauri 需要 Rust → 点 Yes 自动部署
3. **初始化项目环境**：`npm create` 创建 Tauri + React 框架 → 点 Yes
4. **确认项目名称**：package.json 中 name 栏是拼音（`heimajizhang`），确认即可

![Claude Code 创建项目——初始化项目代码文件](/images/vibecoding/yuque/entry-create.png)

后续遇到文件修改，大体看一下没问题就点击 Yes。

### 功能开发——全程做选择题

随着开发推进，AI 不断抛出选择题：
- **数据存储方案**：A（本地 SQLite）vs B（云端）→ 选 A，简单方便
- **统计图表库**：A（Recharts）vs B（ECharts）→ 让 AI 解释后选择
- **导出格式**：Excel / CSV → 两个都要

每一步 AI 都会解释各方案的优劣势。你不需要懂技术，只需要根据常识做判断。

### 打包 APP

**Mac 系统**：AI 直接编译生成 `.app` 文件。

**Windows 系统**：如果在 Mac 上开发，把项目文件夹复制到 Windows 电脑，用 VS Code 打开，发送：

## Part 2：Claude Code 工程化控制——从工具到武器

<small>适用版本：Claude Code CLI（截至 2026 年 7 月）。官方文档：https://code.claude.com/docs</small>

环境搭好了，第一个项目跑通了。但在继续做更复杂的 RAG 项目之前，你必须先搞清楚：**Claude Code 到底有什么武器？** 它不是聊天机器人——它是完整的 AI 软件工程平台。这一节信息量很大，不需要全记住，用到时回来查。

### 2.1 上下文压缩控制

#### 核心概念

Claude Code 的上下文窗口有限（通常约 200K tokens）。对话越长，历史消息、代码片段、工具调用结果不断累积，最终触发"上下文窗口满"。此时 AI 开始"遗忘"——忽略早期指令、响应变慢、牛头不对马嘴。**有效的上下文管理是保持长会话生产力的最关键技能。**

#### `/compact` 命令

这是 Claude Code 最重要的命令，没有之一。

```
/compact
```

**工作原理：**
- Claude 读取完整对话历史，生成结构化摘要
- 摘要包含：已完成的任务、已做的决策、修改过的文件、关键事实
- 早期对话被替换为压缩摘要，仅保留最近的若干轮完整对话
- 压缩后释放大量上下文空间，可以继续工作

**使用时机：**
- ✅ 主动压缩：每 30-50 轮对话后主动执行
- ✅ 任务切换时：完成大任务、开始新任务前
- ✅ 响应变慢时：对话历史过长导致处理速度下降
- ✅ 出现遗忘迹象：Claude 开始忽略早期指令时

**注意事项：** 压缩**不可逆**，压缩质量取决于对话结构清晰度，压缩前可手动总结关键点。

#### 自动压缩（Auto-Compact）

Claude Code 在上下文接近上限时自动触发。但自动压缩发生在"快满"的时候（AI 可能已表现下降），**主动 `/compact` 比被动等待效果更好。**

#### 减少上下文消耗

- **精准提问**：明确指定需要的，避免开放式问题
- **文件读取策略**：不要一次读整个大文件，指定行范围
- **CLAUDE.md 精简**：保持 50-100 行
- **利用 `.gitignore`**：Claude Code 自动忽略其中的文件

#### 上下文状态查看

- Claude 每次响应后显示 token 统计
- **观察响应速度**：明显变慢 → 需要 `/compact`
- 如果 Claude 开始"忘记"重要信息 → 上下文可能已压缩

### 2.2 Memory 记忆管理

#### 三层记忆体系

| 层次 | 位置 | 作用域 | 加载时机 |
|------|------|--------|---------|
| 项目级 CLAUDE.md | `<project>/CLAUDE.md` | 当前项目 | 每次会话启动时完整加载 |

| 用户级 MEMORY.md | `~/.claude/memory/` | 所有项目 | 会话中按需检索 |

#### CLAUDE.md —— 项目宪法

最重要的记忆载体，每次会话初始化时完整加载。用 `/init` 让 AI 自动生成，然后微调。

应该包含：项目结构（目录说明）、编码规范（命名、状态管理、API 调用方式）、重要约定（什么绝对不能碰）。

记忆类型：`user`（偏好）、`feedback`（纠正）、`project`（目标约束）、`reference`（外部链接）。使用 `[[slug-name]]` 语法关联记忆。

直接说"记住我使用 pnpm 而非 npm"，Claude 会自动创建/更新记忆文件。

#### 记忆管理原则

1. 不存代码能推导的信息
2. 不存仅限本次对话的信息
3. 及时更新偏好
4. 定期审查 MEMORY.md

### 2.3 代码回退管理

#### 安全检查点

```bash
git add -A && git commit -m "AI 改版前快照"
git reset --hard HEAD~1  # 改坏了？一键回到过去
```

#### 撤销 Claude 的改动

| 场景 | 回退方式 |
|------|---------|
| 刚改的、还没 commit | `git checkout -- <file>` |
| 已经 commit | `git reset --hard HEAD~1` |
| Claude 正在改 | 说"撤销你刚才的改动" |
| 多个文件被改 | 说"把 xxx 文件恢复到改之前" |

#### Git Worktree 隔离

在独立目录中工作，不影响主工作区。适用：试验性重构、并行多任务。Claude Code 的 `/batch` 底层就是 worktree。

#### 内置回退机制

- **对话自然撤销**："撤销你刚才的改动"、"恢复到 xxx 之前的状态"
- **备份目录**：`~/.claude/backups/`
- **File History**：`~/.claude/file-history/`

#### 安全建议

1. 重要的代码先 commit
2. 在专用分支工作，别在 main 上试验
3. 定期 `git diff` 审查 AI 改动
4. 看不懂改动就让 AI 解释
5. 小步提交，每次小改动后 commit

### 2.5 Hooks 钩子系统

Hooks 在特定事件前后自动执行脚本——"每当 AI 准备做某件事，先跑一段你的自定义脚本"。

| Hook | 触发时机 | 实用场景 |
|------|---------|---------|
| `pre-command` | 执行命令之前 | 敏感命令二次确认 |
| `post-command` | 执行命令之后 | 自动记录操作日志 |
| `on-start` | 会话启动时 | 注入项目上下文 |
| `on-complete` | 工作完成时 | 发送通知、自动 commit |
| `pre-edit` | 编辑文件之前 | 自动备份原文件 |
| `post-edit` | 编辑文件之后 | 自动运行 lint、格式化 |

**Hook 脚本可访问的环境变量：** `CLAUDE_EVENT_TYPE`、`CLAUDE_COMMAND`、`CLAUDE_FILE_PATH`、`CLAUDE_WORKING_DIR`

**配置示例**——每次改完 tsx 文件自动格式化：
```json
{
  "hooks": {
    "post-edit": [{
      "matcher": "**/*.{ts,tsx}",
      "command": "npx prettier --write \"$CLAUDE_FILE_PATH\""
    }]
  }
}
```

## Part 4：CodeX 接入 DeepSeek（为什么选 Claude Code 不选 CodeX）

Codex 是 OpenAI 的编程 Agent。它使用 OpenAI Responses API 与模型通信，因此需要一个转发层——这里用 Moon Bridge。

### CodeX 接入流程（对比）

| 步骤 | Claude Code | CodeX |
|------|------------|-------|
| 安装 | `npm install -g @anthropic-ai/claude-code` | `npm install -g @openai/codex` + Go 1.25+ |
| 转发层 | ❌ 不需要 | ⚠️ `git clone` Moon Bridge |
| 配置文件 | 3 行 JSON | ⚠️ 30+ 行 YAML + TOML + JSON |
| 启动 | 直接 `claude` | ⚠️ 先启动 Moon Bridge，再启动 Codex |
| **总耗时** | **~10 分钟** | **~1-2 小时（顺利的话）** |

Moon Bridge 的 config.yml 长这样（感受一下）：

```yaml
mode: "Transform"
server:
  addr: "127.0.0.1:38440"

  deepseek-v4-pro:
    context_window: 1000000
    max_output_tokens: 384000
    # ... 还有 40+ 行
providers:
  deepseek:
    base_url: "https://api.deepseek.com/anthropic"
    api_key: "sk-your-deepseek-api-key"
```

CodeX 还需要启动 Moon Bridge（`go run ./cmd/moonbridge --config config.yml`）、生成 Codex 配置（config.toml + models_catalog.json）、然后才能启动 Codex。每多一层转发多一层出错可能。**这叫 Vibe Coding？这叫 Vibe Debugging。**

CodeX 常见问题：connection refused（Moon Bridge 未启动）、Codex 看不到模型（需重新执行第 5 步生成配置）、401 认证失败（检查 API Key）、402 余额不足。

## Part 5：我踩过的坑

### 坑 #1：让 AI "随便做"

"帮我做一个好看的首页"→ 霓虹灯风格、自动播放 BGM、粒子特效。办公室打开时全公司看向我。**教训：** 永远设定风格边界。

### 坑 #2：不看 Diff 就点 Yes

连点 20 个 Yes → AI 把所有依赖版本升级到 "latest" → 项目炸了。**教训：** 重要文件多看一眼 diff。

### 坑 #3：不说"停下来"

AI 陷入"修→引入→修→引入"死循环，改 15 个文件还没修好。**教训：** AI 不会尴尬，直接说"停，换思路。"

### 坑 #4：以为 DeepSeek 什么都能做

极端复杂逻辑推理时，关键步骤切到更强模型，日常继续 DeepSeek。混着用。

## Part 6：Vibe Coding 的正确心态

**Vibe Coding 不是"AI 替你干活"，是"AI 负责执行，你负责决策。"**

| 你不需要会…… | 但你需要知道…… |
|------------|-------------|
| 写 TypeScript | "类型安全很重要" |
| 配置 Webpack | "打包太慢了，优化一下" |
| 写 SQL | "数据不能丢，要持久化" |
| 调 ChromaDB 参数 | "搜索不准，调整检索策略" |
| 写 HTML/CSS | "布局很乱，重新排版" |

你的角色从"码农"变成"产品经理 + 架构师 + 质量把控"。这其实更难——因为需要判断力。但好消息是：你身边有个永远不会不耐烦的导师。而且三毛二一次，亏得起。
