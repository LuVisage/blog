## 什么是 Vibe Coding？

简单来说：**你负责 Vibe，AI 负责 Coding。**

这个概念由 Andrej Karpathy 在 2025 年提出。传统编程是你告诉计算机每一步怎么做（"先声明变量，再写循环，然后处理边界条件……"），而 Vibe Coding 是你告诉 AI **你想要什么**，然后躺沙发上看着它干活。

翻译成人话就是：

> 以前写代码是"我写代码，计算机执行"。
> 现在写代码是"我说人话，AI 写代码，AI 自己调试，AI 自己修 bug，我只需要会打字和点 Yes。"

我第一次听到这个概念的反应是：**"这不就是做梦吗？"**

然后我试了。然后我沉默了。然后我开始怀疑自己大学四年到底学了什么。

## 为什么是 Claude Code + DeepSeek？

先说结论：**国内 Vibe Coding 的最优解是 Claude Code + DeepSeek V4 Pro。** 没有之一。

你可能会问——那 OpenAI CodeX 呢？它不是 OpenAI 亲儿子吗？

好问题。我帮你梳理一下 CodeX 接入 DeepSeek 需要做什么：

1. 安装 Node.js 18+
2. **安装 Go 1.25+**（是的，一个编程 Agent 需要你装 Go 运行环境）
3. 克隆 Moon Bridge 仓库（一个第三方转发层）
4. 手写一份 `config.yml`（30+ 行的 YAML 配置，配置错一个缩进就崩）
5. 手写一份 `config.toml`
6. 手写一份 `models_catalog.json`
7. 启动 Moon Bridge 服务（保持终端常驻运行）
8. 再开一个终端启动 CodeX

我就想问一句：**我一个零基础小白，你让我写 YAML 配置文件？** 这和我直接学编程有什么区别？

而 Claude Code 接入 DeepSeek 只需要：

1. 装好 Node.js
2. `npm install -g @anthropic-ai/claude-code`
3. 在 `~/.claude/settings.json` 里填三行配置

**三行。就三行。**

CodeX 本质上是为 OpenAI 生态设计的，对第三方模型的支持靠的是社区用爱发电的转发层（Moon Bridge）。这个转发层需要你自己部署、自己配置、自己维护。每多一层转发，就多一层出错的可能。而 Claude Code 原生就支持自定义 API endpoint，不需要任何中间层。

**结论：Claude Code 是工具，CodeX 是作业。想省事就用 Claude Code。**

## Vibe Coding 四定律

在开始实战之前，先记住这四条生存法则（对，四条，因为我写到第三条的时候 AI 建议再加一条）：

### 第一定律：你不需要会写代码

是的你没看错。你不需要知道 React 是什么，不需要知道向量数据库怎么建索引，甚至不需要知道 `pip` 和 `npm` 的区别——Claude Code 会帮你搞定一切。

你只需要会做一件事：**清楚地描述你想要什么。**

比如：
- ❌ "帮我做个 AI 应用"（太模糊，AI 会给你做个聊天机器人说"已完成"）
- ✅ "帮我做一个 RAG 个人知识库系统，能上传 PDF/Markdown 文档，用 LangChain 做向量检索，用户可以在浏览器里提问，回答要引用原文片段"（清晰，AI 立马开干）

### 第二定律：Plan Mode 是你的好朋友

Claude Code 有三种模式：
- **Ask before edits**：每改一行都问你，像个过度谨慎的驾校教练
- **Edit automatically**：直接改，像个急性子的修车师傅
- **Plan mode**：先出方案给你审，像个靠谱的建筑设计师

**强烈建议新手用 Plan Mode**。因为你自己都不知道要什么，让 AI 先帮你理清楚思路，你再做选择——这比自己瞎指挥靠谱一万倍。

### 第二点五定律：Effort 拉满！

Claude Code 有个 Effort 设置，控制 AI 的"思考深度"。简单说：
- 拉高 → AI 更聪明但更慢，像个深思熟虑的老教授
- 拉低 → AI 更快但更敷衍，像个急着下班的前台

**拉满。别省。** 你省的那点时间会变成后面十倍的 debug 痛苦。

### 第三定律：看不懂就让它解释

当你看到 `chromadb.Client()` 或 `RecursiveCharacterTextSplitter` 这种东西时，不要恐慌，不要百度，更不要假装自己懂。

**直接问 Claude Code："这是什么意思？"**

它会用你能理解的方式解释。这是 Vibe Coding 最大的优势——你身边随时有个终身教授给你一对一辅导。

## 环境部署：唯一需要动手的部分

这是整个 Vibe Coding 旅程中唯一需要你"操作"的阶段。跟着做，十分钟搞定。

### 1. 安装 Node.js

去 [nodejs.org](https://nodejs.org) 下载安装。Windows 用户下载 `.msi` 文件，一路「下一步」即可。Mac 用户下载 `.pkg` 文件，同样一路「继续」。

装完后验证：

```bash
node --version   # 应该显示 v24.x.x
npm --version    # 应该显示 11.x.x
```

> **Windows 用户注意**：如果遇到 PowerShell 脚本执行权限报错，需要以管理员身份打开终端，执行：
> ```powershell
> Set-ExecutionPolicy RemoteSigned -Scope CurrentUser
> ```

### 2. 安装 Git

去 [git-scm.com](https://git-scm.com) 下载安装。一路下一步就行，所有选项用默认值。

```bash
git --version   # 应该显示 2.x.x
```

### 3. 安装 Python

去 [python.org](https://python.org) 下载 Python 3.10+。**安装时勾选「Add Python to PATH」**，这很重要。

```bash
python --version  # 应该显示 3.10.x 或更高
```

### 4. 安装 Claude Code

打开终端（Windows 用 PowerShell，Mac 用终端），执行：

```bash
# 国内用户建议先切镜像源，速度快很多
npm config set registry https://registry.npmmirror.com

# 安装 Claude Code
npm install -g @anthropic-ai/claude-code

# 验证安装
claude --version  # 应该显示版本号
```

### 5. 配置 DeepSeek API

首先去 [platform.deepseek.com](https://platform.deepseek.com) 注册账号，充一点钱（建议先充 10 块钱，够你用很久很久）。

然后创建 API Key——点「API Keys」→「创建 API Key」→ 复制保存好。**注意：API Key 只显示一次，请务必当场复制保存！**

最后配置 Claude Code。打开（或新建）配置文件：

- **Windows**: `C:\Users\你的用户名\.claude\settings.json`
- **Mac**: `~/.claude/settings.json`

填入以下内容（把 `你的APIKEY` 替换成你刚才复制的 key）：

```json
{
  "model": "deepseek-v4-pro",
  "apiKey": "你的APIKEY",
  "baseURL": "https://api.deepseek.com/v1"
}
```

就这三行。不需要 Go 环境，不需要 YAML 配置，不需要启动第三方服务。三行 JSON，搞定。

### 6. 验证一切正常

```bash
mkdir test && cd test
claude
```

进入 Claude Code 界面后，问一句：「你是什么模型？」

如果它回答「我是 DeepSeek V4 Pro……」——恭喜，环境部署完毕！

## 实战：从零搭建 RAG 个人知识库助手

废话不多说，我们直接开干。目标：**用 Claude Code 从零搭建一个能上传文档、自动构建知识库、支持智能问答的 RAG 系统。**

选这个项目不是因为它是"Hello World"级别的玩具——恰恰相反，RAG（Retrieval-Augmented Generation，检索增强生成）是 2025-2026 年最火的企业级 AI 架构之一。学会了这个，你去面试 AI 开发岗都能说两句。

### 第一步：给 AI 一段"梦想描述"

传统开发流程：产品经理写 PRD → 技术评审 → 架构设计 → 编码 → 测试 → 上线。耗时：2 个月。

Vibe Coding 流程：你对着 AI 说一段人话 → AI 帮你设计全套方案 → 你光速审阅 → 开干。耗时：5 分钟。

用 VSCode 打开你的项目文件夹，点击 Claude Code 插件图标，设置成 **Plan Mode + Effort Max**。然后输入：

> 我的目标是开发一个 RAG 知识库问答系统，用户可以通过浏览器上传文档并进行知识库问答。
>
> 技术选型上，LangChain 是必须选的框架。其余技术栈你来决定。
>
> 我需要这些功能：
> 1. 用户在浏览器中管理知识库——上传 PDF、Markdown、TXT 文档
> 2. 用户在浏览器中和知识库问答，回答要引用原文片段，标注来源
> 3. 多用户多会话管理，每人独立会话互不干扰
> 4. 保持用户的会话记录，不同时间登录都能找回历史对话
> 5. 基础的注册登录功能，支持修改密码
> 6. 管理员用户名 admin 密码 123456，只有管理员能管理知识库
> 7. 不仅是基础功能，也要做性能优化，达到可用级别
> 8. 其余你觉得有必要添加的功能
>
> 先出方案给我看，解释清楚为什么这么选。

Claude Code 会思考大概 1 分钟，然后给你甩出一个完整的架构方案。

你只需要**用鼠标点选你喜欢的方案**。这个阶段最魔幻的是：**你明明什么都没干，却有一种"我在主导项目"的错觉。** 这种感觉会上瘾。

### 第二步：项目初始化 + 疯狂点 Yes

方案确认后，Claude Code 会进入执行模式：

1. 检查你的环境（Python 3.10+、Node.js、pip 等装好没）
2. 创建项目目录结构（前端 `frontend/`、后端 `backend/`）
3. 安装所有依赖（LangChain、FastAPI、ChromaDB、React……）
4. 生成 `CLAUDE.md`（项目的 AI 使用说明书）
5. 初始化数据库表结构

这个阶段你的主要工作是：**点 Yes。**

```
Claude: "我要创建 backend/app/main.py，批准吗？"
你: Yes

Claude: "我要安装 langchain, chromadb, fastapi 等 23 个 Python 包，批准吗？"
你: Yes

Claude: "我要创建 React 前端脚手架，批准吗？"
你: Yes... 这事你下次不用问我，直接干！
```

*（小技巧：嫌烦就选 "Yes, allow all edits this session"，让 AI 在这轮对话里自动批准文件修改。但 pip install 之类的终端命令还是会让你手动确认，安全上不用太担心。）*

### 第三步：功能开发——见证魔法

初始化完成后，真正的魔法开始了。Claude Code 会按照 PRD 中规划的路线，逐步推进：

**阶段一：知识库引擎**（LangChain RAG 核心）
- `RecursiveCharacterTextSplitter` — 文档切片，自动识别段落边界
- `OpenAIEmbeddings` — 将文本转换为向量（AI 世界里"词义相近"的数学表达）
- `Chroma` 向量存储 — 支持快速相似度检索，零配置
- `RetrievalQA` 链 — 用户问题 → 检索相关片段 → 喂给 LLM → 返回带引用的答案

**阶段二：用户系统**
- 注册 / 登录 / 修改密码
- JWT Token 认证
- 管理员角色（admin / 123456）

**阶段三：前端界面**
- 知识库管理页面（上传文档、查看切片结果、删除文档）
- 问答对话页面（提问、流式回答、原文引用高亮）
- 历史会话管理（多会话切换、恢复历史对话）

你在这个过程中扮演的角色是：**监工 + 决策者**。

```
Claude: "向量数据库我推荐用 ChromaDB，轻量级适合个人项目。另一个选项是 Pinecone，云端托管但需要注册。你选哪个？"
你: "A，轻量的好，不想注册额外账号"
Claude: "收到，开始集成 ChromaDB..."
```

关键心态再强调一遍：**不要试图全懂，做选择题就够了。** 你不需要知道 ChromaDB 和 Pinecone 的技术细节——你只需要知道一个不用注册、一个要注册。选那个让你省事的。

### 第四步：Bug 自动修复

开发完成后，运行 `python backend/app/main.py`，报错了：

传统开发：Google → Stack Overflow → 试 3 种方案 → 还是不行 → 想砸电脑。

> 安装 chromadb 报了这个错，帮我修：[粘贴错误]

Claude Code 自动分析：Python 3.12 + chromadb 0.5.0 有兼容性问题。它会把版本改成兼容的 `chromadb>=0.4.0`，然后说"重试一下"。

**这个项目我一共遇到了 14 个错误，AI 自动修了 14 个。我全程只做了 Ctrl+C 和 Ctrl+V。**

关键是——因为用的是 DeepSeek V4 Pro，这 14 轮修复总共花的 token 费用不超过 **¥0.30**。如果是 Claude Opus 原生模型，光修 bug 就得十几块钱。

> 帮我写一个 docker-compose.yml，把前后端都容器化，然后告诉我怎么一键启动。

AI 逐字输出一长段总结，**底部引用了原文的三个片段，点击可以直接跳到原文对应位置。**

你盯着屏幕，沉默了。48 小时前你还不知道 RAG 三个字母代表什么。现在你有一个能跑的知识库问答系统。

## 进阶篇：工程化生存指南

如果你不只是玩玩，想正经用 Vibe Coding 做项目，这里有四个保命技巧。

### 1. Memory 系统——AI 的长期记忆

Claude Code 有三层记忆：

- **CLAUDE.md**：项目宪法，每次对话自动加载。写清楚项目结构、技术栈、编码规范。**（50-100 行，别写太长，会吃上下文）**
- **MEMORY.md**：项目记忆，按需检索。存项目事实、用户偏好、已知坑点。
- **用户级 MEMORY.md**：跨项目共享。比如"我偏好 pnpm 而不是 npm"。

**最佳实践**：当你发现 Claude 犯了同样的错误两次，直接说"记住这个问题"，它会写入记忆文件，下次不会再犯。

### 2. /compact —— 续命神技

Claude Code 的上下文窗口大约 200K tokens（DeepSeek V4 Pro 更是支持 100 万 tokens，但 Claude Code 本身有 200K 的会话管理上限）。随着对话进行，历史消息会占满这个窗口。当 Claude 开始：
- 忘记你 10 分钟前说过的话
- 响应速度明显变慢
- 开始东拉西扯

**立刻执行 `/compact`**。它会压缩历史对话为摘要，释放大量空间。

> 我的习惯是每 30-50 轮对话主动 compact 一次。不要等 Claude 开始"失忆"才抢救——那时候已经晚了。

### 3. Git —— 你的后悔药

**这条怎么强调都不过分：每次让 AI 大改代码前，先 `git commit`。**

```bash
git add -A
git commit -m "AI 改版前快照"
```

别在 main 分支上直接让 AI 实验。建一个 `feature/xxx` 分支，玩坏了也不心疼。

### 4. CLAUDE.md —— 你给 AI 的"使用说明书"

这是 Vibe Coding 最被低估的功能。一个写得好的 CLAUDE.md 能让你和 AI 的协作效率翻倍。

一个最小可用的模板：

```markdown
# 项目名

## 技术栈
- 前端: React 19 + TypeScript + Tailwind CSS
- 后端: FastAPI + Python 3.12
- 向量数据库: ChromaDB
- LLM 框架: LangChain

## 目录结构
- frontend/ - React 组件和页面
- backend/ - FastAPI 后端服务
- data/ - 知识库文档

## 编码规范
- 组件用函数式组件 + Hooks
- Python 用 type hints
- API 路由统一在 backend/app/routes/
- 不要随意升级依赖版本

## 重要约定

- 不要改 ChromaDB 的持久化目录路径
```

## 我踩过的坑

本着教学精神，分享几个我翻车的经典时刻：

### 坑 #1：让 AI "随便做"

我说："帮我做一个好看的首页"

结果：AI 给我做了一个霓虹灯风格、自动播放 BGM、带粒子特效的首页。好看是好看了，但在办公室打开的时候全公司都看向了我。

**教训**：永远给 AI 设定风格边界。"简洁专业风格，不要夸张动效"——这句话加到 CLAUDE.md 里。

### 坑 #2：不看 Diff 就点 Yes

我连续点了 20 个 Yes 之后，发现 AI 把我的 `package.json` 里所有依赖版本都升级了。从 React 18 升到 React "latest"——不出意外地，项目炸了。

**教训**：关键文件（package.json、配置文件、数据库 schema）的修改，多看一眼 diff。

### 坑 #3：不说"停下来"

AI 有时候会陷入"修 bug → 引入新 bug → 修新 bug → 引入更多 bug"的死循环。我看到它已经改了 15 个文件还没修好，但不好意思打断它。

**教训**：AI 不是人，不会尴尬。发现方向错了直接说"停，我们换个思路"。**三毛二的 bug 修复预算不是让你浪费在死循环里的。**

### 坑 #4：以为 DeepSeek 什么都能做

第一次用 DeepSeek 的时候，我让它做一个需要复杂多模态推理的项目。它努力了，但效果确实不如 Claude Opus 原生模型。

**教训**：DeepSeek V4 Pro 在纯代码生成和调试方面非常强，性价比炸裂。但如果你的项目涉及大量复杂的逻辑推理、架构设计或需要极端精确的数学计算——可以考虑在关键步骤切到更强的模型，日常开发继续用 DeepSeek。混着用，把每一分钱花在刀刃上。

## Vibe Coding 的正确心态

最后说一个很多人搞错的事情：**Vibe Coding 不是"AI 替你干活，你啥都不管"。**

它是"AI 负责执行层，你负责决策层。"

- 你不需要会写 TypeScript，但你需要知道"类型安全很重要"
- 你不需要会配置 Webpack，但你需要知道"打包太慢了，优化一下"
- 你不需要会写 SQL，但你需要知道"数据不能丢，要持久化存储"
- 你不需要会调 ChromaDB 参数，但你需要知道"搜索结果不准的时候，让 AI 重新调"

你扮演的角色从"码农"变成了"产品经理 + 架构师 + 测试"。你的核心能力从"写代码"变成了"做决策"。

这其实比纯写代码更难——因为你需要**有判断力**。但这种能力会在实践中快速培养起来，因为你身边有个永远不会不耐烦的导师。

而且三毛二一次，你亏得起。

## 写在最后

Vibe Coding 刚刚兴起的时候，很多人说它是"程序员末日"。现在回头看，它不是末日，是工具进化。

就像挖掘机没有让建筑工人失业，只是让一个人能干十个人的活。Vibe Coding 也没有让程序员失业，只是让一个人能做十个人的项目。

而对于零基础的人来说——**这是最好的时代。** 你不需要花四年读一个计算机学位就可以做出能用的软件。你需要的只是：

1. 一台电脑
2. 一个 DeepSeek API Key（¥10 起充，够你玩一年）
3. 一个 Claude Code 终端
4. 清楚的表达能力
5. 点 Yes 的耐心
6. 三毛二

剩下的事情，交给 AI。
