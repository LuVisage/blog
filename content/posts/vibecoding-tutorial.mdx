## 导读：你到底需要"多会写代码"才能开始？

## Part 1：环境部署——唯一需要动手的十分钟

<small>这是整个 Vibe Coding 旅程中唯一需要你"操作"的阶段。每一节都配有来自黑马程序员课程的实操截图，跟着做。十分钟后你就可以纯靠嘴写代码了。</small>

### 1.1 终端基础——你的第一个"黑窗口"

如果你从来没打开过终端，别慌。终端就是一个黑色的文字窗口，你在里面打字，电脑执行。没有鼠标、没有图标——只有你和计算机之间最纯粹的交流。

**Windows 用户：**

Windows 10 的同学可以在应用商店搜索安装 **Windows Terminal**（Win11 自带，名字就叫"终端"）。打开后默认进入 **PowerShell**——这是微软推出的新一代命令行，兼容性和功能都比老式 CMD 更好。本课程所有命令都在 PowerShell 中执行。

![Windows 应用商店搜索 Windows Terminal](/images/vibecoding/yuque/nodejs-terminal.png)

> Windows 的终端分为两种：**CMD**（传统老式命令提示符）和 **PowerShell**（新一代命令行）。为了更好兼容 Claude Code，课程统一使用 **PowerShell**。

![打开终端，标题栏显示 Windows PowerShell](/images/vibecoding/yuque/nodejs-powershell.png)

如果遇到脚本执行权限报错，以管理员身份打开 PowerShell，执行：

```powershell
Set-ExecutionPolicy RemoteSigned -Scope CurrentUser
```

**Mac 用户：**

按 `Cmd + 空格`，输入 `terminal`，回车即可。

**终端基础命令对照表（不用背，用到了回来查）：**

**路径与目录操作：**

| 功能 | Windows CMD | Windows PowerShell | Mac / Linux |
|------|------------|-------------------|-------------|
| 当前路径 | `cd` 或 `echo %cd%` | `pwd` | `pwd` |
| 切换目录 | `cd C:\Users\...` | `cd C:\Users\...` | `cd ~/Documents` |
| 列出文件 | `dir` | `ls`（也支持 `ls -l`） | `ls`、`ls -la` |

**文件增删改：**

| 功能 | Windows CMD | PowerShell | Mac / Linux |
|------|------------|-----------|-------------|
| 创建目录 | `mkdir 文件夹名` | `mkdir 文件夹名` | `mkdir 文件夹名` |
| 创建空文件 | `type nul > 文件.txt` | `New-Item 文件.txt` | `touch 文件.txt` |
| 删除文件 | `del 文件名` | `Remove-Item 文件名` | `rm 文件名` |
| 删除目录 | `rmdir 文件夹名` | `Remove-Item 文件夹名` | `rmdir 文件夹名`（空）/ `rm -r`（⚠️谨慎） |
| 查看文件 | `type 文件.txt` | `cat 文件.txt` | `cat 文件.txt` |

**通用快捷键：**

| 快捷键 | 功能 |
|--------|------|
| `Tab` | 自动补全文件名/命令 |
| `↑` / `↓` | 历史命令切换 |
| `Ctrl+C` | **终止当前命令**（不是复制！） |
| `Ctrl+L` | 清屏（Mac）/ `cls`（Win） |
| `Ctrl+R` | 搜索历史命令 |

> **💡 最重要的提醒**：终端里 `Ctrl+C` 不是复制，是终止！复制用 `Ctrl+Shift+C`（PowerShell）或 `Cmd+C`（Mac）。删除命令（`rm`、`del`、`rmdir`）不可恢复，操作前确认清楚。

掌握以上内容，你已经完全具备使用终端配合 Claude Code 的能力。

### 1.2 安装 Node.js——Vibe Coding 的"地基"

Claude Code 基于 Node.js 运行，这是我们的第一块砖。

1. 打开 [nodejs.org](https://nodejs.org)
2. 下载 **LTS 版本**（Windows 选 `.msi`，Mac 选 `.pkg`）
3. 安装——全程「下一步」，一个设置都不用改
4. 课程资料里也提供了离线安装包（`node-v24.16.0-x64.msi`），可以直接双击运行

![Node.js 官网下载页面——选择 LTS 长期支持版本](/images/vibecoding/deploy-nodejs.jpg)

![Node.js 安装向导——一路下一步](/images/vibecoding/yuque/nodejs-install1.png)

装完后，打开终端验证：

```bash
node --version   # 应显示 v24.x.x 或更高
npm --version    # 应显示 11.x.x 或更高
```

![终端验证——显示版本号即部署成功](/images/vibecoding/yuque/nodejs-verify.png)

看到版本号就说明装好了。如果提示"找不到命令"，重启一下终端再试。

> **国内用户加速技巧**：先把 npm 镜像源切到国内，后面安装 Claude Code 会快很多：
> ```bash
> npm config set registry https://registry.npmmirror.com
> ```

### 1.3 安装 Python——后端的"发动机"

虽然前端用 Node.js，但后续 RAG 项目需要 Python 的 AI 生态（LangChain、ChromaDB 等）。

1. 打开 [python.org](https://python.org)，下载 Python 3.10+
2. 课程资料里提供了离线安装包（`python-3.14.6-amd64.exe`），双击运行

![Python 安装——务必勾选 Add python.exe to PATH](/images/vibecoding/yuque/python-path.png)

3. **安装时务必勾选「Add Python to PATH」**——漏了这步后面到处报错！

![Python 安装选项——勾选后点击 Customize installation](/images/vibecoding/yuque/python-install.png)

4. 选择安装路径，不要带中文、不建议放 C 盘（课程示例：`D:\dev\sdk\Python\Python314`）
5. 一路下一步完成安装

验证：

```bash
python --version  # 应显示 3.10.x 或更高
pip --version     # 应显示 24.x 或更高
```

> **国内用户加速**：切一下 pip 镜像源：
> ```bash
> pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
> ```

### 1.4 安装 Git——你的"后悔药"

Git 是版本控制工具，简单说就是"给代码拍快照"。每次让 AI 大改代码前拍一张，改坏了随时能回到过去。

1. 打开 [git-scm.com](https://git-scm.com)，下载安装
2. 课程资料里提供了离线安装包（`Git-2.54.0-64-bit.exe`），双击运行

![Git 安装向导——GNU General Public License 页面](/images/vibecoding/yuque/git-install.png)

3. 安装全程「下一步」，所有选项用默认值（选择安装目录时注意不要有空格和中文、不建议放 C 盘）
4. 验证：

```bash
git --version   # 应显示 2.x.x
```

### 1.5 安装 Claude Code——Vibe Coding 的"大脑"

终于到主角了。打开终端，敲一行命令：

![Claude Code 终端安装界面](/images/vibecoding/deploy-claude-code.jpg)

```bash
# 如果网络环境不太好可以先执行这条命令
npm config set registry https://registry.npmmirror.com

# 执行如下命令，开始安装 Claude Code（Mac 用户加 sudo）
npm install -g @anthropic-ai/claude-code
```

![Claude Code 安装过程——等待 1~5 分钟](/images/vibecoding/yuque/cc-install.png)

安装完成后验证：

```bash
claude --version  # 应显示版本号，如 2.1.179
```

> **💡 这里停一下**：如果你出于好奇去搜了 OpenAI CodeX，想用它接 DeepSeek，你会发现自己需要安装 Go 1.25+、克隆 Moon Bridge 仓库、手写三个配置文件（YAML + TOML + JSON）、启动代理服务……等你折腾完这些，用 Claude Code 的同学已经把项目部署上线了。CodeX 不是不能用，但它对第三方模型的支持靠的是社区用爱发电的转发层，每多一层转发就多一层出错的可能。Claude Code 原生支持自定义 API endpoint，三行 JSON 搞定。**结论：省事就用 Claude Code。**

### 1.6 VS Code 集成——在编辑器里指挥 AI

虽然 Claude Code 可以在终端里直接用，但配合 VS Code 体验更好——能在编辑器里直接对话，选中代码一键发给 AI。

1. 下载安装 [VS Code](https://code.visualstudio.com)（课程资料提供了安装包：`VSCodeUserSetup-x64-1.124.2.exe`）
2. 安装中文语言包：插件市场搜索 `chinese`，安装后点击 "Change Language and Restart"

![VS Code 扩展市场——搜索并安装 Claude Code 官方插件](/images/vibecoding/deploy-vscode.jpg)

3. 插件市场搜索 `Claude Code`，找到 **Anthropic** 官方发布的 "Claude Code For VS Code"，点击安装

![VS Code 中 Claude Code 插件测试——显示连接成功](/images/vibecoding/yuque/vscode-test.png)

装好后，VS Code 侧边栏会出现 Claude Code 图标，点击就能在编辑器里和 AI 对话了。如果找不到 Claude Code 的 UI，按 `Ctrl+Shift+P` 呼出命令面板，选择 "Claude Code: Open" 即可恢复窗口。

**实用技巧：**
- 选中代码后按 `Ctrl+Shift+L`（Mac 用 `Cmd+Shift+L`），直接把代码发给 Claude
- Claude 修改代码后，VS Code 会显示 diff 对比，你可以逐行审查

### 1.7 配置 DeepSeek API——把"大脑"接上"云端"

Claude Code 本质上是一个"对话框架"，AI 想写出代码需要一个"有思想的模型"来做支撑。课程选择国内 DeepSeek API，原因：**原版 Claude 模型国内无法使用，中转服务不稳定，国产模型在编程方面不落后太多且便宜到令人发指。**

#### 第一步：获取 API Key

1. 打开 [platform.deepseek.com](https://platform.deepseek.com)，注册账号
2. 充值建议：先充 ¥10，够你用很久很久
3. 点击「API Keys」→「创建 API Key」，起个名字（随意）
4. **⚠️ 立即复制保存！API Key 只显示这一次！**

![DeepSeek 开放平台——创建 API Key](/images/vibecoding/yuque/cc-deepseek-key.png)

#### 第二步：配置 Claude Code

打开（或新建）这个文件：

- **Windows**：`C:\Users\你的用户名\.claude\settings.json`
- **Mac**：`~/.claude/settings.json`

填入以下内容（把 `你的APIKEY` 替换成刚才复制的 key）：

```json
{
  "model": "deepseek-v4-pro",
  "apiKey": "你的APIKEY",
  "baseURL": "https://api.deepseek.com/v1"
}
```

**就这三行。** 没有 Go 环境，没有 YAML，没有代理服务。保存，关闭。

#### 第三步：测试

```bash
cd ~/Desktop
mkdir test && cd test
claude
```

首次进入会提示选择文本风格（建议选 1 自动控制），然后会有一些安全警告（直接回车即可），最后选择 "Yes" 信任当前文件夹。

![Claude Code 测试——询问"你是什么大模型？"](/images/vibecoding/yuque/cc-test.png)

输入：

> 你是什么大模型？

如果它回答「我是 DeepSeek V4 Pro……」——🎉 恭喜！环境部署完毕！从现在开始，你只需要做两件事：**清楚地表达需求，以及疯狂点 Yes。**

## 入门实战：用 Vibe Coding 开发"黑马记账"APP

目前我们已经完成了 Node.js、Git、Python 等基础环境、Claude Code 和 VS Code 的集成。现在，以一个小白的视角，完成一个《个人记账 APP》的实战开发。

> **注意**：本次项目开发以小白视角进行——我们不对 Claude Code 提出专业要求，而是要求 Claude Code 给出方案、解释方案，我们做选择题。PS：因为小白本身也无法给出专业方面的要求，所以由 Claude Code 做好引导。

### 项目创建

在电脑中创建文件夹 `黑马记账APP`，用 VS Code 打开它。

### 选择决策方案

在 VS Code 的 Claude Code 面板，点击举手图标，有三种方案：

- **Ask before edits**：每次文件修改都弹窗请求手动审批
- **Edit automatically**：代码修改自动执行，但终端命令仍需审批
- **Plan mode**：AI 先完整扫描、设计改造计划，不直接改文件，等你确认后再执行

我们选择 **Plan mode**，并把 Effort 拉满——以非专业人士视角，由 AI 给出方案并解释，我们做决策。

![VS Code 中 Claude Code 面板——选择 Plan mode 并拉满 Effort](/images/vibecoding/yuque/entry-planmode.png)

### 准备产品文档（CLAUDE.md）

在对话中输入如下提示词：

> 我需要生成一个APP，名字：黑马记账；我不懂编程技术，也是初次使用 Claude Code，你先帮我设计产品文档，并记录到 CLAUDE.md 中；
>
> 我的一些要求如下：
> 1. 我需要这个APP是可以运行在Windows电脑和Mac电脑上；
> 2. APP功能主要是可以记录用户每一次的花销（单位人民币），并可以记录花销的分类，分类分为2级，有一级大类、和二级小类，分类你来设计；
> 3. 技术栈选型你决定，请列出几个方案给我并列出优劣势，我来挑选并决定；
>
> 注意：在整个项目开发过程中，任何关于技术方面的事情，我无法提供具体的要求，必须是你列出方案给我，并向我解释各个方案，由我来决定，请将这个要求详细记录在 CLAUDE.md 中，在整个项目期间遵守；

Claude Code 经过思考后，给出了技术方案选择。课程选择：方案 B（Tauri + React），勾选阅读支出统计图表、数据导出 Excel/CSV。点击 Submit answers 确认。

![Claude Code 给出技术方案——做选择题即可](/images/vibecoding/yuque/entry-prd.png)

经过执行后，Claude Code 生成了 CLAUDE.md 文件。我们选择 **"Yes, and manually approve edits"**（每次手动批准修改），保持对项目的控制感。

### 项目初始化

Claude Code 按照方案自动推进：

1. **项目环境检查**：扫描 Node.js、Rust 等是否齐全 → 点 Yes
2. **Rust 环境安装**：Tauri 需要 Rust → 点 Yes 让它自动部署
3. **初始化项目环境**：`npm create` 创建 Tauri + React 项目框架 → 点 Yes
4. **确认项目名称**：如果 name 栏是拼音（`heimajizhang`），确认即可

![Claude Code 创建项目——初始化项目结构](/images/vibecoding/yuque/entry-create.png)

### 功能开发——全程做选择题

随着开发推进，AI 不断抛出选择题：

- **数据存储方案**：A（本地 SQLite）vs B（云端数据库）→ 选 A，简单方便
- **统计图表库**：A（Recharts）vs B（ECharts）→ 让 AI 解释后选择
- **导出格式**：Excel / CSV / 都需要 → 两个都要

每一步 AI 都会解释各方案的优劣势。你不需要懂技术，只需要根据常识做判断。

### 打包 APP

**Mac 系统**：AI 直接编译生成 `.app` 文件。

**Windows 系统**：如果在 Mac 上开发，将项目文件夹复制到 Windows 电脑，用 VS Code 打开，发送：

> 请帮我将项目打包为 Windows 的 exe 程序；此项目内容在 MacOS 系统下构建，已经完成了 Mac 版本的程序打包，所以复制到 Windows 系统下，你帮我继续打包 Windows 版本的程序 exe

AI 会自动识别平台差异、重新部署环境、编译生成 `.exe`。

### 费用：¥1.30

本次操作全程使用 DeepSeek V4 Pro，共消耗人民币 **1.3 元**。一个带图表统计、数据导出、二级分类的桌面记账 APP。

## Part 2：Claude Code 工程化控制——从工具到武器

<small>适用版本：Claude Code CLI（截至 2026 年 7 月）。官方文档：https://code.claude.com/docs</small>

环境搭好了，第一个项目跑通了。但在继续做更复杂的 RAG 项目之前，你必须先搞清楚一个问题：**Claude Code 到底有什么武器？** 它不是一个聊天机器人——它是完整的 AI 软件工程平台。这一节的内容来自黑马程序员课程的 Part2，信息量很大，但**不需要全记住——用到时回来查。**

### 2.1 上下文压缩控制——别让 AI 变"金鱼"

#### 核心概念

Claude Code 的上下文窗口有限（通常约 200K tokens）。随着对话进行，历史消息、代码片段、工具调用结果不断累积，最终触发"上下文窗口满"。此时 AI 开始"遗忘"——忽略早期指令、响应变慢、牛头不对马嘴。**有效的上下文管理是保持长会话生产力的最关键技能。**

#### `/compact` 命令——最重要的生存技能

`/compact` 是 Claude Code 最重要的命令，没有之一。它的工作原理：

- Claude 读取完整对话历史，生成结构化摘要
- 摘要内容包括：已完成的任务、已做的决策、修改过的文件、关键事实
- 早期对话被替换为压缩摘要，仅保留最近的若干轮完整对话
- 压缩后释放大量上下文空间，可以继续工作

**使用时机（背下来）：**

- ✅ 主动压缩：每 30-50 轮对话后主动执行，不要等 Claude "开始遗忘"才压缩
- ✅ 任务切换时：完成一个大任务、开始新任务前
- ✅ 响应变慢时：对话历史过长会导致处理速度下降
- ✅ 开始出现遗忘迹象：Claude 开始忽略早期指令时

**注意事项：** 压缩是**不可逆**的；压缩质量取决于对话结构清晰度；压缩前可手动总结关键点告诉 Claude。

#### 自动压缩（Auto-Compact）

Claude Code 在上下文接近上限时会自动触发压缩。但依赖自动压缩有两个问题：自动压缩发生在"快满"的时候（AI 可能已经表现下降），**主动 `/compact` 比被动等待效果更好**。

#### 减少上下文消耗的技巧

- **精准提问**：明确指定你需要什么，避免开放式问题产生大量输出
- **文件读取策略**：不要一次性读取整个大文件，指定行范围或搜索特定函数
- **CLAUDE.md 精简**：保持 50-100 行，在每次会话启动时加载
- **利用 `.gitignore`**：Claude Code 会自动忽略其中的文件和二进制文件

#### 上下文状态查看

- Claude 每次响应后显示 token 使用统计
- **观察响应速度**：明显变慢 → 需要 `/compact`
- 如果 Claude 开始"忘记"本轮对话中的重要信息 → 上下文可能已压缩或滚动

### 2.2 Memory 记忆管理——AI 的长期记忆

#### 三层记忆体系

| 层次 | 位置 | 作用域 | 加载时机 |
|------|------|--------|---------|
| **项目级 CLAUDE.md** | `<project>/CLAUDE.md` | 当前项目 | 每次会话启动时完整加载 |
| **项目级 MEMORY.md** | `<project>/.claude/memory/` | 当前项目 | 会话中按需检索 |
| **用户级 MEMORY.md** | `~/.claude/memory/` | 所有项目 | 会话中按需检索 |

#### CLAUDE.md —— 项目宪法

CLAUDE.md 是最重要的记忆载体，每次会话初始化时完整加载。用 `/init` 让 AI 自动生成，然后微调。

应该包含：项目结构（目录说明）、编码规范（命名、状态管理、API 调用方式）、重要约定（什么绝对不能碰）。记忆类型分四种：`user`（偏好）、`feedback`（纠正）、`project`（目标约束）、`reference`（外部链接）。使用 `[[slug-name]]` 语法关联记忆。

关键用法：直接说"记住我使用 pnpm 而非 npm"，Claude 会自动创建/更新记忆文件。

#### 记忆管理原则

1. **不存代码能推导的信息**：项目结构、git 历史不放记忆
2. **不存仅限本次对话的信息**：临时事实不持久化
3. **及时更新**：偏好改变时告知 Claude
4. **定期审查**：MEMORY.md 内容可能过时

### 2.3 代码回退管理——给你的代码上保险

#### 安全检查点策略

在让 Claude 做重大改动之前，**务必创建检查点**：

```bash
git add -A && git commit -m "AI 改版前快照"
git reset --hard HEAD~1  # 改坏了？一键回到过去
```

#### 撤销 Claude 的改动

| 场景 | 回退方式 |
|------|---------|
| 刚改的、还没 commit | `git checkout -- <file>` |
| 已经 commit | `git reset --hard HEAD~1` |
| Claude 正在改 | 说"撤销你刚才的改动" |
| 多个文件被改 | 说"把 xxx 文件恢复到改之前" |

#### Git Worktree 隔离

Worktree 允许在独立目录中工作，不影响主工作区。适用场景：试验性重构、并行多任务。Claude Code 的 `/batch` 功能底层就是 worktree。

#### Claude Code 内置回退机制

- **对话自然撤销**："撤销你刚才的改动" / "恢复到 xxx 之前的状态" / "把 xxx 文件恢复到改之前"
- **备份目录**：`~/.claude/backups/`
- **File History**：`~/.claude/file-history/`

#### 安全建议

1. 重要的代码先 commit——这条怎么强调都不过分
2. 在专用分支工作，别在 main 上试验
3. 定期 `git diff` 审查 AI 的改动
4. 看不懂改动就让 AI 解释，理解了再继续
5. 小步提交，每次小改动后 commit

### 2.4 Skills 技能系统——给 AI 装"专业训练模块"

Skills 是 Claude Code 最被低估的功能。你可以理解为给 AI 装专业训练模块。

#### 内置技能

| 技能 | 用途 | 使用频率 |
|------|------|---------|
| `/code-review` | 全面代码审查：正确性、安全、性能、风格 | ⭐⭐⭐⭐⭐ |
| `/review` | PR 审查：分析完整 diff，生成结构化审查报告 | ⭐⭐⭐⭐ |
| `/verify` | 手动验证：启动服务器、发送请求、确认改动生效 | ⭐⭐⭐ |
| `/security-review` | 安全专项审查：OWASP Top 10、注入漏洞、敏感信息泄露 | ⭐⭐⭐ |
| `/design-sync` | 设计系统同步：与 claude.ai/design 项目保持组件一致 | ⭐⭐ |
| `/fewer-permission-prompts` | 分析操作记录，自动生成合理权限配置 | ⭐⭐ |

commit 前养成 `/code-review` 习惯；安全代码必跑 `/security-review`；AI 的建议需人工判断。

#### 创建自定义技能

**方式一**：通过 `settings.json` 注册简单技能（指令模板）。配置在项目级 `<project>/.claude/settings.local.json` 或用户级 `~/.claude/settings.json`。

**方式二**：在 `~/.claude/plugins/` 下创建技能文件，把重复性操作固化为命令——一次写好，终身受益。

### 2.5 Hooks 钩子系统——自动化你的工作流

Hooks 允许在特定事件前后自动执行脚本。这是 Claude Code 从"工具"升级为"自动化平台"的关键功能。

#### 支持的 Hook 类型

| Hook | 触发时机 | 实用场景 |
|------|---------|---------|
| `pre-command` | 执行命令之前 | 敏感命令二次确认 |
| `post-command` | 执行命令之后 | 自动记录操作日志 |
| `on-start` | 会话启动时 | 注入项目上下文 |
| `on-complete` | 工作完成时 | 发送通知、自动 commit |
| `pre-edit` | 编辑文件之前 | 自动备份原文件 |
| `post-edit` | 编辑文件之后 | 自动运行 lint、格式化 |

#### Hook 脚本可访问的环境变量

- `CLAUDE_EVENT_TYPE` —— 事件类型
- `CLAUDE_COMMAND` —— 将要执行或已执行的命令
- `CLAUDE_FILE_PATH` —— 正在编辑的文件路径
- `CLAUDE_WORKING_DIR` —— 当前工作目录

#### 配置示例

```json
{
  "hooks": {
    "post-edit": [{
      "matcher": "**/*.{ts,tsx}",
      "command": "npx prettier --write \"$CLAUDE_FILE_PATH\""
    }]
  }
}
```

> 💡 初学者可以先放着不用。熟悉工作流后自然会遇到"每次 AI 改完代码我都要手动 format"这种痛点——到那时再配 Hook，一步到位。

|------|------|

### 2.7 代码审查——别让 AI 放飞自我

AI 写的代码不一定都对。好在 **AI 也能审查自己的代码**。

#### 内置审查命令

| 命令 | 作用 | 审查范围 |
|------|------|---------|
| `/code-review` | 代码质量审查 | 当前工作区 diff |
| `/review <PR_URL>` | PR 审查 | 指定的 Pull Request |
| `/verify` | 手动验证改动 | 实际运行应用确认功能 |
| `/security-review` | 安全审查 | 当前分支变更 |

#### `/code-review` 详解

```bash
/code-review            # 默认审查（中等深度）
/code-review --fix      # 审查并自动修复发现的问题
/code-review --comment  # 审查并将发现发布为 PR 内联评论
```

审查维度：正确性 Bug、安全性、代码复用、代码风格、性能。

**Effort 级别：**

| 级别 | 深度 | 适用场景 |
|------|------|----------|
| `low` | 快速扫描 | 小改动、格式修复 |
| `medium` | 标准审查 | 常规 PR |
| `high` | 深度分析 | 核心逻辑、安全敏感代码 |
| `xhigh`/`max` | 全面审查 | 关键基础设施、安全审计 |

#### 最佳实践

1. commit 前审查：养成 `/code-review` 再 commit 的习惯
2. 分级审查：普通改动 medium，核心模块 high 或 max
3. 结合测试：先让 Claude 写测试，再用 `/verify` 确认通过
4. 大 PR 分文件审查：一次改 20 个文件则分多次
5. 审查后不要盲从：Claude 的建议需人工判断是否采纳

### 附录：典型工作流

#### A. 新功能开发流程

1. Plan Mode 下描述需求，让 AI 出方案
2. 审核方案，调整方向
3. `git commit` 创建检查点
4. 切换到 Edit Mode 开始开发

#### C. 代码审查流程

1. `git diff > changes.patch` 导出改动
2. `/review` 分析 diff，生成审查报告
3. 根据报告决定：通过 / 修改 / 重做

## Part 3：LangChain RAG 企业级知识库问答项目实战

### 3.1 项目 init 提示词（课程原文）

> 我的毕设是，通过 langchain 框架，开发 RAG 企业级知识库问答系统，用户可以通过浏览器进行知识库问答操作；

>

### 3.2 第一步：AI 出方案，你做选择题

Claude Code 会思考 1-2 分钟，给你甩出一个完整架构方案：

- **技术栈选型理由**：为什么选 FastAPI 而不是 Flask？为什么选 ChromaDB 而不是 Pinecone？每个决策都有解释
- **项目目录结构**：`frontend/`、`backend/`、`database/` 各司其职

## Part 4：为什么选 Claude Code + DeepSeek 而不是 CodeX？

### CodeX vs Claude Code：一篇血泪史

你可能想——OpenAI CodeX 不是亲儿子吗？应该更强才对。来，看看用 CodeX 接入 DeepSeek 需要做什么：

| 步骤 | Claude Code | CodeX |
|------|------------|-------|
| 1. 安装 Node.js | ✅ `npm install -g @anthropic-ai/claude-code` | ✅ 需要 |
| 2. 安装 Go 1.25+ | ❌ 不需要 | ⚠️ **需要** |
| 3. 克隆 Moon Bridge | ❌ 不需要 | ⚠️ **需要**（第三方转发中间层） |
| 4. 手写 config.yml | ❌ 不需要 | ⚠️ **需要**（30+ 行 YAML + API Key） |
| 5. 手写 config.toml | ❌ 不需要 | ⚠️ **需要** |
| 6. 手写 models_catalog.json | ❌ 不需要 | ⚠️ **需要** |
| 7. 启动代理服务 | ❌ 不需要 | ⚠️ **需要**（保持终端常驻） |
| 8. 配置 Claude Code | ✅ 3 行 JSON | — |
| **总耗时** | **~10 分钟** | **~1-2 小时（顺利的话）** |

CodeX 的 Moon Bridge 配置长这样（给你感受一下）：

```yaml
mode: "Transform"
server:
  addr: "127.0.0.1:38440"
models:
  deepseek-v4-pro:
    context_window: 1000000
    max_output_tokens: 384000
    default_reasoning_level: "high"
    # ... 还有 40+ 行
providers:
  deepseek:
    base_url: "https://api.deepseek.com/anthropic"
    api_key: "sk-your-deepseek-api-key"
# ...
```

我就问一句：**零基础小白手写 30 行 YAML 配置，跟我直接学编程有什么区别？** CodeX 对第三方模型的支持靠 Moon Bridge 社区转发层。多一层转发多一层出错可能。**这叫 Vibe Coding？这叫 Vibe Debugging。**

## Part 5：我踩过的坑

### 坑 #1：让 AI "随便做"

我说："帮我做一个好看的首页"。结果：霓虹灯风格、自动播放 BGM、带粒子特效。办公室打开时全公司都看向我。

**教训**：永远给 AI 设定风格边界。把"简洁、专业、不夸张"写进 CLAUDE.md。

### 坑 #2：不看 Diff 就点 Yes

连点 20 个 Yes 后，AI 把所有依赖版本从锁定版升级到 "latest"——项目炸了。

**教训**：重要文件（package.json、配置文件、数据库 schema）多看一眼 diff。

### 坑 #3：不说"停下来"

AI 陷入"修 bug → 引入新 bug → 修新 bug"的死循环，改 15 个文件还没修好。

**教训**：AI 不会尴尬。发现方向错了直接说——"停，换个思路。"

### 坑 #4：以为 DeepSeek 什么都能做

DeepSeek V4 Pro 在代码生成和调试方面非常强，但涉及极端复杂逻辑推理时，可以关键步骤切到更强模型，日常继续用 DeepSeek。混着用，每一分钱花在刀刃上。

## Part 6：Vibe Coding 的正确心态

**Vibe Coding 不是"AI 替你干活，你啥都不管。"** 它是"AI 负责执行层，你负责决策层。"

| 你不需要会…… | 但你需要知道…… |

| 写 HTML/CSS | "这个页面布局很乱，按照设计规范重新排版" |

你扮演的角色从"码农"变成了"产品经理 + 架构师 + 质量把控"。这其实比纯写代码**更难**——因为需要判断力。但好消息是：这种能力会在实践中快速培养，因为你身边有个永远不会不耐烦的导师。而且三毛二一次，你亏得起。
