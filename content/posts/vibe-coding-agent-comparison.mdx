## 测评方法：先说清楚「横评」是怎么横的

模型月月更新，任何带版本号的结论三个月就过期，所以这篇刻意**只评形态与能力维度，不锁版本**。结论有效期标注为 2026 年 9 月，各家事实（产品定位、发布时间）以官方页面与文档为准。

这份名单横跨三层，评的是各自那一层的核心能力：

- **工具层**——能替你写代码的 agent，按形态分终端系与 IDE/桌面系；
- **办公与通用 agent 平台**——不止写代码，把编程当作众多任务之一；
- **引擎与基础设施**——模型本身与模型路由，决定 agent 的脑子和你的账单。

工具层共用同一组任务：热修复一个跨 3 文件的滚动监听泄漏、从零写一个 sitemap 生成 CLI、把组件库从 props 传值重构为 context、处理一次真实的构建失败。评五个维度：**代码库理解**、**规划**、**终端执行力**、**可控性**、**成本形态**。

## 终端系四家：长任务的脊梁

### Claude Code：终端 agent 的标杆

读整个仓库、改文件、跑命令、看输出、自我纠正，一条龙。规划与长任务稳定性仍是第一梯队：热修复任务里它自己翻日志定位到泄漏点，全程零人工。diff 确认制让可控性很好，`CLAUDE.md` 规则文件与 MCP 生态成熟。坑：按量计费下长任务烧 token 很凶。**适合**：住终端的工程师、大仓库维护、长链路任务。

### Codex CLI：同形态的同级对手

OpenAI 的终端 agent，沙箱分级（只读 / 自动 / 全权）设计清晰，规划与执行同处第一梯队。与 Claude Code 的差距是风格细节而非能力代差，两家订阅并存的话切换成本几乎为零。**适合**：已在 OpenAI 生态的人；以及想对照第一梯队长什么样的参照系。

### OpenCode：开源党与换引擎自由

开源终端 agent（TUI 形态），最大卖点是**引擎无关**：OpenRouter、DeepSeek、GLM 任意接，模型市场卷翻天，你一行配置就能换脑。**适合**：想精控成本、想用国产引擎跑国际级工具、以及一切开源党。

### DeepSeek Harness（DSH）：新入场的开源重量级

DeepSeek 在 2026 年 8 月开源的官方 Agent 运行时框架，定位直接对标 Codex / Claude Code 这类 coding agent——这也解释了为什么它值得和上面三家并列。三个记忆点：**一切皆插件**的 Cordis 架构（能力全靠插件拼装，自带插件市场）；桌面版与多种运行模式，不只是命令行；官方提供免费 API 额度，上手成本几乎为零。单看任务完成度，它是第一梯队的有力挑战者，插件生态的厚度还需要时间。**适合**：想要 DeepSeek 体验全家桶、喜欢插件化定制、预算敏感又想要官方支持的开源用户——它和 OpenCode 是「开源终端 agent」赛道里路线完全不同的两个答案。

## IDE 与桌面系五家：节奏与体验

### Windsurf：Cascade 的体验流

独立 IDE，Cascade 把 agent 的多步操作做成一条可读的「动作流」，代码库索引质量第一梯队，热修复表现接近终端系。**适合**：喜欢独立 IDE、看重 agent 过程可读的人。

### Trae：字节出品，上手零门槛

国内可直接用的 AI IDE，免费档额度大方，中文体验顺滑；SOLO 模式尝试把「需求 → 任务拆解 →执行」全托管。单点能力是追随者水平，但「今天下载今天出活」的门槛全场最低。**适合**：学生、初学者、以及「先免费用起来再说」的场景。

### Qoder：阿里的任务委派派

阿里的 Agentic IDE，两个特色功能记住了：**Quest 模式**——把任务整个委派给后台 agent 跑完再来验收，人从「盯着看」变成「收作业」；**Repo Wiki**——自动给仓库生成结构化文档，接手陌生仓库时是实打实的减负项。规划维度在 IDE 系里排前列。**适合**：接手陌生代码库的人、喜欢「委派式」工作流的团队。

### CodeBuddy：国内生态的务实解

腾讯系，IDE 与插件双形态，Craft 智能体覆盖常规 agent 工作流。最大优势是「顺」：国内网络直连、中文交互自然、与微信小程序和国内云的工具链贴合。**适合**：国内环境、小程序与云开发、不想折腾网络与 Key 的学习者。

### ZCode：智谱的 ADE，模型厂下场做环境

智谱（Z.ai）在 2025 年底发布的 Agentic Development Environment——桌面端 + CLI 双形态，绑定自家 GLM 系引擎（GLM-5.3 起与 ZCode 同步迭代）。长任务工作流、指哪改哪的元素级编辑、多端跟进这些细节能看出「模型厂懂自己模型短处」的针对性设计。配合 GLM Coding Plan 包月，是「官方全家桶」路线：环境、引擎、账单一站式。**适合**：想要订阅制确定性、GLM 系重度用户、以及想观察「模型厂做 IDE 会做成什么样」的人。

## 办公与通用平台三家：代码只是任务之一

### WorkBuddy：腾讯的办公 Agent 工作台

腾讯云代码助手团队（就是 CodeBuddy 背后那支队伍）推出的全场景 AI 办公工作台，覆盖日常办公、代码开发与设计创意：多 Agent 并行、自主规划并交付多模态任务结果。它的定位和 CodeBuddy 是错开的——CodeBuddy 是开发者工具，WorkBuddy 是「办公即 agent」的泛工作台，写代码只是它众多任务里的一类。**适合**：想让 agent 处理「文档 + 表格 + 代码」混合任务的职场人；纯工程场景还是 CodeBuddy 更对口。

### 百度搭子（DuMate）：文心快码并入了这里

百度把文心快码（Baidu Comate，服务超千万开发者的编程助手）并入了通用智能体平台百度搭子，编程成为这座「智能体中央枢纽」里的一条产品线。对开发者的实际影响：Zulu 智能体与代码能力还在，但获取入口、账号体系与周边能力都换成了平台制。**适合**：已有百度智能云生态的团队、以及「一个平台解决办公与编程」的使用习惯。

### 豆包：对话端的轻量编程

豆包是字节的对话助手，编程场景里它的真实形态要说清楚：**工程化的字节系载体是 Trae**——原豆包 MarsCode 插件与 Cloud IDE 已演进为 Trae 桌面端与 TraeCode 插件。豆包本尊适合的是轻量场景：解释报错、起稿小脚本、讨论方案，随问随答没有工程负担；一旦要动仓库、跑构建，就该切到 Trae。**适合**：已经在用豆包对话、编程需求尚轻的用户——把豆包当作 vibecoding 的第一级台阶，台阶之上是 Trae。

## 引擎与基础设施：决定脑子和账单

### DeepSeek（引擎）

DSH 之外，DeepSeek 的 API 是很多 agent 的「脑子」：价格在同档常年最有攻击性，权重开放、可私有化，配合 OpenCode 这类自带 Key 的工具是预算敏感场景的标准答案。**适合**：按量精打细算、需要私有化的团队。

### GLM Coding Plan（智谱引擎订阅）

把 GLM 系模型打包成面向编码的包月计划，可以喂给 Claude Code、OpenCode 等第三方工具当引擎。意义在于**用订阅价把第一梯队工具的油费打下来**，且国内直连；能力上限由 GLM 当前代际决定，日常业务代码够用。**适合**：高频使用终端 agent、想要账单确定的国内开发者。

### OpenRouter（模型超市）

统一网关：一个 API Key 访问几百家模型，切换、比价、看用量一处搞定，OpenCode 这类引擎无关的工具原生支持。它解决「锁死」问题：**引擎可替换，工具的选择就不再绑架你的模型选择**。**适合**：自带 Key 玩法的用户；做模型横评时它本身就是脚手架。

## 组合策略：工具与引擎解耦

这份名单给我最大的认知升级是：**选工具时不必再为「它用什么模型」纠结**。三个成熟组合：

- **订阅确定性**：GLM Coding Plan 包月 → 喂给 Claude Code / OpenCode 当引擎。月费固定，随便烧；
- **极致性价比**：DeepSeek API → OpenCode / DSH。按量付费，成本透明到每一次请求；
- **多引擎横跳**：OpenRouter 一个 Key → 所有自带 Key 的工具随切。新模型发布当天就能在你的工作流里 A/B。

工具层的护城河在形态与工作流细节，引擎层卷价格与代际，两层各自迭代——**把变量拆开，你的选型就从「站队」变成了「配置」**。

四个值得注意的观察：

1. **包月订阅是两个世界**：国际第一梯队（Claude / Cursor）在 20 美元档起步，国产编码订阅（GLM Coding Plan Lite 118 元/月）几乎低一个数量级——对高频使用的国内开发者，这是最容易算清的一笔账。
2. **按量党的地板被 DeepSeek 再次击穿**：峰谷分时 + 缓存命中 0.02 元/百万 token，意味着空闲时段跑长任务的成本可以低到忽略不计；代价是高峰时段双倍价，批处理任务适合挪到谷时。
3. **腾讯把 CodeBuddy 和 WorkBuddy 的积分打通了**：一份订阅覆盖办公与编程两条线，这是「平台制」打法的典型动作，百度搭子同理。
4. **免费档已经够学习期用了**：Trae、Qoder、CodeBuddy 的免费档、DSH 的官方额度、豆包零成本——入门阶段真正需要付费的场景，只有「高频重度使用终端 agent」这一种。

## 三条跨工具都成立的经验

**一、审查成本会反噬效率。** 所有工具在自动化档位都出现过同一类事故：改动范围悄悄扩大。工具越自动，越要把「改动文件清单」列为交付物。

**二、token 消耗的大头是上下文，不是输出。** 同一个任务，喂错上下文能多花十倍。规则文件、精准的文件引用、及时开新会话，三个立竿见影的省钱动作。

**三、「模型厂下场做工具」成了 2026 年的主旋律。** DeepSeek 交出 Harness、智谱交出 ZCode，模型厂比谁都清楚自家模型的长短板，工具也就越做越有针对性；代价是你选的「全家桶」越顺手，被绑得越深——好在 OpenCode 与 OpenRouter 这条解耦路线一直都在。

## 结语

这份名单的构成本身就说明了一个趋势：agent 工具的形态之争基本落幕（终端系与 IDE 系各有霸主），新的战线在两处——**模型厂的自家 Harness** 与 **泛办公的通用 agent 平台**。对使用者的建议不变：拿「同任务横评」的方法自己跑一遍——用你自己的仓库、你自己的坑，半天就能得出比任何测评都可靠的结论。
