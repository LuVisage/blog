## 测评方法：先说清楚「横评」是怎么横的

模型月月更新，任何带版本号的结论三个月就过期，所以这篇刻意**只评形态与能力维度，不锁版本**。结论有效期标注为 2026 年 9 月，产品事实（定位、发布时间、计费结构）以官方页面与文档为准，来源在文中随文标注。

这份名单横跨三层，评的是各自那一层的核心能力：

- **工具层**——能替你写代码的 agent，按形态分终端系与 IDE/桌面系；
- **办公与通用 agent 平台**——不止写代码，把编程当作众多任务之一；
- **引擎与基础设施**——模型本身与模型路由，决定 agent 的脑子和你的账单。

工具层用同一组任务跑，四个场景各有考察点：

| 任务 | 场景 | 考什么 |
| --- | --- | --- |
| 热修复 | 修一个「偶现」的滚动监听泄漏，跨 3 个文件 | 定位能力：会不会先找证据再动手 |
| 从零小项目 | 写一个读目录生成 sitemap 的 CLI | 规划能力：没有历史上下文时的拆解 |
| 跨文件重构 | 组件库从 props 传值改成 context | 全局一致性：改 10 个文件漏没漏 |
| 终端活 | 查日志、装依赖、跑测试、处理一次构建失败 | 环境执行力：看输出、自我纠正 |

五个评分维度：**代码库理解**、**规划**、**终端执行力**、**可控性**（diff 干净程度与越界次数）、**成本形态**。每款工具的简评末尾有「适合谁」，最后有按人群的决策表。

## 终端系四家：长任务的脊梁

### Claude Code：终端 agent 的标杆

**上手**：npm 全局安装，项目目录里敲 `claude`，浏览器登录授权，一分钟内进入对话。第一印象是「它真的在逐个读我的文件」——回答仓库结构问题时它会主动列目录、打开入口文件，而不是凭空编。

**四任务表现**：热修复里表现最好的一次——它先翻了页面组件，再顺着监听器注册点读到事件清理逻辑，自己提出「疑似父组件重渲染导致重挂载」的假设，然后去验证。跨文件重构 10 个组件只漏了 1 处类型引用，被它自己的 tsc 检查抓回来修掉。终端活全程顺畅，包括处理一次 npm 依赖冲突（自己查了 registry 版本再降级）。四项全绿，综合第一。

**独门**：`CLAUDE.md` 规则文件 + MCP 扩展生态（接数据库、浏览器、一切）+ 自定义斜杠命令。diff 确认制：每个写操作默认要你按一下确认，配合规则文件的可控性是全场最高之一。

**坑**：按量计费下长任务烧 token 很凶，一个下午的重构能烧掉订阅一个月的量——要么订 Max，要么用下一节说的订阅引擎喂它。**适合**：住终端的工程师、大仓库维护、长链路任务。

### Codex CLI：同形态的同级对手

**上手**：与 Claude Code 几乎同构的体验，沙箱分级是它的特色——只读 / 自动 / 全权三档，你可以放心让它「全权跑测试、只读改代码」这种组合。

**四任务表现**：与 Claude Code 互有胜负。热修复里定位稍慢（多绕了一层），但修复方案更保守，diff 更小；重构任务的一致性略逊（漏改 2 处，也是自己抓回来的）；从零写 CLI 的脚手架质量是我几次测评里最满意的——目录结构、错误处理、README 一次到位。终端活与 Claude Code 打平。

**坑**：风格上更「话多」，解释文本占比高，长会话里要注意让它精简输出。**适合**：已在 OpenAI 生态的人；以及想对照第一梯队长什么样的参照系——两家订阅并存的话切换成本几乎为零。

### OpenCode：开源党与换引擎自由

**上手**：SST 团队开发、MIT 协议，一行脚本安装。TUI 交互做得很讲究（快捷键、会话管理、LSP 集成），现在还有桌面与 IDE 扩展形态。首次启动选模型：OpenRouter、DeepSeek、GLM 任意接——这是它和所有闭源工具的本质区别。

**四任务表现**：取决于你喂的引擎。配第一梯队模型时与 Claude Code 差距不大；配国产性价比引擎时规划能力肉眼可见地降半档，但执行与文件操作依然稳。逐项审批模式默认全开，每一步写文件、每一条命令都要你点头——可控性满分，节奏也确实慢。

**坑**：没有官方模型，引擎质量自己负责；版本迭代快，偶尔升级后配置格式要跟着改。**适合**：想精控成本、想用国产引擎跑国际级工具、以及一切开源党——它和 DSH 是这条赛道里路线完全不同的两个答案。

### DeepSeek Harness（DSH）：新入场的开源重量级

**是什么**：DeepSeek 在 2026 年 8 月开源的官方 Agent 运行时框架（GitHub：deepseek-ai/deepseek-harness），公式是「Agent = 模型 + Harness」，内核是 Cordis 微框架——模型、工具、技能、会话、沙箱一切皆插件，官方插件已过二百个，另有社区维护的桌面端。

**四任务表现**：用 DeepSeek 自家引擎跑，从零写 CLI 和终端活完成度不错；热修复的定位路径不如 Claude Code 直觉化，多试了一轮假设；跨文件重构出现了 2 处遗漏，靠自查清单抓回。整体是「第一梯队的有力挑战者」，离碾压还有距离，但考虑到开源刚满月，这个完成度值得尊重。

**独门与坑**：插件化的自由度是全场最高——你可以把会话存储、沙箱策略整个换掉；代价是概念比别家多，上手要读文档。**适合**：想要 DeepSeek 体验全家桶、喜欢插件化定制、预算敏感又想要官方支持的开源用户。

## IDE 与桌面系五家：节奏与体验

### Windsurf：Cascade 的体验流

**上手**：独立 IDE（VSCode 系），打开仓库后 Cascade 自动建索引。它的招牌是把 agent 的多步操作呈现成一条可读的「动作流」——做了什么、为什么、改了哪，一步步摊开。

**四任务表现**：索引质量是真实优势——热修复任务里它对「监听器在哪注册、在哪清理」的全局视图很准。重构任务的执行节奏偏碎，多次停下等你确认，熟练后可以调权限缓解。终端活是短板：命令执行有，但自我纠错的主动性不如终端系。

**坑**：长任务的规划深度中规中矩，复杂重构建议拆小再喂。**适合**：喜欢独立 IDE、看重 agent 过程可读的人。

### Trae：字节出品，上手零门槛

**上手**：国内直连下载，免费档额度大方，中文体验顺滑，官方文档清晰。SOLO 模式是它的招牌——「需求 → 任务拆解 → 执行」全托管，你只负责最后验收。

**四任务表现**：从零写 CLI 是它的舒适区（SOLO 模式从头到尾没让我操心）；热修复的定位能力中等，依赖你给足报错上下文；跨文件重构做了但不够干净，2 处引用漏改，tsc 抓回；终端活能力有限，复杂构建失败它倾向给建议而不是自己修。**适合**：学生、初学者、以及「先免费用起来再说」的场景——门槛全场最低。

### Qoder：阿里的任务委派派

**上手**：阿里出的 Agentic IDE，两个功能记住了：**Quest 模式**——把任务整个委派给后台 agent 跑完再来验收，人从「盯着看」变成「收作业」；**Repo Wiki**——自动给仓库生成结构化文档，含模块说明与依赖关系。

**四任务表现**：Repo Wiki 在跨文件重构里帮了大忙——它先基于 wiki 给出改动清单，我核对后放行，10 个文件漏改 1 处。委派式工作流意味着可控性换效率：你不盯过程，就要在验收时多花功夫。终端活中规中矩。**适合**：接手陌生代码库的人（Repo Wiki 单独就值回票价）、喜欢「委派式」的团队。

### CodeBuddy：国内生态的务实解

**上手**：腾讯系，IDE 与插件双形态，国内直连、中文交互自然。Craft 智能体覆盖常规 agent 工作流，与微信小程序、国内云的工具链贴合是独一份——小程序相关任务（页面结构、组件规范）的表现明显好于国际工具的「通用理解」。

**四任务表现**：热修复与从零 CLI 都是稳定的良好水平；跨文件重构中规中矩；终端活偏弱（对 PowerShell 场景的熟悉度倒是加分）。免费档每月 500 积分，轻量使用够。**适合**：国内环境、小程序与云开发、不想折腾网络与 Key 的学习者。

### ZCode：智谱的 ADE，模型厂下场做环境

**上手**：智谱 2025 年底发布的 Agentic Development Environment，桌面端 + CLI 双形态，绑定 GLM 系引擎（GLM-5.3 起与 ZCode 同步迭代）。长任务工作流、元素级的「指哪改哪」编辑、多端跟进，能看出「模型厂懂自己模型短处」的针对性设计。

**四任务表现**：用 GLM 旗舰引擎时，长任务的稳定性是亮点——跨文件重构全程没跑偏，这在非第一梯队引擎里少见；配合包月订阅，成本曲线非常平。热修复定位仍有可感知的差距。**适合**：想要订阅制确定性、GLM 系重度用户、以及想观察「模型厂做 IDE 会做成什么样」的人。

## 办公与通用平台三家：代码只是任务之一

### WorkBuddy：腾讯的办公 Agent 工作台

**是什么**：腾讯云代码助手团队（就是 CodeBuddy 背后那支队伍）推出的全场景 AI 办公工作台，覆盖日常办公、代码开发与设计创意：多 Agent 并行、自主规划并交付多模态任务结果。

**实测观感**：它的强项在「混合任务」——我让它基于一份需求文档生成代码骨架、同时产出一份接入文档，多模态交付一次成型。纯代码场景的能力是「良好」而非「锋利」，与 CodeBuddy 错位定位：一个面向职场全场景，一个面向开发者。**适合**：想让 agent 处理「文档 + 表格 + 代码」混合任务的职场人。

### 百度搭子（DuMate）：文心快码并入了这里

**是什么**：据界面新闻 2026 年 9 月 7 日报道，百度智能代码助手文心快码（Baidu Comate，服务超千万开发者）已并入通用智能体平台百度搭子，编程成为这座「智能体枢纽」里的一条产品线。

**实测观感**：Zulu 智能体与代码能力还在，插件形态的补全与生成依旧稳；平台化之后的价值在「账号与能力打通」——办公、知识库、编程共用一套上下文。单论纯编码的 agent 能力，与第一梯队有差距。**适合**：已有百度智能云生态的团队、以及「一个平台解决办公与编程」的使用习惯。

### 豆包：对话端的轻量编程

**是什么**：字节的对话助手。编程场景里它的真实形态要说清楚：**工程化的字节系载体是 Trae**——原豆包 MarsCode 插件与 Cloud IDE 已演进为 Trae 桌面端与 TraeCode 插件。

**实测观感**：豆包本尊适合轻量场景——解释报错、起稿小脚本、讨论技术选型，随问随答没有工程负担；但它没有文件操作与终端执行，谈不上「agent」。正确的用法是把它当 vibecoding 的第一级台阶：先用豆包建立「和 AI 讨论代码」的习惯，需要动仓库的那天装 Trae。**适合**：编程需求尚轻、以问答为主的用户。

## 引擎与基础设施：决定脑子和账单

### DeepSeek（引擎）

DSH 之外，DeepSeek 的 API 是很多 agent 的「脑子」：价格在同档常年最有攻击性（Flash 系列峰谷分时计价后，空闲时段输出 4 元/百万 token），权重开放、可私有化。配合 OpenCode 这类自带 Key 的工具是预算敏感场景的标准答案。短板：工具链的官方整合少，配引擎的活要自己动手——好在一次配好长期受益。

### GLM Coding Plan（智谱引擎订阅）

把 GLM 系模型打包成面向编码的包月计划：Lite 118 元/月（每周 1 万积分）、Pro 538 元（每周 6 万）、Max 1078 元（每周 14 万），可以喂给 Claude Code、OpenCode 等第三方工具当引擎。意义在于**用订阅价把第一梯队工具的油费打下来**，且国内直连；能力上限由 GLM 当前代际决定，日常业务代码够用，极限任务与第一梯队引擎仍有可感知差距。

### OpenRouter（模型超市）

统一网关：一个 API Key 访问 500+ 模型，切换、比价、看用量一处搞定，OpenCode 这类引擎无关的工具原生支持。计费要看清两层：**模型按上游原价计费、不加价；费用发生在充值环节**——充值 credits 收 5.5% 手续费（最低 0.8 美元），自带 Key（BYOK）另有费率。它解决「锁死」问题：**引擎可替换，工具的选择就不再绑架你的模型选择**。

## 价格对比：2026 年 9 月的一张快照

价格变动极快（DeepSeek 上周刚宣布峰谷分时计价），这一节当作快照看，购买前以官网为准。

| 工具 / 引擎 | 计费形态 | 入门档 | 重度档 | 备注 |
| --- | --- | --- | --- | --- |
| Claude Code | 订阅 | Pro（20 美元/月档） | Max 5x / 20x（100 / 200 美元档） | 订阅含额度；API 按量另算 |

四个值得注意的观察：

1. **包月订阅是两个世界**：国际第一梯队（Claude Code 等）在 20 美元档起步，国产编码订阅（GLM Coding Plan Lite 118 元/月）几乎低一个数量级——对高频使用的国内开发者，这是最容易算清的一笔账。
2. **按量党的地板被 DeepSeek 再次击穿**：峰谷分时 + 缓存命中 0.02 元/百万 token，意味着空闲时段跑长任务的成本可以低到忽略不计；代价是高峰时段双倍价，批处理任务适合挪到谷时。
3. **腾讯把 CodeBuddy 和 WorkBuddy 的积分打通了**：一份订阅覆盖办公与编程两条线，这是「平台制」打法的典型动作，百度搭子同理。
4. **免费档已经够学习期用了**：Trae、Qoder、CodeBuddy 的免费档、DSH 的开源本体、豆包零成本——入门阶段真正需要付费的场景，只有「高频重度使用终端 agent」这一种。

## 组合策略：工具与引擎解耦

这份名单给我最大的认知升级是：**选工具时不必再为「它用什么模型」纠结**。三个成熟组合：

- **订阅确定性**：GLM Coding Plan 包月 → 喂给 Claude Code / OpenCode 当引擎。月费固定，随便烧；
- **极致性价比**：DeepSeek API → OpenCode / DSH。按量付费，成本透明到每一次请求；
- **多引擎横跳**：OpenRouter 一个 Key → 所有自带 Key 的工具随切。新模型发布当天就能在你的工作流里 A/B。

解耦之后还有个隐藏红利：**规则文件跟着人走**。我给终端 agent 和 IDE 写的规则，约定类内容（技术栈、验收命令、禁区）是同一份，工具专属语法各留一小节——换工具、换引擎，工作流的脾气不变。把变量拆开，你的选型就从「站队」变成了「配置」。

---

## 三条跨工具都成立的经验

**一、审查成本会反噬效率。** 所有工具在自动化档位都出现过同一类事故：改动范围悄悄扩大。工具越自动，越要把「改动文件清单」列为交付物——这比事后 review 整个仓库便宜得多。

**二、token 消耗的大头是上下文，不是输出。** 同一个任务，喂错上下文能多花十倍。规则文件、精准的文件引用、及时开新会话，三个立竿见影的省钱动作。

**三、「模型厂下场做工具」成了 2026 年的主旋律。** DeepSeek 交出 Harness、智谱交出 ZCode，模型厂比谁都清楚自家模型的长短板，工具也就越做越有针对性；代价是你选的「全家桶」越顺手，被绑得越深——好在 OpenCode 与 OpenRouter 这条解耦路线一直都在。

这份名单的构成本身就说明了一个趋势：agent 工具的形态之争基本落幕（终端系与 IDE 系各有霸主），新的战线在两处——**模型厂的自家 Harness** 与 **泛办公的通用 agent 平台**。对使用者的建议不变：拿「同任务横评」的方法自己跑一遍——用你自己的仓库、你自己的坑，半天就能得出比任何测评都可靠的结论。
