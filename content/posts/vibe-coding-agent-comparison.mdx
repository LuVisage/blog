## 测评方法：先说清楚「横评」是怎么横的

模型月月更新，任何带版本号的结论三个月就过期，所以这篇刻意**只评形态与能力维度，不锁版本**。结论有效期标注为 2026 年 9 月。

这份名单有个特点：它不是清一色的「agent」，而是横跨三层——**工具层**（Claude Code、Codex CLI、OpenCode、Windsurf、Trae、Qoder、CodeBuddy、Comate）、**引擎层**（DeepSeek、智谱 Z Code / GLM 系）、**基础设施层**（OpenRouter）。我把它们放在同一组任务下跑，但评的是各自那一层的核心能力：

1. **热修复**：在一个中型 Next.js 项目里修一个「偶现」的滚动监听泄漏（跨 3 个文件，需要先定位）；
2. **从零小项目**：写一个 CLI 脚本，读目录生成 sitemap（无历史上下文，考规划）；
3. **跨文件重构**：把一套组件库从 props 传值改成 context（考全局理解与一致性）；
4. **终端活**：查日志、装依赖、跑测试、处理一次构建失败（考 agent 对真实环境的执行）。

工具层评五个维度：**代码库理解**（找不找得到该改哪）、**规划**（大任务拆得对不对）、**终端执行力**（敢不敢且会不会跑命令、看输出、自我纠正）、**可控性**（diff 是否干净、越界多少）、**成本形态**。引擎层与基础设施层评各自的关键指标（价格、开放性、路由能力），单独成节。

## 工具层：终端系三家

### Claude Code：终端 agent 的标杆

读整个仓库、改文件、跑命令、看输出、自我纠正，一条龙。规划与长任务稳定性仍是第一梯队：热修复任务里它自己翻日志定位到泄漏点，全程零人工。diff 确认制让可控性很好，`CLAUDE.md` 规则文件与 MCP 生态成熟。

坑：按量计费下长任务烧 token 很凶；对终端不熟的人有门槛。**适合**：住终端的工程师、大仓库维护、长链路任务。

### Codex CLI：同形态的同级对手

OpenAI 的终端 agent，沙箱分级（只读 / 自动 / 全权）设计清晰，规划与执行同处第一梯队。与 Claude Code 的差距是风格细节而非能力代差，两边订阅并存的话切换成本几乎为零。**适合**：已在 OpenAI 生态的人；以及「想对比第一梯队长什么样」的参照系。

### OpenCode：开源党与换引擎自由

开源终端 agent（TUI 形态），最大卖点是**引擎无关**：OpenRouter、DeepSeek、GLM 任意接。能力上是第一梯队的追随者，但它把「工具归工具、引擎归引擎」做到了极致——模型市场卷翻天，你一行配置就能换脑。**适合**：想精控成本、想用国产引擎跑国际级工具、以及一切开源党。这份名单里它和 DeepSeek / 智谱 / OpenRouter 是天然搭档。

## 工具层：IDE 系五家

### Windsurf：Cascade 的体验流

独立 IDE，Cascade 把 agent 的多步操作做成一条可读的「动作流」，代码库索引质量第一梯队，热修复任务表现接近终端系。与 Cursor 同质但风格更收敛。**适合**：喜欢独立 IDE、看重 agent 过程可读的人。

### Trae：字节出品，上手零门槛

国内可直接用的 AI IDE，免费档额度大方，中文体验顺滑；SOLO 模式尝试把「需求 → 任务拆解 → 执行」全托管。单点能力是追随者水平，但「今天下载今天出活」的门槛全场最低。**适合**：学生、初学者、以及「先免费用起来再说」的场景。

### Qoder：阿里的任务委派派

阿里的 Agentic IDE，两个特色功能记住了：**Quest 模式**——把任务整个委派给后台 agent 跑完再来验收，人从「盯着看」变成「收作业」；**Repo Wiki**——自动给仓库生成结构化文档，接手陌生仓库时是实打实的减负项。规划维度在 IDE 系里排前列。**适合**：接手陌生代码库的人、喜欢「委派式」工作流的团队。

### CodeBuddy：国内生态的务实解

腾讯系，IDE 与插件双形态，Craft 智能体覆盖常规 agent 工作流。最大优势是「顺」：国内网络直连、中文交互自然、与微信小程序和国内云的工具链贴合。能力属第一梯队追随者，迭代频繁。**适合**：国内环境、小程序与云开发、不想折腾网络与 Key 的学习者。

### Comate：百度文心快码，企业存量兼容派

百度系，以 IDE 插件形态为主，Zulu 智能体补了 agent 能力。强项在企业侧：与百度智能云的合规链路、对存量企业的采购友好度，以及对中文注释/中文需求的细腻处理。单点锋利度不如前面几家。**适合**：已有百度云生态的企业团队、政企合规场景。

## 引擎层与基础设施：决定脑子和账单的三家

### DeepSeek：性价比引擎

它不是 agent，是很多 agent 的「脑子」。API 价格在同档里常年最有攻击性，权重开放、可私有化，配合 OpenCode / Cline 这类自带 Key 的工具，是「预算敏感但想要真 agent」的标准答案。短板是工具链的官方整合少——配引擎的活要自己动手，好在一次配好长期受益。**适合**：按量付费精打细算、需要私有化部署的团队。

### 智谱 Z Code：GLM 系的官方编码入口

智谱把 GLM 系模型打包成面向编码的订阅计划，可以驱动 Claude Code、OpenCode 等第三方工具当引擎，也有自家的中文体验入口。意义在于：**用包月价把第一梯队工具的「油费」打下来**，而且国内直连。能力上限由 GLM 当前代际决定，日常业务代码够用，极限任务与第一梯队引擎仍有可感知差距。**适合**：想要订阅制确定性、高频使用终端 agent 的国内开发者。

### OpenRouter：模型超市

严格说它不是 agent，是统一网关：一个 API Key 访问几百家模型，切换、比价、看用量一处搞定。在 vibe coding 里的角色是「给自带 Key 的工具当引擎超市」——OpenCode 这类引擎无关的工具全都原生支持。它解决的是「锁死」问题：**引擎可替换，工具的选择就不再绑架你的模型选择**。**适合**：所有自带 Key 玩法的用户，做模型横评时它本身就是脚手架。

## 怎么选：按人群的决策表

| 你是谁 | 推荐 | 一句话理由 |
| --- | --- | --- |
| 学生 / 刚起步 | Trae（免费档）+ DeepSeek 引擎 | 零成本起步，中文顺，升级路径清晰 |
| 后端 / 全栈，住终端 | Claude Code 或 Codex CLI | 长链路任务与终端执行力是刚需 |
| 预算敏感但高频使用 | 智谱 Z Code 订阅喂终端 CLI，或 DeepSeek + OpenCode | 包月 / 低价按量，把油费打下来 |
| 开源党 / 私有化要求 | OpenCode + DeepSeek | 全链路开源可自托管，无供应商锁定 |
| 接手陌生大仓库 | Qoder（Repo Wiki）或 Claude Code | 全局理解与文档化减负最明显 |
| 国内生态 / 小程序 | CodeBuddy | 直连、贴合国内工具链 |
| 企业合规 / 政企 | Comate 或 CodeBuddy 企业版 | 存量生态兼容与采购链路成熟 |
| 精确控制每次提交 | OpenCode（逐步审批模式） | diff 即语言，每步可见 |

## 组合策略：工具与引擎解耦

这份名单给我最大的认知升级是：**选工具时不必再为「它用什么模型」纠结**。三个成熟组合：

- **订阅确定性**：智谱 Z Code 包月 → 喂给 Claude Code / OpenCode 当引擎。月费固定，随便烧；
- **极致性价比**：DeepSeek API → OpenCode / Cline。按量付费，成本透明到每一次请求；
- **多引擎横跳**：OpenRouter 一个 Key → 所有自带 Key 的工具随切。新模型发布当天就能在你的工作流里 A/B。

工具层的护城河在形态与工作流细节，引擎层卷价格与代际，两层各自迭代——**把变量拆开，你的选型就从「站队」变成了「配置」**。

---

## 三条跨工具都成立的经验

**一、审查成本会反噬效率。** 所有工具在自动化档位都出现过同一类事故：改动范围悄悄扩大。工具越自动，越要把「改动文件清单」列为交付物。

**二、token 消耗的大头是上下文，不是输出。** 同一个任务，喂错上下文能多花十倍。规则文件、精准的文件引用、及时开新会话，三个立竿见影的省钱动作。

**三、国产引擎与第一梯队的差距在收窄，但别只看跑分。** 日常业务代码（增删改查、脚本、小功能）各家引擎已经拉不开体感；差距集中在长任务的规划稳定性和自我纠错的细腻度。选引擎时用你自己的真实任务测半天，比看任何榜单都准。

## 结语

这份名单的构成本身就说明了一个趋势：**agent 工具的形态之争基本落幕（终端系与 IDE 系各有霸主），竞争重心正在转移到引擎与价格**。对使用者的建议不变：拿「同任务横评」的方法自己跑一遍——用你自己的仓库、你自己的坑，半天就能得出比任何测评都可靠的结论。
