## 4.2 检测任务与分类任务的根本差异

| | 分类 | 检测 |
| --- | --- | --- |
| 输入 | 一张图 | 一张图 |
| 输出 | 一个标签 | **不定数量**的 (类别, 框) |
| 数量 | 固定（1 个） | **可变**（0 个到几十个） |
| 评价 | accuracy / F1 | **IoU + mAP** |
| 难点 | 特征提取 | 特征提取 + **定位** + **去重** |

**"输出数量可变"是检测的核心难点**：神经网络擅长输出固定形状的张量，怎么处理"这张图有 2 个目标、那张图有 7 个"？

**答案**：**密集预测 + 后处理**。

1. 在每个位置、每个锚框上都预测一个结果（数量固定）；
2. 后处理（NMS）把重复的框去掉，得到最终的可变数量输出。

## 4.3 边界框的两种表示

| 格式 | 表示 | 使用者 |
| --- | --- | --- |
| **xyxy** | (左上 x, 左上 y, 右下 x, 右下 y) | 画图、IoU 计算 |
| **xywh** | (中心 x, 中心 y, 宽, 高) | 锚框、YOLO 输出、COCO 标注 |

**互相转换**：

```python
def xywh_to_xyxy(boxes):
    cx, cy, w, h = boxes.unbind(-1)
    return torch.stack([cx - w / 2, cy - h / 2, cx + w / 2, cy + h / 2], dim=-1)

def xyxy_to_xywh(boxes):
    x1, y1, x2, y2 = boxes.unbind(-1)
    return torch.stack([(x1 + x2) / 2, (y1 + y2) / 2, x2 - x1, y2 - y1], dim=-1)
```

**为什么两种都要有**：xywh 适合"以某个点为中心生成不同尺度的框"（锚框），xyxy 适合"比较两个框的位置关系"（IoU、交集）。

> **工程提示**：一个项目里**必须统一格式**，并在所有函数名或注释里写清楚。混用是检测代码最常见的 bug 来源。

## 4.4 IoU：衡量两个框有多像

$$\text{IoU}(A,B) = \frac{\text{Area}(A\cap B)}{\text{Area}(A\cup B)}$$

**取值范围 $[0,1]$**：

| IoU | 含义 |
| --- | --- |
| 1.0 | 完全重合 |
| 0.5 | 通常认为"检测到了"（常用阈值） |
| 0.0 | 完全不相交 |

**计算步骤**：

```python
def iou_xyxy(box_a, box_b):
    # ① 交集矩形的左上角 = 两个框左上角的【较大值】
    inter_x1 = max(box_a[0], box_b[0])
    inter_y1 = max(box_a[1], box_b[1])
    # ② 交集矩形的右下角 = 两个框右下角的【较小值】
    inter_x2 = min(box_a[2], box_b[2])
    inter_y2 = min(box_a[3], box_b[3])

    # ③ 宽高必须 clip 到 0（不相交时会是负数）
    inter_w = max(0.0, inter_x2 - inter_x1)
    inter_h = max(0.0, inter_y2 - inter_y1)
    inter = inter_w * inter_h

    area_a = (box_a[2] - box_a[0]) * (box_a[3] - box_a[1])
    area_b = (box_b[2] - box_b[0]) * (box_b[3] - box_b[1])
    union = area_a + area_b - inter
    return inter / union if union > 0 else 0.0
```

**三个必须注意的点**：

1. **交集右下的 `min` 与左上的 `max`** —— 这是最容易写反的地方；
2. **`max(0, ...)` 不能省** —— 不相交时宽高会是负数，乘起来变正数，结果就完全错了；
3. **`union > 0` 的判断** —— 防止除零。

**IoU 的局限（GIoU 的动机）**：

当两个框**完全不相交**时，$\text{IoU} = 0$，**无论它们离得多远**。

这导致 IoU 无法提供"往哪个方向移动可以靠近"的梯度信号。改进方案：

| 指标 | 改进 |
| --- | --- |
| **GIoU** | 加上"最小外接框"的惩罚项 |
| **DIoU** | 加上"中心点距离"的惩罚 |
| **CIoU** | 再加"长宽比"一致性 |

现代检测器（YOLOv5 及以后）默认用 CIoU 作为损失。

## 4.5 NMS：去掉重复的框

**问题**：密集预测会给同一个物体产生几十个高度重叠的框。**必须去重**。

**NMS（Non-Maximum Suppression）流程**：

```
输入: 一堆框（每个带置信度）、IoU 阈值 iou_thr
① 把所有框按置信度【降序】排序
② 取出当前置信度最高的框，加入结果列表
③ 计算它与剩余所有框的 IoU
④ 删掉 IoU > iou_thr 的框（认为它们是同一个物体）
⑤ 重复 ②~④，直到没有框剩下
```

**代码实现**：

```python
def nms(boxes, scores, iou_thr=0.5):
    order = scores.argsort(descending=True)      # ① 按分数降序
    keep = []
    while order.numel() > 0:
        i = order[0].item()
        keep.append(i)                            # ② 保留最高分的
        if order.numel() == 1:
            break
        ious = iou_batch(boxes[i], boxes[order[1:]])   # ③ 算 IoU
        order = order[1:][ious <= iou_thr]             # ④ 删掉重叠的
    return keep
```

**为什么按置信度降序**："最高的那个最可能是真的"，用它去压制其他的。

**NMS 的两个参数**：

| 参数 | 作用 | 调大的后果 |
| --- | --- | --- |
| `iou_thr` | 多大重叠算"重复" | 抑制不足（同一个物体保留多个框） |
| `score_thr` | 低于此分直接丢弃 | 保留更多低置信度的框（召回↑ 精度↓） |

**NMS 的经典问题：重叠的同类物体**

两个人挨得很近，IoU 超过阈值 → NMS 会把其中一个删掉。

**解决方案**：

| 方法 | 思路 |
| --- | --- |
| **Soft-NMS** | 不直接删除，而是按 IoU 衰减置信度 |
| **类别内 NMS** | 只在同一类别内做抑制（跨类别不去重） |
| **降低 iou_thr** | 简单但会保留更多误检 |

> **工程经验**：密集场景（人群、车辆）下，`iou_thr` 通常调到 **0.3~0.5**；稀疏场景可以放宽到 0.6~0.7。

## 4.6 锚框（Anchor）

### 4.6.1 动机

**问题**：物体大小、形状、位置千变万化。怎么让固定输出的网络处理这种变化？

**锚框的答案**：在特征图的每个位置上，**预先生成一组不同尺度和长宽比的参考框**，网络只需要预测"相对于锚框的偏移量"。

```python
# 每个位置生成 9 个锚框（3 种尺度 × 3 种长宽比）
scales = [8, 16, 32]
ratios = [0.5, 1.0, 2.0]
```

**这就是 Faster R-CNN 的 RPN（Region Proposal Network）的核心。**

### 4.6.2 数量爆炸

$$N_{\text{anchors}} = H \times W \times \text{num\_scales} \times \text{num\_ratios}$$

以 $224\times224$ 输入、特征图 $14\times14$、9 个锚框为例：

$$14\times14\times9 = 1764 \text{ 个锚框}$$

**每个锚框都要预测类别和偏移量** → 计算量大、正负样本极度不平衡（绝大多数锚框是背景）。

### 4.6.3 锚框的三大问题

| 问题 | 说明 | 现代方案 |
| --- | --- | --- |
| **超参数多** | 尺度、长宽比都要按数据集调 | **Anchor-free**（FCOS / CenterNet） |
| **数量爆炸** | 计算量大、正负样本不平衡 | 减少锚框 + Focal Loss |
| **不够灵活** | 无法适应罕见形状（如长条形） | 可变形卷积 / Anchor-free |

**Anchor-free 的思路**（现代主流）：

- **FCOS**：直接预测"每个位置到目标四条边的距离"，不需要锚框；
- **CenterNet**：预测目标中心点的热力图 + 宽高；
- **YOLOv8 / RT-DETR**：也是 anchor-free。

> **趋势**：锚框正在被淘汰，但**理解它对理解检测的发展史和现有代码库仍然必要**（大量生产环境还在用 Faster R-CNN 和 YOLOv5）。

## 4.7 mAP：检测的评价指标

### 4.7.1 计算流程

```
对每一个类别 c:
  ① 把所有预测框按置信度降序排列
  ② 逐个判断是 TP 还是 FP（依据与 GT 的 IoU 是否 > 阈值）
  ③ 累积计算 precision 与 recall，画出 PR 曲线
  ④ AP_c = PR 曲线下的面积
mAP = mean(AP_1, ..., AP_C)
```

**关键的匹配规则**：每个 GT 框**只能被匹配一次**。第二个与它 IoU 超阈值的预测框算 FP（因为"重复检测"也是错误）。

### 4.7.2 两个常用变体

| 指标 | 含义 |
| --- | --- |
| **mAP@0.5** | IoU 阈值 0.5（宽松） |
| **mAP@0.5:0.95** | 阈值从 0.5 到 0.95 步长 0.05，取平均（**COCO 主指标**，严格得多） |

**为什么 COCO 用 0.5:0.95**：单看 0.5 无法区分"框得准"和"框得勉强"，多阈值平均能反映定位精度。

### 4.7.3 检测的指标体系比分类复杂得多

| 指标 | 关心什么 |
| --- | --- |
| mAP | 综合精度 |
| AP50 / AP75 | 宽松/严格定位下的精度 |
| AP_s / AP_m / AP_l | **小/中/大目标的精度**（小目标通常最难） |
| AR (maxDets) | 召回率上限 |

> **实践提醒**：看检测结果时，**必须分尺度看**。一个模型 mAP 很高但 AP_s 很低，说明它在大目标上表现好、小目标全漏了 —— 这在安防、遥感等场景是致命的。

## 4.8 常见坑

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| IoU 出现负数或 >1 | 忘了 clip 到 0，或坐标顺序反了 | `max(0, x2-x1)`，统一 xyxy |
| NMS 后框还是很多 | `iou_thr` 设得太大 | 降低到 0.5 或 0.3 |
| NMS 把挨着的物体删了 | 同类物体重叠 | 用 Soft-NMS 或降低阈值 |
| mAP 异常高 | GT 被重复匹配了多次 | 每个 GT 只能匹配一次 |
| 小目标全部漏检 | 锚框尺度太大 / 特征图分辨率不够 | 加小尺度锚框，用 FPN |
| 训练不收敛 | 正负样本极不平衡（99% 是背景） | Focal Loss 或难负样本挖掘 |
| 框的位置偏差大 | 用 xywh 算 IoU | 统一转成 xyxy 再算 |
| 推理速度慢 | 锚框太多 + NMS 串行 | 减锚框，用 anchor-free |
