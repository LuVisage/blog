## 5.2 语言模型：把"生成"变成"预测"

**核心思想**：语言模型不直接"写句子"，而是**不断预测下一个字符**。

$$P(\text{"hello"}) = P(\text{"h"})\cdot P(\text{"e"}|\text{"h"})\cdot P(\text{"l"}|\text{"he"})\cdots$$

**训练目标**：给定前 $t-1$ 个字符，预测第 $t$ 个字符。**这就是分类任务**（类别数 = 字符表大小）。

### 训练数据的构造技巧

**输入和输出是同一段文本，只是错开一位**：

```
原始文本:  h e l l o _ w o r l d

输入 x:    h e l l o _ w o r l d
输出 y:    e l l o _ w o r l d _      <- 向右错一位
```

**一个序列同时提供了 T 个训练样本**（每个位置都是一个"预测下一个"的任务）。

代码实现：

```python
i = data[:, :T]         # 输入
t = data[:, 1:T+1]      # 目标（错一位）
```

> **这是语言模型最优雅的地方**：不需要人工标注，**文本本身就是标签**。这就是"自监督学习"。

## 5.3 字符级 vs 词级

| | 字符级 | 词级 |
| --- | --- | --- |
| 词表大小 | 几十（英文）/ 几千（中文） | 几万~几十万 |
| 序列长度 | 长（一句话几百字符） | 短（一句话几十词） |
| OOV 问题 | **无**（任何字符都能表示） | 有（未登录词） |
| 语义单元 | 小（需要模型自己组合） | 大（自带语义） |
| 适合 | 学习/演示、拼写敏感任务 | 生产环境（配合 BPE 等子词方案） |

**为什么教学用字符级**：

1. 词表小 → 训练快、显存小；
2. 无需分词工具；
3. **生成结果肉眼可读**，便于观察模型学到了什么。

**现代实践用子词（BPE / WordPiece）**：介于两者之间，既控制词表大小又保留语义单元。Week16 会详述。

## 5.4 自回归生成

训练完成后，生成过程是**自回归**的：

```python
def generate(model, start_char, length, temperature=1.0):
    h = None
    x = torch.tensor([[char_to_idx[start_char]]])
    result = [start_char]

    for _ in range(length):
        logits, h = model(x, h)                  # 前向
        logits = logits[0, -1] / temperature     # 温度缩放
        probs = torch.softmax(logits, dim=-1)
        idx = torch.multinomial(probs, 1)        # 采样
        result.append(idx_to_char[idx.item()])
        x = idx.view(1, 1)                        # 把生成的字符作为下一步输入

    return "".join(result)
```

**关键点**：

1. **把自己的输出当作下一步的输入**（这就是"自回归"）；
2. **必须采样而不是取 argmax**（否则每次生成都一样）；
3. **隐藏状态 $h$ 要一直传下去**（这是 RNN 的天然优势 —— 增量生成只需 $\mathcal{O}(1)$ 计算）。

> **注意最后一点**：RNN 生成一个 token 只需一次前向（用缓存的 $h$）。而 Transformer 需要重新计算所有历史位置的注意力（除非用 KV Cache）。这是 RNN 在**推理阶段**少有的优势。

## 5.5 温度采样：控制多样性

**温度 $T$ 作用在 softmax 之前**：

$$p_i = \frac{\exp(z_i / T)}{\sum_j \exp(z_j / T)}$$

| 温度 | 效果 | 适用 |
| --- | --- | --- |
| $T\to 0$ | 退化为 argmax，永远选最高概率 | 确定性任务（翻译、代码） |
| $T=0.5$ | 更保守、更连贯 | 需要准确性的生成 |
| $T=1.0$ | 原始分布 | 默认 |
| $T>1$ | 更随机、更有创造性（也更容易出错） | 创意写作、头脑风暴 |

**直观理解**：

- $T<1$ → 把概率分布"拉尖"，高概率的更高、低概率的更低；
- $T>1$ → 把分布"压平"，低概率的也有机会被选中。

### 其他采样策略

| 策略 | 做法 | 特点 |
| --- | --- | --- |
| **Greedy** | 永远取 argmax | 确定性，但容易重复 |
| **Temperature** | 缩放后采样 | 控制多样性 |
| **Top-k** | 只在概率最高的 k 个里采样 | 避免选到离谱的字符 |
| **Top-p（nucleus）** | 在累积概率达 p 的最小集合里采样 | 自适应候选集大小 |

**实践建议**：`temperature=0.8 + top_k=20` 是常用的组合。

## 5.6 RNN 生成能力的边界

**它会学到什么**：

| 层次 | 学到的内容 | 表现 |
| --- | --- | --- |
| 字符统计 | 哪些字符常一起出现 | 不会拼出完全假的词 |
| 词法 | 常见词、后缀、大小写 | 能拼出真实单词 |
| 句法 | 主谓宾结构、标点位置 | 句子结构基本合理 |
| 语义 | **很有限** | 常常"语法正确但内容空洞" |

**典型现象**：

1. **短距离流畅、长距离失忆** —— 这正是 Day1 的梯度衰减在生成上的体现；
2. **重复退化** —— 生成时可能陷入循环（"the the the..."）；
3. **主题漂移** —— 写着写着换话题。

> **这就是为什么 GPT 需要 Transformer**：RNN 的固定大小隐藏状态是信息瓶颈，它无法在生成第 500 个字符时还清晰记得第 10 个字符。

## 5.7 常见坑

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 生成的文本完全随机 | 训练不足 / 学习率不对 | 多训几轮，确认 loss 在降 |
| 生成的文本一直重复 | 贪心解码 / 训练过度 | 用温度采样 + top-k |
| 每次生成结果完全一样 | 用了 argmax | 改用 `multinomial` |
| OOM | 序列太长（BPTT 展开） | 用截断 BPTT（固定窗口长度） |
| loss 不下降 | 忘了错一位 | 检查 `x` 和 `y` 的错位 |
| 温度=0 时报错 | 除零 | 温度用下限（如 0.01） |
