## 5.2 迁移学习：三种策略

Day5（Week11）讲过基本用法。这里给出**决策框架**。

### 5.2.1 三种策略对比

| 策略 | 做法 | 可训练参数 | 学习率 | 适用 |
| --- | --- | --- | --- | --- |
| **① 特征提取** | 冻结全部 backbone，只训新分类头 | 极少 | head 1e-3 | 数据很少（&lt;1k）+ 任务相似 |
| **② 部分微调** | 解冻后几层 + 分类头 | 中等 | backbone 1e-5 / head 1e-3 | 数据中等（1k~50k） |
| **③ 全网络微调** | 全部解冻 | 全部 | 统一 1e-5 | 数据多（>50k）+ 任务差异大 |

### 5.2.2 决策依据：两个维度

```
                 任务相似度高            任务相似度低
              ┌──────────────────┬──────────────────┐
   数据少     │  ① 冻结 backbone │  ② 解冻后几层    │
   (< 1k)     │     只训分类头    │     + 分类头     │
              ├──────────────────┼──────────────────┤
   数据多     │  ② 部分微调      │  ③ 全网络微调    │
   (> 50k)    │                  │                  │
              └──────────────────┴──────────────────┘
```

**Week11 Day5 的实测教训**：ImageNet → MNIST 属于"任务相似度低"（自然图像 vs 灰度笔画），所以冻结 backbone 只训分类头只有 87.85% —— **迁移学习依赖任务相关性**。

### 5.2.5 实测：三种策略（MNIST → Fashion-MNIST 跨域迁移）

| 策略 | 可训练参数 | 占比 | 验证准确率 | 耗时 |
| --- | --- | --- | --- | --- |
| ① 特征提取 | 4,810 | **6.9%** | 57.65% | 17.5s |
| ② 部分微调 | 60,362 | 86.2% | 60.45% | 17.9s |
| ③ 全网络微调 | 69,994 | 100% | **63.00%** | 18.2s |

**两条结论**：

1. **精度单调递增**：任务差异越大，就越需要让更多层参与适配。只训 head 只能到 57.65%，放开 backbone 才能到 63%。
2. **注意参数量的性价比**：全微调用了 **14.5 倍**的参数，精度只高了 **5.35 个点**。特征提取只用 6.9% 的参数就拿到 57.65% —— 如果场景对模型大小或训练成本敏感，这个性价比非常关键。

> **实践建议**：**先跑"特征提取"**（最快、最不容易过拟合），不够再逐层解冻。

### 5.2.3 学习率怎么分配（关键，且常被说错）

**常见说法**："用分层学习率，head 是 backbone 的 100 倍。" —— **这个说法只在特定前提下成立。**

**分层学习率的写法**：

```python
optimizer = torch.optim.AdamW([
    {"params": backbone.parameters(), "lr": 1e-5},   # 预训练部分：小
    {"params": head.parameters(),     "lr": 1e-3},   # 新加的：大 100 倍
], weight_decay=0.01)
```

**它的道理**：backbone 已学到好特征，大学习率会破坏它（灾难性遗忘）；head 是随机初始化的，需要大步走。

**但它不是铁律。** 实测（MNIST → Fashion-MNIST 跨域迁移，10 epoch）：

| 学习率配置 | 验证准确率 | 说明 |
| --- | --- | --- |
| 分层（bb=2e-5, head=2e-3） | 63.00% | "推荐配置"，但**不是最好** |
| **统一 2e-3** | **82.50%** | **最好** |
| 统一 2e-5 | 35.80% | 最差（head 训不动） |
| 反向（bb=2e-3, head=2e-5） | 81.65% | 与"统一 2e-3"接近 |

**分层配置反而比"统一 2e-3"低了近 20 个百分点。** 原因：

> MNIST（手写数字）→ Fashion-MNIST（服饰）是**大跨度的任务差异**。backbone 学到的"笔画特征"对识别衣服帮助有限，**必须让它大幅调整**。此时把 backbone 的学习率压到 2e-5，等于把它锁死了。

**正确的决策框架**：

| 场景 | backbone_lr | head_lr | 理由 |
| --- | --- | --- | --- |
| 任务相似（同为自然图像） | 1e-5 ~ 1e-4 | 1e-3 | 保护预训练特征 |
| **任务差异大** | **2e-3 ~ 3e-3** | **2e-3 ~ 3e-3** | **允许 backbone 大幅调整** |
| 从头训练（无预训练） | 统一 3e-3 | 统一 3e-3 | 分层无意义 |

> **一句话**：学习率分配回答的是"**backbone 需要改多少**"这个问题，而"需要改多少"取决于**任务差异有多大**。
>
> **判断方法仍然是实测**：三种分配方式各跑一次，看结果。

### 5.2.4 一个常被忽略的坑

**新加的、随机初始化的层不能被冻结。**

```python
# 错误：把新换的 conv1 也冻住了
for p in model.parameters():
    p.requires_grad = False          # 全部冻结
for p in model.fc.parameters():
    p.requires_grad = True           # 只解冻 fc
# -> 如果 conv1 也换成了新的，它就被永久冻在随机状态！
```

**检查方法**：打印可训练参数的数量，确认所有"新加/改动过的层"都在里面。

## 5.3 完整的项目流程

**这是本周的落脚点** —— 一个真实视觉项目的标准步骤：

```
① 明确任务与指标
     ├─ 分类/检测/分割？
     ├─ 指标是什么（accuracy / macro-F1 / mAP）？
     └─ 业务约束（延迟、模型大小）？
          ↓
② 数据检查（Day3 的清单）
     ├─ 随机抽样看图
     ├─ 类别分布
     ├─ 重复样本 / 数据泄漏
     └─ 数值统计、尺寸一致性
          ↓
③ 建立基线（最重要的一步）
     ├─ 先用最简单的模型跑通
     └─ 记录指标 → 这是后续所有改进的参照
          ↓
④ 数据增强（Day3）
     ├─ 逐个测，不要无脑堆
     └─ 必须肉眼检查语义是否保持
          ↓
⑤ 迁移学习（本节）
     ├─ 按 5.2 的框架选策略
     └─ 分层学习率
          ↓
⑥ 评估与错误分析
     ├─ 混淆矩阵、每类指标
     ├─ 看错分样本（Day2 的可视化工具）
     └─ 分尺度/分场景分析
          ↓
⑦ 记录与复现
     └─ 配置落盘（JSON）+ 固定种子
```

**注意 ③ 的位置**：**建基线必须在增强和迁移学习之前**。没有基线，你无法判断后续的改动是否真的有帮助（Week10 Day5 的消融纪律）。

## 5.4 错误分析：比调参更有价值

**当模型效果不好时，第一件事不是调参，而是看错分的样本。**

```python
# 找出错误样本
wrong = (preds != y_test).nonzero().flatten()

# 分类统计：哪些类别之间容易混
cm = confusion_matrix(y_test, preds)
# 找出混淆最多的类别对
for i in range(10):
    for j in range(10):
        if i != j and cm[i, j] > threshold:
            print(f"真实 {i} 被误判为 {j}: {cm[i, j]} 次")
```

**错误分析能回答的问题**：

| 观察 | 可能的结论 |
| --- | --- |
| 错分集中在某几类之间 | 特征不足以区分它们（需要更细粒度的特征） |
| 错分样本的标注本身有问题 | **标注质量问题**（比调参重要得多） |
| 错分样本图像质量差（模糊/遮挡） | 数据采集问题 |
| 错分与类别不平衡对应 | 用加权损失（Day3） |
| 模型置信度很高但错了 | 过拟合，或分布外样本 |

> **工程经验**：**花 30 分钟看错分样本，往往比花 3 小时调参更有效。** 很多时候你会发现是标注错了。

### 实测：Fashion-MNIST 上的错误分析

测试准确率 61.80%（跨域迁移，未充分训练），混淆最多的类别对：

| 真实类别 | 被误判为 | 次数 |
| --- | --- | --- |
| 外套 | 套头衫 | **96** |
| 衬衫 | 套头衫 | 60 |
| 凉鞋 | 运动鞋 | 40 |
| 套头衫 | 衬衫 | 39 |
| 外套 | 衬衫 | 32 |

**读出来的结论**：

- 混淆全部发生在**语义相近的类别内部**：`{T恤, 衬衫, 套头衫, 外套}` 互为混淆（都是上衣），`{凉鞋, 运动鞋, 短靴}` 互为混淆（都是鞋）；
- 而"裤子"的召回率高达 **90.1%** —— 因为它的形状与其他类别差异最大；
- **这说明模型已经学到了有意义的特征**（它知道"上衣"和"鞋"的区别），只是**细粒度区分能力不足**。

**这个结论直接指向下一步该做什么**：

| 如果 | 那应该 |
| --- | --- |
| 需要更好的细粒度区分 | 更高的输入分辨率（服装细节在小图上丢失了） |
| 混淆发生在标注模糊的样本上 | 检查标注质量 |
| 某些类别样本太少 | 补数据或加权（Day3） |

**置信度分布**（同样重要）：

| | 平均置信度 |
| --- | --- |
| 错分样本 | 0.409 |
| 正确样本 | 0.631 |

**错分样本的置信度明显更低** —— 这说明模型的"不确定"是**有意义的信号**，可以用于：

- **拒识**：置信度低于阈值时交给人处理（生产系统常用）；
- **主动学习**：优先标注低置信度的样本。

## 5.6 常见坑

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 微调后精度暴跌 | backbone 学习率太大（且任务相似） | 降到 1e-5 |
| **分层学习率效果反而差** | **任务差异大，backbone 被锁死了** | **统一用大学习率（见 5.2.3）** |
| 只训分类头效果很差 | 任务与预训练差异大 | 解冻后几层 |
| 换了输入通道数后报错 | 没改第一层，或改了但忘了训练它 | 显式替换 conv1 且不冻结它 |
| 训练极慢 | 全网络微调 + 大分辨率 | 先冻结训练几轮，再解冻 |
| 没有基线就上迁移学习 | 无法判断收益 | 先跑一个简单模型当基线 |
| 指标不涨就换模型 | 没做错误分析 | 先看错分样本和混淆矩阵 |
| 换了模型但没固定种子 | 差异无法归因 | `set_seed()` + 落盘配置 |
