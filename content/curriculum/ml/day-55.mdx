## 5.2 什么是消融实验

**消融（Ablation）**：从模型中**移除或添加**某个组件，观察性能变化，从而判断该组件的贡献。

这个词来自医学/神经科学（切除某部分组织观察功能变化）。在深度学习论文里，几乎每篇提出新结构的文章都有一张消融表。

**论文里常见的三种形式**：

| 形式 | 做法 | 回答的问题 |
| --- | --- | --- |
| **累加式**（Additive） | 从基线开始，逐个添加组件 | 每个组件分别贡献多少？ |
| **移除式**（Leave-one-out） | 从完整模型开始，逐个移除 | 少了它性能掉多少？ |
| **替换式**（Replacement） | 把组件换成其他方案 | 这个选择比其他方案好吗？ |

今天用**累加式**，因为它最直观地展示了"每一步改进的收益"。

## 5.3 实验设计的四条铁律

### 铁律 1：单一变量

**一次只改一个因素。** 同时改两个，就不知道是谁的功劳。

写法对比：

```python
# 错误：同时改了激活函数和初始化
runs.append(("改进", dict(use_relu=True, he_init=True)))

# 正确：分两步
runs.append(("+ ReLU", dict(use_relu=True)))
runs.append(("+ He 初始化", dict(use_relu=True, he_init=True)))
```

### 铁律 2：固定随机种子

```python
def set_seed(seed=42):
    random.seed(seed)
    np.random.seed(seed)
    torch.manual_seed(seed)
    torch.cuda.manual_seed_all(seed)
```

**每次实验前都要重新设置种子**，否则各配置的初始化不同，差异无法归因。

### 铁律 3：多次重复，报告均值与方差

单次实验的差异可能只是噪声（呼应 Week02 Day2 的"评估稳定性"）。

```python
results = []
for seed in [0, 1, 2]:
    set_seed(seed)
    acc = run_one_config(...)
    results.append(acc)
print(f"{np.mean(results):.4f} ± {np.std(results):.4f}")
```

**成本与收益的权衡**：

- 探索阶段：1 个种子够了（快速筛掉明显差的）
- 定稿/汇报：至少 3 个种子，报告 `mean ± std`
- 论文级：5 个种子以上

### 铁律 4：只用验证集选配置，测试集最后跑一次

Week02 Day2 已经强调过。消融阶段**全部看验证集**，否则就是在测试集上"挑选"结果，等于作弊。

## 5.4 实验配置设计

从"最朴素的深层网络"出发，逐层添加今天和前几天学到的组件：

| # | 配置 | 相对上一行新增 |
| --- | --- | --- |
| 0 | baseline | 8 层 Sigmoid + 默认初始化 + 无正则 |
| 1 | + ReLU | 激活换成 ReLU |
| 2 | + He 初始化 | 配上与 ReLU 匹配的初始化 |
| 3 | + BatchNorm | 每层归一化 |
| 4 | + Dropout 0.2 | 加正则 |
| 5 | + weight_decay | 加权重衰减 |
| 6 | + 梯度裁剪 | 限制梯度范数 |
| 7 | + 残差连接 | 加恒等通路 |

**每一步的预期**（先写下预测，再看结果 —— 这是好的实验习惯）：

| # | 预期效果 | 理由 |
| --- | --- | --- |
| 1 | 大幅提升 | Sigmoid 的 0.25 导数上界是致命的 |
| 2 | 小幅提升 | 初始化与激活匹配 |
| 3 | 提升 | 稳定各层分布（Day2） |
| 4 | 略升或持平 | 数据量小时正则有效 |
| 5 | 略升 | 补充正则 |
| 6 | 持平 | 没有爆炸时裁剪不生效 |
| 7 | 提升 | 梯度畅通 |

**而实测结果与预期并不完全一致**（这正是消融实验的意义）：

| # | 配置 | 验证准确率 | 与预期 |
| --- | --- | --- | --- |
| 0 | baseline (Sigmoid) | 19.75% | 符合 |
| 1 | + ReLU | 89.45% **(+69.70%)** | 符合 |
| 2 | + He 初始化 | 93.45% (+4.00%) | 符合 |
| 3 | + BatchNorm | 91.65% (**-1.80%**) | **与预期相反** |
| 4 | + Dropout 0.2 | 90.70% (-0.95%) | 略降 |
| 5 | + weight_decay | 91.30% (+0.60%) | 小幅 |
| 6 | + 梯度裁剪 | 92.45% (+1.15%) | 有收益（说明确实有梯度异常） |
| 7 | + 残差连接 | 92.40% (-0.05%) | 持平 |

**BatchNorm 为什么在这里反而下降？**

不是 BN 没用，而是**这个设定恰好避开了 BN 要解决的问题**：

1. 只有 8 层，梯度问题本来就不严重（残差同理，所以第 7 步也持平）；
2. 已经配了 He 初始化，各层尺度已经稳定；
3. 训练 12 个 epoch 就收敛，"加速收敛"的收益无从体现；
4. BN 的 `running` 统计量在 4000 条小数据上还带噪声。

Day2 的实验里，一旦把学习率放大 10 倍，BN 的价值立刻显现（无 BN 直接发散，有 BN 正常收敛）。

**这就是消融实验最核心的价值**：把"论文说它好"变成"在我的设定下它是否好"。

> **重要原则**：不出意外的消融实验没有信息量。**出了意外，才是发现问题的开始。** 此时不要急着删掉"不work"的组件，而要问："它需要什么条件才能发挥作用？"

## 5.5 结果解读的三个层次

拿到表格后，不要只看"谁最高"。要分三层解读：

**第一层：哪些改动有效？**

看每一行的验证准确率变化。注意区分：

- **显著提升**（> 1%）：组件确实有用
- **微小变化**（&lt; 0.5%）：可能是噪声，需要多种子验证
- **下降**：组件与当前配置冲突，或强度不对

**第二层：为什么有效？**

对照前四天的理论：

| 组件 | 作用机制 | 对应知识点 |
| --- | --- | --- |
| ReLU | 导数上界从 0.25 提到 1 | Day4 梯度消失 |
| He 初始化 | 补偿 ReLU 置零一半造成的方差减半 | Week07 Day5 |
| BatchNorm | 稳定激活分布 + 平滑损失曲面 | Day2 |
| Dropout | 隐式集成 | Day1 |
| 残差 | 提供梯度为 1 的通路 | Day4 |

**第三层：有没有意外结果？**

**意外结果比符合预期的结果更有信息量。** 例如：

- 加了 Dropout 反而下降 → 说明当前模型还欠拟合，正则过强
- 加残差没有提升 → 说明当前深度还不够，梯度问题不严重
- 加梯度裁剪没有变化 → 说明本来就没爆炸（这是好事）

## 5.6 实验报告应该包含什么

一份合格的实验记录（写进 `notes/` 或 PR 描述）：

```markdown
## 实验目的
验证 BatchNorm 对 8 层 MLP 的影响

## 配置
- 数据: MNIST 训练集前 4000 条 / 验证 2000 条
- 模型: 8 层，隐层 128，ReLU
- 优化: AdamW lr=1e-3, batch=128, 6 epochs
- 种子: 42（固定）

## 结果
| 配置 | 验证准确率 | 训练时间 |
|---|---|---|
| 无 BN | 88.75% | 12.3s |
| 有 BN | 94.10% | 14.1s |

## 结论
BatchNorm 带来 +5.35% 提升，代价是 15% 的训练时间开销。
提升主要来自训练前期的稳定性（见 loss 曲线）。

## 下一步
1. 试更大学习率（BN 允许）
2. 试在小 batch 下换成 GroupNorm
```

**关键**：结论要能指导下一步行动，而不是只报数字。

## 5.7 常见坑

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 各配置结果差异极小 | 任务太简单或模型太小 | 换更难的任务/更大的模型 |
| 结果每次都不一样 | 没固定种子 | `set_seed()` |
| 加了新组件反而变差 | 组件与配置冲突（如残差配 Sigmoid） | 检查组合的合理性 |
| 累加式实验最后一项最好 | 预期如此，但要警惕"叠加了太多" | 补一个"移除式"验证边际收益 |
| 用测试集选配置 | 数据泄漏 | 只用验证集 |
| 只有一次运行就下结论 | 噪声 | 至少 3 个种子 |
| 训练时间和准确率没有一起报 | 忽略了成本 | 效率也是指标 |

## 5.8 今日自测

1. 把累加式实验改成**移除式**（从最优配置出发逐个移除），对比两种形式得出的结论是否一致。
2. 用 3 个不同的种子重跑 baseline 和最优配置，报告 `mean ± std`，判断差异是否显著。
3. 把 BatchNorm 换成 LayerNorm，观察在 batch=128 时的差异，再改成 batch=8 观察一次。
