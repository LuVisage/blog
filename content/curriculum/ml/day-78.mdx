## 3.2 自定义 Dataset 的标准写法

**三件必须做的事**：

```python
class MyDataset(Dataset):
    def __init__(self, samples, transform=None):
        self.samples = samples          # 只存【路径/索引】，不预加载图像
        self.transform = transform

    def __len__(self):
        return len(self.samples)         # 训练循环依赖它

    def __getitem__(self, idx):
        path, label = self.samples[idx]
        img = load_image(path)           # 在这里才真正读盘
        if self.transform:
            img = self.transform(img)
        return img, label                # 返回 (数据, 标签)
```

**四条工程规范**：

| 规范 | 理由 |
| --- | --- |
| **`__init__` 里不要读图像数据** | 否则创建 Dataset 就要几分钟，且内存爆掉 |
| **`__getitem__` 里才读盘** | 配合 `num_workers>0` 实现并行加载 |
| **增强只加在训练集** | 验证/测试必须用确定性变换 |
| **返回 (数据, 标签) 元组** | DataLoader 的默认 collate 期望这个格式 |

**`num_workers` 的陷阱**：

- `num_workers > 0` 时会 fork 子进程，**每个子进程持有一份数据副本**；
- 如果 `__init__` 里加载了大数据，内存会乘以 worker 数；
- Windows 上 fork 行为不同，自定义 Dataset 必须可 pickle（不要存 lambda、文件句柄、数据库连接）。

## 3.3 在线增强 vs 离线增强

| | 在线增强（on-the-fly） | 离线增强（offline） |
| --- | --- | --- |
| 做法 | 在 `__getitem__` 里随机变换 | 预先变换好存成新文件 |
| 磁盘占用 | 不增加 | **成倍增加** |
| 训练速度 | 稍慢（每 epoch 都要变换） | 快（直接读） |
| 每 epoch 的数据 | **都不同**（更强的正则） | 固定 |
| 修改增强策略 | 改代码即可 | 要重新生成 |
| 适用 | **绝大多数情况** | 增强方式固定 + 训练瓶颈在 CPU |

**结论：默认用在线增强。**

**唯一值得离线增强的场景**：增强本身很慢（如 GAN 生成、复杂的风格迁移），且确定不再改动。

## 3.4 增强策略与"标签语义不变"

**增强的第一原则**：**变换后标签必须仍然正确。**

| 增强 | 安全的前提 | 危险场景 |
| --- | --- | --- |
| 水平翻转 | 类别对左右不敏感 | **数字 6↔9、字母 b↔d**、左右手识别 |
| 垂直翻转 | 类别对上下不敏感 | 数字、字母、人脸 |
| 旋转 | 小幅（±10~15°） | 大幅旋转会让 6 变 9 |
| 缩放 | 类别对尺度不敏感 | 需要尺度判断的任务（如破洞大小检测） |
| 裁剪 | 不裁掉关键特征 | 医学影像（裁掉病灶） |
| 颜色抖动 | 颜色不是判别依据 | 颜色分类、皮肤病诊断 |
| **Cutout / Random Erasing** | 被遮挡区域不是关键 | 小目标检测（容易把目标整个遮掉） |
| **Mixup / CutMix** | —— | 需要标签平滑配合，且不适用于检测 |

**必须做的检查**：**把增强后的图打印出来肉眼看一遍。** 这一步能发现 90% 的增强错误。

```python
# 增强可视化（一定要做）
fig, axes = plt.subplots(2, 5, figsize=(12, 5))
for i, ax in enumerate(axes.flat):
    img, label = train_ds[i]
    ax.imshow(img.squeeze(), cmap="gray")
    ax.set_title(f"label={label}")
    ax.axis("off")
```

### 三条增强强度的经验

| 数据量 | 增强强度 |
| --- | --- |
| 很少（&lt; 5000） | **强增强**（旋转+缩放+平移+翻转） |
| 中等（1万~10万） | 中等（±10° 旋转 + 小幅平移） |
| 很多（> 50万） | 弱或不加（数据本身已足够多样） |

### 实测：增强消融（6000 训练样本，8 epoch）

| 增强方式 | 验证准确率 | 结论 |
| --- | --- | --- |
| 无增强（基准） | **97.45%** | — |
| 旋转 ±12° | 97.55% | 几乎无变化 |
| 平移 10% | 97.30% | 几乎无变化 |
| 缩放 0.9~1.1 | 97.65% | 几乎无变化 |
| 旋转 + 平移 | 97.45% | 几乎无变化 |
| **垂直翻转** | **95.10%** | **有害（-2.35%）** |

**两个结论**：

1. **MNIST 上增强收益几乎为零** —— 数据规整（数字居中、尺度统一、无背景），本身就没有多少"可增强"的空间。对比 Week11 Day3 在同一份数据上的结论一致。
2. **垂直翻转是有害的** —— 它是**语义错误**的增强：翻转后的 "6" 看起来像 "9"，但标签仍是 6，等于给模型灌输错误知识。

> **这里最重要的收获不是"增强有用/没用"，而是"你必须逐个测"**。同一套增强策略在不同数据集上的效果可能完全相反。

## 3.5 类别不平衡

**问题**：类别 A 有 10000 个样本，类别 B 只有 100 个。模型会倾向于全预测 A（准确率仍有 99%），但完全没用。

**四种处理手段**：

| 手段 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **重采样** | 过采样少数类 / 欠采样多数类 | 简单 | 过采样会过拟合，欠采样丢信息 |
| **加权损失** | `CrossEntropyLoss(weight=...)` | 不改数据 | 权重需调 |
| **数据增强** | 对少数类做更强增强 | 增加真实多样性 | 增强空间有限 |
| **Focal Loss** | 降低易分样本的权重 | 效果最好 | 多两个超参 |

**加权损失的标准写法**：

```python
# 权重与类别频率成反比
counts = torch.bincount(y_train)
weights = len(y_train) / (len(counts) * counts.float())
criterion = nn.CrossEntropyLoss(weight=weights.to(device))
```

**实测对比**（案例代码用 4000 : 40 的 100:1 极端不平衡）：

| 配置 | accuracy | macro-F1 | 少数类平均召回 |
| --- | --- | --- | --- |
| 不加权 | **56.65%** | 0.5581 | **51.19%** |
| **加权损失** | **92.60%** | **0.9253** | **92.05%** |

**不加权时，模型几乎"放弃"了 9 个少数类** —— 一半的少数类样本被错分。

**关键**：**别只看准确率！** 类别不平衡时必须看：

- **每类的 precision / recall / F1**（Week02 Day3）
- **混淆矩阵**
- **macro-F1**（各类等权）而不是 accuracy

**"指标陷阱"**：如果验证集也按训练集的分布采样（多数类占 91%），不加权模型的 accuracy 会**看起来很漂亮**（>90%），而 macro-F1 会惨不忍睹。

**所以验证集的采样方式要按任务目标定**：

| 你关心什么 | 验证集怎么采 |
| --- | --- |
| 整体线上表现 | 按真实分布采样 |
| 少数类的识别能力 | 保持均衡采样 |

## 3.6 数据质量的检查清单

**这一节是本周最重要的工程内容。**

在训练任何模型之前，先跑一遍这个清单：

| 检查项 | 具体做法 |
| --- | --- |
| **① 随机抽样看图** | 抽 50 张，肉眼看。像素值是否合理？标签是否正确？ |
| **② 标签一致性** | 同一类别的样本命名/标注规则一致吗？ |
| **③ 分布检查** | `torch.bincount(y)` —— 类别是否严重不平衡 |
| **④ 数值统计** | `X.min() / X.max() / X.mean() / X.std()` 是否符合预期 |
| **⑤ 尺寸一致性** | 所有图像的 shape 是否统一，不统一的要统一处理 |
| **⑥ 重复样本** | 用哈希去重（重复样本会让验证集泄漏） |
| **⑦ 数据泄漏** | 训练集和验证集有没有重叠样本/同一批次采集 |
| **⑧ 预处理一致性** | 训练用 `mean=0.1307`，验证也得用同一个 |

**⑦ 数据泄漏的检测代码**：

```python
def find_leakage(train_files, val_files):
    """用文件内容的哈希找出泄漏"""
    import hashlib
    def h(p):
        return hashlib.md5(open(p, "rb").read()).hexdigest()
    tr = {h(p) for p in train_files}
    va = {h(p) for p in val_files}
    overlap = tr & va
    print(f"训练集 {len(tr)} 张，验证集 {len(va)} 张，重叠 {len(overlap)} 张")
    return overlap
```

**数据泄漏是最致命的错误**：模型指标虚高，上线后完全不能用。

## 3.7 常见坑

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 验证指标异常高 | 训练集/验证集有重叠，或验证集也做了随机增强 | 用哈希去重；验证集用确定性变换 |
| 训练极慢 | `__init__` 里预加载了所有图像 | 改成在 `__getitem__` 里读 |
| `num_workers>0` 报错 | Dataset 里有不可 pickle 的对象 | 移除 lambda / 文件句柄；或设 worker=0 |
| 内存随 worker 数翻倍 | 每个 worker 持有一份数据副本 | 减小 worker 数，或让 Dataset 更轻 |
| 增强后精度反降 | 增强破坏了标签语义 | 逐个关掉增强做消融 |
| 增强后图像全黑 | 归一化把值压到 [0,1] 之外，imshow 显示为黑 | 显示前反归一化 |
| 类别不平衡下准确率虚高 | 只看 accuracy | 看 macro-F1 与混淆矩阵 |
| 每次运行精度不同 | 增强的随机性 + 种子未固定 | 固定种子；评估时关掉增强 |
