> 今日目标：把本周四种技术（1×1 卷积与瓶颈、深度可分离卷积、SE 注意力、复合缩放思路）放进同一个实验框架，用"参数量-FLOPs-精度-时间"四维指标做完整对比，建立**结构选型的工程判断力**。
> 配套案例：`code/day5_fashion_benchmark.py`

## 5.1 实验设计

**唯一变量原则**（Week10 Day5 的纪律）：所有配置共用同一数据划分、同一种子、同一优化器和学习率，**只改卷积块类型**。

| 配置项 | 值 |
| --- | --- |
| 数据 | Fashion-MNIST，训练 15,000 / 验证 2,000 / 测试 10,000 |
| 网络骨架 | stem（1 个卷积）→ 4 个块 → GAP → FC |
| 宽度 / 深度 | 64 / 4 |
| 优化器 | AdamW，lr=3e-3，weight_decay=1e-4，CosineAnnealing |
| epoch | 4 |
| 种子 | 固定 0 |

**五个对比方案**：

| 方案 | 卷积块结构 |
| --- | --- |
| 标准卷积 | `Conv3×3 → BN → ReLU`，带残差 |
| 标准卷积 + SE | 上面 + SE 通道注意力 |
| 深度可分离 | `DWConv3×3 → BN → ReLU → PWConv1×1 → BN`，带残差 |
| 深度可分离 + SE | 上面 + SE |
| **倒残差 + SE** | `PWConv(升维2×) → DWConv3×3 → PWConv(降维) → BN → SE`，带残差 |

## 5.2 实测结果

| 方案 | 参数量 | FLOPs | 验证 acc | 测试 acc | 耗时 |
| --- | --- | --- | --- | --- | --- |
| 标准卷积（baseline） | 149,322 | 116,057,728 | 81.15% | 80.97% | 14.4s |
| 标准卷积 + SE | 151,370 | 116,059,776 | 79.20% | 77.45% | 16.9s |
| **深度可分离** | **21,066** | **15,103,616** | 86.40% | **85.28%** | 13.9s |
| 深度可分离 + SE | 23,114 | 15,105,664 | 83.50% | 83.95% | 16.7s |
| **倒残差 + SE** | 76,106 | 55,447,168 | **88.35%** | **88.36%** | 32.1s |

**相对 baseline**：

| 方案 | 参数量比 | FLOPs 比 | 精度变化 |
| --- | --- | --- | --- |
| 标准卷积 | 1.00 | 1.00 | — |
| 标准卷积 + SE | 1.01 | 1.00 | **-3.52%** |
| 深度可分离 | **0.14** | **0.13** | **+4.31%** |
| 深度可分离 + SE | 0.15 | 0.13 | +2.98% |
| 倒残差 + SE | **0.51** | 0.48 | **+7.39%** |

## 5.3 四条关键结论

### 结论 1：深度可分离卷积是"白捡"的收益

**用 1/7 的参数、1/8 的 FLOPs，精度反而高了 4.31 个百分点。**

原因有两层：

1. **参数量少 → 小数据集上更不容易过拟合**。15,000 样本配 149K 参数是偏多的，压到 21K 反而更匹配；
2. **"通道独立"的归纳偏置在这里恰好合适**。Fashion-MNIST 是灰度简笔画，每个通道承载的局部模式差异较大，先独立处理再融合是合理的选择。

> **但这不意味着"参数越少越好"** —— 而是说参数规模要与数据量匹配（呼应 Week12 Day1 的瓶颈讨论）。

### 结论 2：SE 在这个规模下再次拖后腿

两次实验都是负面结果（Day3 的 -4.5%，这里的 -3.52%）。

**原因很明确**：SE 的价值是"在大数据上学出通道之间的相关性"。15,000 样本不足以学到稳定的通道依赖，新增的参数反而带来过拟合。

**但工业界仍然普遍默认加 SE**，因为：

- 参数代价只有 1.4%；
- 在 ImageNet 级别（128 万张）上稳定提升近 1 个点；
- 真实项目的数据量通常远大于 15,000。

**这正是"论文说好"和"我的场景下好不好"的区别**（Week10 Day5 的核心教训）。

### 结论 3：倒残差结构是最优解

**88.36%，参数量只有 baseline 的一半。**

为什么它比纯深度可分离更好？看结构差异：

```
深度可分离:  64 → DW(64) → PW(64)              通道数全程不变
倒残差:      64 → PW(128) → DW(128) → PW(64)   先升维做空间卷积
```

**关键在"先升维"**：深度卷积在 $C$ 个通道上独立做空间卷积，如果 $C$ 太小（64），每个通道能提取的模式很有限。升到 128 后再做深度卷积，空间表达空间更充足。

这就是 Day2 讲的 **linear bottleneck** 思想的实战验证：**ReLU 在高维空间安全，在低维空间危险**。

### 结论 4：精度最高的方案，训练时间也最长

倒残差用了 **32.1s**，是 baseline 的 2.2 倍。

**四个指标（参数量 / FLOPs / 精度 / 时间）不可能同时最优。** 工程判断力就体现在**知道你的场景里哪个约束最紧**：

| 场景 | 最紧的约束 | 推荐 |
| --- | --- | --- |
| 手机端 App | 参数量 + 延迟 | 深度可分离 + 倒残差 |
| 云端 API | 精度 + 吞吐 | 标准卷积 + SE |
| 边缘设备（低功耗） | FLOPs + 内存 | 深度可分离 + 剪枝 |
| 快速原型 | 开发速度 | 直接用预训练模型 |

## 5.4 本周技术速查

| 技术 | 解决的问题 | 代价 | 适用场景 |
| --- | --- | --- | --- |
| **1×1 卷积** | 跨通道融合 + 通道数变换 | 参数量 $C_{in}C_{out}$ | 配合瓶颈结构 |
| **瓶颈结构** | 减少大通道层的参数 | 压缩过度会损失信息 | 通道数 ≥128 时 |
| **深度可分离卷积** | 减少计算量（1/9） | GPU 上可能不加速 | 移动端 / CPU |
| **SE 注意力** | 通道加权 | +1.4% 参数 | 大数据任务 |
| **复合缩放** | 系统地放大网络 | 需要搜索 $\alpha,\beta,\gamma$ | 从头设计网络时 |

---

## 5.5 常见坑

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 深度可分离精度低 | 通道数太少 + ReLU 损失信息 | 用倒残差（先升维） |
| SE 加入后变差 | 数据量不足 | 数据量小就别加 |
| 参数量少了但更慢 | 计算强度低，受带宽限制 | 测端到端延迟 |
| 各配置不可比 | 超参数没对齐 | 固定种子 + 相同优化器 |
| 只报告精度 | 忽略了成本 | 四维报告（参数/FLOPs/精度/时间） |
| 结论来自单次运行 | 噪声 | 多种子重复（Week10 Day5） |
