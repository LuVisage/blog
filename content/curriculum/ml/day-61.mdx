## 1.2 一个反直觉的事实

$1\times1$ 卷积的核只有一个数。看起来它"什么都没做"—— 不就是把每个像素乘以一个系数吗？

**错在忽略了通道维度。**

输入是 $(C_{in}, H, W)$，而不是 $(H, W)$。$1\times1$ 卷积的实际计算是：

$$y_{c_{out}, i, j} = \sum_{c_{in}=1}^{C_{in}} x_{c_{in}, i, j}\cdot w_{c_{out}, c_{in}} + b_{c_{out}}$$

**对每个空间位置 $(i,j)$，它是一个 $C_{in}\to C_{out}$ 的线性变换。**

$$\mathbf{y}_{i,j} = \mathbf{W}\mathbf{x}_{i,j} + \mathbf{b}$$

**所以 1×1 卷积 = 在每个像素位置上做一次全连接**，且所有位置共享同一组权重。这就是它又叫"**逐点卷积**（pointwise convolution）"的原因。

## 1.3 1×1 卷积的三种作用

### 作用 1：改变通道数（降维 / 升维）

```python
nn.Conv2d(256, 64, 1)     # 256 -> 64 通道，降维
nn.Conv2d(64, 256, 1)     # 64 -> 256 通道，升维
```

**空间尺寸完全不变**，只改通道数。参数量只有 $C_{in}\times C_{out}$（对比 $3\times3$ 卷积的 $9C_{in}C_{out}$）。

这是 1×1 卷积最常见的用法：**在不改变空间结构的前提下压缩或扩张通道**。

### 作用 2：跨通道信息融合

$1\times1$ 卷积输出的每个通道，都是输入所有通道的加权和。这实现了**通道之间的信息交流**。

在它出现之前，标准卷积也有跨通道融合，但代价是 $k^2$ 倍的计算量。1×1 卷积用最低的成本做到了这一点。

**GoogLeNet 的 Inception 模块**正是靠它：在 3×3、5×5 卷积分支之前各加一个 1×1 降维，把计算量压到原来的几分之一。

### 作用 3：增加非线性（不改变空间结构）

$$\text{Conv}_{1\times1} \to \text{ReLU}$$

两个 1×1 卷积中间夹一个 ReLU，就得到了一个"逐像素的两层 MLP"（Network in Network 论文的核心思想）。

**关键优势**：增加了非线性表达能力，但**完全不改变特征图的空间尺寸** —— 这让它可以插进任何位置而不影响形状。

## 1.4 瓶颈结构：省参数的经典设计

### 1.4.1 结构

ResNet 的 Bottleneck 块：

```
输入 (256, H, W)
   │
   ├─ 1x1 Conv(256 -> 64)   ← 降维（压缩）
   ├─ BN + ReLU
   ├─ 3x3 Conv(64 -> 64)    ← 在低维空间做空间卷积
   ├─ BN + ReLU
   ├─ 1x1 Conv(64 -> 256)   ← 升维（恢复）
   ├─ BN
   └─ + 残差连接
输出 (256, H, W)
```

**形状不变，通道先降后升 —— 所以叫"瓶颈"。**

### 1.4.2 参数量对比

**方案 A：直接堆两个 3×3 卷积（256→256）**

$$2 \times (256\times256\times3\times3) = 1{,}179{,}648$$

**方案 B：Bottleneck（256→64→64→256）**

$$256\times64\times1 + 64\times64\times9 + 64\times256\times1 = 16{,}384 + 36{,}864 + 16{,}384 = 69{,}632$$

**结果：省了 94.1% 的参数！**

| 方案 | 参数量 | 比值 |
| --- | --- | --- |
| 两个 3×3 卷积 | 1,179,648 | 100% |
| Bottleneck | 69,632 | **5.9%** |

**为什么这样可以**：CNN 的"表达能力"主要由**空间卷积（3×3）**提供，而**通道数**只需要足够传递信息即可。把 256 维压到 64 维再做 3×3 卷积，信息损失不大，但参数量降了 16 倍。

> **这正是 ResNet-50 能用 Bottleneck 堆到 50 层，而参数量（2500 万）反而比 VGG-19（1.38 亿）少得多的原因。**

### 1.4.3 Bottleneck 的一般形式

设输入输出通道为 $C$，瓶颈通道为 $C/r$（$r$ 是压缩比，ResNet 用 $r=4$）：

$$\text{Params} = C\cdot\frac{C}{r} + \frac{C^2}{r^2}\cdot 9 + \frac{C}{r}\cdot C = \frac{2C^2}{r} + \frac{9C^2}{r^2}$$

对比两个标准 3×3 卷积的 $18C^2$：

$$\frac{\text{Params}_{\text{bottleneck}}}{\text{Params}_{\text{std}}} = \frac{2/r + 9/r^2}{18}\bigg|_{r=4} = \frac{0.5 + 0.5625}{18} = 5.9\%$$

**与上面的实算一致。**

## 1.5 什么时候不该用 Bottleneck

| 情况 | 建议 |
| --- | --- |
| 通道数很小（&lt; 64） | **不要用**，压缩后信息损失过大 |
| 追求极限精度 | 标准卷积可能更好（表达力更强） |
| 移动端极致压缩 | 用深度可分离卷积（Day2）而不是瓶颈 |
| 浅层（通道少） | 直接标准卷积 |

**经验法则**：瓶颈结构的收益与通道数平方相关，所以**只在通道数大（≥128）时才值得用**。ResNet 在小通道的浅层用的就是基础块（两个 3×3），只在深层用瓶颈。

## 1.6 常见坑

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 用了 1×1 卷积但精度没变 | 只加了降维没加非线性 | 中间必须有 ReLU |
| 瓶颈结构训练不收敛 | 压缩比过大（如 $r=16$） | 用 $r=4$ |
| 形状对不上 | 忘了瓶颈后要升维回原通道 | 第二个 1×1 把通道恢复 |
| 参数量没降 | 通道数本来就小 | 见 1.5 |
| 以为 1×1 卷积等于全连接 | 混淆了"逐像素全连接"与"全局全连接" | 1×1 卷积在所有空间位置**共享**权重 |

## 1.8 一句话总结

**1×1 卷积是"逐像素的全连接"：它用最低的计算成本完成了跨通道融合和通道数变换，是 Inception 和 ResNet 瓶颈结构的关键零件，也是现代 CNN 里出现频率最高的层。**
