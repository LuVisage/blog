## 一、为什么需要 Pipeline

### 1.1 手写流程的三个典型错误

```python
# ❌ 错误示范
scaler = StandardScaler()
X_all = scaler.fit_transform(X)               # 错误 1：在全量数据上 fit
X_train, X_test = train_test_split(X_all)     # 划分太晚
model.fit(X_train)
# 错误 2：交叉验证时忘了重新 fit scaler
cross_val_score(model, X_all, y)              # 每一折都会用全量统计量
# 错误 3：推理时忘了 transform
model.predict(new_X_raw)                      # 直接用原始数据预测
```

### 1.2 Pipeline 的价值

| 价值 | 说明 |
| --- | --- |
| **防泄漏** | `fit` 只在训练折内执行，`transform` 自动应用到验证折 |
| **防遗忘** | 推理时 `pipe.predict(raw)` 会自动做全部预处理 |
| **可复用** | 一条链在训练/验证/测试/线上完全一致 |
| **可调参** | 网格搜索可以直接搜 `scaler__with_mean` 这样的嵌套参数 |
| **可序列化** | 一个文件保存"预处理 + 模型"的全部状态 |

## 二、Pipeline 基础

### 2.1 语法

```python
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.decomposition import PCA
from sklearn.linear_model import LogisticRegression

pipe = Pipeline([
    ("scaler", StandardScaler()),
    ("pca",    PCA(n_components=10)),
    ("clf",    LogisticRegression(max_iter=1000)),
])

pipe.fit(X_train, y_train)
print(pipe.score(X_test, y_test))
```

**约定**：除最后一步外，所有步骤都必须实现 `fit` 与 `transform`；最后一步实现 `fit` 与 `predict`。

**用 `make_pipeline` 省去命名**（自动用小写类名）：

```python
from sklearn.pipeline import make_pipeline
pipe = make_pipeline(StandardScaler(), PCA(n_components=10), LogisticRegression())
```

> **建议**：需要网格搜索时**显式命名**（`scaler__with_mean`），否则自动名可能比想象的长。

### 2.2 访问内部步骤

```python
pipe.named_steps["scaler"].mean_           # 取预处理器的属性
pipe[:-1].transform(X_test)                # 取"除最后一步外"的中间输出（很有用）
pipe.set_params(clf__C=0.1)                # 修改嵌套参数
```

### 2.3 为什么能防泄漏

`pipe.fit(X_train, y_train)` 的执行顺序：

```
第 1 步 scaler.fit_transform(X_train)   <- 只用 X_train 统计
第 2 步 pca.fit_transform(第1步输出)     <- 只用变换后的训练集
第 3 步 clf.fit(第2步输出, y_train)
```

在 `cross_val_score(pipe, X, y, cv=5)` 中，**每一折都会重新调用 `pipe.fit(这一折的训练部分)`**，因此验证折的数据**从未参与任何统计量计算**。

> **这就是"把预处理器放进 Pipeline"和"手动预处理"最本质的区别。**

## 三、ColumnTransformer：处理混合类型的表

真实数据表往往长这样：

| 列 | 类型 | 需要的处理 |
| --- | --- | --- |
| 年龄、收入 | 数值 | 标准化 |
| 城市、性别 | 类别 | 独热编码 |
| 用户评论 | 文本 | TF-IDF |
| 是否有缺失 | 布尔 | 直接使用 |

```python
from sklearn.compose import ColumnTransformer
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.impute import SimpleImputer

num_cols = ["age", "income"]
cat_cols = ["city", "gender"]
txt_col   = "review"

pre = ColumnTransformer([
    ("num", Pipeline([
        ("impute", SimpleImputer(strategy="median")),
        ("scale",  StandardScaler()),
    ]), num_cols),
    ("cat", Pipeline([
        ("impute", SimpleImputer(strategy="constant", fill_value="未知")),
        ("onehot", OneHotEncoder(handle_unknown="ignore")),
    ]), cat_cols),
    ("txt", TfidfVectorizer(max_features=2000, ngram_range=(1, 2)), txt_col),
], remainder="drop")        # remainder="drop" 丢弃未指定的列
```

### 3.1 四种常用写法

| 写法 | 适用 |
| --- | --- |
| `(name, transformer, [列名列表])` | 明确指定列 |
| `(name, transformer, make_column_selector(dtype_include=np.number))` | 按类型自动选列 |
| `remainder="drop"` | 丢弃未提到的列 |
| `remainder="passthrough"` | 保留未提到的列（放在末尾） |

### 3.2 输出维度会变化

```python
X_t = pre.fit_transform(df)
print(df.shape, "->", X_t.shape)
# 原始 4 列（含 1 个文本列）-> 变成 2 + onehot列数 + 2000 维
```

**重要**：独热编码与 TF-IDF 会让维度暴涨。**做完一定要打印维度**，否则后续模型会莫名变慢/过拟合。

## 四、与交叉验证、网格搜索结合

### 4.1 交叉验证

```python
from sklearn.model_selection import cross_val_score
scores = cross_val_score(pipe, X, y, cv=5, scoring="f1_macro")
print(f"F1 = {scores.mean():.4f} ± {scores.std():.4f}")
```

**注意**：这里传入的是**原始 DataFrame `X`**（未预处理），一切都在 Pipeline 内部完成。

### 4.2 网格搜索

```python
from sklearn.model_selection import GridSearchCV

param_grid = {
    "clf__C": [0.01, 0.1, 1, 10],
    "pre__num__scale": [StandardScaler(), RobustScaler()],
    "pre__txt__max_features": [1000, 3000],
}

gs = GridSearchCV(pipe, param_grid, cv=5, scoring="f1_macro", n_jobs=-1)
gs.fit(X_train, y_train)
print(gs.best_params_, gs.best_score_)
```

**命名规则**：`步骤名__子步骤名__参数名`，用双下划线连接。

### 4.3 随机搜索（维度高时更高效）

```python
from sklearn.model_selection import RandomizedSearchCV
from scipy.stats import loguniform

param_dist = {
    "clf__C": loguniform(1e-3, 1e2),          # 对数均匀
    "pre__txt__max_features": [500, 1000, 3000],
}
rs = RandomizedSearchCV(pipe, param_dist, n_iter=20, cv=5,
                        scoring="f1_macro", random_state=0, n_jobs=-1)
```

**为什么用对数均匀**：`C` 的有效范围跨几个数量级，线性均匀采样会浪费预算（Week02 Day2）。

## 五、保存与加载（部署必需）

```python
import joblib

joblib.dump(pipe, "model_pipeline.joblib")     # 保存整条链
pipe2 = joblib.load("model_pipeline.joblib")   # 加载

# 直接吃原始数据
pred = pipe2.predict(raw_df)
```

**必须保存整条 Pipeline，而不是只保存模型**：

- 只保存模型 ⇒ 线上还得手工复现标准化 + 独热 + TF-IDF ⇒ 极易不一致；
- 保存整条链 ⇒ 线上只需一行 `predict(raw_df)`。

**版本兼容性注意**：

| 风险 | 对策 |
| --- | --- |
| sklearn 版本升级导致加载失败 | 记录版本号，或用 ONNX 导出 |
| 自定义类（如自己写的 Transformer） | 部署环境必须有同名类 |
| 中文分词器（jieba 词典） | 词典文件也要一起打包 |

## 六、自定义 Transformer

如果内置的预处理器不够用，可以自己写——**只要继承 `BaseEstimator` + `TransformerMixin`**：

```python
from sklearn.base import BaseEstimator, TransformerMixin
import numpy as np

class OutlierClipper(BaseEstimator, TransformerMixin):
    """按分位数裁剪离群点（只在训练集上学习边界）"""

    def __init__(self, lower=0.01, upper=0.99):
        self.lower, self.upper = lower, upper

    def fit(self, X, y=None):
        X = np.asarray(X)
        self.lo_ = np.quantile(X, self.lower, axis=0)
        self.hi_ = np.quantile(X, self.upper, axis=0)
        return self

    def transform(self, X):
        return np.clip(np.asarray(X), self.lo_, self.hi_)
```

**要点**：

1. `fit` 返回 `self`；
2. 学到的参数带**下划线结尾**（`lo_`、`hi_`），这是 sklearn 的约定；
3. 不要修改输入数组（用 `np.clip` 返回新数组）。

**可以直接放进 Pipeline 并参与网格搜索**

## 八、常见坑

| 坑 | 说明 |
| --- | --- |
| 把 `y` 也传进 `ColumnTransformer` | 它只处理特征 |
| 列名在 Pipeline 外部被改动 | 列名必须与 fit 时一致 |
| 忘记 `handle_unknown="ignore"` | 测试集出现新类别会直接报错 |
| 用 `make_pipeline` 后不知道参数名 | 用 `pipe.get_params()` 查看全部可用参数名 |
| 网格搜索里改数据预处理方式 | 会导致维度不一致，应搜"预处理器的参数"而非"换预处理器"（可以在 Pipeline 外做） |
| 保存模型时只 dump 了 `pipe[-1]` | 必须 dump 整个 `pipe` |
| 自定义 Transformer 的 `fit` 不返回 `self` | 会报错 |
| 在 `transform` 里用到了 `y` | 会导致交叉验证泄漏 |
| 用 `pandas` 索引对齐后再进 Pipeline | 建议先 `reset_index(drop=True)` |
| 测试集单独做 `fit_transform` | 必须用训练集拟合好的对象 `transform` |
| **用 `lambda` 当 `tokenizer`** | **lambda 无法被 pickle**，保存 Pipeline 时报 `Can't pickle <lambda>`；必须写成**模块级函数** |
| 特征选择器放在 Pipeline 外面 | 泄漏！本日代码里实测虚高 **+0.45** 准确率 |
| `TF-IDF` 在划分前 `fit` | 词表泄漏，测试集出现了训练时没有的词 |

> **本周最重要的一个实验**：在 `code/day3_preprocessing.py` 的第 6 节，我们构造了 120 个样本、8000 个**纯噪声**特征、**随机标签**的数据集。
> - 把 `SelectKBest` 放在交叉验证**外面** ⇒ 准确率 **0.8583**（完全是假的）
> - 把 `SelectKBest` 放进 **Pipeline** ⇒ 准确率 **0.4083**（≈ 随机水平，真实）
>
> **虚高 0.45 个百分点** —— 这就是数据泄漏的威力。任何"用到 $y$ 的预处理"都必须进 Pipeline。

<summary>第 8 题答案要点</summary>

**泄漏写法一：先对全量数据做预处理，再划分**

```python
X = scaler.fit_transform(X)                    # ❌ 测试集参与了统计
```

**泄漏写法二：交叉验证时在折外做预处理**

```python
X_all = scaler.fit_transform(X)                # ❌
```

```python
sel = SelectKBest(k=100).fit(X, y)             # ❌ 用到了全部 y
```
