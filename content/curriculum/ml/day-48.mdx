## 3.2 为什么需要数据管线

Week07 你是这样切批的：

```python
# Week07 风格
idx = np.random.permutation(len(X))
for s in range(0, len(X), batch_size):
    b = idx[s:s + batch_size]
    xb, yb = X[b], T[b]
    ...
```

能跑，但每次都要重写，而且：

| 需求 | 手写难度 |
| --- | --- |
| 边读边训练（数据装不进内存） | 要自己写生成器 |
| 多进程并行读取 | 要自己写 `multiprocessing` |
| 图像增强（随机裁剪/翻转） | 要自己写 PIL 逻辑 |
| 变长序列补齐 | 每个项目都要重写 |
| 训练集打乱、验证集不打乱 | 靠自觉 |

`DataLoader` 把这些全部标准化了：

```python
for xb, yb in dataloader:      # 一行，全部搞定
    ...
```

## 3.3 Dataset：两个必须实现的方法

```python
from torch.utils.data import Dataset

class MyDataset(Dataset):
    def __init__(self, ...):
        ...                       # 只加载"索引"或"路径"，不要一次读全部数据

    def __len__(self):
        return ...                # 样本总数

    def __getitem__(self, idx):
        ...                       # 返回第 idx 条样本
        return x, y               # 元组（也可以返回字典）
```

**框架只会调用这两个方法**。`DataLoader` 的工作方式是：

```
DataLoader 生成一个索引列表 -> 打乱 -> 按 batch 分组
  -> 对每个索引调用 dataset[i]  （可能并行，可能乱序）
  -> 把结果用 collate_fn 组装成 batch
```

### 最简：TensorDataset

数据已经在内存里、且是张量时，直接用 `TensorDataset`：

```python
from torch.utils.data import TensorDataset, DataLoader

X = torch.randn(1000, 20)
y = torch.randint(0, 3, (1000,))

ds = TensorDataset(X, y)          # 按第一维对齐，dataset[i] 返回 (X[i], y[i])
print(len(ds))                    # 1000
print([t.shape for t in ds[0]])   # [torch.Size([20]), torch.Size([])]

dl = DataLoader(ds, batch_size=32, shuffle=True)
xb, yb = next(iter(dl))
print(xb.shape, yb.shape)          # torch.Size([32, 20]) torch.Size([32])
```

### 更实用：自定义 Dataset

真实项目里，`__init__` 只存**文件路径列表**，`__getitem__` 才真正读盘 —— 这样内存占用与数据集大小无关：

```python
class ImageFolderDataset(Dataset):
    def __init__(self, paths, labels, transform=None):
        self.paths = paths            # 只存路径，不读图
        self.labels = labels
        self.transform = transform

    def __len__(self):
        return len(self.paths)

    def __getitem__(self, idx):
        from PIL import Image
        img = Image.open(self.paths[idx]).convert("RGB")   # 到这里才读盘
        if self.transform:
            img = self.transform(img)
        return img, self.labels[idx]
```

> **注意 `__getitem__` 必须是"无状态"的**：同一个 `idx` 调用两次，除了随机增强外，结果应该一致。不要把"当前读到第几个"这种状态放在 Dataset 里（那是 DataLoader 的职责）。

## 3.4 DataLoader 参数详解

```python
DataLoader(
    dataset,
    batch_size=32,          # 每批样本数
    shuffle=True,           # 是否打乱（训练集 True，验证/测试集 False）
    num_workers=0,          # 子进程数（Windows 上需 __main__ 保护）
    drop_last=False,        # 丢弃最后一个不满的 batch
    pin_memory=False,       # 锁页内存，GPU 训练时设 True 可加速
    collate_fn=None,        # 自定义组装函数
    sampler=None,           # 自定义采样策略（如类别平衡）
)
```

| 参数 | 训练集 | 验证/测试集 | 说明 |
| --- | --- | --- | --- |
| `shuffle` | `True` | **`False`** | 验证集打乱会让指标不可复现 |
| `drop_last` | 视情况 | `False` | 有 BatchNorm 时最后一小批影响统计量，可设 True |
| `num_workers` | 视机器 | 同上 | 0 = 主进程读（可调试）；4 = 四个子进程并行 |
| `pin_memory` | GPU 时 `True` | 同 | CPU 训练设了也没害处 |

**三个易错点**：

1. **`shuffle=False` 不是可选项**。验证集打乱后，你无法把预测和标签按固定顺序对齐做分析。
2. **`DataLoader` 是"每次迭代重新采样"**。写成 `data = list(dataloader)` 会把打乱结果固化，每个 epoch 顺序都一样。
3. **`num_workers` 在 Windows 上必须放在 `if __name__ == "__main__":` 内**，否则子进程会重新导入主模块，导致递归创建进程而崩溃。

**`sampler` 与 `shuffle` 互斥**：需要类别平衡采样（呼应 Week03 的不平衡处理）时：

```python
from torch.utils.data import WeightedRandomSampler

class_counts = np.bincount(y)
weights = 1.0 / class_counts[y]                        # 每样本一个权重
sampler = WeightedRandomSampler(weights, num_samples=len(y), replacement=True)
dl = DataLoader(ds, batch_size=32, sampler=sampler)    # 注意：不能再设 shuffle=True
```

## 3.5 collate_fn：默认组装与自定义

`DataLoader` 拿到一个 batch 的样本列表后，要"拼"成一个张量。这个动作由 `collate_fn` 完成。

**默认行为**（`torch.utils.data.default_collate`）：把每个位置上形状相同的张量用 `torch.stack` 堆起来。

```python
# dataset[i] 返回 (x: (20,), y: scalar)
# 默认 collate 后 -> x: (32, 20),  y: (32,)
```

**问题**：如果形状不同（变长序列），`stack` 会失败：

```python
samples = [torch.randn(5), torch.randn(7), torch.randn(3)]   # 长度不同
torch.stack(samples)     # RuntimeError: stack expects each tensor to be equal size
```

**解决**：自定义 `collate_fn`，做补齐（padding）：

```python
def pad_collate(batch):
    """batch: [(seq_len_i, feat), ...] 等变长样本"""
    xs, ys = zip(*batch)
    lengths = torch.tensor([len(x) for x in xs])
    max_len = lengths.max().item()
    padded = torch.zeros(len(xs), max_len, xs[0].shape[-1])
    for i, x in enumerate(xs):
        padded[i, :len(x)] = x
    return padded, lengths, torch.stack(ys)
```

Week13 做 RNN 处理变长文本时，这个函数会反复出现。`torch.nn.utils.rnn.pad_sequence` 是官方封装版。

## 3.6 transforms：预处理与数据增强

```python
from torchvision import transforms

train_transform = transforms.Compose([
    transforms.RandomResizedCrop(28, scale=(0.8, 1.0)),   # 增强：随机裁剪缩放
    transforms.RandomRotation(10),                        # 增强：随机旋转
    transforms.ToTensor(),                                # 必做：转张量
    transforms.Normalize((0.1307,), (0.3081,)),           # 必做：标准化
])

val_transform = transforms.Compose([
    transforms.ToTensor(),                                # 验证集不做增强！
    transforms.Normalize((0.1307,), (0.3081,)),
])
```

**核心原则：增强只用于训练集。** 验证/测试集必须只用 `ToTensor + Normalize`，否则评估结果不可比。

### ToTensor 到底做了什么

| 变化 | 说明 |
| --- | --- |
| 类型 | `PIL.Image` / `ndarray` → `Tensor` |
| 形状 | `(H, W, C)` → **`(C, H, W)`** |
| 数值 | `uint8 [0, 255]` → `float32 [0.0, 1.0]` |
| 通道 | 单通道图会得到 `(1, H, W)` |

第 2 条是最容易出错的：**NumPy/PIL 是通道在后（HWC），PyTorch 是通道在前（CHW）**。所以 Week15 用 OpenCV 读图后要手工转换。

### Normalize 的两个数字从哪来

$$\hat{x} = \frac{x - \mu}{\sigma}$$

```python
transforms.Normalize((0.1307,), (0.3081,))
```

这两个值是 **MNIST 训练集的全局像素均值与标准差**（官方统计）。CIFAR-10 则是 `(0.4914, 0.4822, 0.4465)` 和 `(0.2470, 0.2435, 0.2616)`。

**新数据集的正确做法**：先算自己训练集的均值/方差，再填进去。

```python
# 计算自定义数据集的 mean / std
loader = DataLoader(dataset, batch_size=64, shuffle=False)
n = 0
mean = torch.zeros(3)
sq = torch.zeros(3)
for x, _ in loader:
    mean += x.mean(dim=(0, 2, 3)) * x.size(0)
    sq += (x ** 2).mean(dim=(0, 2, 3)) * x.size(0)
    n += x.size(0)
mean /= n
std = (sq / n - mean ** 2).sqrt()
print(mean, std)
```

> 呼应 Week08 Day3：标准化（StandardScaler）的思想完全一样，只是从表格数据搬到了图像上。

`torchvision.datasets` 内置了 MNIST / CIFAR10 / FashionMNIST 等：

```python
from torchvision import datasets, transforms

train_set = datasets.MNIST(
    root="./data", train=True, download=True, transform=train_transform

test_set = datasets.MNIST(
    root="./data", train=False, download=True, transform=val_transform

print(len(train_set))              # 60000
print(train_set[0][0].shape)       # torch.Size([1, 28, 28])
print(train_set[0][1])             # 标签（int）
print(train_set.classes)           # ['0 - zero', '1 - one', ...]
```

**首次运行会自动下载**（约 11 MB）。下载慢时手动放置：

```
data/MNIST/raw/train-images-idx3-ubyte.gz
data/MNIST/raw/train-labels-idx1-ubyte.gz
data/MNIST/raw/t10k-images-idx3-ubyte.gz
data/MNIST/raw/t10k-labels-idx1-ubyte.gz
```

**划分验证集的两种做法**：

```python
# 做法 1：从训练集切一部分（推荐，小数据集）
from torch.utils.data import random_split

n_val = int(len(train_set) * 0.1)
n_train = len(train_set) - n_val
train_sub, val_sub = random_split(
    train_set, [n_train, n_val],
    generator=torch.Generator().manual_seed(42)     # ★ 固定种子，保证可复现
)
```

 **`random_split` 的分割是随机的，必须固定 `generator`**，否则每次运行验证集都不一样，指标无法比较。

 **`random_split` 后两个子集的 `transform` 相同**。如果训练集用了数据增强，验证集也会被增强 —— 这时需要给它们分别包装不同的 transform（见 Day5 实战）。

## 3.8 num_workers 与性能

| `num_workers` | 行为 | 适用 |
| --- | --- | --- |
| `0` | 主进程读数据，读到就训练 | 调试、数据小 |
| `2~8` | 子进程预取，训练时数据已备好 | 真实训练 |
| 过大 | 进程切换开销、内存暴涨 | 避免 |

**判断标准**：如果 GPU 利用率忽高忽低（用 `nvidia-smi` 看），说明数据供给跟不上，加大 `num_workers` 和 `prefetch_factor`。

**Windows 注意事项**：

```python
if __name__ == "__main__":              # ★ 必须
    loader = DataLoader(ds, num_workers=4)
    for x, y in loader:
        ...
```

## 3.9 一个 epoch 的完整骨架

```python
def train_one_epoch(model, loader, criterion, optimizer, device):
    model.train()
    total_loss, total_n, correct = 0.0, 0, 0

    for xb, yb in loader:
        xb, yb = xb.to(device), yb.to(device)

        optimizer.zero_grad()
        logits = model(xb)
        loss = criterion(logits, yb)
        loss.backward()
        optimizer.step()

        total_loss += loss.item() * xb.size(0)          # ★ 乘回 batch 大小
        correct += (logits.argmax(1) == yb).sum().item()
        total_n += xb.size(0)

    return total_loss / total_n, correct / total_n
```

**为什么 `loss.item() * xb.size(0)`？** 因为 `CrossEntropyLoss` 默认对 batch 取**平均**。要算整个 epoch 的平均 loss，必须按样本数加权 —— 直接累加平均 loss 会让最后一个不满的 batch 权重过大。

## 3.10 常见坑

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| `stack expects each tensor to be equal size` | 样本形状不一致 | 自定义 `collate_fn` 补齐 |
| Windows 上 `num_workers>0` 卡死/崩溃 | 缺少 `if __name__ == "__main__":` | 加上保护 |
| 验证指标每次波动很大 | 验证集 shuffle=True 或 `random_split` 未固定种子 | 关掉 shuffle、固定 `generator` |
| 训练 loss 远小于实际 | 累加 loss 时没乘 batch 大小 | `loss.item() * xb.size(0)` |
| 显存随 epoch 增长 | 在循环里累积了计算图 | 用 `loss.item()`，验证加 `no_grad()` |
| 图像通道对不上 | HWC vs CHW | `ToTensor()` 或 `permute(2,0,1)` |
| 增强用在验证集上 | 用了同一个 transform | 训练/验证分别构造 |
| `dataset[i]` 很慢 | `__getitem__` 里读盘 + 重计算 | 换 `num_workers`，或预处理成缓存文件 |
