## 一、数据处理流程

### 1.1 标准流程

```
1. 加载原始数据
2. 划分: 训练 / 验证 / 测试  (例如 60% / 20% / 20%)
   - 用【固定随机种子】保证可复现
   - 分类任务用分层划分
3. 统计量计算只能在训练集上做:
   - 均值 / 标准差（标准化）
   - 最小值 / 最大值（归一化）
   - 词表（文本）
   然后【应用到】验证集和测试集
4. 标准化:  x' = (x - μ) / σ
5. 构造 mini-batch: 每个 epoch 打乱后按 batch_size 切分
```

### 1.2 为什么要标准化输入

考虑 $z = \sum_i w_ix_i$。若各 $x_i$ 量纲差异巨大：

- 对应的各 $w_i$ 需要差异巨大的尺度才能平衡；
- 梯度下降在这种"狭长"的损失地形上收敛极慢（Week01 Day4 的条件数问题）。

**标准化的三种效果**：

1. 让损失曲面更接近球形 ⇒ 收敛快；
2. 让权重初始化（Xavier/He）的方差推导成立；
3. 防止数值溢出。

### 1.3 数据增强（在数据不足时）

| 数据类型 | 常用增强 |
| --- | --- |
| 图像 | 翻转、随机裁剪、旋转、颜色抖动、Cutout、Mixup |
| 文本 | 同义词替换、随机删除、回译 |
| 音频 | 变速、加噪、时移 |

**注意**：增强必须**保持标签语义不变**（如数字识别不能水平翻转，否则 6 会变成 9）。

## 二、批处理与迭代

### 2.1 三个易混概念

| 概念 | 含义 |
| --- | --- |
| **batch size** | 一次前向/反向使用的样本数 |
| **iteration / step** | 一次参数更新（处理一个 batch） |
| **epoch** | 遍历一遍全部训练数据 |

$$\text{steps per epoch} = \left\lceil\frac{m}{B}\right\rceil$$

**示例**：$m=60000$，$B=100$ ⇒ 每个 epoch 600 步。训练 10000 步 ≈ **16.7 个 epoch**。

### 2.2 batch size 的选择

| Batch | 优点 | 缺点 |
| --- | --- | --- |
| 1（纯 SGD） | 泛化好、内存小 | GPU 利用率低、噪声大 |
| 32–256 | **折中最好** | — |
| 1024+ | 吞吐高、稳定 | 泛化可能变差、需更大 lr |

**经验规则**：

- batch 翻倍 ⇒ 学习率可近似翻倍（Linear Scaling Rule）；
- 小 batch 需要更小的学习率与更慢的学习率衰减；
- **显存不够时用梯度累积**（累积 $k$ 个小 batch 的梯度再更新，等效于 $k$ 倍大 batch）。

## 三、超参数搜索

### 3.1 哪些超参数最重要

按重要性排序（经验）：

| 优先级 | 超参数 | 典型搜索范围 |
| --- | --- | --- |
| 1 | **学习率** | $10^{-5}$ ~ $10^{-1}$（对数） |
| 2 | 正则化强度 | $10^{-6}$ ~ $10^{-2}$（对数） |
| 3 | 模型容量（层数/宽度） | 由数据量决定 |
| 4 | batch size | 32 ~ 512 |
| 5 | 学习率调度 | 余弦 / 阶梯 |
| 6 | 其他（Dropout 率、初始化） | — |

### 3.2 三种搜索策略

| 策略 | 方法 | 适用 |
| --- | --- | --- |
| 网格搜索 | 笛卡尔积 | 维度 ≤ 2 |
| **随机搜索** | 每维独立随机采样（对数均匀） | **维度 ≥ 3**（更高效） |
| 贝叶斯优化 | 用代理模型指导采样 | 每次训练很贵时 |

**Bergstra & Bengio (2012) 的结论**：**在相同预算下，随机搜索通常优于网格搜索**，因为通常只有少数超参数真正重要。

### 3.3 学习率范围测试（LR Range Test）

**快速找到合适学习率的方法**：

```
1. 从很小的 lr（如 1e-7）开始训练
2. 每个 batch 把 lr 按指数增长到 1
3. 记录 loss 随 lr 的变化曲线
4. 选"loss 下降最快"或"loss 开始上升前的 1/10"处的 lr
```

```
loss
 ↑        ╱ ← loss 开始爆炸
 |      ╱
 |    ╱   ← 最佳区间
 |  ╱
 +────────────────→ lr (log)
```

**这是调参时最省时间的一步**。PyTorch 的 `torch-lr-finder` 包实现了它。

### 3.4 学习率衰减

| 策略 | 公式 |
| --- | --- |
| 阶梯 | $\eta_t = \eta_0\times0.1^{\lfloor t/30\rfloor}$ |
| 余弦退火 | $\eta_t = \eta_{\min}+\frac{1}{2}(\eta_0-\eta_{\min})(1+\cos\frac{t\pi}{T})$ |
| 预热 + 余弦 | 前 5% 线性升温，之后余弦衰减 |
| ReduceLROnPlateau | 验证损失停滞时减半 |

**现代默认**：**预热 + 余弦退火**。

## 四、正则化

### 4.1 权重衰减（L2）

$$L_{\text{total}} = L_{\text{data}} + \frac{\lambda}{2}\sum_l\|\mathbf{W}^{(l)}\|_F^2$$

**梯度**：$\frac{\partial L}{\partial\mathbf{W}} \mathrel{+}= \lambda\mathbf{W}$。

**实现要点**：只对**权重**衰减，**不要对偏置和归一化层的参数衰减**。

```python
optimizer = torch.optim.SGD([
    {"params": model.fc1.weight, "weight_decay": 1e-4},
    {"params": model.fc1.bias,   "weight_decay": 0.0},
    ...
], lr=0.1)
```

### 4.2 Dropout

**原理**：训练时以概率 $p$ 随机置零神经元输出，测试时不丢弃。

**Inverted Dropout**（现代标准）：训练时除以 $(1-p)$，测试时不变。

**取值建议**：

| 层 | 常用 $p$ |
| --- | --- |
| 全连接层（大） | 0.5 |
| 卷积层 | 0.1–0.3（或不用，改用 BN） |
| 输入层 | 0.1–0.2 |
| Transformer | 0.1 |

### 4.3 早停（Early Stopping）

```
每个 epoch 结束后:
    在验证集上评估
    若验证损失【连续 N 个 epoch】没有改善:
        停止训练, 回滚到验证损失最小的那个 checkpoint
```

**$N$ 的典型值**：5–20（称为 patience）。

**为什么早停是一种正则化**：它限制了模型"见过"的优化步数，等价于限制模型复杂度（间接控制方差）。

### 4.4 其他正则化

| 方法 | 说明 |
| --- | --- |
| 标签平滑（Label Smoothing） | 把 one-hot 的 1 换成 $1-\epsilon$，$\epsilon$ 平摊给其他类；防止过度自信 |
| 随机深度（Stochastic Depth） | 随机跳过某些残差块 |
| DropBlock | 卷积特征图上整块丢弃 |
| 数据增强 | 最有效的"免费"正则 |

## 五、训练曲线诊断

### 5.1 六种典型曲线

| 曲线形态 | 诊断 | 对策 |
| --- | --- | --- |
| 训练/验证都高且接近 | 欠拟合 | 增大模型、减小正则、增加特征 |
| 训练↓ 验证↑ | 过拟合 | 加数据/增强、加正则、简化模型、早停 |
| 训练 loss 为 nan | 学习率过大 / 梯度爆炸 | 减小 lr、梯度裁剪、标准化 |
| 训练 loss 不下降 | lr 过小 / 梯度消失 / bug | 调 lr、换激活、梯度检查 |
| 训练 loss 震荡 | lr 偏大、batch 太小 | 减小 lr、增大 batch、加动量 |
| 验证 loss 突然跳升 | 遇到过拟合点或数据问题 | 早停、检查数据 |

### 5.2 三条"黄金"检查

**（1）过拟合单批数据**

```
取 10 个样本，关掉所有正则，训练 500 步。
loss 应该能降到接近 0，准确率 100%。
若不能 -> 代码有 bug（不是"模型不够强"）
```

**这是最有用的调试技巧。**

**（2）梯度检查**

用数值梯度验证解析梯度（Week07 Day3）。

**（3）检查激活值分布**

| 现象 | 诊断 |
| --- | --- |
| 大量激活为 0 | ReLU 死亡 |
| 激活值集中在 0 附近 | 初始化太小 / 梯度消失 |
| 激活值饱和到 ±1 | sigmoid/tanh 饱和 |
| 某些通道方差为 0 | 该层未学习 |

## 六、可复现性

**深度学习的实验结果必须可复现。**

```python
import random, numpy as np, torch

def set_seed(seed=42):
    random.seed(seed)
    np.random.seed(seed)
    torch.manual_seed(seed)
    torch.cuda.manual_seed_all(seed)
    torch.backends.cudnn.deterministic = True
    torch.backends.cudnn.benchmark = False
```

**仍有不确定性的来源**：

- GPU 上的原子操作（浮点加法不满足结合律）；
- 多线程数据加载的顺序；
- 第三方库的非确定性算子。

**实践**：报告结果时说明随机种子、库版本、硬件；重要结论跑 **多个种子取均值 ± 标准差**。

## 七、模型保存与加载

```python
# 保存（推荐只存 state_dict）
torch.save({
    "epoch": epoch,
    "model_state": model.state_dict(),
    "optimizer_state": optimizer.state_dict(),
    "best_val_loss": best_val_loss,
}, "checkpoint.pt")

# 加载
ckpt = torch.load("checkpoint.pt", map_location="cpu")
model.load_state_dict(ckpt["model_state"])
optimizer.load_state_dict(ckpt["optimizer_state"])
```

**要点**：

- 训练时**保存验证损失最低的 checkpoint**（而非最后一个 epoch）；
- 推理时调用 `model.eval()`（关闭 Dropout / BN 的批统计）；
- 用 `with torch.no_grad():` 关闭梯度记录，节省显存。

## 九、常见坑

| 坑 | 说明 |
| --- | --- |
| 用全量数据算标准化参数 | 数据泄漏 |
| 用测试集调超参 | 严重的评估偏差 |
| 训练时忘记 `model.train()` / 推理忘记 `model.eval()` | Dropout/BN 行为错误 |
| 忘记 `zero_grad()` | 梯度累积导致爆炸 |
| 保存模型只存了 `state_dict()` 却用整模型加载 | 加载失败 |
| 只跑一个随机种子就下结论 | 结果不可靠 |
| 对 BN 参数和偏置也做权重衰减 | 性能下降 |
| 学习率调整后没重跑 LR Range Test | 最优 lr 可能变了 |
| 显存不够就减小 batch 而不调整 lr | 训练动态改变 |

## 十、练习题

**基础**

1. 数据 60000 个样本，batch size=128，每个 epoch 多少步？训练 20000 步是几个 epoch？
2. 说明为什么要用训练集的统计量做标准化。
3. 列出学习率搜索的对数网格（$10^{-5}$ 到 $10^{-1}$，每 10 倍一个点）。

**进阶**

4. 推导权重衰减在 SGD 更新中的等价形式：
   $$\boldsymbol{w}\leftarrow\boldsymbol{w}-\eta\nabla L-\eta\lambda\boldsymbol{w} = (1-\eta\lambda)\boldsymbol{w}-\eta\nabla L$$
 并说明为什么它被称为"权重衰减"。
5. 说明 Inverted Dropout 为什么让测试阶段无需缩放。
6. 证明：若训练时以概率 $p$ 置零并除以 $(1-p)$，则输出的期望不变。
7. 设计一个实验，区分"学习率过大"与"代码有 bug"两种情况。

**思考题**

8. 为什么"过拟合单批数据"测试是有效的调试手段？
9. 为什么随机搜索通常优于网格搜索？
10. 早停为什么可以视为一种正则化？它与权重衰减有什么相似之处？

<details>
<summary>第 1 题答案</summary>

$$\text{steps per epoch} = \lceil 60000/128 \rceil = 469$$

$$\text{epochs} = 20000 / 469 \approx 42.6 \text{ 个 epoch}$$
</details>

<details>
<summary>第 4 题答案</summary>

带权重衰减的损失：

$$L_{\text{total}} = L + \frac{\lambda}{2}\|\boldsymbol{w}\|^2 \Rightarrow \nabla L_{\text{total}} = \nabla L + \lambda\boldsymbol{w}$$

SGD 更新：

$$\boldsymbol{w} \leftarrow \boldsymbol{w} - \eta(\nabla L + \lambda\boldsymbol{w}) = (1-\eta\lambda)\boldsymbol{w} - \eta\nabla L$$

**每一项更新前都先乘上 $(1-\eta\lambda) < 1$** —— 这就是"衰减"一词的来源（每一步把权重按比例缩小一点）。

**等价说法**：$L_2$ 正则 = 权重衰减（在 SGD 中）。**注意**：在 Adam 中二者**不等价**（Adam 的自适应缩放会破坏这个等价性），这就是 **AdamW** 出现的原因。
</details>

<details>
<summary>第 6 题答案</summary>

设未加 Dropout 时某神经元输出为 $a$。

加 Inverted Dropout 后，输出为

$$\tilde a = \frac{m\cdot a}{1-p}, \qquad m\sim\text{Bernoulli}(1-p)$$

期望：

$$\mathbb{E}[\tilde a] = \frac{\mathbb{E}[m]\cdot a}{1-p} = \frac{(1-p)a}{1-p} = a$$

**期望不变 ⇒ 测试时直接使用原输出即可，无需任何缩放。**

**对比标准 Dropout**：训练时不缩放（$\tilde a = ma$，期望为 $(1-p)a$），测试时必须乘 $(1-p)$。
</details>

<details>
<summary>第 9 题答案要点</summary>

**核心原因**：超参数的重要性极不均衡——通常只有 1–3 个真正重要。

**网格搜索的问题**：假设有 5 个超参，每维取 10 个值 ⇒ $10^5$ 组合。若其中只有 2 个重要，那么**在这 2 个重要维度上，实际只探索了 10 个不同的取值**（其余 3 维的变化是在浪费预算）。

**随机搜索的优势**：每个超参独立采样，因此在**任意子集**的维度上都能覆盖到更多不同的取值。研究表明，随机搜索在相同预算下找到同等质量配置的概率更高。

**实践提示**：随机搜索时应使用**对数均匀分布**（对 lr、正则系数这类跨数量级的参数）。
</details>
