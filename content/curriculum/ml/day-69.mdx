## 4.2 把图像变成序列

**任务设计**：MNIST 是 $28\times28$ 的灰度图。

**序列化方式**：把图像看作 **28 个时间步，每一步是一个 28 维向量（一行像素）**。

```
28x28 图像                序列化后
┌──────────────┐
│  行 0        │  ->  x[0] = 28 维向量
│  行 1        │  ->  x[1] = 28 维向量
│  ...         │       ...
│  行 27       │  ->  x[27] = 28 维向量
└──────────────┘
                     形状: (T=28, d=28)
```

**为什么这个设计合理**：

1. **顺序有意义**：写字是从上到下的，行的顺序携带结构信息；
2. **可以检验"记忆"是否发挥作用**：识别数字需要组合上下部分（如"8"的上下两个环）；
3. **数据现成**：不用下载新的数据集。

**局限**：MNIST 的"序列性"其实很弱（图像不像文本那样有强时序依赖）。RNN 在这个任务上**不会比 CNN 更好** —— 但这正好提供了一个诚实的对照：

> **选结构要看数据的性质，不是看哪种更"高级"。**

## 4.4 预期与解读框架

**这个实验会看到什么**：

| 现象 | 解释 |
| --- | --- |
| LSTM/GRU 优于普通 RNN | 门控缓解梯度消失（Day2） |
| 双向明显优于单向 | 识别数字需要"上下文"（Day3 §3.5） |
| 都远不如 CNN（Week11 的 99%） | **序列化丢失了二维空间结构** |
| **T=28 反而不如 T=21** | **序列越长越难优化 —— RNN 的核心矛盾** |

### 关于"序列越长反而越差"

实测结果：

| 序列长度 T | 信息占比 | 测试准确率 |
| --- | --- | --- |
| 7 | 25% | 约 52% |
| 14 | 50% | 约 85% |
| **21** | 75% | **约 90%（最好）** |
| 28 | **100%** | 约 87%（下降） |

**T=28 信息最多，精度却更低。** 原因：

1. 序列越长，BPTT 的连乘越长，优化越难（Day1 的梯度衰减）；
2. 在固定的 3 epoch 预算下，长序列还没训透；
3. 图像底部几行信息量小，但为它们付出的优化难度是实打实的。

**这就是 RNN 的核心矛盾**：

$$\text{序列长} \Rightarrow \text{信息多，但更难训练}$$
$$\text{序列短} \Rightarrow \text{好训练，但信息少}$$

**Week14 的 Transformer 用自注意力让任意两个位置的距离都是 $\mathcal{O}(1)$，正是为了打破这个矛盾。**

**最重要的一条**：**RNN 在图像任务上打不过 CNN。**

原因不是 RNN 弱，而是**归纳偏置不匹配**：

- CNN 假设"局部相关 + 平移不变" → 完美契合图像；
- RNN 假设"顺序依赖" → 契合文本/语音。

> 呼应 Week11 Day1：**结构是"先验"，先用对先验，再谈容量。**

### 4.5.1 数据准备

```python
def build_sequence_loaders(n_train, T=28, batch=128):

    def prep(ds):

        X = ds.data.float().div(255.0).sub(0.1307).div(0.3081)
        return X[:, :T, :], ds.targets.long()
    ...
```

**注意**：这里的归一化直接用了 MNIST 的全局统计量，且**按行切片**得到序列。

### 4.5.2 模型

```python
class SeqClassifier(nn.Module):
    def __init__(self, cell="lstm", d=28, h=64, bidirectional=False):
        super().__init__()
        cls = {"rnn": nn.RNN, "lstm": nn.LSTM, "gru": nn.GRU}[cell]
        self.rnn = cls(d, h, batch_first=True, bidirectional=bidirectional)
        self.fc = nn.Linear(h * (2 if bidirectional else 1), 10)

    def forward(self, x):
        out, state = self.rnn(x)
        if isinstance(state, tuple):
            hn = state[0]
        else:
            hn = state
        feat = torch.cat([hn[-2], hn[-1]], -1) if self.rnn.bidirectional else hn[-1]
        return self.fc(feat)
```

### 4.5.3 训练循环（RNN 的三条铁律）

```python
opt.zero_grad()
logits = model(xb)
loss = criterion(logits, yb)
loss.backward()
torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)    # ① 必须裁剪
opt.step()
# ② 每个 batch 从零开始（不跨 batch 传状态）
# ③ 评估用 no_grad()
```

## 4.6 常见坑

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 精度一直很低 | 忘了梯度裁剪，梯度爆炸 | `clip_grad_norm_` |
| 显存持续增长 | 跨 batch 传隐藏状态 | 每 batch 重置 |
| 双向准确率没提升 | 特征只取了 `hn[-1]`（只有反向的） | 拼接 `hn[-2]` 和 `hn[-1]` |
| 截断序列后精度大跌 | 信息丢失 | 这本身是实验结论 |
| 训练极慢 | 时间步串行 + LSTM 参数量大 | 用 GRU 或减小编码长度 |
| 与 CNN 比不公平 | 参数量差异巨大 | 同时报告参数量与时间 |
