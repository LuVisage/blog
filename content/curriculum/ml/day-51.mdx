## 1.2 过拟合：从"现象"到"量化"

Week02 Day4 你已经知道：

$$\mathbb{E}[\text{误差}] = \text{Bias}^2 + \text{Variance} + \text{噪声}$$

现在把它落到训练曲线上。**三种典型形态**：

```
欠拟合                    合适                    过拟合
loss                      loss                    loss
 │\                        │\                      │\
 │ \___ train             │ \___                  │ \___
 │     \___ val           │     \___ train        │     \___ train(→0)
 │         \___           │         \___ val      │
 │             \___       │             \___      │  val  ↗ 掉头向上
 └──────────────         └──────────────           └──────────────
 train ≈ val 且都很高     train ≈ val，都不错      train ≪ val，间隙扩大
 → 加参数 / 减正则        → 保持                 → 加正则 / 加数据
```

**量化判断标准**（比"看感觉"可靠）：

| 指标 | 计算 | 阈值参考 |
| --- | --- | --- |
| 泛化间隙 | $\text{acc}_{\text{train}} - \text{acc}_{\text{val}}$ | > 5% 需警惕 |
| 验证 loss 拐点 | val loss 连续上升的 epoch | 早停位置 |
| 参数量/样本量比 | $N_{\text{param}} / N_{\text{sample}}$ | > 10 易过拟合 |

**为什么深度学习不怕过拟合**（一个反直觉的事实）：经典统计学习理论认为参数量超过样本量必然过拟合，但深度网络（参数量远超样本量）却能泛化良好。原因在于：

1. **隐式正则**：SGD 的噪声、小批量、早停本身就在限制模型的解空间；
2. **参数空间的"平坦解"偏好**：SGD 倾向于收敛到泛化更好的平坦极小值；
3. **真实数据的结构**：图像、语言有强先验，网络结构（卷积、注意力）与之匹配。

> 但这不意味着可以忽略正则化。数据量小、任务特殊时，正则化仍然是必需品。

## 1.3 L2 正则与权重衰减：一个推导

### 1.3.1 从损失函数出发

在原始损失上加上权重的平方惩罚（花书 7.1.1）：

$$\tilde{\mathcal{L}}(\mathbf{W}) = \mathcal{L}(\mathbf{W}) + \frac{\lambda}{2}\lVert \mathbf{W} \rVert_2^2$$

梯度变为：

$$\nabla_{\mathbf{W}}\tilde{\mathcal{L}} = \nabla_{\mathbf{W}}\mathcal{L} + \lambda\mathbf{W}$$

参数更新：

$$\mathbf{W} \leftarrow \mathbf{W} - \eta(\nabla\mathcal{L} + \lambda\mathbf{W}) = \underbrace{(1 - \eta\lambda)\mathbf{W}}_{\text{先衰减}} - \underbrace{\eta\nabla\mathcal{L}}_{\text{再沿梯度走}}$$

**这就是"权重衰减"这个名字的来源**：每一步都在做 $\mathbf{W} \leftarrow \mathbf{W}(1 - \eta\lambda)$，权重被"乘上一个略小于 1 的系数"。

### 1.3.2 两个必须知道的细节

**细节 1：为什么惩罚项写 $\frac{\lambda}{2}$ 而不是 $\lambda$？**

为了让求导后系数干净：$\frac{\partial}{\partial \mathbf{W}}\left(\frac{\lambda}{2}\lVert\mathbf{W}\rVert^2\right) = \lambda\mathbf{W}$，没有那个 2。

**细节 2：为什么偏置通常不参与正则？**

偏置不控制输入特征的影响力，只做平移。正则化偏置对模型的复杂度几乎没有约束作用，反而可能影响拟合能力。所以在 Day4 讲过：**参数分组**，只对权重矩阵做衰减。

### 1.3.3 等价性验证

```python
# 写法 A：在 loss 里手加 L2
loss = criterion(logits, y) + 0.5 * lam * sum(p.pow(2).sum() for p in model.parameters())
loss.backward()
optimizer.step()

# 写法 B：交给优化器
optimizer = torch.optim.SGD(model.parameters(), lr=lr, weight_decay=lam)
```

**两者在 SGD 下完全等价**（案例代码会实测验证，差异应在 $10^{-7}$ 量级）。

 **但在 Adam 下不等价**！Adam 的 `weight_decay` 会让正则项进入自适应缩放，导致实际衰减强度与学习率耦合。这正是 **AdamW** 存在的原因（Day3 详述）。

### 1.3.4 为什么 L2 能防过拟合（两种解释）

**解释 A（权重空间几何）**：L2 约束把解限制在一个球内，避免了"某些权重特别大以至于对输入的微小扰动极度敏感"的解。

**解释 B（函数平滑性）**：对线性模型，$\lVert\nabla_x f(x)\rVert = \lVert\mathbf{W}\rVert$。正则化权重就是压制输出对输入的敏感度 —— 输入稍微变化，输出不该剧烈变化。这是"平滑性先验"。

呼应 Week03 Day1：岭回归的解从 $\mathbf{W}_{\text{OLS}} = (\mathbf{X}^\top\mathbf{X})^{-1}\mathbf{X}^\top\mathbf{y}$ 变成 $(\mathbf{X}^\top\mathbf{X} + \lambda\mathbf{I})^{-1}\mathbf{X}^\top\mathbf{y}$，加 $\lambda\mathbf{I}$ 同时解决了 $\mathbf{X}^\top\mathbf{X}$ 不可逆的问题。这里也一样：**正则化既防过拟合，又改善数值稳定性**。

## 1.4 L1 正则：稀疏的力量

$$\tilde{\mathcal{L}} = \mathcal{L} + \lambda\lVert \mathbf{W} \rVert_1 = \mathcal{L} + \lambda\sum_i |w_i|$$

梯度：$\partial |w_i| / \partial w_i = \text{sign}(w_i)$，所以小权重被**恒定的力度**推向 0（而 L2 的推力正比于 $w_i$，越接近 0 推力越小）。

**几何解释**：

```
       L2 约束：圆球              L1 约束：菱形
          w2                        w2
           │    ╱                   │    ╱
           │  ╱                     │  ╱
        ┌──┼──┐                     ◇
        │  │  │                    ╱ │ ╲
        └──┼──┘                  ╱   │   ╲
           │                        ───┼───
           └────── w1                └────── w1

   切点通常在"斜面上"          切点容易落在"尖角"上
   → 两个权重都不为 0            → 某个权重恰好为 0
```

**L1 的稀疏性使得它可以做特征选择** —— 呼应 Week03 的 Lasso。

| | L1 | L2 |
| --- | --- | --- |
| 惩罚 | $\sum \|w_i\|$ | $\sum w_i^2$ |
| 解 | 稀疏（很多 0） | 平滑（都变小） |
| 深度学习中 | 较少用（不利于梯度） | **主流** |
| 别名 | Lasso | Ridge / 权重衰减 |

**为什么深度学习里 L2 更主流**：L1 在 0 点不可导，梯度是常数 sign，会导致权重在 0 附近来回震荡，与 Adam 这类自适应优化器配合不好。

## 1.5 Dropout：最优雅的正则化

### 1.5.1 机制

训练时，每一层（通常是全连接层之后）以概率 $p$ 随机把神经元的输出置零：

```python
# 训练时
mask = (torch.rand_like(x) > p) / (1 - p)     # 二值掩码 + 缩放
x = x * mask

# 推理时
# 什么都不做！
```

**关键就是那个 `/(1-p)`**。为什么需要它？

### 1.5.2 缩放的必要性（一个必须搞懂的点）

假设某神经元的输出是 $x$，训练时它以概率 $p$ 变成 0，以概率 $1-p$ 保持为 $x$。那么它的**期望**是：

$$\mathbb{E}[\text{输出}] = (1-p)\cdot x + p \cdot 0 = (1-p)x$$

如果推理时直接用完整网络（输出 $x$），期望就变成了 $x$，与训练时的 $(1-p)x$ 相差 $1/(1-p)$ 倍 —— **训练与推理的激活尺度不一致**，会导致推理结果系统性偏大。

两种解决办法：

| 方案 | 训练时 | 推理时 | 现状 |
| --- | --- | --- | --- |
| 原始 Dropout | 直接置零 | **乘以 $(1-p)$** | 已淘汰 |
| Inverted Dropout | 置零后 **除以 $(1-p)$** | 什么都不做 | **现行标准** |

框架用的都是后者（`nn.Dropout`），测试时零开销。

### 1.5.3 为什么有效：三种解释

**解释 A（集成学习视角，花书 7.12）**

$n$ 个神经元的网络，Dropout 会产生 $2^n$ 个不同的子网络。每次训练迭代采样一个子网络并更新它的参数（参数共享）。推理时用的是"完整网络"，而它的输出近似于这 $2^n$ 个子网络输出的**几何平均**。

呼应 Week04 的 Bagging：**都是"训很多个模型然后平均"**，区别在于 Dropout 的子网络共享参数、且数量是指数级。

**解释 B（防止共适应）**

神经元不能依赖"某个特定伙伴一定存在"，必须学会更鲁棒的特征。这迫使每个神经元独立地提取有用信息。

**解释 C（噪声注入）**

Dropout 等价于在激活值上注入乘性噪声，属于"数据/特征层面加噪"的一类正则化（Day1 后面还会见到权重加噪、标签平滑）。

### 1.5.4 使用要点

| 要点 | 说明 |
| --- | --- |
| 加在哪里 | 通常在激活函数之后；**不放在输出层** |
| $p$ 的取值 | 全连接 0.3~0.5；卷积层 0.1~0.2；**小网络慎用** |
| 与 BN 的关系 | 同时用时要小心（BN 与 Dropout 有冲突，实践中常只留 BN） |
| `model.eval()` | **必须调用**，否则推理时仍在随机丢弃 |
| 数据量大时 | 可以不用（正则化是"数据不足"时的补偿手段） |

> **练手技巧**：如果某个 Dropout 层的 $p$ 值很高但模型仍过拟合，说明问题不在参数量，而在数据质量或任务本身。

## 1.6 数据增强

**最有效的正则化手段，没有之一。** 因为它直接增加了有效数据量。

```python
train_tf = transforms.Compose([
    transforms.RandomResizedCrop(28, scale=(0.8, 1.0)),
    transforms.RandomRotation(10),
    transforms.ToTensor(),
    transforms.Normalize((0.1307,), (0.3081,)),
])
```

**关键原则**：增强必须**保持标签不变**。

| 任务 | 可用的增强 | 不能用的增强 |
| --- | --- | --- |
| 手写数字 | 旋转（小角度）、平移、缩放 | **垂直翻转**（6↔9 会变） |
| 自然图像分类 | 翻转、裁剪、颜色抖动、Cutout | 大幅旋转（狗倒过来还是狗，但……） |
| 医学影像 | 弹性变形、噪声 | 翻转（左右器官不同） |
| 文本分类 | 同义词替换、回译 | 改变语序 |

**进阶：Mixup 与 CutMix**

```python
# Mixup：两张图按比例混合，标签也按比例混合
lam = np.random.beta(0.2, 0.2)
x_mix = lam * x1 + (1 - lam) * x2
loss = lam * criterion(pred, y1) + (1 - lam) * criterion(pred, y2)
```

它让模型在"两类之间的过渡区域"也有明确的目标，显著提升鲁棒性。

**Test-Time Augmentation (TTA)**：推理时也做增强，把多次预测平均。用训练时的开销换精度，竞赛常用。

## 1.7 早停

Week09 Day4 已经用过了。这里补上它的理论地位：

**早停是一种"免费"的正则化**。它通过限制优化步数，隐式地限制了参数能走多远（从而限制了模型的复杂度）。

花书 7.8 指出：**早停等价于 L2 正则的某种近似**。直觉上，训练初期权重较小（从零附近出发），步数越少权重越小 —— 与 L2 压权重异曲同工。

```python
best_acc, best_epoch, patience = 0.0, 0, 5
if val_acc > best_acc:
    best_acc, best_epoch = val_acc, epoch
    torch.save(model.state_dict(), "best.pt")
elif epoch - best_epoch >= patience:
    break
```

**实践建议**：

- `patience` 取 5~20，看数据集大小和训练成本；
- **保存的是"最优 epoch"的权重**，不是最后一个 epoch 的 —— 这一点经常被写错；
- 用验证集早停，不用测试集（Week02 Day2 的铁律）。

## 1.8 正则化手段总览

| 手段 | 作用机制 | 代价 | 效果 |
| --- | --- | --- | --- |
| **L2 / 权重衰减** | 压制大权重，平滑函数 | 几乎为零 | 稳定提升 |
| **L1** | 稀疏化，特征选择 | 0 点不可导 | 特定场景 |
| **Dropout** | 隐式集成 + 防共适应 | 训练变慢 | 大数据集上收益递减 |
| **数据增强** | 增加有效样本 | 需要领域知识 | **最强** |
| **早停** | 限制优化步数 | 需要验证集 | 免费 |
| **标签平滑** | 软化目标分布 | 需调平滑系数 | 分类任务常用 |
| **权重加噪** | 噪声注入 | 需调噪声尺度 | 较少用 |
| **BN** | 归一化激活分布 | 增加计算 | Day2 详述 |

**实践中的优先级**（按性价比）：

```
1. 先加数据 / 增强         ← 最有效
2. 加 L2 权重衰减          ← 几乎免费
3. 加 Dropout（大网络才需要）
4. 加早停                  ← 本来就该有
5. 再考虑其他花哨手段
```

## 1.9 常见坑

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 推理结果系统性偏大 | 用了原始 Dropout 而推理忘了乘 $(1-p)$ | 用 `nn.Dropout`（已实现 Inverted） |
| 验证指标抖动 | 忘了 `model.eval()` | 评估前调用 |
| 加了 weight_decay 但没效果 | ① Adam 的自适应缩放吃掉了 L2；② 正则强度与参数量不匹配 | 换 `AdamW`；按参数量调整 $\lambda$（67 万参数配 `1e-3` 基本无感） |
| 偏置也被衰减了 | 没做参数分组 | 只对 `ndim > 1` 的参数设 decay |
| 训练 loss 不降 | 正则太强（Dropout $p$ 过大） | 降低 $p$，或先关掉正则跑通 |
| 旋转增强后精度不升反降 | 增强破坏了标签（如 6/9 翻转） | 检查增强的语义合理性 |
| 早停后精度不如预期 | 保存了最后一个 epoch 而非最优 | 保存 `best.pt` |
| 小数据集上 Dropout 有害 | 正则过强导致欠拟合 | 小数据优先用 L2 + 早停 |
