## 5.2 核心思想：预测下一个 token

**大语言模型做的事情简单到可以用一句话概括**：

> **给定前面的文本，预测下一个 token 是什么。**

$$P(x_t \mid x_1, x_2, \dots, x_{t-1})$$

**训练目标**：

$$\mathcal{L} = -\sum_{t=1}^{T}\log P(x_t \mid x_{<t};\ \theta)$$

**这就是交叉熵损失**（Week01 Day5、Week02 讲过），只不过每一时刻都在算。

**生成时**：把预测出的 token 拼回输入，再预测下一个 —— **自回归**（autoregressive）。

```python
for _ in range(max_new_tokens):
    logits = model(tokens)          # 预测下一个 token 的分布
    next_token = sample(logits)     # 按策略采样
    tokens = cat([tokens, next_token])   # 拼回去，继续
```

> **为什么这么简单的方法能产生"智能"**：为了准确预测下一个 token，模型必须隐式地学会语法、事实、推理模式、代码逻辑……**预测任务本身成了学习世界知识的"杠杆"。**

## 5.3 分词（Tokenization）

**问题**：神经网络只能处理数字，文本要先变成整数序列。

**三种粒度**：

| 粒度 | 做法 | 词表大小 | 优缺点 |
| --- | --- | --- | --- |
| **字符级** | 每个字符一个 id | ~100 | 简单；序列长；不适合中文 |
| **词级** | 每个词一个 id | 10万+ | 序列短；**OOV 问题严重** |
| **子词级**（BPE） | 常见字组合成一个 token | 3万~15万 | **主流**；平衡了长度与覆盖 |

**BPE（Byte Pair Encoding）的核心思路**：

```
① 初始: 每个字符是一个 token
② 统计: 找出出现频率最高的相邻 token 对
③ 合并: 把这一对合并成一个新 token
④ 重复 ②③ 直到词表达到目标大小
```

**为什么 BPE 好**：

- 常见词（`the`、`模型`）会被合成一个 token → 序列短；
- 罕见词（`antidisestablishmentarianism`）会拆成子词 → **没有 OOV**；
- 词表大小可控。

**一个实用的直觉**：

| 语言 | 每个 token 大约对应 |
| --- | --- |
| 英文 | 0.75 个单词（约 4 个字符） |
| 中文 | 1~2 个汉字 |

**为什么这个数字重要**：**API 计费按 token 算，上下文窗口也按 token 算。** 中文的 token 效率低于英文，成本相对更高。

## 5.4 GPT 的结构：Decoder-only Transformer

**复习 Week14 Day3**：Transformer 有三种架构。

| 架构 | 注意力掩码 | 用途 |
| --- | --- | --- |
| **Encoder-only**（BERT） | 双向 | 理解任务（分类、NER） |
| **Decoder-only**（GPT） | **因果（只看左侧）** | **生成任务** |
| Encoder-Decoder（T5） | 双向 + 因果 | 翻译、摘要 |

**GPT = Decoder 堆叠**，每一层包含：

```
① 层归一化 (LayerNorm)
② 因果自注意力 (Masked Self-Attention)   ← 只能看左边的 token
③ 残差连接
④ 层归一化 + 前馈网络 (FFN，通常是 4x 扩张)
⑤ 残差连接
```

**因果掩码是关键**：

$$\text{Attention} = \text{softmax}\left(\frac{QK^\top}{\sqrt{d_k}} + M\right)V$$

其中 $M$ 是上三角为 $-\infty$、下三角为 0 的掩码矩阵。

**为什么必须掩码**：训练时是**并行**预测所有位置的（Teacher Forcing），如果模型能看到右边的答案，就学不到任何东西。掩码保证位置 $t$ 只能看到 $1\dots t-1$。

### 三个现代改进（了解即可）

| 改进 | 作用 |
| --- | --- |
| **Pre-LN** | 把 LayerNorm 放到子层**前**（原始 Transformer 在后），训练更稳定 |
| **RMSNorm** | 简化版 LayerNorm，省掉均值中心化，更快 |
| **RoPE** | 旋转位置编码，比正弦编码的外推性更好 |
| **SwiGLU** | FFN 的激活函数换成 Swish 门控，效果更好 |

**这些几乎是现代 LLM 的标配**（LLaMA 系列全用了）。

## 5.5 三段式训练流程

**这是理解"ChatGPT 是怎么来的"的关键。**

```
① 预训练 (Pre-training)
   数据: 数万亿 token 的网页/书籍/代码
   目标: 预测下一个 token
   产出: 基座模型 (Base Model) —— 会续写，但不会对话
        ↓
② 监督微调 (SFT, Supervised Fine-Tuning)
   数据: 几万~几十万条【人工标注的对话】
   目标: 还是预测下一个 token，但只在"回答"部分算损失
   产出: 会听从指令的模型 (Instruct Model)
        ↓
③ 对齐 (RLHF / DPO)
   数据: 人类对多个回答的【偏好排序】
   目标: 让模型输出更符合人类偏好（有用、无害、诚实）
   产出: ChatGPT 类的对话助手
```

### 三个阶段的关键差异

| | 预训练 | SFT | RLHF |
| --- | --- | --- | --- |
| 数据量 | 万亿 token | 万~十万条 | 万~十万条偏好对 |
| 数据来源 | 网络爬取 | 人工编写 | 人工排序 |
| 损失 | 全部 token 的交叉熵 | **只在回答部分算** | 偏好损失 |
| 学到的 | 语言与世界知识 | **格式与指令遵循** | 有用性/无害性 |
| 成本 | 数百万美元 | 数千美元 | 数万美元 |
| 能跳过的 | **不能** | 不能 | 可以（DPO / 直接 SFT） |

**一个常见误解**：

> "SFT 让模型学会新知识" —— **不对**。
>
> **知识主要来自预训练。** SFT 主要是让模型学会**"以什么格式回答"**。所以你不能靠 SFT 让模型知道今天发生的新闻。

**为什么会"幻觉"（Hallucination）**：模型学的是 $P(x_t|x_{<t})$，它的目标是"生成看起来合理的文本"，而不是"说真话"。当它不知道答案时，仍会生成一个**统计上合理**的内容 —— 这就是幻觉的根源。

## 5.6 采样策略：怎么从概率分布里选词

模型输出的是**整个词表的概率分布**，怎么选下一个 token 直接决定了生成的风格。

### 5.6.1 Greedy（贪心）

```python
next_token = logits.argmax(-1)
```

**问题**：完全确定，每次生成相同结果，且容易陷入重复循环。

### 5.6.2 Temperature（温度）

$$p_i = \frac{\exp(z_i / T)}{\sum_j \exp(z_j / T)}$$

| $T$ | 效果 |
| --- | --- |
| $T \to 0$ | 退化成贪心（永远选最高概率） |
| $T = 1$ | 原始分布 |
| $T > 1$ | **分布变平**，低概率词也可能被选中 → 更有创意，也更容易胡说 |
| $T$ 很大 | 接近均匀随机 |

**直觉**：温度控制"冒险程度"。

| 场景 | 建议温度 |
| --- | --- |
| 代码生成、数学 | 0 ~ 0.3（要准确） |
| 日常对话 | 0.7 ~ 1.0 |
| 头脑风暴、写诗 | 1.0 ~ 1.5 |

### 5.6.3 Top-k

**只从概率最高的 k 个 token 里采样**，其余概率置零后重新归一化。

**问题**：k 是固定的。分布很"尖锐"时（模型很确定），k=50 会引入不该有的随机性；分布很"平"时，k=50 又可能切掉合理的选项。

### 5.6.4 Top-p（Nucleus Sampling，更好）

**按概率从高到低累加，直到累计概率超过 p，只保留这些 token。**

```
排序后的概率: [0.5, 0.3, 0.1, 0.05, 0.03, 0.02]
p = 0.9 时: 0.5+0.3+0.1 = 0.9 -> 只保留前 3 个
```

**优势**：**候选集大小自适应**。

- 模型很确定时（概率集中）→ 候选集自动变小；
- 模型不确定时（概率分散）→ 候选集自动变大。

**这是目前的主流做法**，通常配 `p=0.9~0.95`。

### 5.6.5 重复惩罚

$$z_i \leftarrow z_i / \theta \quad \text{(若 token } i \text{ 已出现过)}$$

**作用**：给已出现的 token 降权，缓解"复读机"现象。

**注意**：惩罚太强会导致语句不连贯（连正常的功能词"的、了"都不敢重复）。

## 5.6.6 实测：一个 2M 参数的小 GPT

案例代码用**本教程自己的 102 个 markdown 文件**（40 万字符，词表 1605）训练了一个 2.1M 参数的字符级 GPT：

| 配置 | 值 |
| --- | --- |
| 上下文长度 | 96 |
| 嵌入维度 / 头数 / 层数 | 192 / 6 / 4 |
| 训练步数 | 3000（batch 32） |
| 训练耗时 | 77 秒（GPU） |
| 参数量 | **2.1M**（对比 GPT-3：175,000M） |

**困惑度的变化**：

| 阶段 | 训练 loss | 验证 loss | 困惑度 |
| --- | --- | --- | --- |
| 初始（随机） | — | — | 1516（≈ 词表大小，等于瞎猜） |
| step 100 | 4.70 | 4.96 | 143 |
| step 3000 | **2.01** | **2.63** | **13.9** |

**生成结果**（提示词 `# Day1：`）：

| 采样策略 | 生成内容 |
| --- | --- |
| greedy | `梯度下降维  $$\boldsymbol{x} = \boldsymbol{x}_t - \boldsymbol{\mu` |
| temperature=1.0 | `因为什么 1.3 形式区分类以集  **进阶**  1. 用表示：**softmax 卷积是概率必须从"变化"后远邻"的` |
| **top_p=0.95 + t=0.8** | `什么是"移学习的闭式  > 今日目标：手写 SE 算 RatchNorm 的三种方法；掌握梯度下降低速度的实战：CLN` |

**三个值得注意的现象**：

1. **它学会了格式**：`$$\boldsymbol{x} = ...$$`、`**进阶**`、`> 今日目标：...` —— 这些**全部是教程自己的 markdown 结构**，模型从数据里把它们学了出来；
2. **greedy 容易陷入重复**：`$$\boldsymbol{x}_t = \boldsymbol{x}_i \boldsymbol{x}_...` —— 这正是 5.6.1 讲的问题，也是实际使用中要配 top-p 的原因；
3. **语义是乱的**：`RatchNorm`、`SE 算` —— 这是模型太小的必然结果。

> **但要看到重点**：**这个 2M 参数玩具的架构、训练目标、生成流程，与 GPT-4 完全同构，只是规模不同。**
>
> 这正是**缩放定律**（5.7.1）的意义 —— 同一个方法，规模放大几个数量级，就从小玩具变成了 ChatGPT。

**困惑度的直觉**：PPL = 13.9 意味着模型在每个位置平均在约 **14 个候选字符**之间犹豫（词表 1605）。对比瞎猜的 1516，它确实学到了不少结构。

> **注意 loss 的绝对值**：字符级预测的 loss 通常在 1.5~3，比图像任务高得多 —— 因为每个位置的候选有 1605 个，且文本本身的熵就很高。真实 LLM 用 BPE 词表（词汇更少），loss 会低一些。

## 5.7 能力从哪来：三个关键现象

### 5.7.1 缩放定律（Scaling Laws）

**Kaplan et al. (2020) / Chinchilla (2022) 的核心发现**：

$$\mathcal{L} \propto N^{-\alpha} \quad\text{（}N\text{：参数量、数据量、计算量）}$$

**这意味着**：损失随规模**平滑下降**，可以用小规模实验预测大规模效果。

**Chinchilla 的关键修正**：**参数量和训练数据量应该同比例增长**。

> GPT-3 有 1750 亿参数但只训练了 3000 亿 token —— **训练不足**。按 Chinchilla 的最优比例，它应该用 3.5 万亿 token。这也是后来 LLaMA 系列"更小的模型 + 更多数据"能超过 GPT-3 的原因。

### 5.7.2 涌现能力（Emergent Abilities）

**某些能力在小模型上几乎为零，超过某个规模后突然出现**：

- 多步算术
- 思维链推理
- 指令遵循
- 代码调试

> **注意**：这个现象有争议。有研究认为"涌现"部分是**评估指标的假象**（指标本身是阶跃函数），不是能力的突然出现。**这是当前活跃的研究话题，不要当作定论。**

### 5.7.3 上下文学习（In-Context Learning）

**不改任何参数**，只通过在提示里给几个例子，模型就能学会任务：

```
任务: 把英文翻译成中文

例子1: sea otter => 海獭
例子2: plum => 李子

现在: chestnut =>
      模型输出: 栗子
```

**这为什么重要**：

- 它是**提示工程**的基础；
- 它说明模型的能力**远超过 SFT 教的内容**；
- **对应用的启示**：先试提示，不行再微调。

## 5.8 从"能生成"到"能用"：RAG 与微调

**LLM 的三个固有限制**：

| 限制 | 表现 | 解决 |
| --- | --- | --- |
| **知识截止** | 不知道训练后的新信息 | **RAG**（检索增强） |
| **幻觉** | 编造看似合理的内容 | RAG + 引用来源 + 拒答 |
| **上下文有限** | 装不下大量文档 | RAG（只塞相关的几段） |

**RAG 的核心流程**（这就是你那份 agent 教程的主题）：

```
① 把文档切块 -> 用 Embedding 模型编码成向量 -> 存入向量库
② 用户提问 -> 编码成向量 -> 检索最相关的 k 个块
③ 把"检索到的内容 + 问题"一起塞进提示词 -> 让 LLM 基于这些内容回答
```

**RAG vs 微调的决策**：

| 需求 | 用 RAG | 用微调 |
| --- | --- | --- |
| **让模型知道新事实** | | 效果差（SFT 不善于灌知识） |
| **改变输出风格/格式** | 效果一般 | |
| **需要引用来源** | | 做不到 |
| 成本 | 低 | 高 |
| 更新速度 | 改数据即可 | 要重新训练 |

> **实践顺序**：**先提示工程 → 再 RAG → 最后才考虑微调。** 三者的成本差了一个数量级。

## 5.9 常见坑

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 生成重复循环 | 采样策略太确定 | 加 temperature / 重复惩罚 |
| 输出完全随机 | 温度太高 | 降到 0.7 以下 |
| 模型胡说八道 | 幻觉，或训练不足 | RAG；降温度；要求引用 |
| 微调后忘掉原有能力 | 灾难性遗忘 | 降学习率（LoRA + 小 lr） |
| 微调后没学到新知识 | SFT 不擅长灌事实 | 改用 RAG |
| 训练不收敛 | 忘了因果掩码 | 检查掩码方向（上三角 -inf） |
| 推理时越生成越慢 | 每次都重算整个序列 | 用 KV Cache |
| 中文效果差 | 词表压缩率低 | 换中文友好的 tokenizer |
