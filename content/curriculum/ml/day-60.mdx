## 5.2 演进主线

| 年份 | 架构 | 要解决的瓶颈 | 关键创新 |
| --- | --- | --- | --- |
| 1998 | **LeNet-5** | 手写数字识别 | 卷积 + 池化 + 全连接的基本骨架 |
| 2012 | **AlexNet** | 深网络难训练 + 数据规模 | ReLU / Dropout / GPU / 数据增强 |
| 2014 | **VGG** | 如何系统地设计更深网络 | **全部 3×3 堆叠 + 通道翻倍** |
| 2014 | **GoogLeNet** | 加深不够，算力有限 | Inception 多尺度并行 + 1×1 降维 |
| 2015 | **ResNet** | **深层网络退化** | **残差连接** |
| 2017 | DenseNet | 特征复用不足 | 密集连接 |
| 2017 | **MobileNet** | 移动端算力受限 | **深度可分离卷积** |

**参数量实测**（都适配 $28\times28$ 输入）：

| 架构 | 参数量 | 关键创新 |
| --- | --- | --- |
| LeNet-5 | 44,426 | 卷积+池化的基本骨架 |
| AlexNet | **8,089,546** | ReLU / Dropout / GPU / 加深 |
| VGG | 241,546 | 3×3 堆叠 + 通道翻倍 |
| ResNet | 204,682 | 残差连接 |

**注意 AlexNet 的参数量爆炸**：8M 参数里绝大部分在 `256×7×7 → 512` 这个全连接层（约 6.4M）。这也是后来**用 GAP 替代全连接**成为主流的直接原因。

## 5.3 VGG 的核心洞察：3×3 堆叠

**实测对比**（$C=64$ 通道）：

| 方案 | 参数量 | 非线性次数 | 感受野 |
| --- | --- | --- | --- |
| 1 个 5×5 | 102,400 | 1 | 5 |
| **2 个 3×3** | **73,728** | **2** | 5 |
| 1 个 7×7 | 200,704 | 1 | 7 |
| **3 个 3×3** | **110,592** | **3** | 7 |

**双重优势**：

- **参数更少**：2 个 3×3 比 1 个 5×5 省 28%；3 个 3×3 比 1 个 7×7 省 45%；
- **非线性更强**：多了一次 ReLU，表达能力提升。

这不是"差不多"的取舍，而是**在两个维度上同时更优**。所以 3×3 从此成为业界默认选择。

**VGG 的另一个贡献**：证明了**深度本身**是性能的来源。用同一套积木（3×3 + 池化 + 通道翻倍）反复堆叠，从 11 层堆到 19 层，精度持续提升。

**VGG 的代价**：参数量大（1.38 亿，其中大部分在全连接层）、计算量高。这也是 GoogLeNet 用 Inception 结构来"更高效地加深"的动机。

## 5.4 ResNet 的核心洞察：退化问题

### 一个被普遍误传的点

**很多人以为 ResNet 是为了解决梯度消失。这是一个常见的错误。**

ResNet 论文（He et al., 2015）明确指出了另一个现象：

> 在 20 层网络上继续加深到 56 层，**训练误差反而更高**。

注意：**训练误差**更高，不是验证误差更高。这意味着**不是过拟合，也不是梯度消失**（BN 已经解决了梯度问题），而是优化本身变难了。

**这就是"退化问题"（degradation problem）**。

### 残差怎么解决它

$$\boldsymbol{y} = \mathcal{F}(\boldsymbol{x}) + \boldsymbol{x}$$

**关键论证**：如果第 $l+1$ 层到第 $L$ 层学不到任何有用的东西，最差也应该学会"什么都不做"（恒等映射）。

- **无残差**：要让堆叠的层学出恒等映射 $\boldsymbol{y}=\boldsymbol{x}$，需要让权重精确地凑成单位矩阵 —— 这很难；
- **有残差**：只要让 $\mathcal{F}(\boldsymbol{x}) \to 0$（权重趋近 0 即可），就自动得到恒等映射。

**所以残差保证了"深网络至少不劣于浅网络"**，这让优化可以在"恒等"的基础上继续叠加改进。

### 实测验证

同一深度（10 个卷积层）、同一结构，唯一区别是有无残差连接：

| 结构 | 参数量 | 训练 loss | 验证 acc | 耗时 |
| --- | --- | --- | --- | --- |
| 无残差 (PlainDeep) | 482,314 | 0.0662 | 96.10% | 7.4s |
| **有残差 (ResNetLite)** | 482,314 | **0.0152** | **97.75%** | 7.5s |

**参数量完全相同，残差版本收敛更好、精度高 1.65 个百分点。**

而且注意**训练 loss 的差距（0.0662 vs 0.0152，差 4 倍多）远大于验证精度的差距** —— 这恰好印证了 ResNet 论文的说法：残差改善的主要是**优化**，不只是最终精度。

> **消融实验的纪律**：这里唯一变量就是残差连接，其他完全一致（同种子、同数据、同超参数）。这才叫"证明残差有用"。

## 5.5 迁移学习：工程上最实用的技能

### 核心思想

**在大数据集（ImageNet）上预训练的模型，已经学到了通用的视觉特征**（边缘、纹理、部件）。这些特征对新的视觉任务往往同样有用。

所以不必从随机初始化开始，而是"站在巨人的肩膀上"。

### 三步法

```python
# 第 1 步：改造结构以适配新任务
import torchvision
from torchvision.models import ResNet18_Weights

model = torchvision.models.resnet18(weights=ResNet18_Weights.DEFAULT)
model.conv1 = nn.Conv2d(1, 64, 3, stride=1, padding=1, bias=False)  # 单通道 + 不降采样
model.maxpool = nn.Identity()                                      # 28x28 太小
model.fc = nn.Linear(512, 10)                                      # 改成 10 类

# 第 2 步：冻结 backbone（但新加的层不能冻结！）
for p in model.parameters():
    p.requires_grad = False
for p in model.conv1.parameters():       # ★ 新加且随机初始化，必须训练
    p.requires_grad = True
for p in model.fc.parameters():          # ★ 新分类头，必须训练
    p.requires_grad = True

# 第 3 步：只训练新层
opt = torch.optim.AdamW([p for p in model.parameters() if p.requires_grad], lr=1e-3)
```

**实测**：总参数 11,172,810，可训练仅 **5,706（0.05%）**，3 个 epoch 达到 87.85% 验证准确率。

### 关于这个结果：一个重要的诚实说明

**87.85% 看起来不高，但这是"任务不匹配"造成的**：

| 数据集 | 特点 |
| --- | --- |
| ImageNet | 彩色自然图像（纹理、物体部件） |
| MNIST | 灰度笔画（结构极简） |

两者的底层特征差别很大，冻结的 ImageNet backbone 帮不上太多忙。

**真正适合迁移的场景是"源任务与目标任务同属自然图像"**：

- ImageNet → 猫狗分类
- ImageNet → 医学影像（X 光片、病理切片）
- ImageNet → 工业缺陷检测

那种情况下只训分类头，**几百张图就能到 95%+**。

> **用 MNIST 演示的原因**：数据现成、跑得快。但要理解这条结论的边界 —— **迁移学习不是万能的，它依赖任务相关性**。

### 三种迁移策略

| 情况 | 策略 | 学习率 |
| --- | --- | --- |
| 数据少 + 任务相似 | 冻结 backbone，只训分类头 | 分类头 1e-3 |
| 数据多 + 任务相似 | 解冻后几层一起微调 | backbone 1e-5 / head 1e-3 |
| 任务差异大 | 全部解冻 | 统一用很小的 lr（1e-5） |

**分层学习率的原理**（呼应 Week10 Day3）：

$$\text{backbone 已学好} \Rightarrow \text{大学习率会破坏它（灾难性遗忘）}$$

所以新分类头的学习率通常是 backbone 的 **10~100 倍**。

## 5.6 两个新手常见误区

### 误区 1：冻结了随机初始化的新层

```python
for p in model.parameters():
    p.requires_grad = False       # 全部冻结
for p in model.fc.parameters():
    p.requires_grad = True        # 只解冻 fc
# -> 如果 conv1 也换成了新的随机层，它就被永久冻在随机状态了！
```

**判断方法**：打印可训练参数量，看看是否包含所有"新加/改动过的层"。

### 误区 2：以为迁移学习一定要冻结

**冻结只是最省事的做法，不是唯一做法。** 数据量大时，全网络微调通常效果更好。冻结的目的是"防止小数据把预训练特征带偏"。

## 5.7 常见坑

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 迁移后精度还不如从头训 | 任务差异大 / 冻结层太多 | 解冻更多层，或从头训 |
| 精度一直不涨 | 冻结了随机初始化的新层 | 检查可训练参数列表 |
| 加载预训练权重形状不匹配 | 输入通道改了但没改第一层 | 显式替换 `conv1` |
| 微调后效果崩了 | backbone 学习率过大 | 分层 lr（backbone 1e-5） |
| 显存不够 | 用了 224×224 输入 | 缩小输入或减 batch |
| 小数据上微调过拟合 | 全部解冻 | 冻结 + 数据增强 |
