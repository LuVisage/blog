## 1.1 先问一个问题：模型到底是什么？

你用过 ChatGPT 网页版，也见过 DeepSeek 的 App。但在程序员的视角里，**模型就是一个函数**：

```
输入文字 ────────▶ [ 大模型 ] ────────▶ 输出文字
```

就这么简单。你发"你好"，它回"你好！有什么可以帮你"。**模型自己没有记忆、没有工具、不会上网**——它只会"接一段文字，吐一段文字"。所谓的"Agent 会思考、会用工具"，全是 LangChain/LangGraph 在模型外面搭的流程。

LangChain 把"这个函数"抽象成一个统一接口：**ChatModel（聊天模型）**。不管是 OpenAI、DeepSeek、智谱还是本地 Ollama，在你的代码里都是同一个类 `ChatOpenAI`（因为它们都说同一种"语言"——OpenAI 兼容协议），唯一的区别是三行配置：

```python
from langchain_openai import ChatOpenAI

model = ChatOpenAI(
    model="deepseek-chat",                       # 用哪个模型
    api_key="sk-xxxx",                           # 你的密钥
    base_url="https://api.deepseek.com",         # 模型服务地址（换厂商就换这行）
    temperature=0.7,                             # 0=严谨稳定  1=天马行空
)
```

> **temperature（温度）**：控制回答的随机性。0 表示每次都尽量给最确定的答案（适合调试、数学、代码）；0.7~1 表示更有创造性（适合写文案）。**调试期一律用 0**，这是老手的习惯。

## 1.2 消息系统：模型的"输入格式"

模型不只是吃一段纯文本。它的标准输入是一段**对话历史**——一个消息列表。就像你和它聊天时，它需要知道你之前说了什么、它自己说过什么。

LangChain 定义了 4 种消息（先记 4 个英文缩写，后面天天见）：

| 类 | 缩写 | 谁说的 | 用途 |
|---|---|---|---|
| `SystemMessage` | system | 开发者 | **系统提示词**：规定模型的角色、规则（"你是一个翻译官"） |
| `HumanMessage` | human | 用户 | 用户输入（"把'你好'翻成英文"） |
| `AIMessage` | ai | 模型 | 模型的回答（"Hello"） |
| `ToolMessage` | tool | 工具 | 工具执行后的结果（Day 5 详解，今天认识一下） |

```python
from langchain_core.messages import SystemMessage, HumanMessage, AIMessage

messages = [
    SystemMessage(content="你是一个中英翻译官，只输出译文，不要解释。"),
    HumanMessage(content="把'今天天气真好'翻译成英文。"),
]
result = model.invoke(messages)      # 模型返回一个 AIMessage
print(result.content)                # "The weather is really nice today."
```

**为什么必须是列表？** 因为"多轮对话"就是这么实现的：把整个历史每次都原样发给模型（模型是金鱼，转头就忘，所以要反复投喂）。Day 2 会专门讲怎么优雅地管理这个列表。

## 1.3 调用模型的三种姿势

LangChain 每个组件都有三种调用方式，**从今天开始成为肌肉记忆**：

| 方式 | 行为 | 什么时候用 |
|---|---|---|
| `invoke(输入)` | 同步调用，阻塞等待完整结果 | 脚本、批处理、简单程序 |
| `ainvoke(输入)` | 异步调用，返回协程，`await` 取结果 | 高并发服务、FastAPI 后端 |
| `stream(输入)` | 流式调用，逐字吐出 | 聊天界面打字机效果（必学！） |

### ① invoke：最基础

```python
result = model.invoke("用一句话介绍北京")     # 传字符串也可以，自动转 HumanMessage
print(type(result).__name__)                 # AIMessage
print(result.content)                        # 北京的介绍……
```

### ② stream：打字机效果

```python
for chunk in model.stream("用 50 个字介绍西湖"):
    print(chunk.content, end="", flush=True)   # 不换行、立即刷新 → 逐字打印
```

`stream` 返回的是一个**迭代器**，模型每生成一小段（chunk），你的循环就收到一小段。这就是 ChatGPT 那种"一个字一个字蹦出来"效果的实现原理。第 8 周做聊天界面时，这个能力会通过网络实时推给浏览器。

### ③ ainvoke：异步

```python
import asyncio

async def main():
    result = await model.ainvoke("异步地问我一个问题")
    print(result.content)

asyncio.run(main())
```

> **坑：`await` 只能写在 `async` 函数里，且要用 `asyncio.run()` 启动。** 初学者最常见的报错 `SyntaxError: 'await' outside function` 就是这么来的。今天能看懂就行，第 8 周做后端时会大量使用。

## 1.4 高手都在看的隐藏信息：token 用量

每次调用模型都花钱。钱按 **token（词元）** 算——大约 1 个汉字 ≈ 1~2 token。模型返回的 `AIMessage` 里藏着账单：

```python
result = model.invoke("你好")
print(result.usage_metadata)
# {'input_tokens': 8, 'output_tokens': 9, 'total_tokens': 17}
```

| 字段 | 含义 |
|---|---|
| `input_tokens` | 你发给模型的（含历史对话、系统提示词）→ **输入越啰嗦越贵** |
| `output_tokens` | 模型生成的 |
| `total_tokens` | 两者之和，乘以单价就是这次调用花的钱 |

> **为什么重要？** ① Agent 循环会反复调用模型，input 里堆满历史，token 会滚雪球（Day 23 的"摘要中间件"就是治这个的）；② 第 6 周 LangSmith 会把这些账单可视化，一眼看出哪个环节最烧钱。

### `day01_hello_chat.py` —— 一个模型，三种厂商

```python
"""Day 1 案例 1：接入 LLM（DeepSeek / 智谱 / 本地 Ollama 三选一）"""
import os
from pathlib import Path
from dotenv import load_dotenv

# 定位教程根目录的 .env 并加载（examples/ 目录向上两级）
env_file = Path(__file__).resolve().parents[2] / ".env"
load_dotenv(env_file)

from langchain_openai import ChatOpenAI

# ── 方式一：DeepSeek（推荐，默认使用）────────────
model = ChatOpenAI(
    model=os.environ["LLM_MODEL"],       # deepseek-chat
    api_key=os.environ["LLM_API_KEY"],
    base_url=os.environ["LLM_BASE_URL"], # https://api.deepseek.com
    temperature=0,
)

# ── 方式二：智谱（想切换时，注释掉上面，打开下面）────────────
# model = ChatOpenAI(
#     model="glm-4-plus",
#     api_key="你的智谱key",
#     base_url="https://open.bigmodel.cn/api/paas/v4",
#     temperature=0,
# )

# ── 方式三：本地 Ollama（免费，需先 ollama pull qwen2.5:7b）──
# model = ChatOpenAI(
#     model="qwen2.5:7b",
#     api_key="ollama",                          # Ollama 不需要真 key，随便填
#     base_url="http://localhost:11434/v1",
#     temperature=0,
# )

result = model.invoke("用一句话介绍你自己，并说出你能做什么、不能做什么。")
print("回答：", result.content)
print("花费 token：", result.usage_metadata["total_tokens"])
```

**逐行要点**：

- `Path(__file__).resolve().parents[2]`：`__file__` 是当前脚本路径，`parents[2]` 往上两级 = `agent-tutorial/`，拼上 `.env`。这样**无论你在哪个目录运行脚本都能找到配置**。
- 三种方式本质相同，只是 `base_url` 不同——这就是"OpenAI 兼容协议"的威力：**换模型 = 换配置，代码零改动**。
- `usage_metadata` 是字典，`["total_tokens"]` 取账单。

### `day01_stream.py` —— 打字机效果

```python
"""Day 1 案例 2：流式输出（打字机效果）"""
import os, time
from pathlib import Path
from dotenv import load_dotenv
load_dotenv(Path(__file__).resolve().parents[2] / ".env")

from langchain_openai import ChatOpenAI

model = ChatOpenAI(
    model=os.environ["LLM_MODEL"],
    api_key=os.environ["LLM_API_KEY"],
    base_url=os.environ["LLM_BASE_URL"],
    temperature=0,
)

print("开始流式输出：\n")
start = time.time()
for chunk in model.stream("用 100 个字介绍杭州西湖"):
    print(chunk.content, end="", flush=True)   # end="" 不换行；flush=True 立即显示
print(f"\n\n耗时 {time.time() - start:.2f} 秒")
```

**逐行要点**：

- `for chunk in model.stream(...)`：`stream` 返回迭代器，每次给一小段文本。
- `end=""`：`print` 默认会换行，传空字符串让它不换行；`flush=True`：Python 的输出有缓冲，不 flush 的话要攒一大段才显示，就没有"打字机"效果了。
- `time.time()` 前后打点，可以直观对比：**流式拿到的"第一个字"比 invoke 拿"完整回答"快得多**，这就是所有聊天产品必须流式的原因。

### `day01_messages.py` —— 手动搭建对话

```python
"""Day 1 案例 3：4 种消息类型与多轮对话的真相"""
import os
from pathlib import Path
from dotenv import load_dotenv
load_dotenv(Path(__file__).resolve().parents[2] / ".env")

from langchain_openai import ChatOpenAI
from langchain_core.messages import SystemMessage, HumanMessage, AIMessage

model = ChatOpenAI(
    model=os.environ["LLM_MODEL"],
    api_key=os.environ["LLM_API_KEY"],
    base_url=os.environ["LLM_BASE_URL"],
    temperature=0,
)

# 第 1 轮对话
history = [
    SystemMessage(content="你是一个只会说四川话的助手。"),
    HumanMessage(content="你好呀"),
]
reply = model.invoke(history)
print("第1轮回答：", reply.content)          # （四川话）你好哟~
history.append(reply)                        # 把模型的回答也塞进历史！

# 第 2 轮对话：把【完整历史】再次发送 —— 这就是"多轮对话"的全部秘密
history.append(HumanMessage(content="我刚说的第一句话是啥子？"))
reply2 = model.invoke(history)
print("第2轮回答：", reply2.content)         # 模型能"记得"，因为历史就在 input 里

# 看看第 2 轮真正发给模型的东西
print("\n第 2 轮实际发送的消息列表：")
for m in history:
    print(f"  [{m.type:6s}] {m.content[:40]}")
print("\n总花费 token：", reply2.usage_metadata["total_tokens"])
```

**逐行要点**：

- 第一轮后 `history.append(reply)`——把 `AIMessage` 追加进历史。**漏掉这步，模型就"失忆"**（它根本没收到过自己的回答）。
- 第二轮再次 `invoke(history)`，把整个列表重发。列表越来越长 → input token 越来越多 → 越来越贵。这就是"记忆管理"（Day 24）要解决的问题的源头。
- `m.type` 是每条消息的类型字符串（`system`/`human`/`ai`/`tool`），打印出来你能直观看到模型的"视野"。
