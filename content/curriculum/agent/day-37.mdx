## 37.1 前端项目的骨架（先看懂再动手）

昨天 `create-agent-chat-app` 生成的项目，核心文件只有几个：

```
agent-chat-ui/
├── src/
│   ├── app/
│   │   ├── layout.tsx          # 页面骨架（侧边栏 + 聊天区）
│   │   └── page.tsx            # 主页面：聊天主逻辑（今天主战场）
│   │   └── api/chat/route.ts   # 后端代理：前端 ←SSE→ LangGraph Server
│   ├── components/
│   │   └── ...                 # 消息组件、侧边栏等
│   └── lib/
│       └── types.ts            # 类型定义
├── .env                        # 前端配置（指向 LangGraph Server）
└── package.json
```

**数据流**（对比 Day 36 的架构图）：

```
浏览器 page.tsx ──useChat──▶ api/chat/route.ts ──HTTP──▶ LangGraph Server ──▶ 你的 Agent
        ▲                        （Next.js 后端路由）
        └────────────── SSE 流式响应 ◀──────────────────────┘
```

`api/chat/route.ts` 是 Next.js 的**后端代理**（BFF 模式）：浏览器不直连 LangGraph Server，而是经过 Next.js 转手——**生产上这是标准做法**（统一鉴权、隐藏内部服务）。

## 37.2 定制一：展示 Agent 的工具调用（今天的重头戏）

用户想看到"Agent 正在查天气"的中间过程。默认模板已自带此能力，但要**看懂原理**。打开 `page.tsx`，找到 `useChat` 的调用：

```tsx
const { messages, input, handleInputChange, handleSubmit, ... } = useChat({
  api: "/api/chat",
  // ...
});
```

`useChat` 是 AI SDK 的 React Hook——它自动处理 SSE 流、消息列表、输入框状态。**Agent 的工具调用过程**藏在消息的 `parts` 里（AI SDK 的消息分块：text / tool-invocation）：

```tsx
{messages.map((message) => (
  <div key={message.id}>
    {message.parts.map((part, i) => {
      if (part.type === "tool-invocation") {
        // ★ 工具调用块：显示"正在调用 get_weather(北京)"
        return <ToolCall key={i} part={part} />;   // 模板内置组件
      }
      return <Markdown key={i}>{part.text}</Markdown>;   // 普通文本块
    })}
  </div>
))}
```

**理解**：后端流里不仅有模型回答，还有工具调用事件（Day 21 你在终端打印的那些）——前端把它们渲染成"工具卡片"。**界面上的智能感，就是把这些中间过程可视化。**

> 把 `page.tsx` 里这段代码找到、读懂、改点样式（如给 ToolCall 加个颜色），你就完成了第一次前端定制。

## 37.3 定制二：多会话切换（thread_id 的前端化）

Day 19 你知道了 thread_id 是会话隔离的钥匙。在 UI 里，它化身"侧边栏的历史会话列表"：

- 点"新建会话" → 前端生成新 thread_id → 后续消息都带它 → 后端该会话的记忆独立；
- 点历史会话 → 用旧 thread_id 继续 → **恢复之前的上下文**。

在 `page.tsx` 里，thread_id 通常这样传给 useChat：

```tsx
const [threadId, setThreadId] = useState<string | null>(null);

useChat({
  api: "/api/chat",
  body: { threadId },          // ★ 每次请求带上当前会话 id
});
```

**这就是 Day 19 的 thread_id 在真实产品里的位置**：前端状态 → 请求 body → Next.js 代理 → LangGraph Server 的 thread 参数。前后贯通了。

## 37.4 定制三：把业务参数传给 Agent（config 传递）

真实产品常需要"这个会话用哪个知识库/什么角色"。LangGraph Server 的 API 支持传 config，前端这样带：

```tsx
useChat({
  api: "/api/chat",
  body: {
    threadId,
    configurable: { user_id: "u-123", role: "vip" },   // ★ 自定义配置
  },
});
```

后端 Agent 里怎么用？还记得 Day 24 的 `InjectedState`/config 注入吗——在 Agent 图里读 `config["configurable"]` 就能拿到 `user_id`/`role`，用于：

- 记忆命名空间按用户隔离（Day 24 自测 4 的答案）；
- 切换知识库（不同用户查不同 Milvus 集合，Day 13 的过滤条件）；
- LangSmith metadata 打标（Day 26）。

**前后端配置通道 = configurable 字典**。今天先在代码里找到这个管道，毕业项目会真正用上。
