## 一、两者定位

| 维度 | Nginx | Caddy |
| --- | --- | --- |
| 定位 | 高性能、成熟的 Web 服务器/反向代理 | 现代、自动 HTTPS 的 Web 服务器 |
| 配置 | 自有 DSL（nginx.conf） | Caddyfile（极简） |
| HTTPS | 需手动配证书/Let's Encrypt 脚本 | **自动申请与续期** |
| 性能 | 业界标杆 | 够用（Go 编写） |
| 生态 | 极丰富（模块、教程、云厂商） | 快速增长 |
| 适合 | 大型生产、复杂路由、已有沉淀 | 小团队/个人服务器、图省事 |

**一句话**：需要自动 HTTPS、配置简单 → Caddy；需要复杂路由与高性能调优 → Nginx。

## 二、Nginx 使用

### 安装（服务器上）

```bash
# Ubuntu/Debian
sudo apt update && sudo apt install nginx
sudo systemctl enable --now nginx

# 检查配置
sudo nginx -t
sudo systemctl reload nginx
```

Windows 可下载 zip 解压运行（开发测试用）。

### 静态网站

```nginx
server {
    listen 80;
    server_name example.com;
    root /var/www/html;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;   # SPA 路由回退（关键）
    }

    location ~* \.(js|css|png|jpg|svg|woff2)$ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }
}
```

### 反向代理

```nginx
server {
    listen 80;
    server_name api.example.com;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade $http_upgrade;      # WebSocket
        proxy_set_header Connection "upgrade";
    }
}
```

### 前端 + 后端同域（避免 CORS）

```nginx
server {
    listen 80;
    server_name app.example.com;

    root /var/www/frontend;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8080/;    # 末尾斜杠会去掉 /api 前缀（按需）
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

### HTTPS（Let's Encrypt）

```bash
sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d example.com -d www.example.com
sudo systemctl status certbot.timer    # 自动续期
```

生成的配置可参考 `/etc/letsencrypt/live/example.com/`。

### 常用命令

```bash
sudo nginx -t                 # 测试配置语法
sudo nginx -s reload          # 热重载
sudo systemctl restart nginx
tail -f /var/log/nginx/access.log
tail -f /var/log/nginx/error.log
```

### 负载均衡

```nginx
upstream api_servers {
    least_conn;
    server 10.0.0.1:3000 weight=3;
    server 10.0.0.2:3000;
    server 10.0.0.3:3000 backup;
}

server {
    location / {
        proxy_pass http://api_servers;
    }
}
```

### 限流与压缩

```nginx
# 压缩
gzip on;
gzip_types text/plain text/css application/json application/javascript image/svg+xml;
gzip_min_length 1024;

# 限流：每 IP 每秒 10 个请求
limit_req_zone $binary_remote_addr zone=api:10m rate=10r/s;
location /api/ {
    limit_req zone=api burst=20 nodelay;
    proxy_pass http://127.0.0.1:8080;
}
```

## 三、Caddy 使用

### 安装

```bash
# Ubuntu
sudo apt install -y debian-keyring debian-archive-keyring apt-transport-https
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | sudo gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
sudo apt install caddy

# macOS
brew install caddy
# Windows
winget install CaddyServer.Caddy
```

### Caddyfile 基础

```
example.com {
    root * /var/www/html
    file_server
    try_files {path} /index.html       # SPA
    encode gzip

    handle /api/* {
        reverse_proxy 127.0.0.1:8080
    }
}
```

就这么多——**HTTPS 证书自动申请、自动续期**，无需任何额外配置。

### 常见配置

```caddy
# 本地开发（自动用内部证书，local 域名走 https）
localhost {
    reverse_proxy 127.0.0.1:5173
}

# 多域名 + 重定向
example.com, www.example.com {
    redir https://example.com{uri} permanent
}

# 反向代理 + 负载均衡
api.example.com {
    reverse_proxy 10.0.0.1:3000 10.0.0.2:3000 {
        lb_policy round_robin
        health_uri /healthz
    }
}

# 静态文件 + 缓存头
static.example.com {
    root * /srv/static
    file_server
    header Cache-Control "public, max-age=31536000, immutable"
}

# 基础认证
admin.example.com {
    basicauth {
        admin $2a$14$...   # caddy hash-password 生成
    }
    reverse_proxy 127.0.0.1:9000
}

# 日志
example.com {
    log {
        output file /var/log/caddy/access.log
        format json
    }
    reverse_proxy 127.0.0.1:8080
}
```

### 常用命令

```bash
caddy run                      # 前台运行
caddy start / stop
caddy reload --config Caddyfile    # 热重载
caddy validate --config Caddyfile  # 校验
caddy fmt --overwrite Caddyfile    # 格式化配置
caddy adapt                        # 转换为 JSON 配置（排错）
caddy hash-password                # 生成密码哈希
```

### 作为系统服务

```bash
sudo systemctl enable --now caddy
# 配置放 /etc/caddy/Caddyfile
```

## 四、配置模板：典型单机部署

### 方案 A：Caddy（推荐小团队）

```caddy
app.example.com {
    encode gzip
    reverse_proxy web:3000 api:8080
}
```

用 docker compose 时 Caddy 与服务同网络，直接写服务名。

### 方案 B：Nginx

```nginx
server {
    listen 443 ssl http2;
    server_name app.example.com;
    ssl_certificate     /etc/letsencrypt/live/app.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/app.example.com/privkey.pem;

    location / {
        proxy_pass http://web:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
    location /api/ {
        proxy_pass http://api:8080/;
        proxy_set_header Host $host;
    }
}
server {
    listen 80;
    server_name app.example.com;
    return 301 https://$host$request_uri;
}
```

## 五、常见问题

| 问题 | 解决 |
| --- | --- |
| 配置改完没生效 | `nginx -t` 校验 → `reload`；Caddy 用 `caddy reload` |
| 502 Bad Gateway | 后端未启动/端口错/容器名错；查 error.log |
| 404 但文件存在 | 权限（www-data 需可读）、root 路径错 |
| SPA 刷新 404 | 加 `try_files $uri /index.html` |
| WebSocket 连不上 | Nginx 需 Upgrade/Connection 头；Caddy 默认支持 |
| HTTPS 证书申请失败 | 80/443 端口被占、DNS 未解析、防火墙拦截 |
| 中文/大文件上传 413 | Nginx `client_max_body_size 50m;` |
| Caddy 自动 HTTPS 在测试环境 | 用 `localhost` 或 `{file_server}`；或配 `tls internal` |
