## 一、Git 是什么

Git 是最流行的**分布式版本控制系统**，用于记录代码的每一次变更、支持多人并行开发、随时回退到任意历史版本。

核心模型（四个区域）：

```
工作区（Working Directory） --git add--> 暂存区（Staging） --git commit--> 本地仓库（Repository） --git push--> 远程仓库（Remote）
```

## 二、安装与初始配置

### 安装

```powershell
# Windows（任选其一）
winget install --id Git.Git -e
# 或 scoop install git / choco install git

# macOS
brew install git

# Linux（Debian/Ubuntu）
sudo apt update && sudo apt install git
```

安装后在 PowerShell 中验证：

```powershell
git --version   # git version 2.x.x
```

### 首次配置（必做）

```powershell
git config --global user.name "你的名字"
git config --global user.email "you@example.com"
git config --global init.defaultBranch main        # 新仓库默认分支用 main
git config --global core.autocrlf true             # Windows 推荐，自动转换换行符
git config --global pull.rebase true               # pull 时使用 rebase，保持历史线性
```

国内加速与常用增强：

```powershell
git config --global core.quotepath false           # 中文文件名不转义
git config --global alias.st status                # 设置别名
git config --global alias.lg "log --oneline --graph --decorate --all"
```

查看配置：`git config --list --show-origin`。

## 三、日常开发工作流

### 1. 创建/克隆仓库

```powershell
git init myapp                    # 在当前目录初始化
git clone https://github.com/user/repo.git
git clone git@github.com:user/repo.git   # SSH 方式（推荐，免密）
```

### 2. 查看状态与差异

```powershell
git status                # 当前文件状态
git diff                  # 工作区 vs 暂存区
git diff --staged         # 暂存区 vs 最后一次提交
git diff HEAD~1 HEAD      # 最近两次提交之间的差异
```

### 3. 提交

```powershell
git add file.txt          # 添加单个文件
git add .                 # 添加所有改动
git commit -m "feat: 新增登录接口"
git commit -am "fix: 修改拼写"   # 跳过 add（仅对已跟踪文件有效）
```

提交信息规范推荐 [Conventional Commits](https://www.conventionalcommits.org/)：

| 前缀 | 用途 |
| --- | --- |
| `feat:` | 新功能 |
| `fix:` | 修复 Bug |
| `docs:` | 文档变更 |
| `refactor:` | 重构（无行为变化） |
| `test:` | 测试相关 |
| `chore:` | 构建/工具/依赖杂项 |

### 4. 分支

```powershell
git branch                      # 列出本地分支
git switch -c feature/login     # 新建并切换分支（推荐）
git switch main                 # 切回 main
git merge feature/login         # 合并分支到当前分支
git branch -d feature/login     # 删除已合并分支
git branch -D feature/login     # 强制删除
```

### 5. 远程协作

```powershell
git remote add origin git@github.com:user/repo.git
git remote -v                   # 查看远程地址
git push -u origin main         # 首次推送并建立追踪
git pull                        # 拉取并合并
git fetch --prune               # 拉取远程分支信息并清理已删除分支
```

## 四、后悔药：撤销与回退

```powershell
# 工作区改动想丢弃
git restore file.txt

# 暂存区内容想撤回（保留工作区改动）
git restore --staged file.txt

# 修改最后一次提交（消息或漏掉的文件）
git add forgotten.txt
git commit --amend

# 回退到某个历史版本（保留改动到工作区）
git reset --soft HEAD~1

# 彻底回退（危险！会丢失未提交内容）
git reset --hard HEAD~1

# 安全撤销远程已推送的提交（生成反向提交，不改写历史）
git revert <commit-hash>
```

> 原则：**已推送的公共分支不要用 `reset --hard` + `push -f` 改写历史**，用 `revert`。

## 五、进阶技巧

### stash 临时保存

```powershell
git stash                # 暂存当前未提交改动
git stash list
git stash pop            # 恢复并删除最近一次 stash
git stash apply stash@{2}
```

### rebase 变基

```powershell
git switch feature/login
git rebase main          # 把本分支提交"搬"到 main 最新提交之后
```

交互式 rebase（合并多个提交、修改历史消息）：

```powershell
git rebase -i HEAD~3
# 编辑器中把 pick 改为 squash / reword / drop 等
```

### cherry-pick 挑单个提交

```powershell
git cherry-pick <commit-hash>    # 把指定提交复制到当前分支
```

### 定位问题提交

```powershell
git bisect start
git bisect bad                   # 当前版本有问题
git bisect good v1.0.0           # 这个版本是好的
# 按提示测试每次 checkout 的版本，标记 good/bad，直到定位到问题提交
git bisect reset
```

### 查看历史

```powershell
git log --oneline --graph --decorate --all
git log -p file.txt              # 查看某文件每次改动内容
git blame file.txt               # 每行代码最后修改人/提交
git show <commit-hash>           # 查看某次提交详情
```

## 六、配置 SSH 免密（推荐）

```powershell
ssh-keygen -t ed25519 -C "you@example.com"     # 一路回车，默认存 ~/.ssh/id_ed25519.pub
Get-Content ~/.ssh/id_ed25519.pub | clip       # Windows 复制公钥
```

把公钥粘贴到 GitHub → Settings → SSH and GPG keys → New SSH key，然后测试：

```powershell
ssh -T git@github.com    # 输出 "Hi user! You've successfully authenticated" 即成功
```

## 七、`.gitignore` 常用模板

```gitignore
node_modules/
dist/
.env
.env.local
*.log
.DS_Store
.idea/
.vscode/*
!.vscode/settings.json
coverage/
```

规则：`/dir` 只忽略根目录；`**/dir` 任意层级；`!pattern` 表示不忽略。

## 八、常见问题排查

| 问题 | 解决思路 |
| --- | --- |
| `fatal: refusing to merge unrelated histories` | `git pull origin main --allow-unrelated-histories` |
| 推送提示 `non-fast-forward` | 先 `git pull --rebase`，再 push |
| 提交了不该提交的文件 | `git rm --cached secret.env` 后加入 `.gitignore` |
| 误删分支想找回 | `git reflog` 找到 hash，再 `git branch recover <hash>` |
| 中文乱码（Windows） | `git config --global core.quotepath false`，终端设为 UTF-8 |
| 换行符警告 LF/CRLF | `git config --global core.autocrlf true` |

## 九、最佳实践

1. **小步提交**：一次提交只做一件事，便于 review 和回滚。
2. **分支命名规范**：`feature/xxx`、`fix/xxx`、`hotfix/xxx`。
3. **每日同步**：开工前 `git pull --rebase`，减少冲突。
4. **提交前自查**：`git status` + `git diff --staged`，确认没有误提交密钥、调试代码。
5. **善用 PR/MR**：所有改动走 Pull Request，至少一人 review 后合并。
