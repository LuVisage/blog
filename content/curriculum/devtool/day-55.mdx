## 一、为什么需要任务运行器

项目一复杂，命令就变长：

```powershell
docker compose -f docker-compose.dev.yml up -d && pnpm --filter api migrate && pnpm --filter api dev
```

任务运行器把这些封装成 `make dev` / `just dev` / `task dev`，让**命令可复用、可组合、可文档化**。

## 二、Make

最古老、几乎所有系统都有的构建工具。用 `Makefile` 定义「目标 + 依赖 + 命令」。

### 基本语法

```makefile
.PHONY: install dev build test lint clean

install:
	pnpm install

dev: install
	pnpm dev

build: install
	pnpm build

test:
	pnpm test

lint:
	pnpm lint

clean:
	rm -rf dist node_modules
```

> **注意**：命令前必须是 **Tab**，不是空格。

### 使用

```powershell
make build
make dev
make          # 默认第一个目标
make -j4      # 并行执行
make -n build # 只打印将执行的命令
```

### 变量与参数

```makefile
IMAGE ?= myapp
TAG ?= latest

docker-build:
	docker build -t $(IMAGE):$(TAG) .
```

```powershell
make docker-build TAG=v1.0
```

### 优缺点

- 优点：无需安装、跨语言、依赖图成熟；
- 缺点：语法古怪（Tab、shell 差异）、Windows 上需借助 Git Bash/WSL。

Windows 安装：

```powershell
winget install GnuWin32.Make
# 或 choco install make
```

## 三、Just

Just 是「现代版 Make」：语法清晰、默认并行、跨平台，专注做**命令别名与参数化**，不像 Make 那么在意文件时间戳。

### 安装

```powershell
winget install Casey.Just
# macOS
brew install just
```

### 基本用法

`justfile`：

```makefile
# 列出所有配方
default:
    @just --list

# 安装依赖
install:
    pnpm install

# 启动开发环境（依赖 install）
dev: install
    pnpm dev

# 构建，支持参数
build target="all":
    pnpm build {{target}}

# 带说明的配方
test:
    echo "运行测试"
    pnpm test
```

```powershell
just               # 执行 default
just dev
just build
just build web     # 传参
just --list        # 列出所有命令
```

### 特色功能

- **参数与默认值**，无需环境变量 hack；
- **`@` 前缀**隐藏命令回显；
- 支持 **shebang 脚本**、多种 Shell；
- 跨平台（Windows 原生支持）；
- `just --choose`（配合 fzf）交互式选择命令。

## 四、Task（Taskfile）

Go 编写的任务运行器，YAML 配置，支持依赖、变量、环境变量、文件监视。

### 安装

```powershell
winget install Task.Task
# 或 scoop install task / choco install go-task
```

### Taskfile.yml

```yaml
version: '3'

vars:
  APP: myapp
  VERSION:
    sh: git describe --tags --always

tasks:
  default:
    desc: 列出所有任务
    cmds:
      - task --list

  install:
    desc: 安装依赖
    cmds:
      - pnpm install

  dev:
    desc: 启动开发
    deps: [install]
    cmds:
      - pnpm dev

  build:
    desc: 构建
    cmds:
      - pnpm build
    sources:
      - src/**/*
    generates:
      - dist/**

  test:
    desc: 运行测试
    cmds:
      - pnpm test

  clean:
    desc: 清理产物
    cmds:
      - rm -rf dist
    status:
      - test ! -d dist     # 条件：dist 不存在则跳过
```

```powershell
task             # 执行 default
task build
task --list      # 列出所有任务及描述
task build VERSION=1.0.0
task --watch build   # 文件变化自动重跑
```

### 特色功能

- `sources` / `generates`：**基于文件变更决定是否重跑**（类 Make 的增量）；
- `deps` / `cmds`：任务依赖与并行；
- `status`：自定义跳过条件；
- `dotenv`：加载 `.env` 文件；
- 跨平台（Linux/macOS/Windows 二进制）。

## 五、三者对比

| 维度 | Make | Just | Task |
| --- | --- | --- | --- |
| 配置格式 | Makefile | justfile | YAML |
| 学习曲线 | 陡（历史包袱） | 平缓 | 平缓 |
| Windows 支持 | 一般（需额外安装） | 好 | 好 |
| 增量构建（文件时间戳） | 强 | 弱 | 有（sources） |
| 参数传递 | 环境变量为主 | 原生参数 | 变量 |
| 依赖编排 | 强 | 中 | 强 |
| 最适合 | C/系统项目、通用构建 | 日常命令封装 | 现代多语言项目 |

## 六、如何选择

- 团队全是 Windows + Node/Python 项目 → **Task** 或 **Just**；
- 已有 Makefile 历史 / C/C++ 项目 → **Make**；
- 只想用最少的语法封装 20 个常用命令 → **Just**。

## 七、常见问题

| 问题 | 解决 |
| --- | --- |
| Make 报 `missing separator` | 命令行前用了空格，改成 Tab |
| Make 在 Windows 中文乱码 | 用 WSL2 或 Git Bash 执行 |
| Just 参数为空 | 用默认值 `param="default"`，或 `{{param}}` 前判断 |
| Task 任务没有重跑 | 检查 `status` / `sources` 条件是否误判 |
| 命令里的 `$` 被展开 | Make 中用 `$$` 转义；Just 中脚本用 `#!/usr/bin/env bash` 块 |
