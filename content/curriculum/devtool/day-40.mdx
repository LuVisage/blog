## 一、为什么用调试器

`console.log` 只能看「结果」，调试器可以：
- 在任意位置**暂停**程序；
- 查看**完整作用域变量**；
- **单步执行**，追踪逻辑分支；
- 修改运行时变量值再继续。

## 二、核心配置：launch.json

位置：`.vscode/launch.json`（按 `F5` 时自动创建）。

```jsonc
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Debug Node (当前文件)",
      "type": "node",
      "request": "launch",
      "program": "${file}",
      "console": "integratedTerminal",
      "skipFiles": ["<node_internals>/**"]
    }
  ]
}
```

### 变量占位符

| 变量 | 含义 |
| --- | --- |
| `${file}` | 当前打开文件 |
| `${workspaceFolder}` | 项目根目录 |
| `${fileBasename}` | 文件名（含扩展名） |
| `${command:pickNodeProcess}` | 交互式选择进程 |

## 三、调试 Node.js

### 普通脚本

```jsonc
{
  "name": "Debug Script",
  "type": "node",
  "request": "launch",
  "program": "${workspaceFolder}/src/index.ts",
  "outFiles": ["${workspaceFolder}/dist/**/*.js"],
  "sourceMaps": true,
  "env": { "NODE_ENV": "development" },
  "args": ["--port", "3000"]
}
```

TypeScript 项目需 `ts-node` 或 sourcemap：

```jsonc
{
  "type": "node",
  "request": "launch",
  "runtimeArgs": ["-r", "ts-node/register"],
  "args": ["${workspaceFolder}/src/index.ts"]
}
```

或使用 `tsx`：

```jsonc
{ "runtimeExecutable": "npx", "runtimeArgs": ["tsx", "src/index.ts"] }
```

### 附加到已运行进程

```jsonc
{
  "name": "Attach to Node",
  "type": "node",
  "request": "attach",
  "port": 9229,
  "restart": true
}
```

启动时加 `--inspect=9229`：

```powershell
node --inspect=9229 dist/server.js
```

### 调试 jest / vitest

```jsonc
{
  "name": "Debug Vitest",
  "type": "node",
  "request": "launch",
  "runtimeExecutable": "npx",
  "runtimeArgs": ["vitest", "run", "${file}"],
  "console": "integratedTerminal",
  "autoAttachChildProcesses": true
}
```

### 调试内置 npm script

VS Code 会自动探测 `package.json` 的 scripts，在左侧 **Run and Debug** 面板可直接选 `npm: dev`（需 `"type": "node-terminal"` 配置才可断点）。

## 四、调试浏览器（Chrome）

```jsonc
{
  "name": "Debug Chrome",
  "type": "chrome",
  "request": "launch",
  "url": "http://localhost:5173",
  "webRoot": "${workspaceFolder}/src",
  "sourceMaps": true
}
```

需安装 VS Code 扩展 **Debugger for Chrome**（现已内置 JS Debugger）。这样可以在 VS Code 里打断点调试前端代码，无需切浏览器 DevTools。

## 五、调试 Python

装扩展 **Python** + 用 `debugpy`：

```jsonc
{
  "name": "Python: 当前文件",
  "type": "debugpy",
  "request": "launch",
  "program": "${file}",
  "console": "integratedTerminal",
  "justMyCode": false,
  "env": { "PYTHONPATH": "${workspaceFolder}" }
}
```

调试 FastAPI / Flask：

```jsonc
{
  "name": "FastAPI",
  "type": "debugpy",
  "request": "launch",
  "module": "uvicorn",
  "args": ["app.main:app", "--reload", "--port", "8000"],
  "jinja": true
}
```

附加到运行中的进程：

```jsonc
{ "type": "debugpy", "request": "attach", "connect": { "host": "localhost", "port": 5678 } }
```

## 六、调试 Go

装扩展 **Go**：

```jsonc
{
  "name": "Debug Go",
  "type": "go",
  "request": "launch",
  "mode": "auto",
  "program": "${workspaceFolder}/cmd/server"
}
```

远程调试：

```jsonc
{
  "name": "Go Attach",
  "type": "go",
  "request": "attach",
  "mode": "remote",
  "remotePath": "/app",
  "port": 40000,
  "host": "127.0.0.1"
}
```

## 七、断点类型与技巧

| 类型 | 用法 |
| --- | --- |
| 普通断点 | 行号左侧点击 |
| 条件断点 | 右键断点 → 输入条件 `user.id === 42` |
| 命中次数断点 | 右键 → Hit Count `> 10` |
| 日志点（Logpoint） | 右键 → Log Message `user=${user.name}`（不暂停，替代 console.log） |
| 函数断点 | Run and Debug → Breakpoints → `+` 输入函数名 |
| 异常断点 | Breakpoints 面板勾选 Caught/Uncaught Exceptions |

调试面板：
- **VARIABLES**：当前作用域变量，可右键 `Set Value` 修改；
- **WATCH**：添加表达式持续观察；
- **CALL STACK**：调用栈，点击任意帧可查看该层上下文；
- **LOADED SCRIPTS**：已加载脚本列表。

## 八、快捷键

| 操作 | 快捷键 |
| --- | --- |
| 启动/继续 | `F5` |
| 暂停 | `F6` |
| 重启 | `Ctrl+Shift+F5` |
| 停止 | `Shift+F5` |
| 单步跳过（step over） | `F10` |
| 单步进入（step into） | `F11` |
| 单步跳出（step out） | `Shift+F11` |
| 切换断点 | `F9` |

## 九、常见问题

| 问题 | 解决 |
| --- | --- |
| 断点变灰/不生效 | 源文件与运行文件路径不一致：配 `sourceMaps`、`outFiles`、`webRoot` |
| TS 断点停在编译后文件 | 确保生成 sourcemap（`"sourceMap": true`） |
| `Cannot find module` | 加 `"env": { "NODE_OPTIONS": "--enable-source-maps" }` 或检查 cwd |
| 调试子进程 | 开 `"autoAttachChildProcesses": true` |
| 调试 serverless / docker | 用 `request: "attach"`，暴露 9229 端口 |
| 变量显示 `undefined` | 可能被 TS 类型擦除或已优化；检查构建目标 |

## 十、最佳实践

1. **团队共享 `launch.json`**（提交到仓库），新人开箱即用。
2. 用 Logpoint 代替临时 `console.log`，不污染代码。
3. 条件断点处理循环中的特定迭代，避免手动 F10 几十次。
4. 复杂 bug：先在断点处观察，再用 Watch 验证假设。
5. 前端项目同时配 Chrome launch + 网络面板使用。
