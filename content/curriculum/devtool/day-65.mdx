## 一、Jenkins 是什么

老牌开源自建 CI/CD 服务器，核心特点：

- **插件生态极大**（1800+ 插件，几乎能对接任何工具）；
- 完全可控（自建、内网、私有化）；
- 支持分布式构建（Master/Agent）；
- Pipeline as Code（Jenkinsfile）。

适合：企业内网、需要高度定制、已有 Jenkins 沉淀的团队。
不适合：小团队新项目（维护成本高于 GitHub Actions/GitLab CI）。

## 二、安装

### Docker 方式（推荐）

```powershell
docker run -d --name jenkins `
  -p 8080:8080 -p 50000:50000 `
  -v jenkins_home:/var/jenkins_home `
  jenkins/jenkins:lts-jdk17
```

访问 http://localhost:8080，初始密码：

```powershell
docker exec jenkins cat /var/jenkins_home/secrets/initialAdminPassword
```

### Windows 安装包

```powershell
winget install Jenkins.Jenkins
# 或下载 msi 安装，服务方式运行
```

> 生产建议：Jenkins 本体跑在 Linux 容器，构建任务由 Agent 执行。

## 三、核心概念

| 概念 | 说明 |
| --- | --- |
| Job / Project | 一个构建任务 |
| Pipeline | 流水线（推荐，代码化） |
| Jenkinsfile | 流水线定义文件（进仓库） |
| Agent / Node | 执行构建的机器 |
| Credentials | 凭证管理（密钥、token、证书） |
| Stage / Step | 阶段/步骤 |
| Workspace | 每次构建的工作目录 |

## 四、Pipeline（Jenkinsfile）

### 声明式（推荐）

```groovy
pipeline {
    agent any

    tools {
        nodejs 'node20'          // 需先在「全局工具配置」中定义
    }

    environment {
        CI = 'true'
        REGISTRY = 'registry.example.com'
    }

    options {
        timeout(time: 30, unit: 'MINUTES')
        disableConcurrentBuilds()
        buildDiscarder(logRotator(numToKeepStr: '20'))
    }

    stages {
        stage('Checkout') {
            steps {
                checkout scm
            }
        }

        stage('Install') {
            steps {
                sh 'corepack enable && pnpm install --frozen-lockfile'
            }
        }

        stage('Quality') {
            parallel {
                stage('Lint') {
                    steps { sh 'pnpm lint' }
                }
                stage('TypeCheck') {
                    steps { sh 'pnpm typecheck' }
                }
            }
        }

        stage('Test') {
            steps {
                sh 'pnpm test -- --run --coverage'
            }
            post {
                always {
                    junit 'reports/junit.xml'
                    publishHTML(target: [
                        reportDir: 'coverage',
                        reportFiles: 'index.html',
                        reportName: 'Coverage'
                    ])
                }
            }
        }

        stage('Build') {
            steps {
                sh 'pnpm build'
                archiveArtifacts artifacts: 'dist/**', fingerprint: true
            }
        }

        stage('Deploy') {
            when {
                branch 'main'
            }
            steps {
                withCredentials([sshUserPrivateKey(
                    credentialsId: 'deploy-key',
                    keyFileVariable: 'KEY'
                )]) {
                    sh 'ssh -i $KEY user@server "cd /app && ./deploy.sh"'
                }
            }
        }
    }

    post {
        success { echo '构建成功' }
        failure {
            // 通知（钉钉/飞书/Slack）
            sh 'curl -X POST $WEBHOOK_URL -d "构建失败: $BUILD_URL"'
        }
        always { cleanWs() }
    }
}
```

### 脚本式（更灵活）

```groovy
node {
    stage('Build') {
        checkout scm
        sh 'pnpm install && pnpm build'
    }
    if (env.BRANCH_NAME == 'main') {
        stage('Deploy') { sh './deploy.sh' }
    }
}
```

## 五、凭证管理

`Manage Jenkins → Credentials → System → Global credentials`：

| 类型 | 用途 |
| --- | --- |
| Username with password | Git 账号、Registry 登录 |
| SSH Username with private key | 服务器部署、Git SSH |
| Secret text | API Token、Webhook |
| Secret file | kubeconfig、证书文件 |

使用：

```groovy
withCredentials([string(credentialsId: 'api-token', variable: 'TOKEN')]) {
    sh 'curl -H "Authorization: Bearer $TOKEN" https://api.example.com'
}
```

**禁止**把密钥写进 Jenkinsfile 或脚本明文。

## 六、Git 集成与自动触发

1. Job 配置中 Git SCM 填仓库地址 + 凭证；
2. 触发方式：
 - **Webhook**：GitHub/GitLab 推送事件触发（推荐）；
 - **轮询 SCM**：`H/5 * * * *`（每分钟检查，不推荐，浪费资源）；
 - **定时**：`Build periodically`。
3. 多分支流水线（Multibranch Pipeline）：自动为每个分支/PR 创建流水线，配合 `Jenkinsfile` 使用。

## 七、分布式构建（Agent）

`Manage Jenkins → Nodes → New Node`：

- 用 SSH 或 JNLP 连接 Agent 机器；
- 通过 **标签（Labels）** 分配任务：

```groovy
pipeline {
    agent { label 'linux && docker' }
    // ...
}
```

好处：构建负载分散、不同环境（Windows/macOS/GPU）分别处理。

必装插件：

| 插件 | 用途 |
| --- | --- |

## 九、常见问题

| 问题 | 解决 |
| --- | --- |
| `sh: command not found: node` | 全局工具配置中定义 Node，或用 `tools { nodejs 'node20' }` |
| 构建卡住 | 检查 Agent 在线状态、并发限制、`timeout` 设置 |
| 磁盘爆满 | `buildDiscarder` 限制保留数；workspace 清理；定期清理 artifacts |
| 中文乱码 | 设置 `LANG=zh_CN.UTF-8`；Windows Agent 用 `chcp 65001` |
| Webhook 不触发 | 检查 Jenkins URL 外网可达、token/secret 配置 |
| Jenkinsfile 语法错误 | 用 `Declarative Pipeline` 校验工具或 Blue Ocean 编辑器 |
| 权限混乱 | 用 Role-based 插件按项目/团队授权 |

## 十、最佳实践

1. **一切 Pipeline as Code**，Jenkinsfile 进仓库，禁止 UI 手配 job（除触发器）；
2. **Jenkins 本体不跑构建**，用 Agent 分担；
3. 密钥统一用 Credentials，定期轮换；
4. 用 **Shared Library** 复用流水线逻辑：

```groovy
@Library('my-shared-lib') _
standardPipeline(nodeVersion: '20')
```

5. 配置即代码：用 JCasC（Jenkins Configuration as Code）插件管理 Jenkins 配置；
6. 备份 `JENKINS_HOME`。
