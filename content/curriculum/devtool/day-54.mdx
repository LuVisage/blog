## 一、Nx 是什么

Nx 是**企业级 monorepo 平台**，除了任务编排与缓存，还提供：

- 插件体系（React、Next、Nest、Go、Rust...）；
- 代码生成器（generator）与迁移器（migrator）；
- **依赖图与影响分析**（`nx affected`）；
- 模块边界约束（enforce module boundaries）；
- 交互式可视化 `nx graph`。

适合中大型团队、需要统一工程规范的场景。

## 二、创建与初始化

```powershell
# 新建 Nx 工作区
pnpm dlx create-nx-workspace@latest my-org
# 选择 preset：integrated（集成式，含 apps/libs）或 package-based

# 在已有仓库中加入 Nx
pnpm add -D nx
npx nx init
```

## 三、目录结构

```
my-org/
├── apps/
│   ├── web/                 # 应用
│   └── api/
├── libs/
│   ├── shared/ui/           # 库（可被依赖）
│   └── shared/utils/
├── nx.json                  # 全局配置
├── package.json
└── tools/                   # 自定义脚本/生成器
```

## 四、常用命令

```powershell
nx run web:build                # 执行单个目标
nx run-many -t build            # 所有项目跑 build
nx run-many -t test lint        # 多目标任务

nx affected -t build            # 只跑受影响的（对比 base）
nx affected -t test --base=main

nx graph                        # 打开依赖图（交互式）
nx graph --affected             # 只看受影响项目图

nx g @nx/react:component Button # 生成组件
nx g @nx/js:lib utils           # 生成库

nx show project web             # 查看项目所有可用目标
nx reset                        # 清空本地缓存
nx migrate latest               # 升级 Nx 与插件版本
```

## 五、project.json 与目标

每个项目的 `project.json` 声明任务：

```json
{
  "name": "web",
  "sourceRoot": "apps/web/src",
  "projectType": "application",
  "targets": {
    "build": {
      "executor": "@nx/vite:build",
      "outputs": ["{options.outputPath}"],
      "options": { "outputPath": "dist/apps/web" },
      "cache": true
    },
    "test": {
      "executor": "@nx/vitest:test",
      "options": { "reportsDirectory": "coverage/web" }
    }
  }
}
```

## 六、缓存配置（nx.json）

```jsonc
{
  "$schema": "./node_modules/nx/schemas/nx-schema.json",
  "targetDefaults": {
    "build": {
      "cache": true,
      "dependsOn": ["^build"],
      "inputs": ["production", "^production"],
      "outputs": ["{projectRoot}/dist"]
    },
    "test": { "cache": true, "inputs": ["default", "^production"] }
  },
  "namedInputs": {
    "default": ["{projectRoot}/**/*", "sharedGlobals"],
    "production": ["default", "!{projectRoot}/**/*.spec.ts"],
    "sharedGlobals": []
  }
}
```

远程缓存：

```powershell
nx cloud connect      # Nx Cloud（官方托管）
# 或自建：设置 NX_CACHE_DIRECTORY / 任务缓存插件
```

## 七、模块边界约束

`eslint.config.js` 中配置：

```js
'@nx/enforce-module-boundaries': ['error', {
  depConstraints: [
    { sourceTag: 'scope:shared', onlyDependOnLibsWithTags: ['scope:shared'] },
    { sourceTag: 'type:app',   onlyDependOnLibsWithTags: ['type:lib', 'type:util'] },
  ],
}]
```

配合 `project.json` 的 `tags`，可阻止「底层库反向依赖上层应用」等架构腐化。

## 八、CI 集成

```yaml
- run: pnpm install --frozen-lockfile
- run: npx nx affected -t lint test build --base=origin/main --parallel=3
```

配合 Nx Cloud 可实现：分布式任务执行、远程缓存、失败自动重跑。

## 九、Nx vs Turbo

| 能力 | Nx | Turbo |
| --- | --- | --- |
| 任务缓存 | | |
| 影响分析 | （更精细） | 基础 |
| 代码生成 | generators | |
| 插件生态 | 丰富 | 无 |
| 模块边界约束 | | |
| 学习成本 | 高 | 低 |
| 适合规模 | 中大型 | 中小型 |

## 十、常见问题

| 问题 | 解决 |
| --- | --- |
| `nx affected` 结果不对 | 检查 git base/head 参数，以及项目是否有正确的 `project.json` |
| 缓存没生效 | 确认 target 的 `cache: true`、outputs/inputs 配置正确 |
| 生成器写了不该覆盖的文件 | 先用 `--dry-run` 预览 |
| 依赖图过于复杂 | 用 tags + module boundaries 拆分治理 |
| Windows 长路径报错 | 开启长路径支持，或换 WSL2 开发 |
| 升级后大量报错 | `nx migrate latest` 后按 `migrations.json` 逐步执行 |
