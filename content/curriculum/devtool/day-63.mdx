## 一、基本概念

| 概念 | 说明 |
| --- | --- |
| Pipeline | 一次完整流水线运行 |
| Stage | 阶段（串行），如 build → test → deploy |
| Job | 阶段内的任务（同阶段并行） |
| Runner | 执行任务的机器（共享/专用/自建） |
| `.gitlab-ci.yml` | 流水线定义文件（放仓库根目录） |
| Artifacts | Job 产物（测试报告、构建包） |
| Cache | 跨 Pipeline 的依赖缓存 |

## 二、第一个 Pipeline

```yaml
# .gitlab-ci.yml
stages:
  - build
  - test
  - deploy

variables:
  NODE_VERSION: "20"

default:
  image: node:20-alpine
  cache:
    key:
      files:
        - pnpm-lock.yaml
    paths:
      - .pnpm-store/

build:
  stage: build
  before_script:
    - corepack enable
    - pnpm config set store-dir .pnpm-store
  script:
    - pnpm install --frozen-lockfile
    - pnpm build
  artifacts:
    paths:
      - dist/
    expire_in: 1 week

test:
  stage: test
  script:
    - pnpm install --frozen-lockfile
    - pnpm test -- --run
    - pnpm lint
  coverage: '/Lines\s*:\s*(\d+\.\d+)%/'   # 从日志提取覆盖率

deploy:
  stage: deploy
  script:
    - echo "部署 $CI_COMMIT_REF_NAME ..."
  only:
    - main
  environment:
    name: production
    url: https://app.example.com
```

## 三、关键语法

### 触发规则（新语法推荐）

```yaml
workflow:
  rules:
    - if: $CI_PIPELINE_SOURCE == "merge_request_event"
    - if: $CI_COMMIT_BRANCH == $CI_DEFAULT_BRANCH
    - if: $CI_COMMIT_TAG

deploy:
  rules:
    - if: $CI_COMMIT_BRANCH == "main"
      when: manual            # 手动触发
    - if: $CI_COMMIT_TAG
```

### 预定义变量（常用）

| 变量 | 含义 |
| --- | --- |
| `CI_COMMIT_BRANCH` | 当前分支 |
| `CI_COMMIT_TAG` | 标签 |
| `CI_COMMIT_SHA` | 提交 hash |
| `CI_PIPELINE_SOURCE` | 触发来源（push/merge_request_event/schedule） |
| `CI_MERGE_REQUEST_IID` | MR 编号 |
| `CI_REGISTRY_*` | 内置镜像仓库凭证 |
| `CI_ENVIRONMENT_NAME` | 环境名 |

### 缓存 vs 产物

```yaml
# cache：跨 pipeline 复用，加速安装（不需要下载，直接在执行机上）
cache:
  key: ${CI_COMMIT_REF_SLUG}
  paths: [node_modules/]

# artifacts：job 间传递 + 用户下载
artifacts:
  paths: [dist/]
  reports:
    junit: reports/junit.xml
    coverage_report:
      coverage_format: cobertura
      path: coverage/cobertura-coverage.xml
```

### 并行与矩阵

```yaml
test:
  parallel: 4                     # 4 个并行 job（$CI_NODE_INDEX 区分）
  script:
    - pnpm vitest run --shard=$CI_NODE_INDEX/4

test-matrix:
  parallel:
    matrix:
      - NODE: ["18", "20", "22"]
        OS: ["linux"]
  image: node:${NODE}-${OS}
```

### 模板复用

```yaml
.node-base:
  image: node:20
  before_script:
    - corepack enable && pnpm install --frozen-lockfile

lint:
  extends: .node-base
  script: [pnpm lint]

test:
  extends: .node-base
  script: [pnpm test -- --run]
```

### 手动部署与审批

```yaml
deploy:prod:
  stage: deploy
  script: ./deploy.sh production
  when: manual
  allow_failure: false      # 手动任务不被跳过
  environment:
    name: production
    url: https://app.example.com
```

### 定时任务

GitLab UI → CI/CD → Schedules 添加（cron 语法）。

## 四、Docker 构建与推送

```yaml
build-image:
  stage: build
  image: docker:27
  services:
    - docker:27-dind
  variables:
    DOCKER_TLS_CERTDIR: "/certs"
  script:
    - docker login -u $CI_REGISTRY_USER -p $CI_REGISTRY_PASSWORD $CI_REGISTRY
    - docker build -t $CI_REGISTRY_IMAGE:$CI_COMMIT_SHA .
    - docker push $CI_REGISTRY_IMAGE:$CI_COMMIT_SHA
```

GitLab 内置容器镜像仓库（Container Registry），凭证由 `CI_REGISTRY_*` 自动提供。

## 五、Secrets 与变量

位置：`Settings → CI/CD → Variables`

- 勾选 **Masked**：日志中打码；
- 勾选 **Protected**：只在受保护分支/tag 可用；
- 类型可选 Variable（变量）或 File（文件，如 kubeconfig、证书）。

```yaml
deploy:
  script:
    - echo "$DEPLOY_KEY" > /tmp/key && chmod 600 /tmp/key
    - ssh -i /tmp/key user@server "cd /app && ./deploy.sh"
```

## 六、常见问题

| 问题 | 解决 |
| --- | --- |
| Job 卡在 pending | 没有可用 Runner：检查 Runner 注册与 tag 匹配 |
| 缓存不生效 | key 策略（`files` 基于 lock 文件）；不同 Runner 不共享本地缓存（用分布式缓存） |
| `only/except` 与 `rules` 冲突 | 统一改用 `rules` |
| MR 时 Pipeline 不跑 | 加 `workflow.rules` 包含 `merge_request_event` |
| 变量在日志里没打码 | 变量需勾选 Masked，且值符合打码规则（长度/字符集） |
| dind 构建慢 | 用 `docker buildx` + 缓存；或 Kaniko / Buildah 无守护构建 |
| 想只跑受影响的子项目 | 用 `rules:changes` 或子流水线（`trigger:`） |

## 七、最佳实践

1. **模板化**：用 `extends` / `!reference` / `include` 减少重复；
2. **include 拆文件**：

```yaml
include:
  - local: .gitlab/ci/test.yml
  - template: Security/SAST.gitlab-ci.yml     # GitLab 官方安全模板
```

3. **覆盖率可视化**：配 `coverage:` 正则 + Cobertura 报告；
4. **环境审批**：`environment` + 受保护环境控制生产发布；
5. **Runner 隔离**：生产部署用专用 Runner，不与普通 CI 共享；
6. 用 `interruptible: true` + `retry` 优化重跑行为。

## 八、与 GitHub Actions 对照

| 能力 | GitLab CI | GitHub Actions |
| --- | --- | --- |
| 配置文件 | `.gitlab-ci.yml` | `.github/workflows/*.yml` |
| 阶段模型 | stages 一级公民 | 用 `needs` 表达依赖 |
| 复用 | extends / include / templates | reusable workflows / composite actions |
| Secret | CI/CD Variables | Secrets |
| 镜像仓库 | 内置 Container Registry | GHCR |
| 审批 | Protected Environments | Environments + reviewers |
