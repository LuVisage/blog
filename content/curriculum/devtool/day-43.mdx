## 一、抓包能解决什么

- 手机 App / 小程序请求了什么接口、参数是什么；
- 请求被谁改了、响应为什么不对；
- 排查 TLS 层、TCP 层的连接问题；
- 弱网、超时、重试行为的真实表现。

## 二、三款工具定位

| 工具 | 层级 | 特点 | 适合 |
| --- | --- | --- | --- |
| **Charles** | HTTP/HTTPS 代理 | 图形化，Mac/Win/Linux，移动端配置成熟 | 日常 HTTP(S) 调试、移动端 |
| **mitmproxy** | HTTP/HTTPS 代理 | 命令行 + 脚本（Python），可编程改写流量 | 自动化、批量改写、CI |
| **Wireshark** | 网络层（L2-L7） | 抓所有协议包（TCP/UDP/DNS/TLS） | 网络故障、协议分析 |

> 抓 HTTPS 的原理都是 **中间人（MITM）**：工具作为代理，用自己的证书解密流量。**只能在你自己有权限的网络/设备上使用。**

## 三、Charles 使用

### 安装与基础配置

1. 下载：https://www.charlesproxy.com/（收费，有 30 天试用）
2. `Proxy → Proxy Settings`：默认端口 8888，勾选 `Enable transparent HTTP proxying`；
3. 电脑配置系统代理指向 `127.0.0.1:8888`（Charles 会询问是否自动设置）。

### 抓 HTTPS

1. `Proxy → SSL Proxying Settings → Add`：Host 填 `*`，Port 填 `443`（或指定域名）；
2. 安装 Charles 根证书：
 - **Windows**：`Help → SSL Proxying → Install Charles Root Certificate`；
 - **macOS**：安装后需在钥匙串中设为「始终信任」。

### 抓手机 App

1. 手机与电脑连同一 Wi-Fi；
2. 手机 Wi-Fi 设置代理：服务器=电脑 IP，端口=8888；
3. 手机浏览器访问 `chls.pro/ssl` 下载证书：
 - iOS：设置 → 通用 → VPN与设备管理 → 安装描述文件，再到「关于本机 → 证书信任设置」开启完全信任；
 - Android：设置 → 安全 → 安装证书（CA 证书）。

### 常用功能

| 功能 | 位置 / 用法 |
| --- | --- |
| 只关注某域名 | `Proxy → Recording Settings → Include` 添加 |
| 重写请求/响应 | `Tools → Rewrite`（改 header、body） |
| 本地映射（Mock） | `Tools → Map Local`（用本地文件当响应） |
| 远程映射 | `Tools → Map Remote`（把 A 域名转发到 B） |
| 断点（改包） | 右键请求 → `Breakpoints`，可修改后再放行 |
| 限速（弱网） | `Proxy → Throttle Settings` |
| 保存会话 | `File → Save Session`（.chls 文件可分享） |
| 反向代理 | `Proxy → Reverse Proxies`（抓手机直连服务器的流量） |
| 过滤 | 底部 Filter 输入关键字 |

## 四、mitmproxy 使用

### 安装与启动

```powershell
pip install mitmproxy
mitmproxy            # 交互式 TUI
mitmweb              # 浏览器界面（更直观，推荐新手）
mitmdump             # 纯命令行输出
```

默认端口 8080。手机/浏览器代理指向 `电脑IP:8080`，访问 `http://mitm.it` 下载证书安装。

### 常用命令

```powershell
mitmweb --listen-port 8080

# 只抓特定域名
mitmdump "~d api.example.com"

# 保存流量到文件
mitmdump -w flows.mitm

# 回放
mitmdump -nr flows.mitm
```

### 用脚本改写流量（核心优势）

`rewrite.py`：

```python
from mitmproxy import http

def request(flow: http.HTTPFlow) -> None:
    # 给所有请求加 header
    flow.request.headers["X-Debug"] = "1"
    # 修改请求体
    if "/api/login" in flow.request.pretty_url:
        flow.request.text = flow.request.text.replace("old", "new")

def response(flow: http.HTTPFlow) -> None:
    # Mock 响应：把用户列表改成假数据
    if "/api/users" in flow.request.pretty_url:
        flow.response.set_text('{"users":[{"id":1,"name":"mocked"}]}')
        flow.response.headers["Content-Type"] = "application/json"
```

```powershell
mitmdump -s rewrite.py
```

其他用途：批量压测录制回放、自动注入埋点、分析接口耗时。

## 五、Wireshark 使用

### 安装与抓包

1. 下载：https://www.wireshark.org/
2. 选择网卡 → 开始抓包 → 复现问题 → 停止；
3. 过滤器（**先抓后滤**，避免漏包）：

| 过滤表达式 | 含义 |
| --- | --- |
| `ip.addr == 192.168.1.10` | 某 IP 的流量 |
| `tcp.port == 443` | 某端口 |
| `dns` | 只看 DNS |
| `tcp.flags.syn == 1 && tcp.flags.ack == 0` | TCP 建连请求 |
| `http.request` | HTTP 请求 |
| `tcp.analysis.retransmission` | 重传（网络质量问题） |
| `tls.handshake.type == 1` | TLS Client Hello |

### 典型排查场景

- **连接失败**：看 SYN → 是否有 SYN/ACK，是否 RST；
- **慢**：看 TCP 三次握手耗时、重传、窗口大小；
- **DNS 问题**：`dns` 过滤看解析是否超时/失败；
- **TLS 握手失败**：看 Client Hello → Server Hello 之间是否中断。

> Wireshark **不能解密 HTTPS**（除非你有服务器私钥或导出会话密钥），抓 HTTP 调试请用 Charles/mitmproxy。

## 六、HTTPS 抓不到的常见原因

| 现象 | 原因 / 解决 |
| --- | --- |
| 只看到 CONNECT 隧道，没有内容 | 未开启 SSL Proxying（Charles）或未配 `~d` 过滤；证书未信任 |
| App 请求失败/闪退 | App 做了证书固定（SSL Pinning），需逆向绕过（仅限自有应用） |
| 手机装了证书仍不行 | Android 7+ 用户证书不受 App 信任；需 root + 系统证书，或 App 自行配置信任 |
| 小程序抓不到 | 部分小程序走自有通道；改用真机 + 代理 + 关闭小程序「校验」选项 |
| 提示证书无效 | 时间不对、证书未安装到「受信任根」、装的是旧代理证书 |

## 七、合规与安全提醒

1. **只抓自己有权调试的流量**（自有 App、自有服务、已获授权的测试环境）。
2. 生产环境抓包注意**脱敏**：请求里可能有 token、手机号、密码。
3. 抓包工具证书是**高敏感凭证**，用完及时卸载。
4. 公司网络抓包遵守内部规范与当地法律。

## 八、选型建议

- 手机 App / 网页日常调试 → **Charles**（图形化最省心）
- 要写脚本自动改包、批量回放 → **mitmproxy**
- 排查「连不上、时快时慢」等网络层问题 → **Wireshark**
