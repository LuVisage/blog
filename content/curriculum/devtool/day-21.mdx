## 一、Turbo 是什么

Turborepo 是面向 **JavaScript/TypeScript monorepo** 的高性能构建系统，用 Rust 编写，核心能力：

1. **任务编排**：一条命令按依赖顺序跑所有包的任务；
2. **智能缓存**：内容哈希命中缓存则直接跳过（本地 + 远程）；
3. **增量执行**：只重跑受影响的包。

> 它**不替换** Vite/Webpack，而是在它们之上做「多包任务调度」。底层打包仍由各包自己的工具负责。

## 二、快速开始

```powershell
# 创建新 monorepo
pnpm dlx create-turbo@latest my-monorepo

# 或在已有 pnpm workspace 中启用
pnpm add -D turbo -w
```

## 三、目录结构

```
my-monorepo/
├── apps/
│   ├── web/            # Next.js 应用
│   └── docs/           # 文档站
├── packages/
│   ├── ui/             # 共享组件库
│   ├── utils/          # 工具函数
│   └── tsconfig/       # 共享配置
├── package.json
├── pnpm-workspace.yaml
└── turbo.json          # Turbo 配置
```

## 四、turbo.json 配置

```jsonc
{
  "$schema": "https://turbo.build/schema.json",
  "tasks": {
    "build": {
      "dependsOn": ["^build"],       // 先构建依赖的包
      "outputs": ["dist/**", ".next/**", "!.next/cache/**"]
    },
    "test": {
      "dependsOn": ["build"],
      "outputs": ["coverage/**"]
    },
    "lint": {},
    "dev": {
      "cache": false,                // 开发服务不缓存
      "persistent": true             // 长驻进程
    }
  }
}
```

- `dependsOn: ["^build"]`：`^` 表示「上游依赖的 build 先完成」；
- `outputs`：声明产物路径，缓存恢复时按此还原；
- `inputs`：默认所有源文件参与哈希，可自定义缩小范围。

## 五、常用命令

```powershell
turbo run build                    # 跑所有包的 build
turbo run build --filter=web       # 只跑 web 包
turbo run test --filter=...[HEAD^1]  # 只跑受最近提交影响的包
turbo run lint --filter=./packages/*

turbo run build --force            # 忽略缓存，强制重跑
turbo run build --dry              # 打印将执行的任务（不实际执行）
turbo run build --graph=graph.html # 可视化任务依赖图
turbo run dev --parallel           # 并行跑 dev
```

`package.json` 中封装：

```json
{
  "scripts": {
    "build": "turbo run build",
    "dev": "turbo run dev",
    "lint": "turbo run lint",
    "test": "turbo run test"
  }
}
```

## 六、缓存机制

**哈希输入** = 源文件内容 + 环境变量 + 任务配置 + 依赖包哈希。

命中缓存时输出类似：

```
web:build: cache hit, replaying logs [f3a2b1]
>>> FULL TURBO
```

### 远程缓存（团队共享）

```powershell
turbo login
turbo link
# 之后 CI 与本地共享缓存
```

或自建缓存服务（`turbo.json`）：

```json
{
  "remoteCache": { "signature": true }
}
```

环境变量：`TURBO_TOKEN`、`TURBO_TEAM`。

## 七、CI 中的典型用法

```yaml
- run: pnpm install --frozen-lockfile
- run: pnpm turbo run build test lint --filter='...[origin/main]'
```

含义：只构建/测试相对 main 分支发生变化的部分，CI 时间从 20 分钟降到 2 分钟很常见。

## 八、常见问题

| 问题 | 解决 |
| --- | --- |
| 缓存命中错误（该跑没跑） | 检查环境变量是否声明在 `env` 字段；`--force` 验证 |
| `dev` 任务被缓存卡住 | 加 `"cache": false, "persistent": true` |
| 缓存目录占磁盘 | 定期清理 `node_modules/.cache/turbo` |
| CI 无法共享缓存 | 配置 `TURBO_TOKEN` / `TURBO_TEAM`，或自建 |
| Windows 下路径分隔符问题 | 升级 turbo 至最新版本 |
| 任务顺序不对 | 检查 `dependsOn` 与包间 `dependencies` 声明是否一致 |

## 九、Turbo vs Nx 选择

| 维度 | Turbo | Nx |
| --- | --- | --- |
| 定位 | 任务编排 + 缓存，极简 | 全功能 monorepo 平台 |
| 配置成本 | 低（一个 turbo.json） | 高（插件、generator） |
| 代码生成 | 无 | 强（generators） |
| 依赖图分析 | 基础 | 强（影响分析、graph） |
| 适合 | 中小团队、已有 pnpm workspace | 大型团队、需要脚手架与治理 |

**结论**：想快速给现有 monorepo 提速 → Turbo；需要完整工程治理 → Nx。
