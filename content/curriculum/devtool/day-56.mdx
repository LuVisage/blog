## 一、compose 是什么

用**一个 YAML 文件**定义多个容器（web + api + db + redis + nginx），一条命令启动整套环境：

- 本地开发一键起环境；
- 小型生产部署；
- CI 中起依赖服务（数据库、消息队列）。

> 新版命令是 `docker compose`（v2 插件，VSCode 插件已内置）；旧版是 `docker-compose`（v1，已停更）。

## 二、快速开始

`compose.yaml`（推荐文件名，也可用 `docker-compose.yml`）：

```yaml
services:
  web:
    build: ./web
    ports:
      - "5173:5173"
    environment:
      - VITE_API_URL=http://localhost:8080
    depends_on:
      - api
    volumes:
      - ./web:/app
      - /app/node_modules

  api:
    build: ./api
    ports:
      - "8080:8080"
    environment:
      DATABASE_URL: postgres://postgres:secret@db:5432/app
      REDIS_URL: redis://cache:6379
    depends_on:
      db:
        condition: service_healthy
      cache:
        condition: service_started
    restart: unless-stopped

  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: secret
      POSTGRES_DB: app
    volumes:
      - db-data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 5s
      timeout: 5s
      retries: 5

  cache:
    image: redis:7-alpine

  nginx:
    image: nginx:alpine
    ports:
      - "80:80"
    volumes:
      - ./nginx.conf:/etc/nginx/conf.d/default.conf:ro
    depends_on:
      - web
      - api

volumes:
  db-data:

networks:
  default:
    name: app-net
```

## 三、常用命令

```powershell
docker compose up -d              # 后台启动全部
docker compose up -d --build      # 重新构建镜像后启动
docker compose up api             # 只启动 api 及其依赖
docker compose ps                 # 查看状态
docker compose logs -f api        # 跟踪日志
docker compose restart api
docker compose stop               # 停止（保留容器）
docker compose down               # 停止并删除容器/网络
docker compose down -v            # 连数据卷一起删（清空数据库！）
docker compose exec api sh        # 进入容器
docker compose run --rm api npm test    # 一次性执行命令
docker compose config             # 校验并展开配置（排错用）
docker compose pull && docker compose up -d    # 更新镜像
```

## 四、多环境配置

`compose.yaml` + 覆盖文件：

```powershell
docker compose -f compose.yaml -f compose.prod.yaml up -d
```

`compose.prod.yaml`：

```yaml
services:
  api:
    build: !reset null
    image: registry.example.com/api:1.2.3
    restart: always
  web:
    image: registry.example.com/web:1.2.3
```

`.env` 文件（compose 自动读取）：

```ini
TAG=1.2.3
POSTGRES_PASSWORD=secret
```

yaml 中引用：

```yaml
services:
  api:
    image: registry.example.com/api:${TAG}
```

## 五、开发场景最佳实践

### 1. 热更新挂载

```yaml
services:
  web:
    volumes:
      - ./web:/app            # 源码挂载
      - /app/node_modules     # 匿名卷保护容器内依赖（关键！）
    command: pnpm dev
```

### 2. 只起依赖服务（本地跑应用）

```powershell
docker compose up -d db cache    # 只起数据库和缓存，应用本地运行
```

### 3. 等待依赖就绪

用 `healthcheck` + `depends_on.condition: service_healthy`，避免应用比数据库先启动导致崩溃。

（更严格时配合 `wait-for-it.sh` 或应用自身重试逻辑。）

### 4. 生产注意事项

- 使用 `restart: unless-stopped` / `always`；
- 日志限制大小，防止占满磁盘：

```yaml
services:
  api:
    logging:
      driver: json-file
      options:
        max-size: "10m"
        max-file: "3"
```

- 敏感信息用 `.env`（不提交）或 secrets；
- 数据库卷必须持久化，且定期备份；
- 镜像使用固定 tag，不用 `latest`。

## 六、常用服务模板

**MySQL**：

```yaml
db:
  image: mysql:8.0
  command: --default-authentication-plugin=mysql_native_password --character-set-server=utf8mb4
  environment:
    MYSQL_ROOT_PASSWORD: root
    MYSQL_DATABASE: app
  ports: ["3306:3306"]
  volumes:
    - db-data:/var/lib/mysql
    - ./init.sql:/docker-entrypoint-initdb.d/init.sql:ro
```

**MongoDB**：

```yaml
mongo:
  image: mongo:7
  ports: ["27017:27017"]
  volumes: [mongo-data:/data/db]
```

**RabbitMQ（带管理台）**：

```yaml
mq:
  image: rabbitmq:3-management
  ports: ["5672:5672", "15672:15672"]
```

## 七、常见问题

| 问题 | 解决 |
| --- | --- |
| 应用连不上 db | 用服务名（`db`）而非 localhost；确认在同一 network |
| 改代码不生效 | 检查 volumes 挂载；确认容器内工作目录正确 |
| node_modules 被宿主覆盖 | 加匿名卷 `- /app/node_modules` |
| `down -v` 后数据没了 | `-v` 会删卷；生产禁用，或先备份 |
| 端口冲突 | 改宿主机端口；或 `docker compose ps` 找残留 |
| compose 启动顺序乱 | 用 healthcheck + depends_on condition |
| WSL 下文件变更不触发热更新 | 项目放 WSL 文件系统；或用 polling 模式（`CHOKIDAR_USEPOLLING=true`） |
| 构建缓存不生效 | 优化 Dockerfile 顺序；`--build` 时用 `--no-cache` 排查 |
