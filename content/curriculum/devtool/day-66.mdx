## 一、GitOps 是什么

**用 Git 仓库作为系统唯一事实来源**：集群的期望状态写在 Git 里，工具持续对比 Git 与集群实际状态，自动同步。

```
开发者 push 代码/配置
        │
        ▼
   Git 仓库（期望状态）
        │  持续监听
        ▼
  Argo CD / Flux CD（集群内 Agent）
        │  对比 + 同步
        ▼
   Kubernetes 集群（实际状态）
```

与「CI push 部署」的区别：

| 方式 | 机制 | 问题 |
| --- | --- | --- |
| 传统 CI/CD | CI 里 `kubectl apply` | CI 需持有集群凭证；状态漂移无人发现 |
| GitOps | 集群内 Agent 拉取 Git | CI 不接触集群；漂移自动纠正；回滚 = git revert |

## 二、核心概念

| 概念 | 说明 |
| --- | --- |
| 期望状态 | Git 中的 K8s 清单（YAML/Helm/Kustomize） |
| 实际状态 | 集群里正在运行的东西 |
| Sync | 把期望状态应用到集群 |
| Drift | 两者不一致（被人手动改了集群） |
| 自动同步 | 检测到差异自动纠正 |
| 渐进式交付 | 灰度发布（配合 Argo Rollouts / Flagger） |

## 三、Argo CD

### 安装

```powershell
kubectl create namespace argocd
kubectl apply -n argocd -f https://raw.githubusercontent.com/argoproj/argo-cd/stable/manifests/install.yaml
kubectl -n argocd get svc argocd-server      # 等待就绪

# 端口转发访问 UI
kubectl port-forward svc/argocd-server -n argocd 8080:443
# 初始密码
kubectl -n argocd get secret argocd-initial-admin-secret -o jsonpath="{.data.password}" | base64 -d
```

CLI：

```powershell
winget install argocd.cli
# 或下载 release 二进制
argocd login localhost:8080
argocd app list
```

### 定义一个 Application

`app.yaml`：

```yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: my-api
  namespace: argocd
spec:
  project: default

  source:
    repoURL: https://github.com/myorg/k8s-manifests.git
    targetRevision: main
    path: apps/api/overlays/prod        # 用 Kustomize overlay
    # 或用 Helm：
    # chart: api
    # repoURL: https://charts.example.com
    # helm:
    #   valueFiles: [values-prod.yaml]

  destination:
    server: https://kubernetes.default.svc
    namespace: api

  syncPolicy:
    automated:
      prune: true          # 删除 Git 中已移除的资源
      selfHeal: true       # 集群被手改后自动恢复
    syncOptions:
      - CreateNamespace=true
    retry:
      limit: 5
```

```powershell
kubectl apply -f app.yaml

argocd app get my-api
argocd app sync my-api
argocd app history my-api
argocd app rollback my-api 3
argocd app diff my-api         # 查看 Git 与集群差异
```

### 多环境目录结构（推荐）

```
k8s-manifests/
├── base/
│   ├── deployment.yaml
│   ├── service.yaml
│   └── kustomization.yaml
├── overlays/
│   ├── dev/
│   │   ├── kustomization.yaml       # 引用 ../../base
│   │   └── patch-replicas.yaml
│   ├── staging/
│   └── prod/
└── apps/                            # Argo CD Application 定义
    ├── api-dev.yaml
    └── api-prod.yaml
```

`overlays/prod/kustomization.yaml`：

```yaml
resources:
  - ../../base
images:
  - name: myapi
    newTag: 1.2.3        # CI 更新这一行 → GitOps 自动部署
patches:
  - path: patch-replicas.yaml
```

### App of Apps（管理大量应用）

根 Application 指向 `apps/` 目录，其中每个文件定义一个 Application，实现「一个入口管理所有应用」。

### 配合 CI 的完整流程

```yaml
# GitHub Actions：CI 只负责构建镜像 + 更新清单仓库
- name: 更新 manifest 仓库
  run: |
    git clone https://github.com/myorg/k8s-manifests.git
    cd k8s-manifests
    sed -i "s/newTag: .*/newTag: ${{ github.sha }}/" overlays/prod/kustomization.yaml
    git commit -am "chore: bump api to ${{ github.sha }}"
    git push
# 之后 Argo CD 检测到 Git 变更 → 自动同步到集群
```

（也可用 `argocd app set` / `argocd-image-updater` 自动化。）

## 四、Flux CD

### 安装

```powershell
# 前置：GitHub Token（repo 权限）
brew install fluxcd/tap/flux    # 或下载二进制
flux check --pre

flux bootstrap github `
  --owner=myorg --repository=fleet-infra `
  --branch=main --path=clusters/production --personal
```

bootstrap 会把 Flux 组件安装到集群，并把自身配置提交到仓库。

### 定义 GitRepository 与 Kustomization

```yaml
apiVersion: source.toolkit.fluxcd.io/v1
kind: GitRepository
metadata:
  name: my-app
  namespace: flux-system
spec:
  interval: 1m
  url: https://github.com/myorg/k8s-manifests
  ref: { branch: main }
---
apiVersion: kustomize.toolkit.fluxcd.io/v1
kind: Kustomization
metadata:
  name: my-app
  namespace: flux-system
spec:
  interval: 10m
  path: ./overlays/prod
  prune: true
  sourceRef:
    kind: GitRepository
    name: my-app
  healthChecks:
    - kind: Deployment
      name: api
      namespace: api
```

```powershell
flux get kustomizations
flux reconcile kustomization my-app --with-source    # 立即同步
flux logs
flux suspend kustomization my-app                     # 暂停自动同步
```

### HelmRelease（Helm 发布）

```yaml
apiVersion: helm.toolkit.fluxcd.io/v2
kind: HelmRelease
metadata:
  name: postgresql
  namespace: db
spec:
  interval: 30m
  chart:
    spec:
      chart: postgresql
      version: "15.x"
      sourceRef:
        kind: HelmRepository
        name: bitnami
  values:
    auth:
      existingSecret: pg-secret
```

## 五、Argo CD vs Flux CD

| 维度 | Argo CD | Flux CD |
| --- | --- | --- |
| 界面 | 功能强大的 Web UI | 以 CLI 为主（有 Weave GitOps UI） |
| 架构 | 中心化 Application 概念 | 每个 CRD 各司其职（GitRepository/Kustomization） |
| 多集群 | 强（一个实例管多集群） | 支持（需配置） |
| 上手难度 | 低（UI 直观） | 中（概念更多） |
| 与 Helm | 原生支持 | 原生支持（HelmRelease） |
| 渐进式交付 | Argo Rollouts | Flagger |
| 适合 | 想要 UI、多集群管理 | 喜欢纯声明式、轻量组合 |

## 六、最佳实践

1. **双仓库**：应用代码仓库 + 清单仓库（分离权限与变更频率）；
2. **镜像 tag 用不可变值**（sha/digest），清单里禁止 `latest`；
3. **自动同步谨慎开启**：生产环境可先手动 sync，稳定后开 `selfHeal`；
4. **漂移检测告警**：`OutOfSync` 状态接入监控（见 12-日志与监控）；
5. **渐进式发布**：配合 Argo Rollouts 做金丝雀（5% → 50% → 100%）；
6. **回滚就是 `git revert`**，简单可靠；
7. Secrets 用 Sealed Secrets / External Secrets，不要明文进 Git。

## 七、常见问题

| 问题 | 解决 |
| --- | --- |
| Application 一直 OutOfSync | `argocd app diff` 看差异；可能是集群默认字段、探针改的字段 |
| 同步失败（权限） | 检查 Argo CD ServiceAccount 的 RBAC 权限 |
| 私有仓库拉不到 | 添加 repo 凭证（https token 或 SSH） |
| 资源被手动改后又被改回 | `selfHeal: true` 的正常行为，禁止手动改生产集群 |
| 大量应用难管理 | 用 ApplicationSet 按目录/集群自动生成 Application |
| Helm values 被覆盖 | 检查 valueFiles 顺序与 `values:` 合并优先级 |
