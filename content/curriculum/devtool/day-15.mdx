## 一、Webpack 是什么

Webpack 是最成熟的**模块打包器**：从入口出发递归构建依赖图，把所有模块（JS/CSS/图片/字体）打包成浏览器可用的静态资源。

优点：生态极其丰富、可插拔、几乎支持一切场景。
缺点：配置复杂、构建速度相对慢（相比 Vite/esbuild）。

> 现状：新项目多数选 Vite；但大量存量项目、微前端、复杂自定义场景仍用 Webpack。

## 二、快速开始

```powershell
mkdir webpack-demo && cd webpack-demo
pnpm init
pnpm add -D webpack webpack-cli webpack-dev-server html-webpack-plugin
```

`webpack.config.js`：

```js
const path = require('node:path');
const HtmlWebpackPlugin = require('html-webpack-plugin');

module.exports = {
  mode: 'development',
  entry: './src/index.js',
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: '[name].[contenthash].js',
    clean: true,
  },
  module: {
    rules: [
      {
        test: /\.(js|jsx)$/,
        exclude: /node_modules/,
        use: 'babel-loader',
      },
      {
        test: /\.css$/,
        use: ['style-loader', 'css-loader'],
      },
      {
        test: /\.(png|svg|jpg)$/,
        type: 'asset',
        parser: { dataUrlCondition: { maxSize: 8 * 1024 } },
      },
    ],
  },
  plugins: [
    new HtmlWebpackPlugin({ template: './public/index.html' }),
  ],
  devServer: {
    port: 3000,
    hot: true,
    open: true,
    historyApiFallback: true,
    proxy: [{ context: ['/api'], target: 'http://localhost:8080' }],
  },
  resolve: {
    extensions: ['.js', '.jsx', '.ts', '.tsx'],
    alias: { '@': path.resolve(__dirname, 'src') },
  },
  devtool: 'source-map',
};
```

`package.json` scripts：

```json
{
  "scripts": {
    "dev": "webpack serve --mode development",
    "build": "webpack --mode production"
  }
}
```

## 三、四个核心概念

| 概念 | 作用 |
| --- | --- |
| entry | 入口，依赖分析的起点 |
| output | 输出位置与命名规则 |
| loader | 把非 JS 文件转成模块（**Webpack 只懂 JS**） |
| plugin | 介入构建生命周期的钩子，做打包以外的事 |

常用 loader：`babel-loader`、`ts-loader`、`css-loader`、`style-loader`、`sass-loader`、`postcss-loader`。
常用 plugin：`HtmlWebpackPlugin`、`MiniCssExtractPlugin`、`DefinePlugin`、`CopyWebpackPlugin`、`BundleAnalyzerPlugin`。

```js
// 动态 import 自动分包

      },

  },

```

## 六、性能优化

| 方向 | 手段 |
| --- | --- |
| 构建速度 | `cache: { type: 'filesystem' }`、`thread-loader`、babel 缓存（`cacheDirectory`）、缩小 `include/exclude` |
| 产物体积 | Tree Shaking（`sideEffects` 标记）、`splitChunks`、`MiniCssExtractPlugin`、图片压缩 |
| 运行时加载 | 懒加载、prefetch/preload、CDN externals |
| 分析 | `webpack-bundle-analyzer` |

```js
// externals：React 走 CDN 不打进包
externals: { react: 'React', 'react-dom': 'ReactDOM' }
```

## 七、Webpack vs Vite

| 维度 | Webpack | Vite |
| --- | --- | --- |
| 冷启动 | 慢（全量构建） | 毫秒级（按需） |
| HMR | 随项目增大变慢 | 恒定快 |
| 生产打包 | 自身 | Rollup |
| 生态/插件 | 最多 | 快速追赶 |
| 配置复杂度 | 高 | 低 |
| 适用 | 老项目、复杂定制 | 新项目 |

## 八、常见问题

| 问题 | 解决 |
| --- | --- |
| `Can't resolve 'xxx'` | 检查 alias、extensions、依赖是否安装 |
| 打包产物过大 | 分析 `bundle-analyzer`，做 splitChunks + 按需引入 |
| devServer 跨域 | 配置 `devServer.proxy` |
| 构建慢 | 开 filesystem cache、thread-loader、swc-loader 替代 babel-loader |
| CSS 不生效 | loader 顺序：`style-loader` 必须在前（从右往左执行） |
| 生产环境 React 报错重复 | `resolve.alias` 固定 react 单实例，或 `splitChunks` 调整 |
