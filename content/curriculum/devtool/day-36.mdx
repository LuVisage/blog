## 一、Pytest 是什么

Python 最流行的测试框架，相比内置 `unittest`：

- 用 `assert` 直接断言（无需 `self.assertEqual`）；
- fixture 机制优雅地管理测试资源；
- 参数化、插件生态极其丰富；
- 自动发现测试文件（`test_*.py` / `*_test.py`）。

## 二、安装

```powershell
# 推荐 uv
uv add --dev pytest pytest-cov
# 或 pip
pip install pytest pytest-cov
```

## 三、编写测试

`test_calculator.py`：

```python
import pytest
from calculator import add, div

def test_add():
    assert add(1, 2) == 3

def test_div_normal():
    assert div(10, 2) == 5

def test_div_by_zero():
    with pytest.raises(ZeroDivisionError):
        div(1, 0)

@pytest.mark.parametrize("a, b, expected", [
    (1, 1, 2),
    (0, 0, 0),
    (-1, 1, 0),
])
def test_add_param(a, b, expected):
    assert add(a, b) == expected
```

运行：

```powershell
pytest                          # 运行全部
pytest -v                       # 详细输出
pytest test_calculator.py       # 指定文件
pytest test_calculator.py::test_add   # 指定用例
pytest -k "add and not slow"    # 按名称过滤
pytest -x                       # 第一个失败即停止
pytest --lf                     # 只跑上次失败的
pytest -n auto                  # 并行（需 pytest-xdist）
pytest --cov=src --cov-report=html   # 覆盖率
```

## 四、Fixture（核心机制）

```python
import pytest
from myapp.db import Database

@pytest.fixture
def db():
    """每个测试一个干净数据库"""
    d = Database(":memory:")
    d.init_schema()
    yield d          # yield 前是 setup，后是 teardown
    d.close()

def test_insert(db):
    db.insert("users", {"name": "Ada"})
    assert db.count("users") == 1

# 作用域：function（默认）/ class / module / session
@pytest.fixture(scope="session")
def api_client():
    client = APIClient("https://test.local")
    yield client
    client.close()

# 带参数 fixture
@pytest.fixture(params=["sqlite", "postgres"])
def any_db(request):
    yield make_db(request.param)
```

`conftest.py` 中定义的 fixture 对整个目录生效，无需 import。

## 五、标记与跳过

```python
@pytest.mark.slow
def test_big_job():
    ...

@pytest.mark.integration
def test_db_roundtrip():
    ...

@pytest.mark.skip(reason="尚未实现")
def test_todo():
    ...

@pytest.mark.skipif(sys.platform == "win32", reason="不支持 Windows")
def test_unix_only():
    ...

@pytest.mark.xfail(reason="已知缺陷 #123")
def test_known_bug():
    ...
```

`pytest.ini` / `pyproject.toml`：

```toml
[tool.pytest.ini_options]
testpaths = ["tests"]
addopts = "-ra -q --strict-markers"
markers = [
  "slow: 耗时测试",
  "integration: 需要外部依赖",
]
```

运行指定标记：

```powershell
pytest -m "not slow"            # CI 快速通道
pytest -m integration
```

## 六、Mock

内置 `unittest.mock`：

```python
from unittest.mock import patch, MagicMock

def test_send_email(mocker=None):
    with patch("myapp.mail.smtp_send") as mock_send:
        send_welcome("a@b.com")
        mock_send.assert_called_once_with("a@b.com", subject="欢迎")

# 或用 pytest-mock 插件（fixture 风格）
def test_send_email(mocker):
    mock_send = mocker.patch("myapp.mail.smtp_send")
    send_welcome("a@b.com")
    mock_send.assert_called_once()
```

## 七、异步测试

```powershell
pip install pytest-asyncio
```

```python
import pytest

@pytest.mark.asyncio
async def test_fetch_user():
    user = await fetch_user(1)
    assert user["name"] == "Ada"
```

`pyproject.toml` 中配置 `asyncio_mode = "auto"` 可省去装饰器。

## 九、常见问题

| 问题 | 解决 |
| --- | --- |
| `ModuleNotFoundError: myapp` | 项目根目录执行；或配置 `pythonpath = ["src"]`（pytest 7+） |
| fixture 找不到 | 检查 `conftest.py` 位置（应在测试目录或其上层） |
| 测试间相互污染 | fixture 默认 function 作用域；避免模块级可变全局 |
| 异步测试报 `coroutine was never awaited` | 装 `pytest-asyncio` 并加 marker |
| 覆盖率统计了 tests 目录 | `--cov=src` 明确指定源码目录 |
| 并行测试出错 | 检查共享资源（文件、DB）冲突；给每个 worker 独立资源 |

## 十、最佳实践

1. 目录结构：`src/myapp/` + `tests/test_*.py`，与源码分离但对应。
2. 一个测试函数只验证一个行为，命名 `test_<行为>_<条件>_<期望>`。
3. 用 fixture 管理资源与数据构造，避免每个测试重复 setup 代码。
4. 外部依赖（HTTP、DB、时间）一律 mock 或隔离。
5. CI 分层：快速单测每次提交跑，`-m integration` 的集成测试按需跑。
