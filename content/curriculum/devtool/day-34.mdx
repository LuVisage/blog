## 一、Testing Library 是什么

一套**以用户视角测试 UI 组件**的工具库，适用于 React / Vue / Svelte / Angular 等（`@testing-library/react`、`@testing-library/vue`...）。

核心理念（官方口号）：

> **The more your tests resemble the way your software is used, the more confidence they can give you.**
> 测试越接近用户真实使用方式，越能给你信心。

实践含义：
- 通过**可见文本、角色、标签**找元素，而不是 class / 组件内部 state；
- 不测实现细节（私有方法、内部变量）；
- 重构 UI 结构时测试不容易坏。

## 二、安装

```powershell
# React + Vitest
pnpm add -D @testing-library/react @testing-library/jest-dom @testing-library/user-event jsdom

# React + Jest（jest-dom 引入方式见下）
pnpm add -D @testing-library/react @testing-library/jest-dom @testing-library/user-event
```

setup 文件：

```ts
// Vitest: src/test/setup.ts
import '@testing-library/jest-dom/vitest';
// Jest: 直接 import '@testing-library/jest-dom';
```

## 三、查询（Queries）优先级

官方推荐顺序：

1. **`getByRole`** —— 无障碍角色（button、textbox、heading、link...），最推荐；
2. **`getByLabelText`** —— 表单元素关联 label；
3. **`getByPlaceholderText`**；
4. **`getByText`** —— 非表单元素的文本；
5. **`getByDisplayValue`** —— 表单当前值；
6. **`getByAltText`** / **`getByTitle`** —— 图片/标题；
7. **`getByTestId`** —— 兜底手段（上述都不可用时）。

变体：

| 前缀 | 行为 |
| --- | --- |
| `getBy...` | 找不到即抛错（同步） |
| `queryBy...` | 找不到返回 null（用于断言不存在） |
| `findBy...` | 返回 Promise，等待出现（异步场景） |
| `getAllBy...` | 返回数组 |

## 四、基本测试写法

```tsx
import { render, screen } from '@testing-library/react';
import userEvent from '@testing-library/user-event';
import { Counter } from './Counter';

test('点击按钮数字加一', async () => {
  const user = userEvent.setup();
  render(<Counter />);

  // 断言初始状态
  expect(screen.getByRole('heading')).toHaveTextContent('0');

  // 用户操作
  await user.click(screen.getByRole('button', { name: '加一' }));

  // 断言结果
  expect(screen.getByRole('heading')).toHaveTextContent('1');
});

test('输入非法邮箱显示错误', async () => {
  const user = userEvent.setup();
  render(<SignupForm />);

  await user.type(screen.getByLabelText('邮箱'), 'not-an-email');
  await user.click(screen.getByRole('button', { name: '提交' }));

  expect(await screen.findByText('邮箱格式不正确')).toBeInTheDocument();
});

test('加载完成后显示数据', async () => {
  render(<UserList />);
  expect(screen.getByText('加载中...')).toBeInTheDocument();
  expect(await screen.findByText('Ada')).toBeInTheDocument();
});
```

## 五、user-event vs fireEvent

优先用 **user-event**：它模拟真实用户行为（点击会触发 focus、hover 等完整事件链）。

```ts
// 推荐
const user = userEvent.setup();
await user.click(btn);
await user.type(input, 'hello');
await user.clear(input);
await user.selectOptions(select, 'shanghai');
await user.tab();
await user.keyboard('{Enter}');

// 不推荐（除非测特定底层事件）
fireEvent.click(btn);
```

## 六、jest-dom 常用断言

```ts
expect(el).toBeInTheDocument();
expect(el).toBeVisible();
expect(el).toBeDisabled();
expect(el).toBeChecked();
expect(el).toHaveTextContent('文字');
expect(el).toHaveValue('值');
expect(el).toHaveClass('active');
expect(el).toHaveAttribute('href', '/x');
expect(el).toHaveStyle({ color: 'red' });
expect(el).toBeEmptyDOMElement();
expect(el).toHaveFocus();
```

## 七、测试自定义 Hook（React）

```ts
import { renderHook, act } from '@testing-library/react';
import { useCounter } from './useCounter';

test('useCounter 可自增', () => {
  const { result } = renderHook(() => useCounter(0));

  act(() => result.current.inc());
  expect(result.current.count).toBe(1);
});
```

## 八、异步与等待

```ts
// 等元素出现
await screen.findByText('完成');

// 等断言通过（重试直到超时）
await waitFor(() => expect(screen.getByText('已完成')).toBeVisible());

// 等元素消失
await waitForElementToBeRemoved(() => screen.queryByText('加载中'));
```

> 不要在测试里 `await new Promise(r => setTimeout(r, 1000))` —— 用 `findBy` / `waitFor`。

## 九、常见问题

| 问题 | 解决 |
| --- | --- |
| `Unable to find an element` | 用 `screen.debug()` 打印 DOM 排查；检查是否有多个匹配 |
| 多个元素匹配报错 | 收窄查询条件（`{ name: /确定$/ }` 或用 `within()` 限定范围） |
| 异步数据测不到 | 用 `findBy*` 或 `waitFor` |
| 报 `not wrapped in act(...)` | 交互一律 `await user.xxx()`；状态更新用 `await waitFor` |
| 想测实现细节 | 换思路：从用户视角描述场景 |
| 表单 label 关联不上 | 组件里用 `<label htmlFor>` 或 `aria-label` |

## 十、最佳实践

1. **只与 DOM 交互，不碰组件内部**（不要 `component.state`）。
2. 一次测试只走一条用户路径。
3. 断言用户可见结果（文本、可见性、禁用态），而非内部 props。
4. `within()` 缩小查询范围，避免全局碰撞。
5. 组件测试负责分支与交互；视觉回归交给 Playwright 截图。
