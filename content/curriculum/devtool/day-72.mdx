## 一、Sentry 是什么

错误监控与性能追踪平台，核心能力：

- **异常聚合**：同样的错误合并成一条，显示发生次数、影响用户数、首次/最近出现时间；
- **完整上下文**：堆栈、用户信息、请求参数、浏览器/系统版本、面包屑（用户操作路径）；
- **Source Map 还原**：前端压缩代码也能看到原始堆栈；
- **性能追踪**：慢事务、慢接口、慢组件渲染；
- **告警**：错误暴增时自动通知（钉钉/飞书/Slack/邮件）。

支持前端（React/Vue）、后端（Node/Python/Go/Java）、移动端（iOS/Android/Flutter）。

## 二、接入（以 React 为例）

```powershell
pnpm add @sentry/react
```

```tsx
// src/main.tsx
import * as Sentry from '@sentry/react';

Sentry.init({
  dsn: import.meta.env.VITE_SENTRY_DSN,
  environment: import.meta.env.MODE,          // development / production
  release: import.meta.env.VITE_APP_VERSION,  // 版本号，用于定位回归
  integrations: [
    Sentry.browserTracingIntegration(),
    Sentry.replayIntegration({ maskAllText: true, blockAllMedia: true }),
  ],
  tracesSampleRate: 0.1,          // 采样率：生产 10%，避免配额爆炸
  replaysSessionSampleRate: 0.05,
  replaysOnErrorSampleRate: 1.0,  // 出错时 100% 录制会话回放
  beforeSend(event) {
    if (event.user?.email) delete event.user.email;   // 脱敏
    return event;
  },
});
```

### 手动上报

```ts
try {
  await submitOrder(order);
} catch (err) {
  Sentry.captureException(err, {
    tags: { module: 'order' },
    extra: { orderId: order.id },
  });
  throw err;
}

Sentry.captureMessage('库存同步异常', 'warning');
Sentry.setUser({ id: user.id, username: user.name });
Sentry.addBreadcrumb({ category: 'ui', message: '点击结算按钮' });
```

### Error Boundary

```tsx
import * as Sentry from '@sentry/react';

<Sentry.ErrorBoundary fallback={<ErrorPage />} showDialog>
  <App />
</Sentry.ErrorBoundary>
```

## 三、上传 Source Map（关键）

Vite 项目：

```powershell
pnpm add -D @sentry/vite-plugin
```

```ts
// vite.config.ts
import { sentryVitePlugin } from '@sentry/vite-plugin';

export default defineConfig({
  build: { sourcemap: true },
  plugins: [
    react(),
    sentryVitePlugin({
      org: 'my-org',
      project: 'my-app',
      authToken: process.env.SENTRY_AUTH_TOKEN,
      release: { name: process.env.VITE_APP_VERSION },
    }),
  ],
});
```

CI 中设置 `SENTRY_AUTH_TOKEN` secret。**上传后必须删除 dist 中的 .map 文件**（避免源码泄露），Sentry 插件可配置 `sourcemaps.filesToDeleteAfterUpload`。

## 五、Sentry 平台使用

### 错误处理流程

```
1. Issues 列表：按频率/影响用户数排序
2. 点进去看：
   - Stack Trace（含源代码上下文）
   - Breadcrumbs（用户操作时间线）
   - Tags（版本、环境、浏览器）
   - Device / OS 信息
3. 处理动作：
   - Resolve（已修复，指定下一个版本）
   - Ignore（噪音，如浏览器扩展报错）
   - Assign（指派给同事）
   - Merge（合并重复 issue）
4. 集成到 GitHub/Jira（一键建 issue）
```

### 降噪技巧

```ts
Sentry.init({
  ignoreErrors: [
    'ResizeObserver loop limit exceeded',
    'Non-Error promise rejection captured',
    /^Network Error$/,
  ],
  denyUrls: [/extensions\//i, /^chrome:\/\//i],   // 浏览器扩展报错
});
```

### 告警配置

`Alerts → Create Alert`：

| 规则类型 | 场景 |
| --- | --- |
| 错误数阈值（如 5 分钟 > 100） | 突发故障 |
| 新 Issue 首次出现 | 上线引入新问题 |
| 影响用户数 > N | 影响面评估 |
| 性能 P95 超标 | 性能回归 |

通知渠道可接 Slack / 飞书 Webhook / 邮件。

## 六、性能监控

```ts
// 自定义事务
const transaction = Sentry.startInactiveSpan({ name: 'loadUserProfile', op: 'http' });
await fetchProfile();
transaction.end();
```

Sentry 会展示：
- **P50 / P75 / P95 / P99** 延迟；
- 慢事务列表与瀑布图；
- Web Vitals（LCP、FID、CLS）。

## 七、最佳实践

1. **一定要配 release + source map**，否则堆栈无意义；
2. **采样率控制成本**：错误 100% 上报，性能追踪 5-20%；
3. **脱敏**：`beforeSend` 中删除密码、token、身份证等字段；
4. **区分环境**：development/staging/production 分开，避免噪音；
5. **配额告警**：Sentry 免费额度有限（5k errors/月），设置用量提醒；
6. 国内可考虑 **自建 Sentry**（Docker 部署）或国产替代（如阿里云 ARMS）。

## 八、自建 Sentry（Docker）

```powershell

```

## 九、常见问题

| 问题 | 解决 |
| --- | --- |
| 前端堆栈是压缩代码 | 未上传 source map 或 release 不匹配 |
| 报错量爆炸 | 调采样率、加 ignoreErrors、检查是否有循环报错 |
| 本地开发一直上报 | 只在生产 init，或用 `enabled: import.meta.env.PROD` |
| 用户信息缺失 | `Sentry.setUser()` 登录后调用 |
| 免费额度不够 | 降采样率、过滤噪音错误、自建 |
| Source map 泄露源码 | 上传后从部署产物中删除 .map |
