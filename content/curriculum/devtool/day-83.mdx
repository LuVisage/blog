## 一、工具定位

| 工具 | 定位 | 特点 |
| --- | --- | --- |
| Slack | 团队即时沟通 | 频道制、集成生态最强、国外主流 |
| 飞书 | 一体化协作平台 | 即时沟通 + 文档 + 日历 + 审批 + 多维表格，国内主流 |
| Notion | 知识库与协作文档 | 块编辑器、数据库视图、模板生态 |

**关系**：Slack/飞书负责「同步沟通」，Notion/飞书文档负责「异步沉淀」。

## 二、Slack 使用

### 频道组织

```
#general           公司公告（全员必读）
#team-frontend     团队频道（日常沟通）
#proj-order-v2     项目频道（一项目一频道）
#deploy            部署通知（CI/机器人）
#alerts            监控告警（Sentry/Prometheus）
#random            生活闲聊
```

命名规范：`#proj-*` 项目、`#team-*` 团队、`#bot-*` 机器人。

### 核心技巧

| 技巧 | 说明 |
| --- | --- |
| 线程（Thread） | 回复用线程，避免刷屏（Slack 核心礼仪） |
| @ 提及 | `@someone` 指名、`@channel` 全体（慎用）、`@here` 在线者 |
| 消息格式化 | `**粗体**`、`` `代码` `` 、``` ```代码块``` ```、`> 引用` |
| 快捷命令 | `/remind`、`/poll`、`/status`、`/away` |
| 保存消息 | 悬停 → 书签图标（Later 列表） |
| 搜索语法 | `from:@user`、`in:#channel`、`has:link`、`before:2026-09-01` |

### 集成与自动化

| 集成 | 用途 |
| --- | --- |
| GitHub/GitLab | PR 创建、合并、CI 结果通知 |
| Sentry | 错误告警 |
| Prometheus/Grafana | 指标告警 |
| Jira/Linear | 任务更新通知 |
| Google Drive | 文档分享预览 |

Webhook 示例（发消息到频道）：

```powershell
curl.exe -X POST -H "Content-Type: application/json" `
  -d '{\"text\":\"部署完成: v1.2.3\"}' `
  https://hooks.slack.com/services/T00/B00/XXXX
```

### 使用礼仪

1. **提问直接问**（Don't ask to ask）；
2. 复杂讨论**开线程**，别在主干刷屏；
3. 重要结论**沉淀到文档**并回帖链接；
4. 非紧急别 @channel；
5. 状态设为「专注中」时减少被打扰（配合通知设置）。

## 三、飞书使用

### 核心模块

| 模块 | 用途 |
| --- | --- |
| 消息 | 单聊/群聊，支持话题、快捷表情回复 |
| 云文档 | 协作文档（类 Notion/Google Docs） |
| 多维表格 | 表格 + 数据库（项目管理、需求池） |
| 日历 | 会议安排、会议室预订 |
| 视频会议 | 妙记（自动转写会议纪要） |
| 审批 | 请假、报销等流程 |
| 机器人/开放平台 | 自定义通知与自动化 |

### 高效用法

| 功能 | 说明 |
| --- | --- |
| 群机器人 Webhook | 部署/告警通知（最常用） |
| 消息话题 | 长讨论聚合 |
| 置顶 + 群公告 | 重要信息不丢 |
| 文档协作 | 多人实时编辑、评论、@人 |
| 妙记 | 会议自动生成纪要（转写 + 待办） |
| 知识库 | 团队文档统一管理（Wiki） |
| 快捷指令 | `/` 唤起功能 |

Webhook 通知示例：

```powershell
curl.exe -X POST -H "Content-Type: application/json" `
  -d '{\"msg_type\":\"text\",\"content\":{\"text\":\"API 错误率超过 5%\"}}' `
  https://open.feishu.cn/open-apis/bot/v2/hook/xxxx
```

卡片消息（更美观，用于告警）：

```json
{
  "msg_type": "interactive",
  "card": {
    "header": {
      "title": { "tag": "plain_text", "content": "部署通知" },
      "template": "green"
    },
    "elements": [
      { "tag": "div", "text": { "tag": "lark_md",
        "content": "**服务**: order-api\n**版本**: v1.2.3\n**环境**: production\n**状态**: 成功" } }
    ]
  }
}
```

### 与研发流程结合

- CI/CD 完成 → 群机器人发卡片；
- 监控告警 → 飞书群 + 电话升级（值班）；
- 需求评审 → 飞书文档 + 评论；
- 周报 → 多维表格自动汇总。

## 四、Notion 使用

### 核心概念

| 概念 | 说明 |
| --- | --- |
| Page / Block | 页面与块（一切皆块，可拖拽嵌套） |
| Database | 数据库（表格/看板/日历/画廊多视图） |
| Template | 模板（一键创建规范文档） |
| Relations / Rollup | 数据库关联与汇总 |
| Synced Block | 同步块（一处修改多处更新） |

### 团队空间结构建议

```
📁 团队主页
├── 📄 新人入职指南（环境搭建、账号申请、常用链接）
├── 📁 产品
│   ├── 📄 需求文档（Database：状态/负责人/优先级）
│   └── 📄 竞品调研
├── 📁 研发
│   ├── 📄 架构决策记录（ADR）
│   ├── 📄 API 文档索引
│   ├── 📄 部署手册 / 应急预案
│   └── 📄 技术分享（每周）
├── 📁 会议纪要（Database：日期/参与人/行动项）
└── 📁 规章制度
```

### 常用模板

**周报模板**：

```markdown
## 本周完成
- [ ] xxx

## 下周计划
- [ ] xxx

## 阻塞与风险
- xxx

## 需要协助
- xxx
```

**技术方案模板（RFC）**：

```markdown
# 方案名称：订单导出性能优化

## 背景与问题
当前导出 10 万单耗时 3 分钟，超时频繁。

## 目标
P95 < 30 秒，支持 100 万单。

## 方案对比
| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| 异步任务 + 轮询 | 实现简单 | 用户等待感强 |
| 流式导出（CSV 边查边写） | 内存友好、速度快 | 需改造查询 |

## 结论
采用流式导出 + 游标分页。

## 影响与风险
- 需新增索引 (user_id, created_at)
- 网关需放开长连接超时

## 排期
设计 1d / 开发 3d / 测试 2d
```

**会议纪要模板**：

```markdown
# 2026-09-14 订单模块周会

参与人：@张 @李 @王

## 议题
1. 导出优化方案评审
2. 下周发布计划

## 结论
- 采用流式导出方案（详见 RFC 链接）
- 发布定于周四晚 20:00

## 行动项
- [ ] @张 完成索引变更脚本（9/16）
- [ ] @李 补充压测报告（9/17）
```

（飞书文档同样适用以上模板。）

## 五、沟通与文档的分工

| 类型 | 工具 | 原则 |
| --- | --- | --- |
| 即时问题、快速确认 | Slack / 飞书消息 | 5 分钟内能说清的用消息 |
| 需要多人讨论的方案 | 文档 + 评论 | 异步评审，留痕 |
| 决策记录 | 文档（ADR） | 写清「为什么这么决定」 |
| 例行通知 | 机器人 Webhook | 自动化，不靠人肉同步 |
| 紧急故障 | 电话 / 视频会议 | 先解决问题，事后补文档 |

**核心原则**：

> 讨论可以发生在聊天里，但**结论必须写进文档**。

## 六、常见问题

| 问题 | 解决 |
| --- | --- |
| 消息太吵 | 精简频道、关闭非关键通知、用线程 |
| 文档找不到 | 建立统一入口（团队主页）；命名规范；定期整理 |
| 文档过时 | 每篇文档标记负责人与更新时间；季度审查 |
| 信息孤岛 | 避免私聊决策；重要结论回帖到频道 |
| 机器人通知刷屏 | 分级：一般通知进 #alerts，严重才 @人；开启聚合 |
| 飞书/Slack 混用 | 公司统一一个为主，跨公司协作用另一个 |
