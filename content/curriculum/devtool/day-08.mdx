## 一、四者对比

| 工具 | 安装方式 | 磁盘占用 | 速度 | 特点 |
| --- | --- | --- | --- | --- |
| npm | 随 Node 自带 | 高（每项目独立拷贝） | 一般 | 官方标配，最稳定 |
| pnpm | 独立安装 | 极低（全局硬链接） | 快 | 严格依赖隔离，monorepo 首选 |
| yarn（v1 / Berry） | 独立安装 | 中 | 快 | 老牌，Berry 支持 PnP 零 node_modules |
| bun | 独立安装 | 低 | 最快 | 集运行时/包管理/测试于一体 |

## 二、npm

```powershell
npm -v
npm init -y                       # 生成 package.json
npm install                       # 安装 package.json 中所有依赖
npm install express               # 生产依赖
npm install -D typescript         # 开发依赖
npm install -g pnpm               # 全局安装
npm uninstall express
npm update
npm run dev                       # 运行 package.json scripts
```

常用补充：

```powershell
npm ci                # CI 专用：严格按 lock 文件安装，比 install 快且可复现
npm ls --depth=0      # 查看顶层依赖
npm outdated          # 检查可升级依赖
npm audit             # 安全漏洞检查
npm audit fix
npm cache clean --force
npm config set registry https://registry.npmmirror.com   # 国内镜像
```

`package.json` 版本号语义（semver）：

```
^1.2.3  允许 1.x.x 升级（不改变主版本）
~1.2.3  允许 1.2.x 升级
1.2.3   锁定精确版本
*       任意版本（不推荐）
```

## 三、pnpm（推荐）

```powershell
# 安装
winget install pnpm.pnpm
# 或 corepack enable && corepack prepare pnpm@latest --activate
# 或 npm install -g pnpm
```

```powershell
pnpm install            # 安装（内容寻址存储 + 硬链接，秒级）
pnpm add axios
pnpm add -D vitest
pnpm remove axios
pnpm run build
pnpm -r build           # 递归在所有 workspace 包中执行
pnpm --filter web dev   # 只对 web 包执行
```

常用配套：

```powershell
pnpm dlx create-vite    # 不安装直接执行（类似 npx）
pnpm approve-builds     # pnpm v10 后需显式允许依赖的 postinstall 脚本
pnpm store prune        # 清理未使用缓存
```

`pnpm-workspace.yaml`（monorepo）：

```yaml
packages:
  - "apps/*"
  - "packages/*"
```

优势：
- 全局只存一份包内容（`~/.pnpm-store`），项目里是硬链接，**节省大量磁盘**；
- 默认禁止访问未声明的依赖（幽灵依赖问题），更严谨。

## 四、yarn

```powershell
corepack enable
corepack prepare yarn@4 --activate    # 现代推荐方式
# 或 npm install -g yarn
```

```powershell
yarn                    # 安装依赖
yarn add react
yarn add -D eslint
yarn remove react
yarn up react           # 升级
yarn dlx create-next-app
```

`.yarnrc.yml`（Berry 常用配置）：

```yaml
nodeLinker: node-modules     # 默认 PnP，改成 node-modules 兼容性更好
enableGlobalCache: true
npmRegistryServer: "https://registry.npmmirror.com"
```

## 五、bun

```powershell
# Windows
powershell -c "irm bun.sh/install.ps1 | iex"
# macOS/Linux
curl -fsSL https://bun.sh/install | bash
```

```powershell
bun install             # 安装依赖（极快）
bun add zod
bun add -d @types/node
bun remove zod
bun run dev
bun test                # 内置测试框架
bunx create-vite        # 类似 npx
```

> bun 同时是运行时：`bun run index.ts` 可直接执行 TypeScript。

## 六、锁定与一致性（团队/CI 必读）

| 工具 | 锁文件 | CI 严格安装命令 |
| --- | --- | --- |
| npm | package-lock.json | `npm ci` |
| pnpm | pnpm-lock.yaml | `pnpm install --frozen-lockfile` |
| yarn | yarn.lock | `yarn install --immutable` |
| bun | bun.lock | `bun install --frozen-lockfile` |

**锁文件必须提交进 Git**，且团队统一包管理器（用 `packageManager` 字段约束）：

```json
{
  "packageManager": "pnpm@9.1.0"
}
```

配合 corepack 后，其他成员误用 npm 会被拦截。

## 七、常见问题

| 问题 | 解决 |
| --- | --- |
| 安装卡住 / 下载慢 | 切换 npmmirror 镜像；检查代理 |
| `ERESOLVE unable to resolve dependency tree` | 依赖冲突，先试 `npm install --legacy-peer-deps`，长期方案是修版本约束 |
| node_modules 删不掉（Windows） | 关闭占用进程；`npx rimraf node_modules` |
| pnpm 装完依赖后某些包构不出二进制 | `pnpm approve-builds` 放行对应包 |
| 公司私有包 404 | 配置 `.npmrc`（`@corp:registry=https://npm.company.com`） |
| 意外升级依赖导致线上问题 | CI 用 frozen lockfile；升级走 PR + review |

## 八、最佳实践

1. **一个项目只用一种包管理器**，用 `packageManager` 字段固定。
2. **不要在 CI 里跑 `npm update`**，锁文件是唯一事实来源。
3. monorepo 用 **pnpm workspace**（或 yarn/npm workspaces），避免多仓库同步问题。
4. 依赖定期升级：`npm outdated` → 小步升级 → 跑测试。
5. 提交前检查是否有 `node_modules` 误入 Git（`.gitignore`）。
