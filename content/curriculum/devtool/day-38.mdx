## 一、Go 测试的特点

Go **内置**测试框架，无需第三方库即可完成：单元测试、基准测试、示例测试、覆盖率、竞态检测。

约定：
- 测试文件命名 `xxx_test.go`；
- 测试函数命名 `TestXxx(t *testing.T)`；
- 与被测文件同目录、同包（也可用 `_test` 后缀包做黑盒测试）。

## 二、基本测试

`calc.go`：

```go
package calc

func Add(a, b int) int { return a + b }

func Div(a, b int) (int, error) {
	if b == 0 {
		return 0, fmt.Errorf("division by zero")
	}
	return a / b, nil
}
```

`calc_test.go`：

```go
package calc

import "testing"

func TestAdd(t *testing.T) {
	got := Add(1, 2)
	if got != 3 {
		t.Errorf("Add(1,2) = %d, want 3", got)
	}
}

func TestDivByZero(t *testing.T) {
	_, err := Div(1, 0)
	if err == nil {
		t.Fatal("expected error, got nil")
	}
}
```

> `t.Errorf` 继续执行；`t.Fatalf` 立即终止当前测试。

## 三、表驱动测试（Go 惯用法）

```go
func TestAdd(t *testing.T) {
	tests := []struct {
		name string
		a, b int
		want int
	}{
		{"正数", 1, 2, 3},
		{"负数", -1, 1, 0},
		{"零", 0, 0, 0},
	}

	for _, tt := range tests {
		t.Run(tt.name, func(t *testing.T) {
			if got := Add(tt.a, tt.b); got != tt.want {
				t.Errorf("Add(%d,%d) = %d, want %d", tt.a, tt.b, got, tt.want)
			}
		})
	}
}
```

## 四、常用命令

```powershell
go test ./...                    # 测试所有包
go test -v ./...                 # 详细输出
go test -run TestAdd ./calc      # 按名称过滤
go test -run 'TestAdd/正数' ./calc   # 子测试过滤
go test -count=1 ./...           # 禁用缓存，强制重跑
go test -race ./...              # 竞态检测（重要！）
go test -cover ./...             # 覆盖率
go test -coverprofile=cover.out ./... && go tool cover -html=cover.out
go test -short ./...             # 跳过标记为 -short 的重测试
go test -timeout 30s ./...
```

## 五、基准测试

```go
func BenchmarkAdd(b *testing.B) {
	for i := 0; i < b.N; i++ {
		Add(1, 2)
	}
}

// 带子基准
func BenchmarkStringJoin(b *testing.B) {
	for _, n := range []int{10, 100, 1000} {
		b.Run(fmt.Sprintf("n=%d", n), func(b *testing.B) {
			for i := 0; i < b.N; i++ {
				strings.Join(make([]string, n), ",")
			}
		})
	}
}
```

```powershell
go test -bench=. -benchmem ./...
# 输出：ns/op 表示单次耗时，B/op、allocs/op 为内存分配
```

## 六、示例测试（生成文档）

```go
func ExampleAdd() {
	fmt.Println(Add(1, 2))
	// Output: 3
}
```

`go test` 会验证 `// Output:` 注释与实际输出是否一致，同时出现在 godoc 里。

## 七、测试辅助

**跳过与并行**：

```go
func TestSlow(t *testing.T) {
	if testing.Short() {
		t.Skip("skipping in short mode")
	}
	// ...
}

func TestParallel(t *testing.T) {
	t.Parallel()   // 标记可并行
	// ...
}
```

**临时目录**：

```go
func TestWriteFile(t *testing.T) {
	dir := t.TempDir()          // 测试结束自动清理
	path := filepath.Join(dir, "a.txt")
	os.WriteFile(path, []byte("hi"), 0o644)
}
```

**testify（可选，断言更省事）**：

```go
import "github.com/stretchr/testify/assert"
import "github.com/stretchr/testify/require"

assert.Equal(t, 3, Add(1, 2))
require.NoError(t, err)      // 失败立即终止
```

**gomock / mockery（接口 Mock）**：

```powershell
mockgen -source=repository.go -destination=mocks/repository_mock.go
```


## 九、常见问题

| 问题 | 解决 |
| --- | --- |
| 测试结果被缓存（改了代码没重跑） | `-count=1` |
| 覆盖率统计到测试文件 | 覆盖率默认排除 `_test.go`，但会把未测试代码算作 0%，可接受 |
| 偶发失败（flaky） | 用 `-race` 排查数据竞争；检查共享状态与时间依赖 |
| 单测依赖真实 DB | 用接口 + mock；或 testcontainers-go 起临时容器 |
| `t.Fatal` 在子测试里的行为 | 子测试中只终止该子测试，符合预期 |
| 并行测试数据竞争 | 循环变量需 `tt := tt`（Go 1.22 已修复）；共享资源加锁或隔离 |

## 十、最佳实践

1. **表驱动测试**是 Go 社区标准写法，覆盖边界值。
2. 测试文件与源码同目录，包名相同（可访问未导出成员）。
3. CI 固定加 `-race`，早发现并发问题。
4. 用 `httptest` 测 HTTP handler，用接口 + mock 隔离外部依赖。
5. 覆盖率作为参考：核心包目标 80%+，handler/胶水层不必强求。
