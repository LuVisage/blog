## 一、Jest 是什么

Facebook 出品的 JS/TS 测试框架，特点是**开箱即用**：断言、Mock、快照、覆盖率、并行执行全部内置。是目前生态最成熟的 JS 测试工具，CRA、React Native、大量存量项目默认使用。

## 二、安装与初始化

```powershell
pnpm add -D jest @types/jest ts-jest
# React 项目
pnpm add -D jest-environment-jsdom @testing-library/react @testing-library/jest-dom
```

TypeScript 项目初始化：

```powershell
npx ts-jest config:init
```

## 三、配置

`jest.config.ts`：

```ts
import type { Config } from 'jest';

const config: Config = {
  preset: 'ts-jest',
  testEnvironment: 'jsdom',
  roots: ['<rootDir>/src'],
  testMatch: ['**/*.test.ts', '**/*.test.tsx'],
  setupFilesAfterEnv: ['<rootDir>/src/test/setup.ts'],
  moduleNameMapper: {
    '^@/(.*)$': '<rootDir>/src/$1',
    '\\.(css|less|scss)$': 'identity-obj-proxy',
    '\\.(png|jpg|svg)$': '<rootDir>/src/test/fileMock.ts',
  },
  transform: {
    '^.+\\.tsx?$': ['ts-jest', { tsconfig: 'tsconfig.test.json' }],
  },
  collectCoverageFrom: ['src/**/*.{ts,tsx}', '!src/**/*.d.ts'],
  coverageThreshold: {
    global: { lines: 70, functions: 70 },
  },
};

export default config;
```

> 大型项目建议 `ts-jest` 换 `@swc/jest`（快 10x 以上）：

```ts
transform: { '^.+\\.(t|j)sx?$': '@swc/jest' }
```

## 四、编写测试

```ts
describe('购物车', () => {
  let cart: Cart;

  beforeEach(() => {
    cart = new Cart();
  });

  test('添加商品后总价正确', () => {
    cart.add({ name: '书', price: 50 });
    cart.add({ name: '笔', price: 5 });
    expect(cart.total()).toBe(55);
  });

  test('移除不存在的商品不报错', () => {
    expect(() => cart.remove('nope')).not.toThrow();
  });

  test.each([1, 2, 3])('数量 %i 的折扣计算', (n) => {
    expect(cart.discount(n)).toBeGreaterThanOrEqual(0);
  });
});
```

### 异步测试

```ts
test('异步获取', async () => {
  await expect(fetchUser(1)).resolves.toMatchObject({ id: 1 });
});

test('回调风格', (done) => {
  fetchUser(1, (err, user) => {
    expect(user.id).toBe(1);
    done();
  });
});
```

### Mock

```ts
// 函数 Mock
const mockFn = jest.fn().mockReturnValue(1);
const mockAsync = jest.fn().mockResolvedValue({ ok: true });

// 模块 Mock
jest.mock('./api');
import { fetchUser } from './api';
(fetchUser as jest.Mock).mockResolvedValue({ id: 1 });

// 局部 Mock
jest.mock('./utils', () => ({
  ...jest.requireActual('./utils'),
  now: () => 1700000000000,
}));

// spy
const spy = jest.spyOn(console, 'error').mockImplementation(() => {});

// 定时器
jest.useFakeTimers();
jest.advanceTimersByTime(1000);
```

### 快照

```ts
test('组件渲染快照', () => {
  const { asFragment } = render(<Button>OK</Button>);
  expect(asFragment()).toMatchSnapshot();
});
// 更新：jest -u
```

## 五、常用命令

```powershell
jest                       # 运行全部（watch 需 --watch）
jest --watch               # 监听模式
jest --coverage
jest src/utils             # 按路径过滤
jest -t "购物车"            # 按名称过滤
jest -u                    # 更新快照
jest --clearCache
jest --runInBand           # 串行（排查并发问题时）
jest --onlyChanged         # 只跑改动相关的（需 git）
```

## 七、Jest vs Vitest

| 维度 | Jest | Vitest |
| --- | --- | --- |
| 生态成熟度 | 极高 | 高 |
| 速度（TS 项目） | 中（需转换） | 快 |
| ESM | 需配置开关，易踩坑 | 原生 |
| 配置 | 独立一份 | 复用 Vite 配置 |
| 覆盖面 | React Native / 老项目 | Vite 新项目 |

**结论**：新项目（尤其 Vite）用 Vitest；React Native / 大型 jest 存量项目继续 Jest。

## 八、常见问题

| 问题 | 解决 |
| --- | --- |
| `Cannot use import statement outside a module` | 配 ts-jest/babel-jest；node_modules 里的 ESM 包加 `transformIgnorePatterns` 白名单 |
| `SyntaxError: Unexpected token 'export'` | 同上，把该包加入 transform 白名单 |
| jsdom 里 `matchMedia` 未定义 | setup 文件里 mock 掉 |
| 测试莫名串行慢 | 检查 `testEnvironment` 全部 jsdom 的开销；纯逻辑用 `node` 环境 |
| mock 不生效 | `jest.mock` 提升；检查路径大小写、模块缓存 `jest.resetModules()` |
| 覆盖率统计了无关文件 | `collectCoverageFrom` 明确包含范围 |

## 九、最佳实践

1. 每个测试文件独立、无执行顺序依赖。
2. `beforeEach` 中清理 mock：`jest.clearAllMocks()`。
3. 测试命名用中文/英文完整描述行为。
4. 快照测试只用于稳定 UI，避免频繁 `-u`。
5. 大项目用 `--onlyChanged` + CI 分片（`--shard=1/3`）加速。
