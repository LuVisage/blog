## 2.2 为什么需要装饰器

**问题**：有些逻辑需要「包在」很多函数外面。

```
需要"包在外面"的逻辑:
  · 记录日志
  · 统计耗时
  · 失败重试
  · 结果缓存
  · 限流
  · 鉴权
  · 事务管理
```

**这叫「横切关注点」（cross-cutting concern）** —— 它不属于任何单个函数的业务逻辑，但很多函数都需要。

**不用装饰器的写法**（重复代码）：

```python
def fetch_user(uid):
    start = time.time()
    try:
        result = _do_fetch_user(uid)
    except Exception:
        logger.exception("fetch_user failed")
        raise
    finally:
        logger.info(f"fetch_user took {time.time() - start:.3f}s")
    return result

def fetch_order(oid):
    start = time.time()
    try:
        result = _do_fetch_order(oid)
    except Exception:
        logger.exception("fetch_order failed")
        raise
    finally:
        logger.info(f"fetch_order took {time.time() - start:.3f}s")
    return result
```

**用装饰器**：

```python
@log_and_time
def fetch_user(uid): ...

@log_and_time
def fetch_order(oid): ...
```

**业务逻辑与横切逻辑彻底分离。**

## 2.3 前置：函数是一等公民

```python
# 1. 函数可以赋值给变量
f = print
f("hello")

# 2. 函数可以作为参数
def apply(func, x):
    return func(x)

apply(len, "hello")      # 5

# 3. 函数可以作为返回值
def make_adder(n):
    def adder(x):
        return x + n
    return adder

add5 = make_adder(5)
add5(10)                 # 15
```

**第 3 点是装饰器的基础。**

## 2.4 闭包

**定义**：内层函数记住了外层函数的变量，即使外层函数已经返回。

```python
def make_counter():
    count = 0                    # 外层变量
    def counter():
        nonlocal count           # 声明要修改外层变量
        count += 1
        return count
    return counter

c = make_counter()
c()      # 1
c()      # 2
```

**关键**：`count` 是**每个闭包实例独有**的。

```python
c1 = make_counter()
c2 = make_counter()
c1()     # 1
c1()     # 2
c2()     # 1  ← 独立的，不是 3
```

**闭包能"记住"状态，这是装饰器能实现"每个函数独立计时/独立缓存"的原因。**

### 查看闭包内容

```python
c.__closure__           # (<cell at 0x...: int object>,)
c.__closure__[0].cell_contents    # 当前值
```

## 2.5 无参装饰器

**装饰器的本质**：**接收一个函数，返回一个新函数。**

```python
def timer(func):
    @functools.wraps(func)                  # ★ 保留原函数信息
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        try:
            return func(*args, **kwargs)
        finally:
            elapsed = time.perf_counter() - start
            print(f"{func.__name__} 耗时 {elapsed * 1000:.2f}ms")
    return wrapper

@timer
def slow():
    time.sleep(0.1)

slow()      # slow 耗时 100.32ms
```

**`@timer` 是语法糖**，完全等价于：

```python
def slow():
    ...
slow = timer(slow)
```

## 2.6 `functools.wraps`：不能省

**不加会怎样**：

```python
def bad_decorator(func):
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper

@bad_decorator
def greet(name: str) -> str:
    """打招呼"""
    return f"hi {name}"

print(greet.__name__)    # wrapper   ← 变成了 wrapper！
print(greet.__doc__)     # None      ← 文档丢了！
print(greet.__annotations__)  # {}    ← 类型注解丢了！
```

**加上 `@functools.wraps(func)` 后**：

```python
print(greet.__name__)         # greet     ✓
print(greet.__doc__)          # 打招呼    ✓
print(greet.__annotations__)  # {'name': str, 'return': str}  ✓
```

**为什么这很重要**：

| 场景 | 不加 wraps 的后果 |
| --- | --- |
| **FastAPI 路由** | 依赖注入失效、文档显示 `wrapper` |
| **Pydantic 校验** | 读取不到参数类型 |
| 日志 | 记录的函数名全是 `wrapper` |
| 调试 | 堆栈信息不可读 |
| `inspect.signature` | 拿到空签名 |

> **记住：写装饰器第一件事就是 `@functools.wraps(func)`。** 这不是可选项。

## 2.7 带参数的装饰器（三层结构）

**需求**：`@retry(times=3, delay=1)` —— 装饰器本身要接收参数。

**结构变成了三层**：

```python
def retry(times=3, delay=1.0, exceptions=(Exception,)):
                    #  ↑ 第 1 层：接收装饰器参数
    def decorator(func):
                    #  ↑ 第 2 层：接收被装饰的函数
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
                    #  ↑ 第 3 层：实际执行的包装逻辑
            last_exc = None
            for attempt in range(1, times + 1):
                try:
                    return func(*args, **kwargs)
                except exceptions as e:
                    last_exc = e
                    if attempt < times:
                        time.sleep(delay * (2 ** (attempt - 1)))   # 指数退避
            raise last_exc
        return wrapper
    return decorator
```

**为什么是三层**：

```
@retry(times=3)          <- 先调用 retry(times=3)，返回 decorator
def fetch(): ...
# 等价于:
fetch = retry(times=3)(fetch)
#        ↑ 第1层返回 decorator   ↑ 第2层接收 func，返回 wrapper
```

**对比**：

```python
@timer                   # 无参：两层
def f(): ...

@retry(times=3)          # 带参：三层
def f(): ...
```

**记忆方法**：**看到装饰器带括号，就多一层。**

## 2.8 生产级的五个装饰器

### 2.8.1 重试（`retry`）

**必须的三个特性**：

| 特性 | 为什么 |
| --- | --- |
| **只重试特定异常** | 参数错误重试一万次也没用 |
| **指数退避** | 服务过载时疯狂重试会雪上加霜 |
| **上限** | 防止无限循环 |

```python
@retry(times=3, delay=0.5, backoff=2.0,
       exceptions=(ConnectionError, TimeoutError))
def call_llm(prompt: str) -> str:
    ...
```

**退避时间**：`0.5s → 1.0s → 2.0s`（总等待 3.5s 而不是固定的 1.5s）

**为什么要退避**：如果下游是**因为过载**而失败，固定间隔重试会让它更过载。

### 2.8.2 计时（`timer`）

```python
@timer
def query():
    ...
# query 耗时 12.34ms
```

**进阶**：记录到结构化日志而不是 print（Day4 会讲）。

### 2.8.3 缓存（`lru_cache` / 自定义）

```python
from functools import lru_cache

@lru_cache(maxsize=128)
def expensive(n: int) -> int:
    time.sleep(1)
    return n * n
```

**注意**：

| 坑 | 说明 |
| --- | --- |
| **参数必须可哈希** | `list` / `dict` 不能作为参数 |
| **缓存不会自动失效** | 数据变了还是返回旧值 |
| **内存占用** | `maxsize` 要设置 |
| **异步函数不适用** | `lru_cache` 不支持协程 |

**对 LLM 调用的启示**：相同 prompt 的调用可以缓存，能省大量钱。但要考虑**用户隔离**（不同用户不该共享缓存）。

### 2.8.4 限流（`rate_limit`）

```python
@rate_limit(max_calls=10, period=60)
def call_api():
    ...
# 超过 10 次/分钟 抛 RateLimitExceeded
```

**生产环境**用 Redis 做（Week3 会讲），单机版可以用内存。

### 2.8.5 日志（`logged`）

```python
@logged(level="INFO", log_args=True)
def create_user(name: str, age: int):
    ...
```

** 安全红线**：**绝不能记录密码、token、API Key。**

```python
SENSITIVE = {"password", "token", "api_key", "secret", "authorization"}

def _safe_repr(kwargs):
    return {k: ("***" if k.lower() in SENSITIVE else v)
            for k, v in kwargs.items()}
```

**这条在面试里是加分项** —— 说明你有安全意识。

## 2.9 装饰器要支持异步

**Day3 会讲 async，但这里先埋一个伏笔**：

```python
def timer(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        ...
        return func(*args, **kwargs)      # ← 如果 func 是 async，这里返回的是协程对象
    return wrapper
```

**问题**：如果 `func` 是 `async def`，`wrapper` 调用它只是**创建了协程**，并没有执行 —— 计时会得到 0.00ms，而且协程不会被 await。

**正确写法**：

```python
def timer(func):
    if inspect.iscoroutinefunction(func):
        @functools.wraps(func)
        async def async_wrapper(*args, **kwargs):
            start = time.perf_counter()
            try:
                return await func(*args, **kwargs)     # ← 要 await
            finally:
                ...
        return async_wrapper
    else:
        @functools.wraps(func)
        def sync_wrapper(*args, **kwargs):
            ...
        return sync_wrapper
```

**或者写一个通用的**（更简洁）：

```python
def timer(func):
    @functools.wraps(func)
    async def async_wrapper(*args, **kwargs):
        start = time.perf_counter()
        try:
            result = func(*args, **kwargs)
            if inspect.isawaitable(result):
                result = await result
            return result
        finally:
            ...
    return async_wrapper
```

**这一点在实际工作中非常重要** —— 否则你的计时装饰器在异步代码上会静默失效。

## 2.10 常见坑

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| `greet.__name__` 变成 `wrapper` | 忘了 `functools.wraps` | 加上装饰 |
| FastAPI 路由依赖注入失效 | 同上 | 加上 |
| 计时结果全是 0.00ms | 装饰了 async 函数但没 await | 用 `iscoroutinefunction` 分支 |
| 带参装饰器报 `missing 1 required positional argument` | 层数写错 | 确认是三层结构 |
| `lru_cache` 报 unhashable | 参数是 list/dict | 转成 tuple，或自己实现缓存 |
| 缓存返回了过期数据 | 没有失效机制 | 加 TTL 或手动清除 |
| 装饰器顺序导致行为异常 | 多个装饰器从下往上执行 | 见下方说明 |
| 日志里打印了密码 | 没做敏感字段过滤 | 加敏感字段黑名单 |

**装饰器的执行顺序**：

```python
@a
@b
@c
def f(): ...

# 等价于: f = a(b(c(f)))
# 应用顺序: c -> b -> a（从下往上）
# 执行顺序: a 的 wrapper -> b 的 wrapper -> c 的 wrapper -> f
```

**记忆**：**离函数越近的越先被"包"进去，所以最外层的 a 最先执行。**

## 2.12 一句话总结

**装饰器就是「接收函数、返回函数」的高阶函数，它把日志/重试/计时/缓存/限流这些横切关注点从业务逻辑里剥离出去；写装饰器必须加 `functools.wraps`（否则框架会失效），带参数的装饰器是三层结构，而装饰异步函数时必须 `await` —— 这三点在实际工作中都会踩。**
