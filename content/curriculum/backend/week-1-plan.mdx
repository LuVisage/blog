## 为什么第一周讲这个

**先看两段代码**：

```python
# 脚本思维
def get_user(id):
    conn = pymysql.connect(host="localhost", user="root", password="123456", db="test")
    cur = conn.cursor()
    r = cur.execute(f"SELECT * FROM users WHERE id = {id}")
    return cur.fetchone()
```

```python
# 工程思维
async def get_user(user_id: int, db: AsyncSession) -> User | None:
    """按 ID 查询用户。

    Args:
        user_id: 用户 ID，必须为正整数。
        db: 数据库会话（由依赖注入提供）。

    Returns:
        找到则返回 User，不存在返回 None。
    """
    logger.info("query_user", extra={"user_id": user_id})
    result = await db.execute(select(User).where(User.id == user_id))
    return result.scalar_one_or_none()
```

**差别不是「好不好看」，而是**：

| 脚本 | 工程 |
| --- | --- |
| `id` 是整数还是字符串？不知道 | 类型明确，IDE 能提示 |
| 密码硬编码，泄漏风险 | 配置外置，密钥管理 |
| **SQL 注入漏洞**（f-string 拼接） | 参数化查询 |
| 连不上数据库就崩 | 有错误处理与重试 |
| 同步阻塞，一次只能服务一个 | 异步并发 |
| 出问题只能 print | 结构化日志可检索 |

**面试官看你的代码，30 秒就能判断你是「写过脚本」还是「做过项目」。**

## 关键认知：为什么 Day3 最重要

**LLM 应用的本质是「等 I/O」**：

```
一次 LLM 调用耗时: 2 ~ 30 秒（几乎全是等网络）
一次数据库查询:    1 ~ 50 毫秒
一次向量检索:      5 ~ 100 毫秒
```

**同步代码的问题**：

```python
# 同步：处理 10 个用户请求，每个请求调一次 LLM（每次 3 秒）
for user in users:              # 串行
    result = llm.chat(...)      # 阻塞 3 秒
# 总耗时 = 10 × 3 = 30 秒
```

```python
# 异步：同时发出
results = await asyncio.gather(*[llm.chat_async(u) for u in users])
# 总耗时 ≈ 3 秒（并发）
```

**10 倍差距，只需要把函数改成 `async`。**

**现实**：

- OpenAI SDK 的 `AsyncOpenAI`
- LangChain 的 `ainvoke` / `astream`
- 你的 agent 教程里第 8 周的流式输出

**全部是 async 接口。** 不会异步，你只能写出最慢的版本。
