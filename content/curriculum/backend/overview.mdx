> **这套教程解决什么问题**：你学完了 16 周 AI 基础，会训模型了。
> 但把模型变成**别人能用的产品**，缺的是软件工程能力。
>
> 这套教程直接对着「AI 应用工程师 / Agent 开发工程师」的岗位缺口打。

---

## 一、为什么需要这一套

**一个扎心的事实**：市面上大多数 AI 教程教你训模型，但**岗位要的是交付产品**。

| 只会训模型 | 岗位真正要的 |
| --- | --- |
| 在 Jupyter 里跑通 demo | 写成可维护的服务，部署到服务器 |
| 同步代码，一次处理一条 | 异步并发，同时服务几百个请求 |
| 手写 `while True` 重试 | 超时、重试、熔断、可观测 |
| 密码写在代码里 | 密钥管理、鉴权、限流 |
| 只在自己的机器上能跑 | Docker 打包，一条命令在任何机器启动 |
| 出错了 print | 结构化日志、监控、告警 |

**来源**：这是从「[Agent开发工程师路线图.md](/learn/ml/agent-roadmap)」里识别的 6 个缺口，其中**缺口 1、2、3（Python 工程化 + 后端 + 部署）占了成功率的 70%**。

## 五、每周详细大纲

### Week1｜Python 工程化

> **目标**：把「能跑的脚本」变成「别人敢维护的代码」。

| 天 | 主题 | 关键内容 |
| --- | --- | --- |
| Day1 | 类型注解与数据校验 | `typing` / `Optional` / `Literal` / Pydantic / mypy |
| Day2 | 装饰器与高阶函数 | 闭包 / 装饰器 / `functools` / 重试与计时装饰器 |
| Day3 | 异步编程（重点） | `async/await` / 事件循环 / `asyncio.gather` / 并发控制 |
| Day4 | 测试与日志 | pytest / fixture / mock / 结构化日志 / 配置管理 |
| Day5 | 项目结构与打包 | 包组织 / `pyproject.toml` / 依赖管理 / CLI 入口 |

**为什么 Day3 最重要**：所有 LLM 框架（LangChain / OpenAI SDK）的流式接口都是 `async`。不会异步，就只能写最慢的串行代码。**这是本教程最重要的一天。**

### Week2｜FastAPI 后端开发

> **目标**：写出一个能给前端和 Agent 调用的 API 服务。

| 天 | 主题 | 关键内容 |
| --- | --- | --- |
| Day1 | HTTP 与 FastAPI 基础 | 请求/响应 / 路由 / Pydantic 模型 / 自动文档 |
| Day2 | 依赖注入与中间件 | `Depends` / 中间件 / 生命周期 / CORS |
| Day3 | 鉴权与安全 | JWT / OAuth2 / 密码哈希 / 限流 / 密钥管理 |
| Day4 | **SSE 流式输出**（重点） | Server-Sent Events / `StreamingResponse` / 打字机效果 |
| Day5 | 错误处理与可观测性 | 异常处理 / 结构化日志 / 请求追踪 / 健康检查 |

**为什么 Day4 最重要**：LLM 应用的「打字机效果」靠的就是 SSE。这是 AI 应用与前端的**主要接口形式**。

### Week3｜PostgreSQL 与 Redis

> **目标**：让数据持久化、可查询、可缓存。

| 天 | 主题 | 关键内容 |
| --- | --- | --- |
| Day1 | SQL 基础与 Python 连接 | 建表 / CRUD / psycopg / **参数化查询（防注入）** |
| Day2 | 索引与查询优化 | B-Tree / 复合索引 / `EXPLAIN ANALYZE` / N+1 问题 |
| Day3 | ORM 与迁移 | SQLAlchemy 2.0 / Alembic / 关系建模 |
| Day4 | Redis 与缓存 | 缓存策略 / 过期 / 会话 / 限流计数器 |
| Day5 | 事务与并发安全 | 事务隔离级别 / 乐观锁 / 连接池 |

### Week4｜Docker 与云部署

> **目标**：从「在我机器上能跑」到「在任何机器上都能跑」。

| 天 | 主题 | 关键内容 |
| --- | --- | --- |
| Day1 | Docker 基础 | 镜像/容器 / Dockerfile / 多阶段构建 / 体积优化 |
| Day2 | Docker Compose | 编排 API + Postgres + Redis / 网络 / 数据卷 |
| Day3 | Nginx 与 HTTPS | 反向代理 / 负载均衡 / Let's Encrypt / 域名 |
| Day4 | 云服务器部署 | 购买 / SSH / 防火墙 / 环境变量 / 一键部署脚本 |
| Day5 | CI/CD 与监控 | GitHub Actions / 自动测试 / 日志收集 / 告警 |

### Week5｜向量检索与 RAG 工程化

> **目标**：交付一个生产级 RAG 服务。

| 天 | 主题 | 关键内容 |
| --- | --- | --- |
| Day1 | 文本切分与 Embedding | 切分策略 / 重叠 / 元数据 / Embedding 选型与成本 |

| Day5 | 毕业项目 | 把前 5 周全部串起来，部署上线 |

## 六、毕业项目

**要求**：一个部署在公网、可被别人使用的 AI 服务，包含：

```
✅ FastAPI 服务，有 /docs 自动文档
✅ JWT 鉴权（未登录不能调用）
✅ SSE 流式输出（前端能看到打字机效果）
✅ PostgreSQL 存对话历史（带索引，查询 < 10ms）
✅ Redis 做会话与限流（每用户每分钟 N 次）
✅ 向量检索（RAG，支持引用来源）
✅ 结构化日志 + 健康检查端点
✅ pytest 测试覆盖率 > 60%
✅ Docker Compose 一条命令启动全部服务
✅ 部署在有 HTTPS 的云服务器上
✅ README 写清架构图与部署步骤
```

**为什么这个项目能拿到面试**：

| 能上线吗 | Docker + 云部署 + HTTPS |
| 懂 AI 吗 | RAG + 向量检索 + 评估 |

## 八、环境准备

### 阶段一：本地开发（Week1-3 够用）

```bash
# 1. 安装 Python 3.11+（推荐用 pyenv 或官方安装包）
python --version        # 应 >= 3.11

# 2. 创建虚拟环境
python -m venv .venv

# Windows
.venv\Scripts\activate
# macOS / Linux
source .venv/bin/activate

# 3. 安装依赖
pip install fastapi uvicorn pydantic pydantic-settings
pip install sqlalchemy alembic psycopg[binary]
pip install redis pytest pytest-asyncio httpx python-jose[cryptography] passlib[bcrypt]

# 国内加速
pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
```

### 阶段二：Docker（Week4 起）

```bash
# 安装 Docker Desktop（Windows/macOS）或 docker-ce（Linux）
docker --version
docker compose version
```

### 阶段三：云服务器（Week4 Day4 起）

**建议**：任意云厂商的 2核2G 入门机型即可（约 10~30 元/月）。
**学习期省钱技巧**：很多厂商有「学生认证免费试用」，先申请再买。

## 九、怎么用这套教程

1. **代码必须亲手敲**：不要复制粘贴。工程能力来自肌肉记忆。
2. **每天一个可运行产出**：每天结束时，你的项目都应该能跑起来并通过测试。
3. **遇到报错先读完整堆栈**：工程化的核心能力之一是「读懂错误信息」。
4. **每周末做一次「能上线吗」自查**：用第六节的清单逐项打勾。
5. **不要追求「学完再做项目」**：从 Week2 开始，就边学边把毕业项目往里加。
